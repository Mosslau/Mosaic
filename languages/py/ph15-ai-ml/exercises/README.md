## 练习 1：房价预测（★）

- **目标**：从零走一遍「数据 → 划分 → baseline → 特征缩放 → 线性回归 → 评估」的回归工作流（对应 roadmap「房价预测」）
- **要求**：
  - 合成一份带噪声的房价数据（如：`price = 30 + 1.0×面积 − 2.0×房龄 + 10×卧室数 + 5×位置评分 + 噪声`，n≈900）
  - 训练/测试 7:3 划分；**先跑 baseline**（永远预测训练均值）得到 RMSE
  - 标准化后用 LinearRegression / Ridge 建模，报告 train/test RMSE 与 R²
- **验收**：脚本输出 baseline 与模型的 RMSE 并断言「模型 RMSE < baseline 的一半」；**把实测数字写进验证块**；能说清「为什么 baseline 是必须的第一步」（roadmap 必会概念：先建立 baseline 再复杂化）

## 练习 2：故障分类（★★）

- **目标**：分类任务上学会「用准确率之外的指标挑模型」，并体会类别不平衡（对应 roadmap「故障分类」）
- **要求**：
  - 用与示例相同的数据生成方式但**换一个随机种子**（如 seed=7），生成健康 88% / 故障 8% / 故障 4% 的三分类数据
  - 对比 kNN（k=3/5/7）与 RandomForest（含 `class_weight="balanced"` 变体），全部报告 accuracy + macro-F1 + 各类 recall + 混淆矩阵
  - 尝试解释：为什么 acc 相近时 macro-F1 能拉开差距；`class_weight="balanced"` 在本数据上是有益还是有害、为什么
- **验收**：脚本按 macro-F1 选出最优模型并输出混淆矩阵；**把实测数字写进验证块**；能说清「漏报 vs 误报哪个代价更高、指标该怎么选」

## 练习 3：传感器异常检测（★★★）

- **目标**：无监督异常检测 + 用注入异常评测检出质量（对应 roadmap「传感器异常检测」）
- **要求**：
  - 造「电流与功率强相关」（power ≈ 28 × current）的正常数据，异常样本是「电流正常但功率偏低 80~130W」——**每个维度单独看都在正常范围，只有联合起来才异常**
  - 用「已知正常的训练段」估计均值/协方差，分别实现：① 单维 z>3 阈值法；② 马氏距离法（`(x−μ)ᵀ Σ⁻¹ (x−μ) > 阈值`，阈值取 4 维卡方 99.9% 分位）；③ IsolationForest（contamination 参数要自己猜）
  - 在「200 正常 + 50 注入异常」的测试集上报告各自的 recall / precision
- **验收**：脚本输出三组检出数字并断言「马氏距离 recall ≥ 0.9 且明显高于单维 z 法」；**把实测数字写进验证块**；能说清「为什么单维统计法有相关性盲区」「无标签的异常检测靠什么调阈值」

## 练习 4：文本分类（★★）

- **目标**：走通「文本 → 向量 → 模型 → 评估」闭环，理解 TF-IDF 与语料质量（对应 roadmap「文本分类」）
- **要求**：
  - 自建小型日志语料：info / warning / error 三级各 15 条左右，**措辞要有交集**（如 battery、brake、software 跨级出现，否则分类会简单到没意义）
  - `TfidfVectorizer` + `LogisticRegression`（可尝试 `ngram_range=(1,2)`），报告 test accuracy、macro-F1、混淆矩阵，并打印误判示例逐条解释
- **验收**：脚本输出 acc / macro-F1 / 混淆矩阵 / 误判示例；**把实测数字写进验证块**；能说清「TF-IDF 比纯词频好在哪」「语料措辞与样本量如何决定文本分类的天花板」（数据质量决定上限的又一现场）

## 练习 5：简单 RAG 问答（★★★）

- **目标**：实现一个迷你检索增强问答，量出「检索质量 → 回答质量」的因果（对应 roadmap「简单 RAG 问答」）
- **要求**：
  - 自备 8 段左右英文资料（如电动车手册片段），准备 5 个问句——**至少 4 问需要 ≥2 段资料才能答完整**，每题标注「所需资料段」
  - TF-IDF + 余弦检索（numpy 手写即可），取 top-k；评估指标用「资料覆盖率 cover@k = 所需资料段是否都在 top-k 里」，分别报告 cover@1/cover@2/cover@3
  - 找出至少一个检索失败原因，用简单的文本处理改进它（提示：词形归一——`charging/charges`、`discharge/discharges`、`deep/deeply` 互不匹配；同义扩展；或停用词处理），报告**改进前后**的 cover@k
- **验收**：脚本输出改进前后的 cover@1/2/3 并断言 cover@3 有提升；**把实测数字写进验证块**；能说清「RAG 的回答质量为什么主要由检索质量决定、top-1 为什么常常不够用」
