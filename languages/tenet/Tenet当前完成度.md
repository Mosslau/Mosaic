### 6. struct 数组字段

```tenet
struct S {
    fixed: array<int, 3>;
    dynamic: array<int>;
    x: int;
}
```

三套都支持：

- 固定数组字段；
- 动态数组字段；
- 字面量、深拷贝、整体赋值；
- `s.fixed[i]` / `s.dynamic[i]`；
- `push(s.dynamic, x)`、`len(s.dynamic)`；
- `s.dynamic = [..]` / `s.dynamic = t.dynamic`；
- struct 参数/返回值；
- 递归 copy/drop；
- `print(s)` 展开 `fixed: [..]` / `dynamic: [..]`。

### 7. struct 数组中的动态字段

```tenet
struct P { a: array<int>; }
let arr: array<P, 2> = [P { a: [1] }, P { a: [2] }];
push(arr[0].a, 9);
print(arr[0].a[0]);
```

三套都支持：

- `arr[i].a[j]`；
- `arr[i].a = [..]`；
- `push(arr[i].a, x)`；
- 递归 copy/drop；
- 固定 `array<P,N>` 与动态 `array<P>`。

## 二、可以做什么

Tenet 现在可以写：

- 递归算法：斐波那契、阶乘、汉诺塔；
- 循环算法：FizzBuzz、素数、排序、查找；
- 结构化数据：点、线段、学生记录等；
- 固定矩阵：`array<array<int, N>, M>`；
- 动态向量：`array<int>`；
- 动态矩阵/邻接表：`array<array<int>>`；
- struct 数组：`array<P, N>` / `array<P>`；
- 带动态数组字段的 struct；
- 纯计算、无输入的批处理程序。

示例输出：

```text
3 7 5 9
S { a: [7, 2, 3], x: 9 }
[[1, 2], [3]]
```

## 三、不能做什么

### 1. 没有标准库

- 无 `read` / 文件 IO；
- 无字符串索引/切片；
- 无 `int` ↔ `string` 转换；
- 无排序/集合等库函数；
- 只有 `print`。

### 2. 没有模块系统

- 无 `import` / 多文件 / 分离编译；
- 所有代码必须在一个 `.tenet` 文件里。

### 3. 没有高级语言特性

- 无 `Option` / `Result` / `match` / `?`；
- 无泛型；
- 无 trait / 方法；
- 无闭包；
- 无 `for`；
- 无异常。

### 4. 数组仍有限制

- 不支持动态 `array<struct>` 字段；
- 不支持 struct 的动态嵌套字段；
- 不支持更深嵌套 `array<array<array<T>>>`；
- 固定数组字段 `s.a` 不能整体读取；
- `f(s.a)` 不支持；
- `array<struct>` 元素不能整体读成 struct 值；
- `print(arr[i].a)` 不支持；
- 多级数组/字段混用路径有限。

### 5. 内存管理不完整

- 动态数组/struct 动态字段有递归 drop；
- 但没有 RC/GC；
- 字符串拼接是 `malloc`，没有统一释放；
- arm64 `hello.tenet` 用 `leaks` 测到字符串拼接泄漏（约 80B 级）；
- 没有正式泄漏检测/内存安全保证。

### 6. 工程化不足

- 无调试信息；
- 无优化（arm64 完全无优化，Rust/C++ 仅 LLVM 默认）；
- arm64 仅支持 arm64；
- 参数最多 8 个，`print` 最多 9 个；
- 无自举；
- 无包管理/构建系统；
- 无完整语言规范测试集。

## 五、作为编译器，完成度怎么样

### 做得好的部分

- 是真正的 **AOT 编译器**，不是解释器：
  - 词法 → 语法 → 类型检查 → 代码生成 → 原生二进制；
- 三种自主度后端都完整：
  - LLVM 文本；
  - LLVM 库；
  - 手写 AArch64；
- 有自定义 ABI：
  - struct 指针/sret；
  - 固定数组按槽；
  - 动态数组 descriptor；
- 有值语义、深拷贝、递归 drop；
- 有 2405 项测试和三套对拍；
- 能编译结构化、动态容器、嵌套数组程序；
- 错误定位、越界检查、内存释放路径较完整。

### 还差的部分

- **语言广度**：无标准库、IO、模块、泛型、trait、错误处理；
- **工程化**：无优化、调试信息、包管理、独立编译；
- **内存安全**：字符串泄漏，无 GC/RC；
- **平台**：arm64 后端仅 arm64；
- **生态**：无库、无工具链、无自举。

### 结论

> **作为教学/研究型编译器：完成度较高。**
> 前端、三种后端、ABI、数组/struct/动态内存、测试体系都已打通，能编译一批 nontrivial 的算法程序。

> **作为通用编程语言/生产编译器：完成度仍然有限。**
> 缺标准库、IO、模块、错误处理、泛型、优化和完整内存管理，距离“能写真实应用”还有明显距离。

一句话：

> **Tenet 已经是一套能跑、能验证、三后端一致的语言实现；但它是一个“核心语言 + 容器 + 值语义”的强子集，不是完整通用语言。**
