## 练习 1：对比 vector 与 list 遍历性能（★★★）

- **目标**：同一批数据分别放进 `std::vector<int>` 与 `std::list<int>`，实测「顺序遍历求和」的差距并解释为什么
- **要求**：
    - 用同一组随机 int（如 200 万 个）构造两种容器，内容必须逐元素相同
    - 各自实现顺序遍历求和，跑出多轮最优耗时并打印（ns/元素 或 ms）
    - 容器的每次求和结果必须相等（内容相同是前提）；结果要被消费（打印/断言），不能被编译器整体消除
    - 测时注意：预热、多轮取最优、每轮输入略有变化（防公共子表达式消除）
- **验收**：运行输出两种容器的耗时对照与大小；断言两者结果一致且 vector 遍历快于 list 遍历；能口头解释快的原因（连续内存 / 缓存行预取 vs 每节点指针跳转，主文档 4.1）
- **提示**：list 的节点散布在堆上、每次前进要解引用一个 next 指针，而 vector 是 64 B 缓存行连续搬运；数据量要大过缓存（参考实现 `sol-01-vector-vs-list.cpp`）

## 练习 2：优化 CSV 解析（★★★）

- **目标**：对同一份 CSV 文本做解析统计，把「istringstream + 逐 token 拷贝」换成「零拷贝 + `std::from_chars`」，实测吞吐提升并保证结果一致
- **要求**：
    - 在内存里生成一份 CSV（如 10 万行，格式 `id,name,score`），避免把文件 IO 混进被测区
    - **基线实现**：逐行 `std::istringstream` 读取三个字段（每次字段一个 `std::string` 分配 + `std::stod`）
    - **优化实现**：对同一份 `std::string_view` 做单遍扫描，字段直接用 `std::from_chars` 解析（不产生中间字符串）
    - 两种实现统计同一指标（如 id 为偶数的行的 score 之和与计数），结果必须一致
- **验收**：输出两版耗时与吞吐（MB/s 或 行/s）；断言结果一致且优化版明显更快；能解释 `from_chars` 为何比 `stod`/`istringstream` 快（无 locale、无状态构造、无分配）
- **提示**：解析失败要有可诊断处理（ph09 纪律）；注意 id/score 字段的整数与浮点精度（参考实现 `sol-02-csv-parse.cpp`）

## 练习 3：减少热点路径内存分配（★★★）

- **目标**：对一批日志行做词频统计，让热路径上的每词一次堆分配降到「几乎为零」，用全局 `operator new` 计数验证
- **要求**：
    - 输入：若干行文本（如 5 万行，每行几个英文单词），整份输入构造完成后常驻内存
    - **基线**：逐行 `istringstream` 切词，每个词都构造 `std::string` 后再 `++counts[std::string(word)]`——每次出现一次堆分配
    - **优化**：同一份输入用 `string_view` 切词（零拷贝），映射表从 `unordered_map<string, int>` 换成 `unordered_map<string_view, int>`——只有新词首次出现才分配
    - 用重载全局 `operator new` 数出两种实现的区域分配次数，并测量耗时
- **验收**：输出两版分配次数与耗时；断言结果（出现次数最多的词及计数）一致、优化版分配次数显著更少；能说清 string_view 作键的**生命周期前提**（输入必须比映射活得久）
- **提示**：基线里 `istringstream` 切词本身也分配，别让它混进你的计数区；string_view 键的哈希比较只看内容、与指向哪份拷贝无关（参考实现 `sol-03-alloc-reduction.cpp`）
