# exercises —— 并发编程阶段练习

完成顺序建议：按 1~5 顺序完成。参考实现在 `sol-*` 文件中，做完再看。验证环境：Apple clang 21（g++ 兼容），`c++ -std=c++20 -Wall -Wextra -pthread`。

## 练习 1：多线程计数器（★）

- **目标**：分别用 mutex 与 atomic 实现多线程计数，并亲手观察一次数据竞争
- **要求**：
  - 8 个线程各对共享计数器累加 100000 次，最终值必须恰好是 800000
  - 版本 A 用 `std::mutex` + `std::lock_guard` 保护；版本 B 用 `std::atomic<int>`
  - 两个版本写在同一个程序里依次运行，各自校验结果
  - 思考（不必写代码）：去掉保护后结果为什么偏小？用 `-fsanitize=thread` 复现一次
- **验收**：`c++ -std=c++20 -Wall -Wextra -pthread` 零警告；两个版本输出均为 800000，断言通过、退出码 0

## 练习 2：线程安全队列（★★）

- **目标**：实现一个可多生产者、多消费者共用的线程安全队列
- **要求**：
  - 三个接口：`push`（入队并通知）、`pop`（非阻塞，空队列返回 `std::nullopt`）、`wait_pop`（阻塞直到有元素）
  - `wait_pop` 必须用 `cv.wait(lock, pred)` 谓词等待，不允许裸 `wait` + `if`
  - notify 放在锁外；取值与消费动作（如打印）分离，临界区内不做 IO
  - 类模板化（`template <typename T>`），底层容器自选
- **验收**：单生产者单消费者跑 10 个元素，顺序与值全部正确、队尾判空为 true；`c++ -std=c++20 -Wall -Wextra -pthread` 零警告

## 练习 3：生产者消费者（★★）

- **目标**：在练习 2 的基础上实现容量受限的有界队列，体会「双条件变量」
- **要求**：
  - 队列容量固定为 4；满时生产者阻塞等待，空时消费者阻塞等待
  - 需要两个 `std::condition_variable`：`not_empty_` 与 `not_full_`，唤醒方向不能搞反
  - 1 个生产者生产 0~19 共 20 个元素，1 个消费者消费 20 个，不允许丢失、重复或死锁
  - 断言校验消费者收到的序列恰好是 0~19 顺序排列
- **验收**：程序正常结束（无挂起），断言通过、退出码 0；`c++ -std=c++20 -Wall -Wextra -pthread` 零警告

## 练习 4：简单线程池（★★★）

- **目标**：实现固定大小的线程池，掌握线程池的生命周期管理
- **要求**：
  - 构造时启动 N 个 worker 线程；`submit(std::function<void()>)` 投递任务
  - 析构时必须先置停止标志、再 `notify_all` 唤醒、最后 join 全部 worker——已提交的任务必须全部执行完才能退出
  - 任务在锁外执行（锁内只取任务）；worker 退出条件是「已停止且队列为空」
  - 用原子计数器校验：提交 12 个任务、4 个 worker，析构后计数恰好为 12
- **验收**：程序正常结束（无挂起、无 terminate），断言通过、退出码 0；`c++ -std=c++20 -Wall -Wextra -pthread` 零警告

## 练习 5：jthread + stop_token 可取消任务（★★）

- **目标**：用 C++20 jthread 实现一个可优雅取消的周期性后台任务
- **要求**：
  - 后台线程每 200ms 打印一次 tick；主线程约 0.6s 后请求停止
  - 线程函数第一个参数为 `std::stop_token`，循环条件是 `!st.stop_requested()`
  - 收到停止请求后打印一行清理日志再退出；不允许 detach、不允许手动 join（交给 jthread 析构）
  - 断言校验：退出前至少执行过一次 tick（证明任务真的跑过）
- **验收**：输出若干 tick 后以清理日志收尾，断言通过、退出码 0；`c++ -std=c++20 -Wall -Wextra -pthread` 零警告
