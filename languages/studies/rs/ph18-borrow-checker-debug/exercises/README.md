## 练习 1：收集 5 个借用错误并写修复说明（★★）

- **目标**：把「看得到错误」升级成「讲得清错误」（roadmap 练习「收集 5 个借用错误并写修复说明」；对应主文档 3.1 错误号地图）
- **要求**：
  - 从主文档 3.2~3.8 的案例与 `examples/e01~e08` 中，**选 5 个你先前没动手修过的错误码**（也可以自己造触发代码）
  - 每种错误码写一条笔记，固定四段：① 最小触发代码 ② rustc 报错第一行原文（含错误码与 `-->` 定位）③ 一句话归因（错误码语义 + 为什么违反借用规则）④ 修复代码 + 一行「修复后所有权/借用流向」说明
  - 至少覆盖 **3 种不同错误码**，其中至少 1 种要用到 examples 里没演示过的修法（如数据拥有化、消费式 API、字段拆分）
- **验收**：5 条笔记四段齐全；错误码与触发代码语义对得上（参考实现 `sol-01-case1-e0503` ~ `sol-01-case5-e0596` 五个子目录，各含 error/fix 与错误码对应）

## 练习 2：把长借用拆成短作用域（★★）

- **目标**：同一份「先读后写」需求，用两种合法修法表达，并解释错误版为什么被拒（roadmap 练习「把长借用拆成短作用域」；对应主文档 3.6）
- **起点**（原样照抄到你的文件，先 `rustc --edition 2021` 观察报错）：

  ```rust
  /// 把「末尾 n 个元素的和」追加到 items 末尾，然后打印这段尾部（错误版）。
  fn append_tail_sum(items: &mut Vec<u32>, n: usize) {
      let len = items.len();
      let tail: &[u32] = &items[len - n..];
      let sum: u32 = tail.iter().sum();
      items.push(sum);
      println!("尾部 {tail:?} 之和 {sum}");
  }
  ```

- **要求**：不改变「先读尾部、再追加和、后打印尾部内容」的观察顺序，也不允许整体 clone 整个 `items`；实现两种修法并各写一句话解释
  - 修法 A：让尾部借用的「最后一次使用」发生在 push 之前
  - 修法 B：push 之后仍需要这段内容时，把尾部转成拥有的数据
  - 回答：错误版为什么被拒？提示：`Vec::push` 可能触发什么？（对应主文档 4.2 的「重分配」视角）
- **验收**：两种修法都能编译运行且语义与起点一致；对「为什么被拒」的解释提到扩容/重分配（参考实现 `sol-02-tail-sum/`，error.rs + fix.rs）

## 练习 3：比较 clone、索引、拆结构体三种修复方式（★★★）

- **目标**：同一个「读名字 + 改分数」冲突，分别用三种修法解决并写成能辩护的对比（roadmap 练习「比较 clone、索引、拆结构体三种修复方式」；对应主文档 3.7/3.8/3.9）
- **场景**：

  ```rust
  struct Player { name: String, score: u32 }
  struct Team { players: Vec<Player> }
  // 任务：找出最高分玩家，打印它的名字，然后把它的分数清零。
  // 若先把名字借用出去再改分数，会触发 E0502 —— 这就是要绕开的冲突。
  ```

- **要求**：
  - 分别实现三个等价函数（可共用 Team 结构；拆结构体修法允许重新设计数据结构，如平行数组）
    - 修法 1：clone 名字再动手
    - 修法 2：先算下标（索引/临时变量），打印借用到句尾即收口再改
    - 修法 3：重构数据结构，让「读的名字」与「改的分数」落在不重叠的字段/容器上
  - 写一段对比，至少覆盖两条判据：**分配行为**（谁触发了堆分配）、**代码/结构成本**（谁改了数据结构），并给出一句「什么场景下 clone 是可接受的」（对应主文档 5 节判据）
- **验收**：三个函数全部编译运行通过，语义一致（最高分玩家被清零）；对比含 ≥2 条判据（参考实现 `sol-03-three-fixes.rs`，含对照运行与断言）

提示：练习 1 练「错误码归因」，练习 2 练「作用域直觉」，练习 3 练「三种修法的取舍」。做完三题后，你收集/修复的错误代码覆盖面应达到十个左右 —— 去 project/ 把它们沉淀成可被机器自动验证的练习集。
