## 2. 来源与演变

机器学习「用数据拟合规律」的思想可以追溯到 1950 年代感知机（Perceptron），但 Python 把这件事变成工程常规，靠的是**三个时期的叠加**：① 2000 年代**统计学习库**成型——2007 年 David Cournapeau 发起的 scikit-learn（scikit = SciPy 工具包，2010 年后由 INRIA 团队主导）把「fit / predict 统一接口 + 一套评估工具」定成 Python ML 的事实标准，让「换模型只改一行」成为可能（ex03 的模型矩阵就是这么比的）；② 2010 年代**深度学习复兴**——2012 年 AlexNet 在 ImageNet 上碾压传统方法，2016-2017 年 PyTorch（Facebook，2017 年发布、2018 年 1.0）用「动态计算图 + 自动求导」把神经网络训练变成可调试的 Python 代码；③ 2018 年后的**大模型与检索增强**——2017 年 Google 的《Attention Is All You Need》提出 Transformer，2018 年 HuggingFace 的 transformers 库把预训练模型变成「pip install 即用」；2020 年 Lewis 等人的 RAG 论文把「检索 + 生成」拼在一起，催生了向量数据库（FAISS 2017、Milvus 2019、pgvector 2021）这一新基础设施。Python 在这条线上的角色始终如一：**把「数据 → 模型 → 评估」的每次迭代成本压到最低**，让算法研究者与业务工程师共用同一套语言。

| 版本/里程碑 | 年份 | 主要变化 |
|------|------|---------|
| 感知机（Rosenblatt） | 1957 | 第一个可学习的线性分类器，神经网络思想的起点 |
| 统计学习成熟（SVM、AdaBoost、随机森林） | 1995-2001 | 核方法与集成学习成为主流；随机森林 2001（Breiman） |
| scikit-learn 起步 | 2007 | 统一 fit/predict/transform 接口 + 完整评估工具，Python ML 事实标准 |
| AlexNet / 深度学习复兴 | 2012 | CNN 在 ImageNet 碾压传统方法，GPU 训练进入主流 |
| PyTorch 1.0 | 2017-2018 | 动态计算图 + 自动求导，研究与工程同语言的深度学习框架 |
| Attention Is All You Need | 2017 | Transformer 架构；2018 年 BERT/transformers 库，预训练-微调范式 |
| RAG（Retrieval-Augmented Generation） | 2020 | 检索 + 生成结合；向量数据库（FAISS/Milvus/pgvector）随之成为基础设施 |

**这段历史给现在的两个启示**：① **接口的胜利**——sklearn 的 fit/predict 统一接口让"换模型只改一行"（3.5 的模型矩阵就是这么比的），这是它能统治 Python ML 近二十年的关键设计决策，比任何单个算法都重要；② **分层共存而非取代**——统计学习（sklearn）、深度学习（PyTorch）、检索增强（RAG）三者解决的是不同问题，没有谁淘汰谁：3.9 的表格数据用 RF、3.10 的文本检索用 TF-IDF、大模型应用用 RAG，都是"按问题选工具"。

本文示例以 **Python 3.13.9** 为基线（本机验证工具链实测版本），第三方依赖 **numpy 2.3.5 + pandas 2.3.3 + matplotlib 3.10.6 + scikit-learn 1.7.2 + scipy 1.16.3**（全部本机已装并实测，`python3 -c "import numpy, pandas, matplotlib, sklearn, scipy"` 通过）；**PyTorch 与 Transformers 未安装，未在本环境验证**——本阶段涉及它们的内容（3.9、3.10）以 2024-2025 年的公开文档/论文为基线做概念讲解，示例代码一律用 sklearn/numpy 实现并实测。本阶段的核心 API（train_test_split / fit / predict / metrics / cross_val_score / Pipeline）自 sklearn 0.18 起近十年未变，是 Python 生态里最稳定的部分之一——「先划分、先基线、再建模、只看测试集一次」这套纪律长期成立。

## 3. 语法与参数

### 3.1 机器学习工作流总览与数据划分

**一次机器学习实验 = 数据 + 模型 + 评估三件套**，顺序固定（roadmap 必会概念：训练、验证、测试集要分开）：

```text
原始数据
  │  ① 划分（先做！）
  ▼
train（训练） ──► 学参数 ──► val（验证，可反复用：选模型/调参）
  │                              │
  └── 只许碰一次 ◄──── test（测试，验收最终模型，绝不用于调参）
```

sklearn 的标准写法（本阶段所有示例的统一骨架）：

```python
# examples/ex05-crossval-tuning.py 的划分骨架 —— 先切出 test 再切 val（已验证）
X_dev, X_te, y_dev, y_te = train_test_split(X, y, test_size=0.25, stratify=y, random_state=SEED)
# X_dev 上再切 val 用于调参；test 直到最后才碰一次
```

- **为什么先划分**：模型的任何「进步」都可能是记住了划分噪声。测试集一旦参与调参，分数就会虚高（ex05 用 10 个划分 seed 实测：同一个模型，验证集 acc 在 **0.920~0.973** 之间乱跳——单次划分的分数是运气）。
- **stratify=y（分层抽样）**：类别不平衡时按类别比例抽样，避免某一折/某一划分恰好没抽到少数类（本阶段数据健康 88% / 补能过压 8% / 过热振动 4%，分层后各划分的类别比例稳定）。
- **random_state 固定**：划分、模型、数据生成全部固定随机种子 → 实验可复现。本阶段所有数字都是 seed=42（练习 2 故意换 seed=7，让你体会数字随划分/种子波动）。

**为什么要 train/val/test 三层而不是两层**：既然 test 最后才碰，为什么不能只切 train/test、直接在 test 上选模型？——**因为"选模型/调参"本身也是一种学习**：你在 10 个模型里挑 acc 最高的那个，等价于让 test 数据参与了你的决策，test 就不再是"没见过的数据"了（3.3 把它归为第三种泄漏：划分泄漏）。所以标准做法是**三层**：train 学参数 → val（从 train 里再挖一份）反复选模型/调参 → test 只在全部决定做完后验收一次。数据量小时三层切分太奢侈，就用 3.7 的交叉验证在 train 内部替代 val——**本质一样：调参用的数据，绝不能是最终验收用的数据**。

> 阶段内容隔离：数据读取、清洗、缺失值处理的系统技能属于 ph09 数据分析阶段，这里只谈「划分与防泄漏」；**时间序列的划分不能用随机切分（要按时间切）**——时序建模超出本阶段，见 roadmap 第 18 节数据平台分析方向的进阶内容。

### 3.2 先建立 baseline 再复杂化

**任何模型都要先有个「什么都不学」的对照**（roadmap 必会概念）：分类的 baseline 是「永远猜最多的类」，回归的 baseline 是「永远预测均值」。baseline 不是用来赢的，是用来回答「我的模型到底贡献了多少」：

| baseline | 定义 | 本阶段实测 |
|----------|------|-----------|
| 分类：多数类 | 永远预测训练集最常见的类别 | 故障数据全猜「健康」acc **0.880**（ex03） |
| 回归：均值 | 永远预测训练集目标均值 | 房价数据 RMSE **29.2 万**（练习 1） |
| 检索：cover@1 | RAG 只取 top-1 能覆盖多少问答所需资料 | 迷你语料 **0/5**（练习 5） |

于是「模型 acc 0.930」的正确读法是「比多数类 baseline 只高 0.050，且看混淆矩阵：24 个过压故障漏了 13 个、12 个过热振动漏了 6 个」（ex03 实测）——**没有 baseline 的数字没有意义，有 baseline 你才知道该高兴还是该回去改数据**。project/ 的 `cli.py` 把两个 baseline 直接打进验收输出（回归 baseline RMSE 15.13% vs 模型 2.69%）。

### 3.3 数据质量与数据泄漏

**数据质量决定模型上限**（roadmap 必会概念）——模型只是「把数据里的规律榨出来」的工具，源头脏，规律就是脏的。ex01 用同一份数据做了四组对照（全部实测）：

| 场景 | test acc | 读法 |
|------|---------|------|
| 干净数据（60/20/20 划分 + 标准化 + kNN） | **0.930** | 上限参考（少数类 recall 只有 0.46/0.50，见 3.5） |
| 训练集 25% 标签被改成错误类别（**只在划分后污染训练子集**，评估标签干净） | **0.873** | 错标是最伤的脏数据：test 从 0.930 掉到 0.873（−0.057，换 flip seed 实测 0.870~0.900）；若把评估标签也一起污染会虚跌到 0.75 量级——那是把「学错」与「评错」混在一起的测量陷阱 |
| voltage/current 两列 60% 缺失 + 均值填充 | **0.917** | 单列信息损失的影响相对温和（kNN 对列缺失稳健），但均值填充只补回均值、补不回分布 |
| 加入「诊断后才知道的维修码」（泄漏特征） | val **0.990** | 验证分数虚高——换成真实预测输入（无该码）后回落到 **0.897** |

**数据泄漏（leakage）是初学者最隐蔽的错误**：任何「建模时还不存在、预测时才拿不到」的信息一旦进特征，验证分数就会骗人。三类常见泄漏：① 目标衍生特征（把答案混进特征，ex01 的维修码）；② 统计量泄漏（标准化/填充的均值和方差用了全量数据——**缩放器只能 fit 训练集**，ex01/ex02 的 `StandardScaler().fit(X_tr)` 是纪律）；③ 划分泄漏（先全量清洗再切分、重复样本跨 train/test、用测试集反复调参）。真实工程里「模型上线后效果暴跌」的常见原因之一就是开发时不小心用了未来信息。**测试集只在最后碰一次**是这条纪律的总纲。

> ⚠️ 本阶段的「脏数据」都是人为可控的合成噪声（错标、挖空、泄漏列），所以能精确量出「脏到什么程度掉多少分」。真实数据的脏更隐蔽：非随机缺失（故障样本更容易断采时，均值填充会把故障特征拉向均值——漏报率上升）、分布漂移（换了一批传感器/用户后旧模型失效）。识别与应对它们的方法是 ph09 的数据清洗 + 本阶段的评估纪律，诊断出「谁在拖后腿」靠的是对照实验，不是猜。

**缺失的三种机制（概念层，深化上面的"非随机缺失"）**：统计学习把缺失分为三档，决定你该不该填充、能不能填充：

| 机制 | 含义 | 例子 | 均值填充可行？ |
|------|------|------|--------------|
| MCAR（完全随机缺失） | 缺失与任何变量无关 | 偶发采集断点 | 基本可行（只损失信息） |
| MAR（随机缺失，可由其他变量解释） | 缺失与**已观测**变量有关 | 高温时段温度计才失效（可由"环境温度"解释） | 可建模预测填充（更优） |
| MNAR（非随机缺失） | 缺失与**缺失值本身**有关 | 过压故障时电压探头先坏——**坏样本自己爱缺席** | **均值填充会引入系统性偏差**（3.3 ⚠️ 的漏报上升正是它） |

判断顺序：先问"缺失与什么有关"——能被其他列解释（MAR）就值得用模型预测填充；解释不了且疑点指向缺失本身（MNAR），填充前要三思，工程上常改为"缺失本身作为信号"（加一个 is_missing 标志列）。设备的传感器断采大多属 MNAR，这是 ph09 清洗与后续故障建模里反复要用的判断。

### 3.4 特征工程：把数据喂成模型要的形状

模型看到的是矩阵：行是样本，列是特征。**特征工程 = 决定「喂什么形状」，由模型的数学假设决定**（ex02 实测）：

```python
# examples/ex02-feature-engineering.py —— 缩放：只有距离模型在意（已验证）
knn_raw = KNeighborsClassifier(n_neighbors=5).fit(X_tr, y_tr)          # 未缩放
scaler = StandardScaler().fit(X_tr)                                    # 只 fit 训练集！
knn_sc = KNeighborsClassifier(n_neighbors=5).fit(scaler.transform(X_tr), y_tr)
```

| 场景 | 实测（ex02，seed=42） | 机制 |
|------|---------------------|------|
| kNN 未缩放 vs 缩放 | test **0.890 → 0.930** | 五列量纲差异巨大（实测整列 std：temp 6.27 / voltage 0.21 / current 2.88 / vibration 0.45 / resistance 0.16），欧氏距离被大数域列支配，缩放后各列等权 |
| 随机森林 未缩放 vs 缩放 | 完全一致（0.963/0.947） | 树按阈值分裂，对单调缩放不敏感——**树模型不需要缩放** |
| LR 类别编码 label-encoding vs one-hot | test **0.917 → 0.927** | 名义类别（电芯批次 A/B/C/D）没有顺序；label-encoding 把 0..3 当连续值、隐式假设「A<B<C<D」，B/D 批次电压都偏高（非单调）时单系数拟合不了；one-hot 每类一个系数 |

规则总结：**距离模型（kNN、SVM、线性/岭回归）要缩放；树模型（决策树、随机森林）不敏感；名义类别要 one-hot（或树模型内的 Ordinal 编码），有序类别（评分 1~5）才适合 label-encoding**。文本是特殊的「高维稀疏特征」——把它向量化的 TF-IDF 见 3.10 与练习 4。

> ⚠️ 缩放与编码的「统计量/词表」只能从训练集学（`fit` 在 train 上、`transform` 全量用同一个对象）——这既是特征工程规则也是防泄漏规则（3.3 的统计量泄漏）。

### 3.5 模型训练与评估指标

sklearn 的模型接口是**统一的 fit/predict**：`model.fit(X_train, y_train)` 学参数，`model.predict(X)` 出预测，换模型只改构造那一行。先看四个模型在故障数据上的表现（ex03 实测，seed=42）：

| 模型 | acc | macro-F1 | weighted-F1 | 各类 recall（健康/过压/过热振动） |
|------|-----|---------|------------|--------------------------------|
| 多数类 baseline（全猜健康） | 0.880 | — | — | 1.00 / 0.00 / 0.00 |
| kNN(5)（标准化后） | 0.930 | 0.728 | 0.921 | 0.992 / 0.458 / 0.500 |
| LogisticRegression | 0.930 | 0.698 | 0.925 | 0.985 / 0.583 / 0.417 |
| RandomForest | **0.947** | **0.793** | 0.942 | 0.996 / 0.583 / 0.583 |

**指标各回答一个问题**（roadmap 必会概念：能评估模型效果）：

- **accuracy** = 猜对的比例——只适合类别均衡；类别不平衡时被多数类稀释（全猜健康也有 0.880，acc 0.930 看不出 kNN 漏了一半故障）；
- **precision（精确率）** = 预测为某类的样本里有几成真（误报少不少）；
- **recall（召回率）** = 真某类里抓住了几成（漏报少不少）；
- **F1** = 二者的调和平均（`2PR/(P+R)`），单指标权衡误报与漏报；
- **macro-F1** = 各类 F1 直接平均——**对少数类公平的尺子**（kNN 0.728 vs RF 0.793，acc 拉不开、macro-F1 拉开）；weighted-F1 按样本数加权，接近「acc 的另一种表达」。

**怎么挑**：故障检测宁可多报不可漏报（漏一个过热振动可能烧毁设备）→ 看少数类 recall；类别极端不平衡（故障率 1‰）时再上 `class_weight="balanced"` / 重采样——本阶段 8%/4% 属轻度不平衡，练习 2 实测 `balanced` 反而略降（0.822 < 0.859），体会「加权不是免费午餐」。**回归的评估**用 RMSE（和 y 同单位，如房价误差 12 万元）、MAE、R²（模型解释了多少方差，0.968 表示解释了 96.8%）。

**混淆矩阵是「指标之外的地图」**：kNN 的混淆矩阵 `[[262,2,0],[13,11,0],[3,3,6]]`（行=真实，列=预测）直接读出「24 个过压漏 13、12 个过热振动漏 6」——数字是地图，矩阵是哪里出错的坐标。

### 3.6 过拟合与欠拟合：验证曲线与正则化

**模型复杂度太低 → 欠拟合（train 都学不好）；太高 → 过拟合（train 学得很好、test 变差）**。ex04 用「已知真实函数 + 噪声」的数据把这条曲线完整扫出来（实测）：

| degree | train RMSE | test RMSE | 系数范数 ‖w‖ | 判断 |
|--------|-----------|----------|-------------|------|
| 1 | 1.391 | 1.438 | 3.05 | ← 欠拟合（线性拟合不了 sin 曲线） |
| 6 | 0.693 | **0.686** | 8.71 | ← test 最低（最佳区） |
| 12 | 0.681 | 0.802 | 150.9 | ← 过拟合区 |
| 15 | 0.674 | 0.788 | 1858.2 | ← 明显过拟合 |

三条线索：**train RMSE 持续下降**（模型越来越「会背」训练集）；**test RMSE 先降后升**（U 型——test 的最低点就是泛化最优）；**系数范数爆炸**（‖w‖ 从 8.7 到 1858——高次多项式靠巨大的正负系数互相抵消去死记噪声点，这是过拟合的指纹，比肉眼看曲线更可量化）。**读验证曲线**：train/test 差距越大越过拟合；两者都高是欠拟合。

**正则化 = 给大系数交税**：Ridge 在损失里加 `α·‖w‖²`，逼模型求简。ex04 实测 degree 15 + Ridge：α=0.1 时 test RMSE 从 0.788 回到 **0.693**（≈ degree 6 的水平），‖w‖ 压回 7.4；α 过大（10）又欠拟合（1.031）——**正则化强度本身也要调**（调法见 3.7 交叉验证）。

### 3.7 交叉验证与调参

调参（选 degree、选 max_depth、选 α）最怕「在测试集上调」——那就等于把测试集当验证集用，验收就失真了。标准做法是**把训练数据再切出一份验证集**，或用**交叉验证**把「验证」也平均掉（ex05 实测）：

| 方法 | 实测（ex05） | 结论 |
|------|-------------|------|
| 单次 80/20 验证，换 10 个划分 seed | acc 在 **0.920~0.973** 乱跳（跨度 0.053） | 一次划分的分数是运气，「调到验证集最好」可能只是调到了划分噪声 |
| 5 折交叉验证 | **0.941 ± 0.004**（各折 [0.942, 0.942, 0.933, 0.947, 0.942]） | k 折把波动平均掉，估计稳定可信 |

**交叉验证的机制**：把训练数据切 k 份，轮流拿 1 份当验证、其余 k−1 份训练，报告 k 次分数的均值±标准差——每个样本都被当过「没见过的验证样本」。k 的取舍有讲究（ex05 实测三个 k）：3 折 **0.945 ± 0.005**、5 折 **0.941 ± 0.004**、10 折 **0.941 ± 0.011**——折数越多每折训练数据越多（偏差更小），但每折验证的样本越少、单折估计越吵，跨折 std 不降反升（10 折每折只验证 ~110 条，std 反而最大）；k 再逼近样本数（留一法，k=n）时每折只验证 1 条、各折结果高度相关，方差更大且要训练 n 次（见 4.4）。**5 折是这套数据的甜点，工程惯例 5/10 折**。

**用 CV 调参、用测试集只验收一次**（决策树 max_depth 1..15，5 折 CV 实测）：

```python
# examples/ex05-crossval-tuning.py —— CV 选参（已验证）
scores = cross_val_score(DecisionTreeClassifier(max_depth=d, random_state=SEED), X_dev, y_dev, cv=cv)
```

CV mean 最高的是 **depth=4（0.926）** → 重训后 test acc **0.944**；反面教材：把树放太深会过拟合——示例 depth=12 的 train acc 高达 **0.998**（看着像满分），test 却只有 **0.936**，明显低于 CV 挑出的 depth=4（0.944），而且 CV mean 在 depth≥9 后回落到 0.91x 再也上不去——**训练分数会骗你，CV 不会**。调参与防泄漏是一条链：test 只在「调完所有东西之后」碰一次。

### 3.8 异常检测与其他无监督任务

异常检测是「没有标签也能跑」的任务——但**没有标签就无法调阈值**，工程标准做法是「注入已知异常做评测、用已知正常的段做训练」（练习 3 实测）：

| 方法 | recall / precision（250 条：200 正常 + 50 注入异常） | 教学点 |
|------|--------------------------------------------------|--------|
| 单维 z>3 阈值法 | 0.340 / 0.850 | 逐维看阈值，看不到「电流-功率联合」异常（每维都在正常范围） |
| 马氏距离（协方差感知） | **1.000 / 1.000** | 用正常段估计 μ、Σ，`(x−μ)ᵀΣ⁻¹(x−μ)` 一把抓住相关性盲区——numpy 十几行可手写 |
| IsolationForest（contamination 猜 0.05） | 0.200 / 0.357 | 无监督也要猜超参：猜错 contamination 从 0.05→0.10，recall 从 0.20 变 0.56；且对「成簇」的异常不敏感 |

> 本阶段异常检测只用「特征矩阵」形态（马氏距离 / IsolationForest）；**时间序列的滑窗特征（滚动均值/方差）与流式检测**是平台指标场景的进阶，见 roadmap 第 18 节。project/ 的「日志异常检测」扩展方向把文本日志向量化（练习 4 技能）与这里的方法衔接。

### 3.9 深度学习与 Transformers：认知层（PyTorch / Transformers 未在本环境验证）

为什么 sklearn 之外还有 PyTorch / Transformers？一句话：**sklearn 擅长「特征是人设计的表格数据」，深度学习擅长「特征要从原始数据里学出来」**。图像（像素）、音频（波形）、自然语言（词序列）没有人类能手工设计的特征——深度学习用「多层非线性变换」自动学特征：每一层把上一层的表示再抽象一层（线条 → 纹理 → 部件 → 物体；词 → 短语含义 → 句子语义）。PyTorch 的核心贡献是**自动求导**：你声明网络结构与前向计算，框架自动算出每个参数对损失的梯度，训练循环（前向 → 算损失 → 反向传播 → 更新参数）就成了可读可调的 Python 代码。Transformers 则把「注意力机制」做成语言模型的主干：每个词按与上下文中其他词的关联程度加权融合信息——`Attention Is All You Need`（2017）之后，预训练（在海量文本上学语言规律）→ 微调（在下游任务上再训几步）成为范式，HuggingFace transformers 库把「下载一个预训练模型 → 微调 → 推理」压到几行代码。

**本阶段的边界（如实标注）**：本机 **PyTorch / Transformers 未安装，相关代码未在本环境验证**。体量上 PyTorch 安装包约 2GB+、需要 CUDA/GPU 才能体现价值，不在本阶段可验证范围内——因此本阶段不写任何会「看起来能跑」的深度学习代码，只建立三个认知：① 深度学习适合「特征无法人工设计」的模态（图像/音频/语言），表格数据上 sklearn 的随机森林常常又稳又够（3.5 实测 RF 在合成表格数据上 acc 0.947）；② 深度学习的成本是数据量、算力与调参复杂度，先问「sklearn 能不能解决」；③ 大模型时代的应用形态更多是「用现成模型 + 检索/工程」（3.10 的 RAG 路线），而不是从零训练。想真机验证深度学习时：`pip install torch` 后从官方 60 分钟教程起步，属本阶段之后的专题深入。

### 3.10 向量检索、迷你 RAG 与向量数据库

**RAG（检索增强生成）= 检索 + 生成**：把问题先拿去「资料库」里检索相关段落，再把「问题 + 段落」一起交给生成模型回答。它解决大模型的两个毛病：知识过时（模型训练完就冻结）与幻觉（不知道就说编）。**RAG 的上限由检索质量决定**（roadmap 必会概念）——生成模型再强，检索漏了关键段落也答不全；ex06 与练习 5 用纯 numpy + TF-IDF 把这条因果量了出来：

| 检索方案 | hit@1 / hit@3（8 问） | 读法 |
|----------|----------------------|------|
| 清晰措辞 6 问 | **6/6** 命中 | 措辞与资料用词一致时，词面检索就够 |
| 模糊措辞 2 问（「component seems weak…」「car range」） | **0/2** | top1 命中文不对题的文档（补能时长 / 冬季续航）——检索质量先崩 |
| top-3 补救 | hit@3 **7/8** | 「component」问法在 top-3 里救回（含标准文档）；「car range」连 top-3 都没有 → 彻底失败 |
| 文本预处理（练习 5：词形归一） | cover@3 从 **3/5 → 5/5** | `charge/charges/charging`、`deep/deeply` 归一后检索质量直接提升 |

**检索的几何直觉**：把每段资料变成一个向量（TF-IDF 或嵌入），检索 = 在向量空间里找与查询向量最「近」（余弦相似度最大）的 k 个。TF-IDF 是「词面」检索：`discharge` 与 `discharges` 互不匹配（练习 5 实测这就是 cover 掉分的原因）；**嵌入模型**（如 transformers 里的 sentence-embedding）把「语义相近」变成「向量相近」，能匹配同义不同词——这就是为什么 RAG 工程链路是「分块 → 清洗/规范化 → 嵌入 → 向量数据库 → 相似度检索」。**向量数据库**（FAISS、Milvus、pgvector）解决「几百万段落 × 高维向量逐个算余弦太慢」的问题，用 ANN 索引（近似最近邻）把检索从 O(n) 降到亚线性——本阶段概念到此为止，装库实战（`pip install faiss-cpu` 等）留到 ph16 之后与 roadmap 第 18 节数据平台分析方向的进阶。

> 阶段内容隔离：迷你 RAG 的**生成侧**（用 transformers 模型把检索段落拼成回答）依赖 PyTorch/Transformers（未在本环境验证，3.9）；本阶段把 RAG 拆到「检索质量」这一半用 sklearn/numpy 完全实测——**这是 RAG 里最该先弄懂的一半**。

### 3.11 模型保存与最小部署闭环

训练完的模型只是内存里的对象，**部署的第一步是把它变成能跨进程复用的产物**。sklearn 的标准做法是 `joblib`（比 pickle 对 numpy 数组更高效）：

```python
# project/health/model.py —— 模型产物保存/加载（已验证，产物写 /tmp）
def save(self, out_dir: Path) -> Path:
    out_dir.mkdir(parents=True, exist_ok=True)
    path = out_dir / "model.joblib"
    joblib.dump(self, path)          # 整个管线（模型 + 特征名 + 元信息）一个文件
    return path
```

project/ 的命令行演示了完整闭环（本机实测）：`python3 cli.py` 训练并落盘到 `/tmp/health-model/model.joblib` → 另起进程 `python3 cli.py --predict 1500 25 80 1.0` 加载产物预测 → `预测 HEALTH: 79.5% → 健康等级: 临界`。要点：**产物只存「训练好的参数」，不存训练数据**（体积小、可分发）；加载方与训练方用同一套特征名，顺序错了预测就错。再往上「把 predict 包成 HTTP 服务（FastAPI，ph10/ph14 技能）、容器化与监控」就是 [ph16 部署与 DevOps 阶段](../ph16-deploy-devops/16-deploy-devops.md)的内容——**模型部署的 Python 侧最小闭环在本阶段，工程侧在 ph16**。

### 3.12 micro / macro / weighted：三把尺子怎么选（概念辨析）

3.5 里出现过 macro-F1 与 weighted-F1，这里把三把尺子的关系一次说清——**它们是对"平均什么"的不同选择**，没有绝对优劣，只有合不合适：

| 尺子 | 平均方式 | 谁被公平对待 | 什么时候看它 |
|------|---------|-------------|-------------|
| micro-F1 | 把所有类别的 TP/FP/FN **加总**后算一个 F1 | 每个**样本**等权（样本多的类贡献大） | 只关心"总命中率"时；单标签多分类下与 accuracy 同源 |
| macro-F1 | 每类 F1 先算、再**算术平均** | 每个**类别**等权 | 少数类也要照顾时（本阶段的故障检测）——**3.5 里 kNN 0.728 vs RF 0.793 用它才拉开** |
| weighted-F1 | 每类 F1 按**样本占比**加权平均 | 折中：多数类权重大 | 类别不均衡但想要一个"总账"数字时 |

一句话记忆：**micro 对样本公平、macro 对类别公平、weighted 是两者之间的加权折中**。报告指标时建议 macro 与 weighted 一起报（sklearn 的 `f1_score(..., average=...)` 一行切换），并说明数据分布——只报一个 accuracy 等于把多数类当遮羞布，这在 3.5 的实测里已经演示过了。

### 3.13 类别不平衡的三级应对阶梯（概念辨析）

数据里某类样本太少（如故障率 1‰），模型"全猜健康"也能有 99.9% acc——3.5 的 `balanced` 实验（实测反而略降）说明**加权不是免费午餐**。应对不平衡有三层手段，按"改哪里"从低到高：

| 层级 | 手段 | 做什么 | 代价 / 注意 |
|------|------|--------|------------|
| 数据层 | 重采样 | 少数类过采样（复制/合成，SMOTE 概念）或多数类欠采样 | 复制会过拟合重复样本；SMOTE 合成样本可能失真 |
| 模型层 | `class_weight="balanced"` | 给少数类更高损失权重 | 3.5 实测：8%/4% 的轻度不平衡下反而略降——**先用基线确认真的需要** |
| 决策层 | 阈值移动 | 调低少数类的判定阈值（如故障概率 > 0.3 就报警） | 需要概率输出（`predict_proba`），换 recall/precision 的取舍 |

本阶段的数据是 88% / 8% / 4% 的**轻度不平衡**，3.5 的结论（默认权重即可）对它是成立的；真正遇到 1‰ 级极端不平衡（如平台故障预警）时，再沿这个阶梯逐级尝试，并用 3.5 的指标矩阵（重点看少数类 recall）评估每一级的收益——**阶梯本身是本阶段之后的方向，这里先建立"不平衡有三层可动"的地图**。

## 4. 底层原理

### 4.1 为什么「划分」决定你看到的数字：估计的方差

一个模型在验证集上的分数是「在有限样本上的估计」，天然带噪声：换一批验证样本，分数就变。ex05 实测同一个 kNN 换 10 个划分 seed，验证 acc 从 0.920 到 0.973——**跨度 0.053 就是「划分方差」**。交叉验证（k 折）为什么稳：它把验证样本「轮流」覆盖全部数据，k 次分数的均值把单次划分的运气平均掉（5 折实测 0.941 ± 0.004）。这解释了三条工程纪律的机制：划分要固定 seed（可复现）、调参要看 CV 不是单次划分（防调参过拟合）、最终数字要报告「波动范围」而不是单个精确值（本阶段所有实测数字都标注随数据划分/种子波动）。

### 4.2 距离模型与树模型：两种「相似」的定义

**kNN 的「相似」= 特征空间里的欧氏距离**：预测一个点 = 找它最近的 k 个训练点投票。所以特征量纲决定距离——整列 std 6.27 的温度列在未缩放时支配了整列 std 0.21 的电压列（0.21 是 ex02 实测的电压整列 std；生成常量里健康类的电压**类内**波动 σ 只有 0.16——「0.16」是类内口径，不是整列 std），kNN 等于「只看温度」（ex02 实测 0.890 vs 0.930）。**决策树的「相似」= 落在同一个叶子里**：树按特征阈值递归切分（温度 > 41.5°C 走右枝…），阈值比较对单调缩放不敏感——`x > t` 与 `(x−μ)/σ > (t−μ)/σ` 等价，所以随机森林缩放前后完全一致（实测 0.963/0.947 分毫不差）。**随机森林 = 很多棵在随机子集上训练的树取平均**（bagging）：单棵树容易记住噪声（过拟合，见 4.3），平均把「各自乱记的部分」抵消掉，方差下降——这是 ex03 里 RF（macro-F1 0.793）系统性优于单模型（kNN 0.728 / LR 0.698）的机制解释。

### 4.3 过拟合的机制：容量、噪声与系数

过拟合的本质是**模型的表达容量超过了数据里的信号量**：数据 = 真规律 + 噪声。容量足够大时，模型有两种方式解释数据——「学真规律」（泛化好）或「连噪声一起背」（泛化差）。多项式回归给了最透明的解剖：degree 15 的模型有 15 个系数，可以拟合出穿过每个噪声点的弯曲曲线，代价是**系数必须巨大才能互相抵消**（ex04 实测 ‖w‖ 从 8.7 爆到 1858）。所以：① train/test 差距 = 背噪声的程度；② 系数范数 = 过拟合的量化指纹；③ 正则化（Ridge 的 α·‖w‖²）直接惩罚大系数，等价于「假设真规律是简单的，除非数据强烈反对」——α=0.1 时 degree 15 的 test RMSE 从 0.788 回到 0.693，就是这条机制的实测。

### 4.4 交叉验证的机制：bias-variance 权衡

k 折交叉验证估计的是「用 n·(k−1)/k 个样本训练的模型的泛化误差」。k 小时（如 3 折）：每折训练数据少 → 模型偏差大 → CV 分数系统性偏保守；k 大时（如留一法，k=n）：训练数据几乎全量 → 偏差小，但每折只验证 1 个样本、k 次结果高度相关 → 方差大且计算贵（训练 n 次）。5~10 折是工程惯例：偏差可接受、方差被平均、计算量可控。调参时 CV 的另一个作用是**防「验证集过拟合」**：你在 15 个超参里挑 CV mean 最高的那个，本质是在「超参空间」里做一次小规模搜索——CV 的均值±标准差告诉你这个选择稳不稳（ex05 实测 depth 4 与 depth 8 的 CV mean 只差 0.006，此时选哪个都行，别为 0.006 纠结）。

### 4.5 TF-IDF 的几何与嵌入的本质（概念层）

TF-IDF 向量化把文档变成词袋向量：**TF**（词频）强调「这个词出现了几次」，**IDF**（逆文档频率 `log((1+N)/(1+df))+1`）惩罚「到处都有的词」——「component」在 8 段资料里出现 6 次，IDF 就低；「contactor」只出现 1 次，IDF 就高，检索时一字命中顶十次。余弦相似度 = 向量夹角的余弦，只关心「方向」不关心「长度」（长文档和短文档可比）。TF-IDF 的盲区是**词面**：`discharge` 与 `discharges` 是两个维度（练习 5 实测词形归一前 cover 掉分）。**嵌入模型**用神经网络把词/句映射成稠密向量，训练目标让「语义相近的句子向量相近」——本质是把「相似」从「词面重合」升级为「语义重合」，代价是需要预训练模型（GPU/大内存，3.9 未验证标注）。向量数据库的 ANN 索引（如 HNSW）则是「在高维空间找最近邻」的数据结构优化——**向量检索链路 = 表示（嵌入）+ 索引（ANN）+ 排序**，每一环都有质量与代价的权衡，这就是「RAG 关注检索质量」的工程含义。

### 4.6 神经网络与注意力（概念层，未在本环境验证）

神经网络的底层机制一句话：**线性变换 + 逐元素非线性，层叠 n 次**——`h₁ = σ(W₁x + b₁)`，`h₂ = σ(W₂h₁ + b₂)`……σ（ReLU 等）提供非线性，层叠提供抽象。训练 = 反向传播：把「损失对输出的梯度」按链式法则逐层传回，算出每个 W 该往哪个方向调（这就是 PyTorch 自动求导在做的事，3.9）。注意力的机制一句话：**每个词是上下文中所有词的加权平均，权重由「相关性」决定**——`Attention(Q,K,V) = softmax(QKᵀ/√d)·V`，Q（查询）、K（键）、V（值）是同一序列经过三个线性变换的版本；自注意力让「bank」这个词根据上下文在「河岸/银行」间消歧。Transformer = 自注意力层叠 + 位置编码（词序信息），预训练目标（预测下一个词）让它从海量文本里学到语言规律。这些机制的具体数值实验依赖 GPU 与 transformers，超出本环境可验证范围——本阶段到「能看懂别人在说什么、能判断什么时候该用它」为止。

### 4.7 懒惰学习 vs 急切学习：为什么 kNN 的"训练"特别快

3.5 里 kNN 与随机森林同为分类器，但它们的学习方式完全不同——**kNN 是懒惰学习（lazy learning），树是急切学习（eager learning）**：

| 维度 | kNN（懒惰） | 决策树 / 随机森林（急切） |
|------|------------|-------------------------|
| "训练"做什么 | 几乎什么都不做——只是把训练数据存下来 | 训练时就递归切分、建好整棵树 |
| 训练耗时 | 近乎为零 | 有实际成本（RF 要建很多棵树） |
| 预测耗时 | **慢**：每个待测样本都要与全部训练样本算距离 | **快**：一次从根走到叶子的阈值比较 |
| 内存 | 要保留全部训练数据 | 只保留树结构（RF 还要每棵树的节点） |
| 适合 | 数据量小、训练频繁更新 | 数据量大、预测延迟敏感（在线服务） |

这就解释了 3.4 的一个观察：kNN 对**特征缩放敏感**，本质是因为它把"距离"当预测依据、每个维度都要参与计算——特征的处理方式直接决定预测质量。工程选型的启示：**预测延迟敏感的服务优先树模型**（这也是 3.5 实测 RF 综合最优的另一个侧面），数据要频繁增量更新时 kNN 的"零训练"才显出优势。

| 问答 / 知识库检索（手册、运维 FAQ） | 检索质量 + top-k + 向量库概念 | ex06、练习 5 |
| 模型交付给别的系统用 | joblib 产物 + 命令行/服务推理 | 3.11、project/ |

**选型决策**（什么时候用什么，一句话版）：

| 问题形态 | 首选 | 为什么 | 反面 |
|---------|------|--------|------|
| 表格数据 + 特征明确 | 随机森林 | 非线性、对缩放不敏感、bagging 稳（实测 acc 0.947） | 上来就上深度学习（数据/算力不值） |
| 小样本线性关系 | 线性回归 / Ridge | 可解释、系数即权重、正则化防过拟合 | 高次多项式（ex04 实测过拟合） |
| 距离/相似度直觉强 | kNN | 无需训练、解释直观 | 不缩放就废（ex02 实测 0.890） |
| 少量故障的检测 | 马氏距离 / IsolationForest | 无标签可用、注入异常定标 | 单维阈值（练习 3 实测漏 2/3） |
| 图像/语言/音频 | 深度学习（PyTorch/Transformers） | 特征无法人工设计 | 本环境未装未验证——先 sklearn 后深度学习 |
| 知识问答 | RAG | 资料可更新、可溯源 | 直接问生成模型（幻觉 + 知识过时） |

**要不要上 ML？先问三个问题**（与"先 baseline 再复杂化"一脉相承——**很多问题根本不需要模型**）：

| 问题 | 答"否"时的替代方案 |
|------|-------------------|
| 数据够吗？（几百条以下很难学到稳定规律） | 规则引擎 / 查表——故障检测里"温度 > 阈值"就是规则，可解释且零训练成本 |
| 规律稳定吗？（业务规则下月就变，模型白训） | 规则或持续重训的流程，而不是一次性模型 |
| 要可解释吗？（合规/审计场景必须能说清"为什么这么判"） | 线性模型 / 决策树（系数与阈值可读）优先于黑盒 |

ML 是"从数据里找规律"的锤子，但**不是所有钉子都是数据问题**——本阶段的四个必会概念（baseline、数据质量、划分、检索质量）本质上都在教你同一件事：先确认问题真的需要模型、再确认喂给模型的数据靠谱、最后才谈模型。

**不适合此阶段的事项**：深度学习从零训练与 GPU 调优（3.9，未验证）、大模型微调与提示工程、生产级向量数据库部署（FAISS/Milvus 集群）、模型服务化与容器化部署（[ph16 部署与 DevOps 阶段](../ph16-deploy-devops/16-deploy-devops.md)）、分布式训练与 ML 平台（超出本路线）。

**与其他语言同类机制的对比**（一句话级，为 analysis/ 与 Tenet 合成积累素材）：Python 的 ML 生态（numpy/scipy/sklearn/PyTorch）是「算法研究者用 C/C++ 写核心、Python 做胶水」的典范——sklearn 的 fit 内部是编译过的 C/Fortran（LAPACK），Python 层只负责数据流与配置；对比之下 Go 的 ML 生态（gonum/gorgonia）与 Rust 的（ndarray/linfa/tch-rs）都有「类型安全」优势但生态体量差一个数量级；R 是统计学的原生语言但工程化（服务、异步、Web）远不如 Python——**Python 赢在「科研迭代速度 + 工程化生态」的交集，这正是它成为 AI 事实语言的原因**。

## 7. 总结

### 关键要点

1. **工作流顺序是纪律**（必会概念）：先划分 train/val/test（stratify + 固定 seed），test 只在最后碰一次——ex05 实测单次划分 acc 在 0.920~0.973 乱跳，划分方差是真实存在的（3.1/3.7/4.1）
2. **先 baseline 再复杂化**（必会概念）：多数类 baseline acc 0.880、「预测均值」RMSE 15.13%——模型的贡献 = 与 baseline 的差，不是 acc 本身（3.2、ex03、project/）
3. **数据质量决定模型上限**（必会概念）：仅训练集 25% 错标就把 acc 从 0.930 压到 0.873、两列信息缺失掉到 0.917；泄漏特征让 val 虚高到 0.990、真实输入回落 0.897——脏数据进、脏结果出；评估标签只许用干净的（若连评估一起污染，数字会虚跌到 0.75 量级，那是学错+评错混在一起），测试集只碰一次（3.3、ex01）
4. **特征工程由模型假设决定**：距离模型要缩放（kNN 0.890→0.930）、树模型不需要（RF 分毫不差）、名义类别 one-hot 优于 label-encoding（0.917→0.927）（3.4、ex02）
5. **指标要会挑**：acc 会被多数类稀释，故障检测看少数类 recall，跨类比较用 macro-F1（kNN 0.728 vs RF 0.793）——混淆矩阵告诉你错在哪（3.5、ex03）
6. **过拟合有指纹**：train/test 差距 + 系数范数爆炸（‖w‖ 8.7→1858）；正则化（Ridge α）给大系数交税，α 也要调（3.6、ex04）
7. **无监督也要评测**：注入异常定标，马氏距离抓相关性盲区（recall 1.0 vs 单维 z 的 0.34），IsolationForest 的 contamination 要猜（3.8、练习 3）
8. **RAG 上限 = 检索质量**（必会概念）：清晰措辞 6/6、模糊问法 0/2、top-3 补救到 7/8；词形归一把 cover@3 从 3/5 提到 5/5（3.10、ex06、练习 5）
9. **深度学习是另一条路**：特征无法人工设计时才值得（图像/语言）；PyTorch/Transformers **未在本环境验证**，先 sklearn 后深度学习（3.9）
10. **部署从产物开始**：joblib 保存模型到 /tmp，另起进程加载推理——最小闭环在 3.11/project/，服务化与容器化属 [ph16 部署与 DevOps 阶段](../ph16-deploy-devops/16-deploy-devops.md)
11. **调参用的数据 ≠ 验收用的数据**：train 学参数、val/CV 反复选模型、test 只在全部决定后碰一次——"在 test 上调参"是第三种数据泄漏（3.1 / 3.7）
12. **先确认问题需要模型，再谈模型**：micro/macro/weighted 是按数据分布选尺子，不平衡有三层应对阶梯，kNN 懒惰/树急切决定工程选型——本阶段的"地图"比任何一个 API 都值钱（3.12 / 3.13 / 4.7）

### 下一阶段

[部署与 DevOps 阶段](../ph16-deploy-devops/16-deploy-devops.md) — 本阶段 3.11 的「joblib 产物 + 命令行推理」只是部署的第一公里，ph16 把它升级为「能上生产」的服务：Linux/Docker 镜像、Nginx/Gunicorn/Uvicorn 的服务栈、CI/CD 流水线、Prometheus/Grafana 监控——本阶段的 `cli.py` 在那里变成容器里的入口，模型产物变成环境变量挂载进服务的依赖（ph16 project/ 的部署模板演示了完整链路）。

离开 ph15 之前，值得记住本阶段最可迁移的一句话：**机器学习最难的从来不是模型，而是"如何诚实地知道模型到底行不行"**。baseline、数据质量、三层划分、cross-validation、macro-F1、cover@k——这些工具的共同点是把"我觉得行"翻译成"数字证明行"，并且堵住"数字骗我"的每一条路（泄漏、过拟合、指标失真、未验证冒充已验证）。这套"测量观"在 ph16 的部署监控、ph17 的性能优化里会原样复用；换语言、换框架、换模型形态，它都不变。

如何练习这套测量观？一个可操作的习惯：**跑每个示例前，先写下你预期的数字**——比如"缩放应该把 kNN 的 test 从 0.890 抬到 0.93 附近"，跑完对照。预测对了，说明你理解的是机制而不是步骤；预测错了，对照 3.x 的解释找偏差，那正是理解裂缝所在。这个"先假设、后验证、用差异找误解"的循环，比把示例干跑十遍有效得多——它也是 3.7"调参看 CV、不靠猜"在个人学习上的同款应用。

最后把视线拉远一点：sklearn 把复杂的建模细节藏进统一的 `fit`/`predict` 接口、把可塑性留给上层的 Python——这种"复杂下沉、体验上浮"的设计，正是本项目 analysis/py（Python 设计解剖台）里"开发者体验优先的取舍"主题的又一次现身。机器学习生态与语言设计在这里汇合到同一个哲学点上：**让最常用的路径最简单，把复杂留给少数专家**。等你走到分析阶段，会看到 Python 与它的 ML 生态用的是同一套成功的配方。
