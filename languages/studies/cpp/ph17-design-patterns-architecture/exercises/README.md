## 练习 1：用策略模式封装协议解析（★★★）

- **目标**：把「从字节流中提取消息帧」的规则族封装成可替换策略，做到换协议不改解析器本体
- **要求**：
    - 定义策略接口（如 `IFramingStrategy`：给定字节串，返回消息帧列表）
    - 实现两个策略：**分隔符分帧**（按 `'\n'` 切帧，丢弃空帧）与**长度前缀分帧**（每帧前 4 字节大端长度 + payload）
    - 上下文类持有策略（构造注入 + 运行期可换），对上层暴露 `decode(data)` 一个入口
    - 同一段字节用两个策略解析应得到不同结果——演示「换协议 = 换策略」
    - 长度前缀帧头越界（声称长度 > 剩余字节）要抛可诊断异常（ph09 纪律：失败要响亮）
- **验收**：运行程序输出两个策略各自的解析结果与断言行；能口头说清：为什么分隔符分帧不适合承载任意二进制 payload
- **提示**：先在纸上画出两种帧的字节布局再写代码；长度前缀可以用 `\x00\x00\x00\x05` 这类字面量构造测试字节（参考实现 `sol-01-protocol-strategy.cpp`）

## 练习 2：用观察者实现状态变化通知（★★★）

- **目标**：实现一对多状态通知：设备状态（开关 + 温度）变化时通知全部订阅者，**只有真的变化才通知**
- **要求**：
    - Subject（如 `DeviceMonitor`）持开关与温度两个状态，提供 `set_power(bool)` / `set_temperature(int)` 修改接口
    - 订阅者以回调形式注册（`std::function<void(const DeviceState&)>`）；订阅返回句柄，**句柄析构自动退订**（RAII，杜绝「忘了退订 → 悬挂」）
    - 三个订阅者：两个常驻、一个在收到第一次通知后销毁订阅句柄
    - 状态未变时（重复 set 同值）不触发通知——变化检测是观察者的语义核心
- **验收**：运行输出每个订阅者的通知次数；退订者不再增长；重复赋值不产生通知；程序退出前无悬挂访问（ASan 构建零报告可加分）
- **提示**：句柄要禁拷贝、可移动（一次订阅对应唯一句柄）；通知期间回调可能修改订阅表，想想怎么防迭代器失效（参考实现 `sol-02-observer.cpp`）

## 练习 3：为存储引擎抽象 IStorage 接口（★★★）

- **目标**：设计存储抽象接口，让上层服务不依赖任何具体存储实现（roadmap：为存储引擎抽象 IStorage 接口）
- **要求**：
    - 定义 `IStorage` 纯虚接口：`put(key, value)` / `get(key)`（返回 `std::optional<std::string>`，缺键返回 `std::nullopt`）/ `remove(key)` / `size()`（现存键数）
    - 实现两个互不相同的实现：**MemoryStorage**（哈希表直存）与 **JournaledStorage**（内部只追加日志：set/删除墓碑两种条目，`get` 时从最新条目往前找——换一种内部设计演示「同一接口、不同内部结构」）
    - 写一个上层 `KVClient`，只依赖 `IStorage&`（构造注入），提供 `put/get/remove/overwrite` 业务语义
    - 同一个 KVClient 分别注入两个实现，跑同一组操作序列，可观察结果必须一致
- **验收**：两组操作序列的输出逐行一致；`get` 缺键返回空、覆盖写取到新值、remove 后再 get 为空；能说出为什么上层不依赖具体存储类
- **提示**：先写接口再写两个实现，最后才写 KVClient——「面向接口」的顺序会强迫你把接口设计成最小够用（参考实现 `sol-03-istorage.cpp`）

## 练习 4：为查询执行器抽象 IExecutor 接口（★★★）

- **目标**：设计 pull 模型（拉取式）执行器接口，用组合把执行节点搭成管道（roadmap：为查询执行器抽象 IExecutor 接口）
- **要求**：
    - 定义 `IExecutor` 纯虚接口：`open()` / `next()`（无更多行返回 `std::nullopt`）/ `close()` / `describe()`（返回节点描述，用于打印执行计划）
    - 行类型自带（如 `Row{int id; std::string name; int score;}`）
    - 实现三个节点：**ScanExecutor**（扫内存行源，非拥有引用注入）、**FilterExecutor**（包上游节点 + 谓词 `std::function<bool(const Row&)>`，谓词不通过就继续向上游拉）、**LimitExecutor**（包上游 + 行数上限）
    - 执行器组合即管道：`scan → filter(score>=60) → limit(2)`，把结果行逐行取出打印
    - 谓词、上限是「参数」，在组合处注入——同一个 ScanExecutor 可复用于不同管道
- **验收**：打印出执行计划（三个 describe）与结果行；换个谓词重建管道结果随之变化；`next()` 拉空后返回空（结束语义正确）
- **提示**：每个包装节点**独占持有**上游（`std::unique_ptr<IExecutor>` 成员），生命周期沿管道自然传递；`FilterExecutor::next()` 是「循环拉直到满足谓词或上游耗尽」（参考实现 `sol-04-iexecutor.cpp`）

> **提示**：练习 1~4 分别对应主文档 3.3（策略）/ 3.4（观察者）/ 3.7（接口抽象）/ 3.8（分层与模块边界）与 examples/ex02、ex03 及 project/ 的同主题实现——先看题目自己写，卡住再看 examples/ 的载体技术（不是抄答案，是学手法）。
