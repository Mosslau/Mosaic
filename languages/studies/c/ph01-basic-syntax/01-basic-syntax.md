# C 语言基础语法阶段

> 面向系统底层、数据库存储引擎、KV 库方向，从 C 程序结构和编译模型起步。

## 1. 概述

C 语言基础语法阶段是整个 C 学习路线的起点，目标是：**能读懂并写出简单 C 程序，理解编译、链接和可执行文件的基本关系**。

| 核心维度 | 覆盖内容 |
|----------|---------|
| 程序结构 | `.c` 源文件、`.h` 头文件、`main` 函数、注释 |
| 数据 | 变量、常量、基本数据类型（`int`/`float`/`char`） |
| 控制流 | 运算符、`if`/`switch`、`for`/`while` |
| 工具链 | `gcc main.c -o app` 编译、链接 |
| I/O | `printf`/`scanf`、标准输入输出 |

这个阶段停留在一个源文件内，**不涉及指针、堆内存、结构体和多文件编译** — 那些是后续阶段的内容。

## 2. 来源与演变

C 语言由 Dennis Ritchie 于 1972 年在贝尔实验室设计，最初用于重写 Unix 操作系统。其设计哲学是**信任程序员、最小运行时、贴近硬件**。

| 版本 | 年份 | 主要变化 |
|------|------|---------|
| K&R C | 1978 | 第一版《The C Programming Language》，定义早期 C 方言 |
| C89/ANSI C | 1989 | 标准化，引入函数原型、`void` 指针、标准库 |
| C99 | 1999 | `//` 注释、变长数组、`inline`、`stdint.h` |
| C11 | 2011 | `_Generic`、`_Atomic`、匿名结构体、多线程支持 |
| C17 | 2017 | 主要是缺陷修复，无重大新特性 |
| C23 | 2023 | `nullptr`、`typeof`、`constexpr`、二进制字面量 |

本文示例以 **C99** 为基线（`//` 注释、`for` 循环内声明变量、`stdbool.h` 均为 C99 引入），现代编译器（GCC / Clang / MSVC）默认支持 C11 及以上，无需任何编译选项即可直接编译。这个阶段的语法是 C 语言最稳定的部分。

**为什么今天还要从 C 起步**：现代语言层出不穷，但操作系统内核、嵌入式固件、数据库存储引擎这些"离硬件最近"的软件仍然以 C 为主——Linux 内核、SQLite、Redis、Nginx 的核心都是 C。原因正是它的设计哲学：零运行时、直接操作内存、性能可预测。本路线的终点（ph16 存储引擎阶段）就是要亲手写一个这样的软件；所以从基础阶段就要建立"类型占多少字节、变量住哪里"的意识——这是 C 带给其他语言无法替代的视角。

## 3. 语法与参数

### 3.1 C 程序结构

```c
#include <stdio.h>   // 预处理指令：引入标准输入输出库

int main(void) {     // 程序入口，int 表示返回整数状态码
    printf("Hello, C\n");  // 库函数调用
    return 0;        // 返回 0 表示成功，非零表示错误
}
```

每一个 C 程序必须有且仅有一个 `main` 函数。`#include` 是预处理指令（Preprocessor Directive），在编译前由预处理器展开。

**源文件 `.c` 与头文件 `.h`**

C 项目由两种文本文件组成：

- **源文件（Source File，`.c`）**：存放函数的**实现**（函数体）与可执行代码，是编译的基本单位，一个 `.c` 文件对应一个编译单元（Translation Unit）
- **头文件（Header File，`.h`）**：存放**声明**（函数原型、宏、类型定义、常量），供源文件通过 `#include` 引入，自身通常不包含可执行代码

上面示例里的 `#include <stdio.h>` 引入的正是标准库头文件 `stdio.h`——它声明了 `printf`、`scanf` 等函数原型。编译器看到头文件里的声明，才能检查调用格式是否正确；而函数真正的实现位于标准库中，要到**链接**阶段才会被找到：

```text
stdio.h（声明 printf/scanf）──#include──▶ 程序.c ──编译──▶ 程序.o ──链接 libc──▶ 可执行文件
```

> 本阶段只用单文件，**`.h` 与 `.c` 分离、多文件编译属于 ph02 函数与模块化阶段**，这里只需理解头文件「提供声明、被 `#include` 引入」的角色。

**`main` 的两种标准签名与退出码**：

```c
int main(void);                     // 无参数形式（本阶段示例都用它）
int main(int argc, char *argv[]);   // 带命令行参数形式（ph07 构建与调试阶段用）
```

`main` 的返回值是**进程退出码（Exit Code）**：`return 0` 表示成功，非 0 表示某种错误。Shell 和 CI 系统靠它判断程序成败——`echo $?` 可以查看上一个命令的退出码。脚本里常见的 `gcc main.c -o app && ./app` 正是"编译成功（退出码 0）才运行"的链式写法。这个约定从 C 沿用到了几乎一切命令行工具。

### 3.2 变量与基本数据类型

| 类型 | 典型大小 (64位) | 范围 | 说明 |
|------|----------------|------|------|
| `char` | 1 字节 | -128 ~ 127 | 字符/小整数 |
| `short` | 2 字节 | -32768 ~ 32767 | 短整数 |
| `int` | 4 字节 | -2.1×10⁹ ~ 2.1×10⁹ | 默认整数类型 |
| `long` | 8 字节 | -9.2×10¹⁸ ~ 9.2×10¹⁸ | 长整数 |
| `float` | 4 字节 | ~6 位精度 | 单精度浮点 |
| `double` | 8 字节 | ~15 位精度 | 双精度浮点 |

```c
int age = 25;           // 整型变量
float pi = 3.14159f;    // 浮点常量加 f
char grade = 'A';       // 字符用单引号
const int MAX = 100;    // const 限定只读
```

**关键概念**：C 是静态类型语言（Static Typing），变量类型在编译时确定且不可改变。每种类型在内存中占用固定字节数，超出范围会产生溢出。

**命名与声明习惯**：标识符由字母、数字、下划线组成，不能以数字开头，也不能与关键字（`int`、`if`、`return` 等）冲突；C 区分大小写，`age` 与 `Age` 是两个不同变量。常见工程风格是 `snake_case`（`max_score`、`buffer_size`）。

**未初始化即不确定**：局部变量若声明时不赋值，它的值是"不确定的"——直接读取是未定义行为（实践中常表现为一个随机的"脏"值）：

```c
int count;         // 未初始化：值是垃圾
printf("%d\n", count);   // UB——可能打印任何数
int total = 0;     // 好习惯：声明即初始化
```

C99 起允许在块内任意位置声明变量，惯例是**在使用前最近处声明并顺手初始化**——这能让"忘记初始化"这类 bug 在编译警告阶段就被发现（`-Wall` 会提示 `used uninitialized`）。

### 3.3 运算符

| 类别 | 运算符 | 示例 |
|------|--------|------|
| 算术 | `+ - * / %` | `a + b`, `x % 2` |
| 关系 | `== != < > <= >=` | `a == b`（注意：不是 `=`） |
| 逻辑 | `&& \|\| !` | `a > 0 && b > 0` |
| 赋值 | `= += -= *= /=` | `x += 1` 等价于 `x = x + 1` |
| 自增自减 | `++ --` | `i++`（后置）, `++i`（前置） |
| 三元 | `? :` | `max = a > b ? a : b` |

### 3.4 控制流

**条件判断**：

```c
if (score >= 90) {
    printf("A\n");
} else if (score >= 60) {
    printf("Pass\n");
} else {
    printf("Fail\n");
}

// switch: 多分支选择，注意 break
switch (day) {
    case 1: printf("Mon\n"); break;
    case 2: printf("Tue\n"); break;
    default: printf("Other\n"); break;
}
```

**循环**：

```c
// for: 已知循环次数
for (int i = 0; i < 10; i++) {
    printf("%d\n", i);
}

// while: 前置条件判断
int n = 10;
while (n > 0) {
    printf("%d\n", n--);
}

// do-while: 至少执行一次
int m = 0;
do {
    printf("%d\n", m);
} while (m > 0);  // 条件为假，但循环体已执行一次
```

### 3.5 注释

```c
// 单行注释（C99 引入）
/* 多行
   注释 */
```

注释是写给**下一个读代码的人**（往往是几个月后的自己）看的。三档用途：

| 用途 | 写法 | 例子 |
|------|------|------|
| 解释"为什么" | 行注释放在代码上方或行尾 | `// 用 0 表示空闲：避免与合法 id 冲突` |
| 块级说明 | `/* */` 块注释 | 算法步骤、函数整体职责 |
| 文件头 | 文件顶部 `/* */` | 作者、用途、编译方式 |

新手容易写"是什么"注释（`// 把 i 加 1`），这类注释与代码重复、纯属噪音；**值得注释的是"为什么这样写"**——那些一眼看不出来的约束与取舍。

### 3.6 输入输出

```c
#include <stdio.h>

int main(void) {
    int age;
    printf("Enter your age: ");   // 输出到 stdout
    scanf("%d", &age);            // 从 stdin 读取，注意取地址符 &
    printf("You are %d years old.\n", age);
    return 0;
}
```

| 格式说明符 | `printf`（输出） | `scanf`（输入） |
|-----------|-----------------|-----------------|
| `%d` / `%i` | `int` | `int*` |
| `%f` | `double`（`float` 实参会自动提升为 `double`） | `float*` |
| `%lf` | 同 `%f`（`l` 被忽略） | `double*` |
| `%c` | `char`（提升为 `int` 传递） | `char*` |
| `%s` | 字符串（`char*`） | `char*` 缓冲区 |
| `%p` | 指针地址 | —（极少使用） |

格式说明符还能带**宽度与精度修饰**，让输出对齐、可读：

| 写法 | 效果 | 示例输出 |
|------|------|---------|
| `%5d` | 右对齐占 5 列 | `printf("%5d", 42)` → `   42` |
| `%-5d` | 左对齐占 5 列 | `printf("%-5d", 42)` → `42   ` |
| `%.2f` | 保留 2 位小数 | `printf("%.2f", 3.14159)` → `3.14` |
| `%-8.1f` | 左对齐 8 列、1 位小数 | `printf("%-8.1f", 3.14)` → `3.1     ` |

示例 4（九九乘法表）里的 `%-2d` 就是靠左对齐让各列对齐——表格化输出全靠这类修饰符。

**注意**：`printf` 和 `scanf` 的格式符含义并不对称——`printf` 的可变参数会发生**默认实参提升**（`float` → `double`），而 `scanf` 接收的是指针，必须和变量的真实类型严格匹配（`float` 用 `%f`、`double` 用 `%lf`），写错就是未定义行为。

**为什么 `scanf` 需要 `&` 而 `printf` 不需要？**

```c
int age;
scanf("%d", &age);    // scanf 需要修改 age 的值 → 必须知道 age 的地址
printf("%d", age);    // printf 只需要读取 age 的值 → 传值即可
```

C 函数默认**按值传递**（Pass by Value）：`printf` 拿到的是 `age` 的副本，读取即可；而 `scanf` 需要**修改**调用者的变量，只能通过传递变量地址（指针）来实现。这是 C 语言设计的基础权衡——基础阶段只需要记住"输入要加 `&`"，指针阶段会深入理解原因。

### 3.7 整数除法与类型转换

两个整数相除的结果仍是整数——这是新手最常踩的"小数点消失"坑：

```c
int a = 7, b = 2;
int q = a / b;            // 3 —— 整数除法直接向零截断，不四舍五入
double r1 = a / b;        // 3.0 —— 先做整数除法得 3，再把 3 转成 double
double r2 = (double)a / b; // 3.5 —— 先把 a 转成 double，再做浮点除法
```

| 代码 | 实际结果 | 说明 |
|------|---------|------|
| `7 / 2` | `3` | 两个 `int` 相除是整数除法，小数部分丢弃 |
| `7.0 / 2` | `3.5` | 混合运算：`int` 自动提升（Promotion）为 `double` |
| `(double)7 / 2` | `3.5` | `(类型)表达式` 是显式转换（Cast），先转再除 |
| `(int)3.9` | `3` | 显式转 `int` 截断小数（不是四舍五入） |

**判断转换方向的规则**：`int` 与 `double` 混合运算时，`int` 自动提升为 `double`（小范围向大范围，无损）；反之 `double` 转 `int` 会丢小数，编译器通常给出警告——显式 `(int)` 转换等于告诉编译器"我知道会丢精度，我接受"。

**字面量（Literal）的类型**由写法决定，必要时用后缀标注：

```c
double pi = 3.14159;   // 浮点字面量默认 double
float f  = 3.14f;      // f 后缀：float 字面量
long big = 42L;        // L 后缀：long 字面量
char c = 'A';          // 字符字面量，本质是 int 值 65
```

**字符就是小整数**：`char` 在运算中按小整数处理——`'A' + 1 == 'B'`（65 + 1 == 66）；数字字符转数值用 `ch - '0'`（`'7' - '0' == 7`）。这个"字符编码即数值"的性质在后面做字符处理（大小写转换、数字解析）时处处要用。

> 类型转换的完整规则（整型提升、寻常算术转换的每一步、隐式转换何时丢精度）在后续阶段遇到具体场景时逐个展开，本阶段先内化两个直觉：**要保留小数就先把操作数转成浮点**、**字符就是小整数**。

### 3.8 本阶段高频易错点速查

| 陷阱 | 典型症状 | 正确做法 |
|------|---------|---------|
| 丢分号 / 括号 | 编译错误 `expected ';'` | 编译器报错行常指向**上一行**，往前看 |
| `=` 与 `==` 混淆 | `if (score = 90)` 恒为真，条件形同虚设 | 条件里用 `==`；赋值不要写进条件 |
| `switch` 忘记 `break` | case 结束后"贯穿"执行下一个 case | 每个 case 结尾写 `break`（或 `return`） |
| 整数除法当浮点 | `double r = 1 / 3;` 得到 `0.0` | 至少一个操作数转浮点（见 3.7） |
| `scanf` 忘记 `&` | 运行崩溃或读到垃圾值 | `scanf("%d", &age)`——除数组名外都要 `&` |
| 格式符与类型不匹配 | 输出乱码或未定义行为 | `%d` 配 `int`，`%lf` 配 `double*`（scanf） |
| 循环边界多 1 | 访问 `a[n]`（下标越界）却不报错 | 遍历 N 个元素用 `< N`，别用 `<=`（越界是安静的 UB，详见 ph10） |

这一节的每条都是 C 社区几十年沉淀的经典错误。犯一次记不住很正常——**关键是会从编译警告和运行结果反推原因**，而不是死记清单。

## 4. 底层原理

### 4.1 编译与链接不是一回事

```
源文件 .c  ──预处理──▶  展开后的 .i  ──编译──▶  汇编 .s  ──汇编──▶  目标文件 .o  ──链接──▶  可执行文件
```

- **预处理**（Preprocessing）：处理 `#include`、`#define`、条件编译指令
- **编译**（Compilation）：将 C 代码翻译成汇编代码
- **汇编**（Assembly）：将汇编代码翻译成机器码，生成目标文件（Object File，`.o`）
- **链接**（Linking）：将多个 `.o` 文件和库合并，解析符号引用，生成可执行文件

理解这个流程是后续处理编译错误和链接错误的基础。

### 4.2 栈上变量的生命周期

```c
void func(void) {
    int x = 42;    // x 分配在栈上
}                  // x 随函数返回自动销毁
```

函数内定义的局部变量（Local Variable）分配在**栈**（Stack）上，函数返回后内存自动回收。超出作用域（Scope）访问变量是未定义行为（Undefined Behavior）。

### 4.3 类型的物理约束

- `int` 在 32 位和 64 位系统上通常都是 4 字节，但标准只规定最小范围
- `char` 默认有无符号取决于实现
- 有符号整数溢出是未定义行为（UB）：`INT_MAX + 1` 的后果编译器和优化级别都可能改变结果
- 浮点数遵循 IEEE 754 标准，但存在精度问题

### 4.4 有符号溢出为什么是"未定义行为"

同样是"加过头"，有符号与无符号的待遇完全不同：

```c
#include <limits.h>

int x = INT_MAX;
x + 1;              // UB：有符号整数溢出是未定义行为

unsigned u = UINT_MAX;
u + 1;              // 定义行为：无符号按模 2^N 回绕（wrap around），结果是 0
```

| 类型 | 溢出行为 | 原因 |
|------|---------|------|
| 有符号（`int` 等） | **未定义行为**——优化器假设它不会发生 | 历史硬件对溢出处理不一；如今主要是给编译器优化空间（利用"不会溢出"的假设做边界推断与循环优化） |
| 无符号（`unsigned` 等） | **定义行为**——按模 `2^N` 回绕 | C 标准明确要求，哈希计算、位运算等场景正是靠它才可移植 |

初学者的直觉往往是"溢出就该报错或回绕"——但在 C 里，有符号溢出时**什么结果都是合法的**，包括看起来完全无关的值。这也解释了为什么 3.7 强调"转换前先想清楚范围"：`int` 存不下的数，换成 `long` 或 `unsigned` 是第一步。

> C 的未定义行为目录远不止溢出（空指针解引用、数组越界、除零……），完整清单与实战避坑是 [ph10 未定义行为阶段](../ph10-ub/10-ub.md) 的内容，本阶段先建立"有符号溢出不可依赖"的直觉。

| ph10 未定义行为 | 有符号溢出、类型混用的 UB 直觉（4.4） |
| ph16 存储引擎 | 数据类型与二进制表示（学习路线的最终落地场景之一） |

所以这一阶段值得慢一点——把**编译错误信息怎么读、类型占多大、变量何时销毁**这三件事内化，后面每个阶段都会受益。

### 示例 1：命令行计算器

完整文件：`examples/ex01-calculator.c`

```c
#include <stdio.h>

int main(void) {
    double a, b;
    char op;

    printf("输入算式 (如 3 + 4): ");
    scanf("%lf %c %lf", &a, &op, &b);

    switch (op) {
        case '+': printf("%.2f\n", a + b); break;
        case '-': printf("%.2f\n", a - b); break;
        case '*': printf("%.2f\n", a * b); break;
        case '/':
            if (b != 0.0)
                printf("%.2f\n", a / b);
            else
                printf("错误: 除数为零\n");
            break;
        default: printf("不支持的操作符\n"); break;
    }
    return 0;
}
```

### 示例 2：判断素数

完整文件：`examples/ex02-is-prime.c`

```c
#include <stdio.h>
#include <stdbool.h>

bool is_prime(int n) {
    if (n < 2) return false;
    for (int i = 2; i * i <= n; i++) {
        if (n % i == 0) return false;
    }
    return true;
}

int main(void) {
    for (int i = 1; i <= 100; i++) {
        if (is_prime(i)) printf("%d ", i);
    }
    printf("\n");
    return 0;
}
```

### 示例 3：数组统计

完整文件：`examples/ex03-array-stats.c`

```c
#include <stdio.h>

int main(void) {
    int scores[] = {78, 92, 85, 63, 99, 71};
    int count = sizeof(scores) / sizeof(scores[0]);
    int sum = 0, max = scores[0], min = scores[0];

    for (int i = 0; i < count; i++) {
        sum += scores[i];
        if (scores[i] > max) max = scores[i];
        if (scores[i] < min) min = scores[i];
    }

    printf("人数: %d\n", count);
    printf("平均: %.2f\n", (double)sum / count);
    printf("最高: %d, 最低: %d\n", max, min);
    return 0;
}
```

## 7. 总结

### 关键要点

1. **C 程序以 `main` 为入口**，返回值表示程序状态（0 = 成功）
2. **编译和链接是两步**：编译检查语法，链接解析跨文件符号
3. **静态类型**：每种变量的类型在编译时确定，不可改变
4. **栈变量生命周期由作用域控制**：离开花括号即销毁
5. **整数和浮点都有范围限制**：超出范围会导致溢出或精度丢失
6. **`=` 是赋值，`==` 是相等比较**——混淆是最常见的 bug 之一

### 跨语言对比：基础语法

| 特性 | C | C++ | Java | Python |
|------|---|-----|------|--------|
| 执行方式 | 编译为机器码 | 编译为机器码 | 字节码 + JVM | 解释执行 |
| 程序入口 | `int main(void)` | `int main()` | `public static void main(String[])` | 无需入口，逐行执行 |
| 空值 | `NULL` | `nullptr` | `null` | `None` |
| 字符串 | `char[]` / `char*` | `std::string` | `String` | `str` |
| 动态数组 | `malloc` / `free` | `std::vector` | 定长数组 + `ArrayList` | `list` |
| 布尔 | `_Bool`（C99 `stdbool.h` 提供 `bool`） | `bool` | `boolean` | `bool`（`True`/`False`） |
