# 02 · 移动语义与右值引用

> demo: `make && ./demos/02_move`

## 1. 设计动机

C++ 的值语义有个性能问题：函数传参、返回都要**拷贝**。拷贝 `std::vector` 要复制
全部元素——传个大对象就爆炸。但很多拷贝其实是"临终转移"：临时对象马上销毁，
拷贝纯属浪费。C++11 的命题：**区分"左值（有名字，还会用）"和"右值（临时对象，马上没）"，让右值可以"偷走"资源而不是拷贝**。

## 2. 机制拆解

**右值引用 `T&&`** 绑定临时对象，配合**移动构造函数/移动赋值**实现资源转移：

```cpp
class Buffer {
    char* data_;
    size_t size_;
public:
    // 移动构造：偷走临时对象的指针，临时对象被置空
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // 防止临时对象析构时 double-free
        other.size_ = 0;
    }
    ~Buffer() { delete[] data_; }
};

std::vector<Buffer> v;
v.push_back(make_buffer());   // 临时对象 → 移动而不是拷贝
```

**规则**：
- 左值（`x`）→ 拷贝；右值（`make_buffer()`、`std::move(x)`）→ 移动
- `std::move(x)` 只是把左值**标成**右值，让你主动放弃 `x` 的所有权
- 移动是 O(1)（换指针），拷贝是 O(n)（复制数据）

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 规则复杂 | 值类别（左值/右值/纯右值/亡值）是 C++ 最难的主题之一 |
| 心智负担 | 必须区分"拷贝 vs 移动 vs 引用传递" |
| 误用风险 | `std::move` 一个还在用的对象 = 悬空状态 |

**换来的**：大对象传递零拷贝；`vector` 扩容从 O(n) 拷贝变 O(1) 移动。

## 5. 对 Tenet 的启示

- ✅ **吸收"值语义 + 按需转移"的思维**：Tenet 的值都是小标量（int/float/bool/string），
  拷贝成本可忽略——所以**不需要**移动语义，这正是"最小类型集"的隐性收益
- ✅ **吸收"显式所有权转移"**：Tenet 的函数参数按值传递，无隐式共享——与
  Rust 的 move 精神一致，但成本为零
- ❌ **拒绝右值引用/移动语义**：对只有 4 种标量类型的语言是纯负担
- 💡 若未来加数组/结构体（大对象），才需要重新考虑传值 vs 引用语义

**一句话**：C++ 用移动语义把"拷贝大对象"的成本消灭；Tenet 用「只有小标量」
让这个问题从一开始就不存在。
