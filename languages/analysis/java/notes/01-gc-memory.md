# 01 · 垃圾回收与自动内存管理

> demo: `java demos/01_gc.java`

## 1. 设计动机

C 要求手动 `free`，C++ 用 RAII 把释放绑到作用域——但都要求程序员**想清楚谁拥有谁**。
Java 的命题：**把内存管理整个交给运行时，程序员只 `new`，从不 `delete`**。
这是"托管运行时"路线（managed runtime）的第一块基石：没有悬垂指针、没有 double-free、
没有内存泄漏（理想情况），换来的是**GC 停顿与不可预测性**。
Java 赌的是：对企业级长跑服务，内存安全的价值 >> 手动内存的极致性能。

## 2. 机制拆解

JVM 用**可达性分析**（reachability）而非引用计数：从 GC Roots（栈帧局部变量、静态字段、
JNI 引用等）出发遍历对象图，**不可达的对象就是垃圾**——天然处理循环引用。

```java
class Node { Node next; }          // 单链表结点

void demo() {
    Node a = new Node();
    Node b = new Node();
    a.next = b;  b.next = a;       // 互相引用成环
    // a、b 局部变量出作用域后，环不可达 → 引用计数会漏，可达性分析能收
}
```

**分代假说**驱动主流收集器（G1/ZGC）：绝大多数对象朝生夕灭。
堆分新生代（Eden + Survivor，拷贝收集）/老年代（标记-整理/并发标记）；
`new` 的对象先进 Eden，熬过几轮 Minor GC 的晋升老年代。对象"活多久"用**年龄**记账，
年龄超过阈值（默认 15）晋升——无需扫描全堆。

GC Roots 遍历 + 分代 + 三色标记（并发标记时白/灰/黑三色防止漏标）构成现代 JVM
收集器的骨架。ZGC 进一步把标记与移动做成**并发 + 读屏障**，把停顿压到毫秒级
（与堆大小无关），代价是额外的 CPU 与内存开销。

## 3. 代码验证（demos/01_gc.java）

demo 演示三件事：① 无法手动释放——`finalize`/`Cleaner` 都只是"提醒"，释放时机归运行时；
② 循环引用能被回收（对比引用计数会漏）；③ `-Xlog:gc` 看真实的 Minor GC / Full GC 日志，
亲眼看"停顿"发生。

```bash
java demos/01_gc.java                # 直接跑（JDK 11+ 单文件模式）
java -Xlog:gc demos/01_gc.java       # 开 GC 日志，看分代收集过程
```

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 停顿（stop-the-world） | 回收要暂停应用线程；ZGC 压到毫秒级但换 CPU/内存开销 |
| 释放时机不可控 | 程序员无法保证"文件/连接立刻关闭"——资源得靠 `try-with-resources` 手动管 |
| 内存不可预测 | 峰值占用高于手动/RAII（拷贝收集、碎片整理都要空间） |
| 无法做实时系统 | 硬实时场景（航天/音视频低延迟）是 GC 禁区 |
| 调优是门手艺 | 堆大小/收集器/GC 日志解读是 Java 工程师的必修课 |

**换来的**：C/C++ 时代的内存错误（悬垂、double-free、泄漏）从"日常"变成"罕见"；
`new` 随便写不心疼，开发速度显著提升。企业 Java 的工程现实证明这个取舍划算。

## 5. 对 Tenet 的启示

- ✅ **吸收"运行时自动管理内存"**：Tenet 已选择"值语义 + 引用计数"（见 `Tenet架构设计.md`
  §1.1 内存行）——与 Java 同属"托管"阵营；区别是引用计数**确定性释放**（作用域结束即回收），
  没有 GC 停顿，这是教学语言与解释器最舒服的形态
- ✅ **吸收"分代/可达性的思想但拒绝其复杂度"**：Tenet 用 `Rc` 引用计数即可覆盖循环引用
  以外的全部场景；若未来要处理循环引用，可加"弱引用"而非引入可达性分析
- ❌ **拒绝把 GC 停顿带进语言设计**：解释器 + 引用计数是"少即是多"的最小实现，
  GC 的调优复杂度（`-Xmx`/收集器选型）与 Tenet 的"一种惯用法"原则相悖
- 💡 Java 的 `try-with-resources` 值得借鉴为 `with` 形态（若 Tenet 将来有文件/网络 IO），
  即"自动管理内存 + 显式管理外部资源"的分工——这正是 Java 实践多年得出的正确边界

**一句话**：Java 把内存管理收进运行时换内存安全与开发速度；Tenet 用「值语义 +
引用计数」拿到同样的安心，却不必付 GC 停顿的代价。
