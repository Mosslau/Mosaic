# ph21 IoT / 数据平台 / 嵌入式相关 Go 练习

> 先自己做，再对照 sol-* 参考实现。四题与 roadmap §21 练习对应：MQTT 采集端接入服务 / 数据源指标数据接收服务 / 采集器灰度发布服务 / WebSocket 实时监控面板。每题标注难度（★~★★★），全部离线可测（零第三方依赖），参考实现文件头附运行与测试命令。

## 练习 1：MQTT 采集端接入服务（★★）

**目标**：写出一个"采集端接入核心"——维护采集端连接会话（含鉴权与心跳超时判离线），把采集端的指标消息按主题路由给处理函数；传输层用接口抽象，便于离线单测。
**要求**：
- 定义 Transport 接口（`Connect` / `Subscribe` / `Publish` / 通知断线），自带一个内存假传输做演示与测试（不引第三方 MQTT 库）
- 接入核心要处理：连接时 token 鉴权（拒绝未授权采集端）、心跳超时判离线（超过 N 秒无消息标记 offline）、主题解析（`veh/{sourceID}/metrics` 之类）后回调处理
- 保持核心与传输解耦：若将来换真 paho，核心代码不用改
**验收**：给 3 台采集端各发若干条指标，能断言"每台收到的消息条数正确、坏 token 被拒、超时采集端被标记离线"。

## 练习 2：数据源指标数据接收服务（★★）

**目标**：写一个指标接收/清洗核心——解析上行 JSON、校验字段（sourceID/seq/value 量程）、按 (sourceID, seq) 去重，输出"生效/重复/坏数据"三路计数。
**要求**：
- 输入可以是行文本或事件切片；清洗是纯函数，便于表格驱动测试
- 去重要有界（最近 N 条窗口或单调水位），超量程/缺字段进"坏数据"分类并计数
- 输出一份可打印的汇总（生效 N / 重复 N / 坏数据 M）
**验收**：构造含重复与坏数据的确定性输入，断言三类计数精确匹配、生效数据的换算（如原始计数 0.1% → %）正确。

## 练习 3：采集器灰度发布服务（★★★）

**目标**：实现一个"分批灰度决策器"——采集器版本目标版本下发多批 数据源 ID，逐台报告成功/失败，引擎输出 hold/advance/rollback/complete。
**要求**：
- 批次是 数据源 ID 名单，规则可配（如批内失败率 >20% 即回滚）
- 决策必须确定性纯函数（同输入同输出），可离线回放
- 提供状态查询（当前批、是否已终态）与回滚目标（升级前版本）
**验收**：全批成功走到 complete；某批失败率越限判 rollback 且回滚目标正确；终态后报告不改变状态。

## 练习 4：WebSocket 实时监控面板（★★★）

**目标**：实现一个"实时推送广播器"——多个面板会话订阅数据源状态，状态每次变更都广播给所有订阅会话；断线重连的面板要能补到最近状态。
**要求**：
- 会话用接口抽象（`Send(msg)` / `Close()`），自带内存假会话与可断开的测试会话，不引第三方 WS 库
- 广播去重/乱序交给版本号：每条状态带单调 version，会话可据此丢弃旧消息
- 新会话入会先收当前快照（重连补齐语义）
**验收**：两会话收到相同顺序的状态流且版本单调；中途"断开再连"的会话能补回最新状态；版本回退的消息被拒。
