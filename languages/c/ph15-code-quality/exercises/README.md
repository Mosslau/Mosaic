# exercises —— C 语言高级 C 与代码质量阶段练习

> 先自己做，再对照 sol-* 参考实现。每题标注难度（★~★★★）。

五题与 roadmap ph15「练习」一一对应：练习 1「通用状态机框架」、练习 2「事件驱动框架」、练习 3「命令行解析器」、练习 4「ring buffer」、练习 5「可复用 frame 解析库」（roadmap 写的是"可复用 WAL / frame 解析库"，WAL 落盘语义已在 ph12/ph13/ph16 展开，本题聚焦 ph15 的**可复用解析组件 API**：状态机驱动 + 回调 + 稳定错误码）。所有题目的共同纪律——**`-Wall -Wextra -std=c11` 零警告、稳定错误码（0 成功/负数错误，不用 errno）、内部零全局状态、每题的"行为输出"（状态转移序列 / 回调顺序 / 满空错误）以自测断言锁定**。参考实现在 `sol-*` 文件中，做完再看。

## 练习 1：通用状态机框架（★★★）

- **目标**：用"转移表"（`(from, event) → (action, to)` 的只读数组）实现连接管理状态机，非法事件返回错误码且状态不变
- **要求**：
  - 状态：`CLOSED / LISTEN / ESTAB / FIN_WAIT / CLOSE_WAIT`；事件：`CONNECT / ACCEPT / DATA / CLOSE / PEER_FIN`
  - 动作是函数指针（数组里存函数指针 + 目标状态）；循环查表驱动转移，不用 switch-case
  - 记录"走过的状态序列"（状态号拼成的字符串），自测断言：末状态 = CLOSED、非法事件被拒次数、序列长度
  - 演示路径：正常连一次（含 ESTAB 下 DATA 自环）→ 在 CLOSED 下发 DATA（应被拒）→ 再正常连一次
- **验收**：零警告；每步打印 `转移: 旧状态 --事件--> 新状态` 与动作；非法事件打印"拒绝, 状态不变"并返回 -1；序列与长度断言全过、退出码 0
- 提示：参考 examples/ex03-state-machine.c 的表结构，但要求**自己设计动作集合与状态序列**，并至少让状态机"复用"两次（第一次含非法事件、第二次干净走完）

## 练习 2：事件驱动框架（★★★）

- **目标**：实现一个小型事件分发器：注册（尾部追加保持顺序）→ 分发（同一事件按注册顺序回调全部处理器）→ 注销（移除后不再被调）
- **要求**：
  - 处理器签名：`void (*)(int ev, void *ctx)`；内部只存 `(fn, ctx)` 对，不关心回调业务
  - 注册返回槽位号；注销把后续槽位前移（其余注册的相对顺序不变）
  - 每次分发记录"本次被调用的槽位顺序"，供自测断言
  - 演示：注册 A/B/C → 分发（应 A,B,C）→ 注销 B → 分发（应 A,C）→ 再注册 D → 分发（应 A,C,D）
- **验收**：零警告；打印每次回调与"分发顺序: X Y Z (期望 …)"；自测断言 A=3 次、B=1 次（注销后不再增加）、C=3 次、D=1 次，全过退出码 0
- 提示：ctx 生命周期由注册方负责（回调只读用不释放）；分发期间不得注销（简化版约定，见主文档 3.4）

## 练习 3：命令行解析器（★★）

- **目标**：实现一个"选项表驱动"的命令行解析器：选项表声明 `(长名, 短名, 是否带值, 帮助)`，解析主体查表，不写一长串 if-else 判断选项名
- **要求**：
  - 支持 `--host H`（或 `-h H`）、`-p PORT`、`-v`（无值）、`--workers N`
  - 稳定错误码：`CLI_ERR_UNKNOWN=-1`（未知选项）/ `CLI_ERR_NOVALUE=-2`（缺值）/ `CLI_ERR_BADVALUE=-3`（值非法），配 `cli_strerror`
  - 演示 4 个用例：合法参数（长短名混用）→ rc=0；未知选项 → -1；缺值 → -2；`--port abc` 值非法 → -3
- **验收**：零警告；4 个用例输出 rc 与解析后的 host/port/verbose/workers 全部与期望一致；错误用例不崩溃、错误码正确
- 提示：解析结果放进 struct（默认值先填好，解析只覆盖命中的字段）；选项表加新选项只需加一行表 + 一行 apply

## 练习 4：ring buffer（★★）

- **目标**：用 opaque handle + create/destroy 封装定长环形缓冲，满/空用稳定错误码汇报，内部回绕对调用方不可见
- **要求**：
  - API：`rb_create(cap)` / `rb_destroy` / `rb_push`（满返回 `RB_ERR_FULL=-1`）/ `rb_pop`（空返回 `RB_ERR_EMPTY=-2`）/ `rb_count` / `rb_is_empty` / `rb_is_full`，另配 `rb_strerror`
  - 用 `head + len` 两个游标实现回绕（`(head+len) % cap`），**禁止** `memmove` 搬运
  - 演示：压满 cap=4 → 再 push 应报 FULL；弹出 2 个再压 2 个（触发回绕）；顺序弹出应保持 FIFO
- **验收**：零警告；满/空错误码正确、回绕后弹出顺序 = `c d e f`、自测断言全过、退出码 0
- 提示：零全局状态（句柄自包含，可同时开两个缓冲）；这是 ph16 数据库阶段 Buffer Pool / LRU 淘汰的基础组件，API 要一次设计好

## 练习 5：可复用 frame 解析库（★★★）

- **目标**：把"从字节流里拆 length-prefix frame"做成可复用组件：状态机驱动 + 每解出一个 frame 回调一次 + 稳定错误码
- **要求**：
  - frame 格式：`[len: u16 大端][payload: len]`；`len > 64` 直接判超限
  - 内部状态机：`LEN_HI → LEN_LO → PAYLOAD`，数据分块喂入也能正确拆帧（增量解析）
  - 回调约定：`void (*on_frame)(const uint8_t *payload, uint16_t len, void *ctx)`，解出完整 frame 才回调
  - 错误码：超限返回 `FR_ERR_OVERSIZE=-1` 并进入错误态（错误态下继续喂返回 `FR_ERR_STATE=-2`，调用 `fp_reset` 后才能继续解析新流）
  - 演示：① 三个 frame（"ping"/"pong"/"data!"）分 4 块（1/2/3/剩余字节）喂入全部解出；② 一个超限 frame 被拒；③ 同一解析器 reset 后解析第二个流（证明句柄自包含、可复用）
- **验收**：零警告；分块喂入解出总数 = 3 且 payload 顺序内容正确；超限/错误态/重置路径正确；自测断言全过、退出码 0
- 提示：参考 examples/ex05 的 trace/诊断思路给解析器加 `last_len` 之类的诊断字段；字节序/CRC/落盘属 ph12/ph13/ph16，本题不做

> **提示**：练习 1~5 依次对应主文档 3.5（状态机）、3.3/3.4（函数指针/回调）、3.6（错误码）与 examples/ 对应示例——先独立完成，再对照 `sol-*` 复盘。所有 sol 文件头的"验证环境/编译/运行/验证状态"块里的数字与输出均来自本机（Apple clang 21.0.0，macOS arm64）实测。
