## 练习 1：解析固定格式二进制 record（★）

- **目标**：写一个解析"固定 16 字节 record"的函数，正确处理截断
- **要求**：
  - record 布局（多字节字段大端）：`id`(u32, 4 字节) + `name`(8 字节, 不足补 0) + `score`(u16, 2 字节) + `level`(u8, 1 字节) + `reserved`(u8, 1 字节)，共 16 字节
  - `parse(buf, size)`：`size` 不是 16 的倍数时，报告"尾部剩余 N 字节判为截断"；`level` 不在 1~5 范围判为非法 record
  - 用一段字节数组（3 条合法 record）验证解析输出；再传一个截断的缓冲区验证截断检测
  - 不依赖 `sizeof(struct)` 做 I/O——布局写死在解析逻辑里（为什么？见主文档 3.3/3.6）
- **验收**：`cc -Wall -Wextra -std=c11` 零警告；3 条 record 的 id/name/score/level 全部正确打印；截断缓冲区报告"剩余 N 字节不足一条 record"

## 练习 2：实现大端、小端转换函数（★）

- **目标**：自己实现 `read_be16/be32`、`read_le16/le32`、`write_be32` 与 `swap16/swap32`，并验证正确性
- **要求**：
  - 用逐字节组装/拆解实现（不调用 `htonl` 完成核心逻辑；`htonl` 只用于对照）
  - 验证：`write_be32(0x01020304)` 落线字节固定为 `01 02 03 04` 且与平台无关；`read_be32` 读回一致；`swap32` 与大小端的对应关系正确
  - 运行期检测当前平台字节序（提示：把 `0x0102` 用 `memcpy` 搬进 `uint8_t[2]` 判读低地址字节）
- **验收**：零警告；输出显示大端/小端写入字节序列的差异、往返一致；`htonl(0x01020304)` 在本机（小端）的首字节为 `01`（网络序 = 大端）

## 练习 3：实现 length-prefix frame 解析器（★★）

- **目标**：实现一个增量式 frame 解析状态机：数据分块喂入，仍能正确拆帧并识别截断/超限
- **要求**：
  - frame 格式：`[len: u16 大端][payload: len 字节]`；`len` 超过上限（如 4096）直接判非法
  - 解析器维护"已缓冲未消费"窗口（参考 examples/ex05-frame.c 的 `FrameReader` 思路但自己写）：返回 `1=解出一个 frame` / `0=还差数据` / `-1=长度非法`
  - 把一条含 3 个 frame 的字节流按变长块（如 1/2/3/4/... 字节）喂入，统计解出的 frame；再演示截断（只喂一半）与超限
- **验收**：零警告；任意分块方式下 3 个 frame 全部解出且 payload 内容正确；截断场景返回"还差数据"（EOF 时应判截断），超限场景返回 -1

## 练习 4：实现 varint 编码和解码（★★）

- **目标**：实现无符号 varint（LEB128）的编解码，正确处理截断与超长
- **要求**：
  - 编码：低 7 位一组，非末字节带续位标记 `0x80`；`uint32_t` 最多 5 字节
  - 解码：逐字节累加，遇无续位字节结束；输入截断（全是续位）或超过 5 字节判非法返回 0
  - 验证：`0/127/128/16383/16384/0xFFFFFFFF` 编码字节序列正确且往返一致；连续多个 varint 依次解码
- **验收**：零警告；6 组边界值往返全部一致；`{0x80, 0x80}` 判非法；连续解码结果与预期一致

## 练习 5：为 WAL record 设计 header 和 checksum（★★★）

- **目标**：设计并实现一个带 magic + 类型 + 长度 + CRC32 的 WAL record 格式（追加写 + 回放读 + 损坏/截断检测）
- **要求**：
  - record 布局（大端）：`magic`(u32 = "WAL1") + `type`(u8, 1=PUT 2=DEL) + `len`(u16) + `crc32`(u32, 覆盖 type+len+payload) + `payload[len]`
  - 写路径 `append`：校验长度不超上限 → 组装 → 计算 CRC 追加到内存日志
  - 读路径 `replay`：先校验剩余长度 ≥ 11 → 校验 magic/type → 校验 payload 长度 → 校验 CRC → 才拷贝 payload
  - 自测（可参考 examples/ex06-selftest.c 的 CHECK 宏思路）：3 条 record 往返一致；翻转 payload 一位应触发 CRC 错误；截断应触发长度错误；`main` 返回 `failures == 0 ? 0 : 1`
- **验收**：零警告；往返 + 损坏 + 截断三类自测全部通过、退出码 0；故意在 `replay` 里去掉长度检查后重编译，自测应能抓住（截断用例失败）
