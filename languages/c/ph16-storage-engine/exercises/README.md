# exercises —— C 语言数据库存储引擎基础阶段练习

> 先自己做，再对照 sol-* 参考实现。每题标注难度（★~★★★）。

五题与 roadmap ph16「练习」一一对应：练习 1「实现 WAL append / replay」、练习 2「实现 Mini SSTable writer / reader」、练习 3「实现 Bloom Filter」、练习 4「实现 LRU Cache」、练习 5「实现简化 B+Tree 或 LSM 文件层」（本题选简化 B+Tree；LSM 文件层由 project/ 落地）。所有题目的共同纪律——**`-Wall -Wextra -std=c11` 零警告、文件格式多字节字段显式大端（ph12 纪律）、行为输出（回放计数 / 查询结果 / 淘汰顺序 / 扫描序列）用自测断言锁定并反映在退出码**。参考实现在 `sol-*` 文件中，做完再看。

## 练习 1：WAL append / replay（★★）

- **目标**：实现带 type 字段的 WAL：`append` 追加 PUT/DEL 记录，`replay` 顺序回放并统计 PUT/DEL 条数，识别并修复崩溃残尾
- **要求**：
  - 记录格式：`[magic u32 "WAL1"][type u8][klen u32][vlen u32][key][value][crc32 u32]`，多字节字段显式大端，crc32 覆盖 type..value
  - append 用 O_APPEND + write_full（短写循环，EINTR 重试）；replay 按「长度 → magic → 上限 → CRC」四道校验，任一失败停在残尾并报告偏移
  - 演示：写 5 PUT + 2 DEL → 回放计数正确；手工写 5 字节残尾 → 回放停在准确偏移；ftruncate 修复 → 回放干净且可继续追加
- **验收**：零警告；自测断言覆盖干净 EOF / PUT=5 DEL=2 / 残尾偏移 / 修复后可追加，全过退出码 0
- 提示：参考 examples/ex02，但要求回放把 PUT/DEL **应用到一张内存表**（put 覆盖、del 删除），验证"WAL 恢复内存态"这条核心语义

## 练习 2：Mini SSTable writer / reader（★★★）

- **目标**：把一组已升序的 key/value 写成带稀疏索引的 SSTable 文件，再实现只读查询
- **要求**：
  - 布局：`[entry: klen u32 / type u8 / vlen u32 / key / value]*`（数据区升序）+ 稀疏索引（每 4 条索引一条 `(key, offset)`）+ 定长 footer（index_off u64 / index_cnt u32 / magic u32 "SST1"）
  - reader 从文件尾读 footer → 载入索引 → 二分找"最后一个 ≤ target 的索引项" → 块内顺扫至多 4 条；tombstone（type=DEL）返回"不存在"
  - 统计并打印命中时块内实际扫过的条数
- **验收**：零警告；9 条记录（含 1 条 tombstone）写入后：get 命中值正确、tombstone 与范围外 key（比最小还小/比最大还大）返回不存在、索引项首条 key 命中时只扫 1 条；自测断言全过退出码 0
- 提示：footer 定长才能从文件尾直接定位；索引项存"块首 key"才能用 `<=` 二分

## 练习 3：Bloom Filter（★★）

- **目标**：实现位数组 + k 个哈希的 Bloom Filter，实测误判率并与理论值对比
- **要求**：
  - 双哈希法：`h_i(x) = h1(x) + i*h2(x)`（两个 FNV-1a 合成 k 个哈希），位数组按字节存放
  - 配置：插入 n=10000 个 key，每 key 10 位，k=7
  - 回查全部已插入 key（漏报必须为 0）；再用 100000 个未插入 key 探测误判率，打印实测值与理论值 `(1-e^(-kn/m))^k`
- **验收**：零警告；自测断言：漏报 = 0、实测误判率 < 理论值 2 倍（宽松上界，容忍哈希非理想独立）、假阳性确实存在；全过退出码 0
- 提示：理论最优 k ≈ (m/n)·ln2 ≈ 6.9，可顺带验证 k=4/7/10 的理论误判率曲线；math 函数需 `-lm`

## 练习 4：LRU Cache（★★）

- **目标**：实现 O(1) get/put 的 LRU Cache：哈希表定位 + 双向链表维护使用顺序
- **要求**：
  - 容量固定（如 3）；get/put 命中都把节点挪到头部；满了淘汰尾部（最久未用）
  - put 已存在的 key 是覆盖 + 挪头部，不增容量
  - 把每次被淘汰的 key 记进日志数组，供自测断言淘汰顺序
- **验收**：零警告；演示序列「put 1/2/3 → get 1 → put 4（应淘汰 2）→ put 1 覆盖 → put 5（应淘汰 3）」；断言淘汰序列 = 2,3、被淘汰 key 查不到、未被淘汰的仍命中；全过退出码 0
- 提示：链表操作先写 detach / push_front 两个小函数，所有路径只调它们；这是 ph16 examples/ex06 Buffer Pool 去掉"脏页写回"的纯缓存版

## 练习 5：简化 B+Tree（★★★）

- **目标**：实现内存版 B+Tree（阶 4，每节点最多 3 个 key）：插入（含分裂）、点查、范围扫描
- **要求**：
  - B+Tree 约束：数据全在叶子节点；叶子间用 `next` 指针串联；内部节点只存路标 key
  - 插入溢出即分裂：叶子 4 个 key → 左 2 右 2、上提右兄弟首 key 的**副本**；内部节点 4 个 key → 左 2 右 1、中位 key 上提（不保留在原层）；根分裂时新建根
  - 乱序插入 1..20（固定置换保证可复现），val = key×10；重复 key 覆盖
- **验收**：零警告；自测断言：树高 ≤ 3、1..20 全部可查且值正确、不存在的 key（0/21/99）查不到、范围扫描 [5,12] 输出 8 个且严格升序、重复 key 覆盖生效；全过退出码 0
- 提示：递归插入返回"是否分裂 + 上提 key + 新右兄弟"三件套；叶子分裂上提副本、内部分裂上提本体——这一字之差是 B+Tree 最易错的点

练习 1~5 依次对应主文档 3.1/3.2（WAL）、3.4（SSTable）、3.5（Bloom Filter）、3.8（LRU）、3.6（B+Tree）——先独立完成，再对照 `sol-*` 复盘。所有 sol 文件头的"验证环境/编译/运行/验证状态"块里的数字与输出均来自本机（Apple clang 21.0.0，macOS arm64）实测。
