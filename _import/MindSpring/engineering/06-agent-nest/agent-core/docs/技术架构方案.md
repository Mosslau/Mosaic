# agent-core 技术设计文档（架构）

> 版本：v0.2 · 状态：**设计存档**（2026-08-27 决定暂不开发，文档归档于 agent-core/docs）
> 配套文档：[实施方案](./实施计划方案.md)（分阶段路线图，含工时 / 验收 / 风险）

## 1. 概述

agent-core 是一个**完全自研的 Agent 核心（agent-core）**——服务端部署的企业级 Agent
执行引擎：通过 HTTP/gRPC API 对外提供服务，内部完成"模型调度 → 工具执行 → 会话管理 →
策略审批 → 审计观测"的全链路。

**定位区分（重要）**：在 [frameworks/](../frameworks/README.md) 的**统一平台底座**架构下，
agent-core 是**第五个运行时适配器**——唯一完全自研、最可控的 Agent 内核（与 agentscope /
langchain-graph / codex / dsh 四个框架适配器并列，通过运行时端口接入同一底座）：

| | 框架适配器（agentscope / langchain-graph / codex / dsh） | agent-core 自研适配器 |
|---|---|---|
| 技术基座 | 基于框架组装（Python / TS / 闭源） | **完全自研**（Rust，不依赖任何 Agent 框架） |
| 核心循环 | 框架提供的运行时（适配器翻译） | 自研运行时：循环/工具/策略/路由全部自有代码 |
| 接入底座方式 | 扩展点注入 / 进程编排 / 插件树 | HTTP/gRPC 直连（端口最干净、最可控） |
| 适用场景 | 快速平台化、多端生态（企微/飞书） | 深度定制、性能与可控性优先、长期演进 |
| 关系 | 各框架目录三件套 = 该适配器的详细方案 | 本文档 = 自研运行时蓝本 + AI 基础设施（模型网关等）蓝本 |

- **技术栈**：Rust（tokio 异步运行时），单二进制部署
- **产品形态**：服务端服务；CLI/TUI/IM 均为客户端，不承载核心逻辑
- **应用场景**：通用任务执行（代码仓库、文档、数据库、运维、审批流），工具按需插拔
- **模型接入**：多提供商抽象层（Anthropic / OpenAI / DeepSeek / Qwen / GLM 统一接口），
  带路由、fallback、成本预算

### 1.1 目标质量（稳定、灵活、健壮）

| 维度 | 工程含义 | 落地机制 |
|---|---|---|
| 稳定 | 长时间运行不泄漏、不抖动、可恢复 | 资源配额、会话持久化、优雅停机、幂等重试 |
| 灵活 | 工具/模型/策略可插拔，不改核心 | 端口-适配器架构、注册表、策略即配置 |
| 健壮 | 面对模型故障、工具失控、恶意输入不崩 | 错误分类恢复、超时/取消、沙箱、限额 |
| 可审计 | 企业合规要求"谁在何时做了什么" | 全量 transcript、结构化审计日志、tracing |

### 1.2 设计原则

1. **循环不变，机制环绕**。Agent 主循环（模型 ↔ 工具）是唯一不变式；一切能力（权限、
   hooks、压缩、记忆、调度）都是环绕机制，通过扩展点接入，绝不改写循环。来源：
   AgentNest/tutorials 的核心教学抽象，生产化后保留。
2. **端口-适配器（Ports & Adapters）**。`Provider`、`Tool`、`Hook`、`SessionStore`、
   `Policy` 全部是 trait（端口）；具体实现（anthropic 线、bash 工具、内存存储…）是适配器。
   核心引擎只依赖端口，保证可测试、可替换。
3. **错误分类优先，恢复分级**。所有外部调用先分类（瞬态/永久/超长），再决定重试、降级
   或失败。来源：tutorials/rust s11（typed error + 抖动退避 + fallback 模型），生产化后
   增加熔断与成本感知。
4. **默认拒绝，最小权限**。工具沙箱、路径白名单、审批门禁默认关闭能力，按需放开。
5. **一切可观测**。每次 LLM 调用、每次工具执行、每次审批决策都有结构化记录；
   流式事件对客户端可见。
6. **失败要快，降级要优雅**。瞬态错误重试有界；fallback 链有序；单点故障不拖垮整机。

## 2. 系统形态与部署拓扑

```
                        ┌──────────────────────────────────────────┐
                        │                agent-core 服务端            │
  CLI ──┐               │  ┌──────────┐   ┌──────────────────────┐  │
  TUI ──┼── HTTP/gRPC ──┼─▶│ API 层    │──▶│ 会话/租户域           │  │
  IM   ─┘   (SSE 流式)   │  │ authn/z  │   │ SessionStore(DB)     │  │
                        │  └──────────┘   └──────────┬───────────┘  │
                        │                            ▼              │
                        │  ┌─────────────────────────────────────┐  │
                        │  │           Agent 运行时               │  │
                        │  │  主循环 · 工具注册表 · hooks · 策略    │  │
                        │  └───────┬──────────────┬─────────────┘  │
                        │          ▼              ▼                │
                        │   ┌────────────┐   ┌──────────────────┐  │
                        │   │ agent-llm   │   │ 工具执行器（沙箱）   │  │
                        │   │ 路由/回退   │   │ bash/fs/db/…      │  │
                        │   └────────────┘   └──────────────────┘  │
                        └──────────────────────────────────────────┘
  模型侧: Anthropic ─ OpenAI ─ DeepSeek ─ Qwen ─ GLM（统一 Provider 端口）
```

- **部署**：容器（K8s）单进程多会话；无状态 API 层 + 有状态会话存储分离（Phase 2）。
- **多租户**：租户是隔离与配额的最小单位——命名空间隔离（会话/任务/工具权限按租户）、
  模型配额、密钥隔离、审计归属。
- **扩展形态**：同一引擎可服务"编码助手"与"通用工作流"两种产品，差异只在工具集与策略。

## 4. 核心数据模型

### 4.1 消息与内容块

```
Message { role: user|assistant|tool, content: [ContentBlock] }
ContentBlock = Text | Thinking{signature} | ToolUse{id,name,input}
             | ToolResult{tool_use_id, content, is_error}
```

**不变量：`tool_use_id` 配对完整性** —— 任何 ToolResult 必须与其 ToolUse 同处上下文，
且顺序为 use → result。运行时在发送前做 `sanitize_tool_pairs`（学习自 tutorials/rust s14
实测 bug：cron 注入打断配对导致 API 400）。

### 4.2 会话

```
Session { id, status, meta{tenant_id, model, user_id, tags}, messages[],
          total_usage, created_at, updated_at }
状态机: Active → Running ⇄ Active → Completed | Failed | Cancelled
```

- 会话是**服务端持久化**对象（Phase 2 接 PostgreSQL/Redis，`SessionStore` 端口先行）。
- Running 状态防并发写入（同一会话同时只允许一个执行任务）；多实例部署下由
  `SessionStore` 以租约 / 乐观锁（版本号 CAS 或 advisory lock）保证跨实例互斥（P2 落地）。

### 4.3 Token 用量

```
Usage { input, output, cache_read, cache_write }
```

归一化自各提供商；`cache_read/cache_write` 为 prompt 缓存监控与计费预留。

## 5. Agent 执行循环（运行时）

### 5.1 主循环流程

```
用户输入（追加为 user 消息）
  │
  ▼
┌─ while true ─────────────────────────────────────────────┐
│ 1. [hooks] on_turn_start                                  │
│ 2. 组装 ChatRequest（system + messages + tools，缓存断点）  │
│ 3. 流式调用模型（agent-llm：路由→重试→fallback）             │
│    流事件实时转发给调用方（SSE）                            │
│ 4. 错误处理（见 5.3）                                      │
│ 5. 追加 assistant 消息；若无 tool_use → 结束                │
│ 6. 逐工具执行：                                            │
│    [hooks] on_pre_tool_use → 策略审批 → 执行（超时/取消）    │
│    → 截断/落盘 → [hooks] on_post_tool_use                  │
│ 7. 追加 tool_result 消息；sanitize_tool_pairs；轮次+1       │
└─ 轮次 ≥ max_rounds 或取消 → 结束 ──────────────────────────┘
```

### 5.2 流式与会话事件

- 模型流式事件（TextDelta / ToolUseInputDelta / Stop…）归一化为 `StreamEvent`，
  运行时原样转发给客户端（SSE），同时增量重建 `ContentBlock`。
- **流中错误语义**：首个事件之前的错误可安全重试；流中间错误不重试（副作用已可能
  发生），通过 `StreamEvent::Error` 上抛，由调用方决策（Phase 5 支持续接）。

### 5.3 错误恢复（移植自 tutorials/rust s11，生产化）

```
LlmError = RateLimited{retry_after} | Overloaded | PromptTooLong | Auth
         | InvalidRequest | Provider{status} | Network | Timeout | Protocol | Cancelled
分类 → 瞬态? → 指数退避重试（抖动 ±30%，尊重 Retry-After，有界 4-6 次）
     → 连续过载/速率受限 → fallback 链下一个模型
     → 永久错误 → 立即失败（不浪费重试）
```

## 6. 多提供商抽象（agent-llm）

### 6.1 Provider 端口

```rust
trait Provider: Send + Sync {
    fn id(&self) -> &str;                                   // "anthropic" | "openai" | ...
    async fn chat(&self, req: ChatRequest) -> Result<ChatResponse, LlmError>;
    fn chat_stream(&self, req: ChatRequest)
        -> Pin<Box<dyn Stream<Item = Result<StreamEvent, LlmError>> + Send>>;
    async fn embed(&self, req: EmbedRequest) -> Result<EmbedResponse, LlmError>; // P4 记忆检索
}
```

适配器职责：协议翻译（消息/工具/停止原因/用量归一化）+ 认证 + 超时 + SSE 解析。
**归一化规则**：thinking 块只在 anthropic 线原样回传（signature 保留）；OpenAI 兼容线
丢弃 thinking；stop_reason 映射统一为 `StopReason`。

**embed 端口**：`embed()` 为 P4 记忆检索预留——OpenAI 兼容线原生支持，anthropic 线经
兼容 embedding 端点接入；契约测试锁定向量维度与归一化行为。

### 6.2 模型路由与 fallback

```
routes: model_name → { provider, max_tokens 默认, 参数覆盖 }
chains: model_name → [fallback 模型...]   # 按优先级
```

- `chat_stream` 在**首事件之前**做重试与 fallback（打开流 = 请求已发出，之后不再换线）；
- 每次调用记录：provider、model、tokens、耗时 → 成本核算（单价表，Phase 1 预留钩子）。

### 6.3 成本预算（Phase 1 预留，Phase 3 落地）

- 会话级/租户级 token 与金额双预算；超预算 → 降级到便宜模型或拒绝新轮次。

## 7. 工具体系

### 7.1 端口与注册表

```rust
trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn input_schema(&self) -> &Value;             // JSON Schema（draft-07 子集）
    async fn run(&self, ctx: &ToolContext, input: Value) -> Result<ToolOutput, ToolError>;
}
```

- **注册表**：`ToolRegistry`（注册/查询/列表/执行）；执行前 schema 校验输入，
  执行带超时与取消（`tokio::select!`），输出按字节配额截断（按行截断，不切 UTF-8）。
- **工具上下文** `ToolContext`：租户、会话、工作目录、环境变量白名单、取消令牌。
- **插拔方式**：内置工具（agent-tools）+ MCP 外部工具（Phase 3，真实传输层）+ 进程外
  工具插件（Phase 6，IPC）。

### 7.2 内置工具（Phase 1）

`bash`（超时/进程组击杀/输出截断）、`read_file`、`write_file`（原子写）、`glob`。
路径策略：词法解析 + canonicalize + **必须落在租户工作区内**（防 symlink 穿越，移植
tutorials/rust s18 的越界检查经验）。

### 7.3 沙箱（Phase 3）

bash 类工具默认在**沙箱进程**中执行：landlock/seccomp 起步（无 root 权限要求），
容器（gVisor/普通 OCI）作为部署选项；网络 egress 按租户策略（默认拒绝外联）。

> 平台约束：landlock/seccomp 为 **Linux 专用**——本地开发（macOS）以路径沙箱降级验证，
> 沙箱行为在 Linux CI / 容器中固化测试。

## 8. 会话与多租户（Phase 2 重点）

| 维度 | 设计 |
|---|---|
| 存储 | `SessionStore` trait → 内存（测试）/ PostgreSQL（生产）；消息历史按会话追加写 |
| 租户隔离 | 数据：session/任务/审计按 tenant_id 分区；密钥：每个租户自己的模型密钥池 |
| 配额 | 并发会话数、RPS、token 预算、工具调用次数（按租户） |
| 策略 | 每租户一套工具白名单 + 权限模式 + 审批规则（Phase 3） |
| 认证 | API key（服务级）+ OIDC（用户级，Phase 2 末） |

## 9. 上下文管理（Phase 4）

- **Prompt 缓存优先**：system/tools 常驻缓存段（`cache_control` 断点），会话历史
  增量续写——缓存是生产环境成本与延迟的第一杠杆。
- **压缩兜底**：tutorials/rust s08 四层管线生产化（snip → micro → budget → LLM 摘要），
  摘要后**保留可缓存前缀**（缓存感知压缩）。
- **记忆分级**：工作记忆（会话内）→ 长期记忆（文件/向量库，Phase 5）。

## 10. 可观测性与运维

| 面 | 机制 |
|---|---|
| 日志 | tracing（结构化，JSON 输出），请求 ID 贯穿全链路 |
| 指标 | 每模型调用量/延迟/错误率、工具执行量/失败率、会话吞吐（Prometheus，Phase 2） |
| 审计 | 审批决策、工具调用（含输入输出摘要）、租户操作，只追加存储 |
| 健康 | /healthz（存活）、/readyz（依赖就绪）、优雅停机（ draining → 取消进行中工具 → 落盘会话） |
| 配置 | 分层配置：默认值 ← 租户覆盖 ← 运行时热更新（Phase 2） |

## 11. 安全模型

| 威胁 | 对策 |
|---|---|
| 提示注入（恶意文档/命令） | 工具输入脱敏、关键工具审批、模型输出不直接拼 shell（参数化/白名单） |
| 路径穿越 | canonicalize + 工作区边界（Phase 1 已内置） |
| 命令注入 | bash 工具仅限租户工作区 + 沙箱（Phase 3）；后续工具一律参数化 |
| 密钥泄漏 | 密钥只进服务端 vault；日志脱敏（mask key/token）；.env 永不提交 |
| 资源耗尽 | 工具超时/配额、输出截断、并发限额、轮次上限 |
| 多租户越权 | tenant_id 贯穿所有查询与配额；策略按租户评估 |

## 12. 关键设计决策（ADR 摘要）

| # | 决策 | 理由 | 状态 |
|---|---|---|---|
| 1 | 主循环唯一不变式，机制全部外挂 | 可演进、可测试；learn 轨道验证过的纪律 | 已采纳 |
| 2 | Provider/Tool/Hook/Store 全端口化 | 企业环境换模型/换存储/加策略零侵入 | 已采纳 |
| 3 | 流式优先，事件上抛 | 用户体验 + 故障可观测；流中错误不盲目重试 | 已采纳 |
| 4 | 错误分类 + 有界退避 + fallback 链 | 学自 s11，生产级恢复的最小完备集 | 已采纳 |
| 5 | 先 landlock/seccomp，容器为部署选项 | 无特权进程内沙箱最易落地，容器留给重隔离场景 | 提案 |
| 6 | 会话先内存后 PostgreSQL | 端口先行，存储后置，避免过早绑定 | 已采纳 |
| 7 | 租户级密钥池 + 模型路由表 | 企业自备密钥、按租户计费 | 提案 |
| 8 | OpenAI 兼容线丢弃 thinking 块，仅 anthropic 线保留 signature | 归一化简单、成本可控；如需思考过程可见再扩展 | 已采纳 |
| 9 | P1 自研迷你 JSON-schema 校验器，P3 换正式库 | 避免早期引入重依赖；端口隔离保证可替换 | 已采纳 |
