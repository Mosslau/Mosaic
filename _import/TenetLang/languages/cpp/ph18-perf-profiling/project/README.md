# ph18 阶段项目：向量距离计算性能对比

对应 roadmap §18「推荐项目」第一个「向量距离计算性能对比」（另两个——列式扫描性能优化实验、高性能日志/数据文件解析器——分别由主文档 3.5/3.8 的方法论与 exercises 2/3、examples/ex04 的思路覆盖，留作后续自选）。**边界声明：本项目是「实现技术阶梯」的基准 demo，不是真检索库**——无索引、无 HNSW/IVF/PQ、无 topK 堆、无多线程（那些属于 roadmap 第 23 节向量检索与 AI 推理引擎方向 C++ 阶段与 ph08 并发编程阶段）；本项目只回答一件事：**同一份 128 维 float 向量库上，暴力 L2 扫描的四种写法差多少倍，以及它们的结果为什么必须一致**。

## 需求

对 100k 个 128 维 float 向量做全量 L2 距离暴力扫描：6 个查询向量各自找最近邻，统计每种实现的耗时与吞吐。三种实现共享同一语料与查询集、同一距离语义（`∑(q_i - c_i)²` 逐向量取最小）：

| 实现 | 手法 | 教学点 |
|------|------|--------|
| ① scalar | 朴素单 float 累加器 | 正确性基线；每维串行依赖链 |
| ② unroll4 | 4 路独立累加器 | 拆依赖链（examples/ex05 ③ 手法；编译器可能进一步自动向量化——那也是教学点） |
| ③ neon | NEON 8 宽双向量累加（arm64；x86 退化为 ②） | 布局连续 + 并行度同时到位的极限形态 |

## 功能清单

- [x] 确定性语料/查询生成（固定种子，跨实现、跨机器可复现）
- [x] 三种实现 + 一致测时框架（预热、3 轮取最优、每轮微扰查询集防 LICM/CSE）
- [x] 输出耗时表 + 吞吐（M dist/s）+ 相对 ① 的倍率
- [x] 跨实现一致性断言：最近邻索引逐查询相同、距离值在容差内一致
- [x] `--selftest` 小规模一致性自检（CI 信号）+ `--help`
- [x] Makefile：`make` / `make run` / `make test` / `make clean`，产物隔离 `build/`

## 验收标准

- [ ] `make clean && make test` 退出码 0：scalar 与 unroll4、scalar 与 neon 两两「最近邻结果一致」全部 [通过]
- [ ] `make run` 打印三行耗时/吞吐对照表，且「scalar 与 neon 最近邻结果一致」[通过]
- [ ] 双编译器 `clang++ -std=c++20 -O3 -Wall -Wextra` 编译零警告（Apple clang 21 / Homebrew clang 21）
- [ ] 代码无裸 new/delete（R.11）、无 C 风格数组指针裸管理（语料用 `std::vector`、向量用 `std::array`）、常量用 `constexpr`（Con.5）、无魔法数字散落（ES.45）
- [ ] 能口头说清：为什么三种实现计算顺序不同仍必须给出**相同**的最近邻结果；为什么 `--selftest` 用 4k 语料而默认基准用 100k 语料（缓存能否装下决定测的是实现还是内存带宽）

## 扩展方向（可选）

- **x86-64 intrinsics**：把 ③ 补成 AVX2/SSE 版本，形成「同一套方法、两套指令集」对照（衔接 roadmap 第 23 节）
- **topK 与批量查询**：目前每次查询只取最近邻（argmin）；改成 `top-k` 需要小顶堆/`std::partial_sort`，距离计算与排序解耦（衔接 roadmap 第 23 节 ANN 工程化）
- **多线程分块**：语料按块分给线程、各自找局部最近邻再合并——线程模型属 ph08 并发编程阶段，能顺带验证「多线程是否让内存带宽饱和」
- **列式 vs 行式再深入**：本项目三种实现都在行式连续布局上；换成 SoA 多数组布局重跑一遍，与 examples/ex05 的结论互证（列式扫描主题，衔接 roadmap 第 23 节）
- **真检索库对照**：用 Faiss 的 `IndexFlatL2` 跑同一语料，对比「手写暴力扫描 vs 工业库」的距离计算吞吐差距

## 验证环境

- 实测环境：macOS arm64，Apple clang 21.0.0 + Homebrew clang 21.1.8，C++20（libc++）
- 构建：`make`；运行：`make run` 或 `./build/vec_bench`；测试：`make test` 或 `./build/vec_bench --selftest`；清理：`make clean`
- 验证状态：**已验证**（本机实测：`make test` 全绿退出码 0；默认基准 scalar 29.1 ms → unroll4 23.3 ms → NEON 5.3 ms（约 5.5x），最近邻结果跨实现一致）
