# 04 · 生成器与迭代器（惰性求值）

> demo: `python3 demos/04_generators.py`

## 1. 设计动机

一次生成 10 亿个数的列表？内存直接爆掉。Python 的命题：
**序列可以是"按需生产"的——迭代器协议 + yield 让"无限序列"和
"流式处理"成为日常**。这是函数式语言（Haskell 惰性求值）思想的实用版。

## 2. 机制拆解

**迭代器协议**：任何对象实现了 `__iter__` + `__next__` 就能被 `for` 消费。
**生成器**：含 `yield` 的函数自动变成迭代器——每 `yield` 一次暂停，
下次 `next()` 从暂停处继续：

```python
def count_up_to(n):
    i = 1
    while i <= n:
        yield i        # 暂停，把 i 交给调用方
        i += 1         # 下次继续从这里走

for x in count_up_to(3):   # 惰性：一次只生产一个
    print(x)
```

**关键收益**：
- 内存 O(1)：无限序列（如斐波那契）随便生成
- 惰性求值：`itertools` 组合出"管道"，只算需要的部分
- 生成器是"协程"的雏形：yield 可以双向通信（send）

## 3. 代码验证（demos/04_generators.py）

demo 演示：无限斐波那契生成器（`for` 取前 N 项）、惰性求值省内存的对比。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 隐式状态 | 生成器的暂停/恢复状态藏在内部，难调试 |
| 心智模型 | "yield 暂停"需要新思维方式 |
| 性能 | 逐项生成比一次性列表慢（换内存节省） |

**换来的**：无限序列、流式处理、内存可控的大数据遍历。

## 5. 对 Tenet 的启示

- ✅ **吸收"按需求值"的意识**：Tenet 的 `&&`/`||` **短路求值**就是最小的惰性——
  右侧表达式只在需要时求值，这正是惰性求值思想在语言核心的体现
- ✅ **吸收"遍历是语言一等概念"**：Tenet 的 `while` 循环是唯一的遍历原语，
  简洁且无歧义
- ❌ **拒绝生成器/yield**：教学语言没有大数据场景，`while` 足够；
  惰性求值只保留了"短路"这一个最小形态
- 💡 若未来加数组，可参照 Go 的 `range` 设计统一遍历，而非完整迭代器协议

**一句话**：Python 用生成器把"序列"变成按需生产；Tenet 把惰性收缩成
「短路求值」这一个点，用最小机制继承精髓。
