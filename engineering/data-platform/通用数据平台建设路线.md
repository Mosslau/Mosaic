# 通用数据平台建设路线

> 版本：v01 · 待评审
> 形态：**方案设计 + 实施设计合体**——§1–§4 回答“建什么”，§5–§8 回答“怎么建、怎么验、花多少”。
> 定位：通用数据平台的当前架构与建设路线；业务/职业路线见 roadmap 对应文档。

## 1. 设计目标与原则

**目标**：以「集成成熟开源 + 薄自研胶水」构建企业级 Data+AI 数据平台——湖仓为真相源、控制面统一治理、语义层唯一口径，业务能自助接入、安全消费。

五条原则：

1. **湖为真相源，Doris 只做 serving**：任何服务层表都能从湖重建。
2. **先能管才能放**：质量、权限、审计先于对外 API/BI。
3. **一个阶段一个能力域**：阶段结束必须有端到端证明，不接受“组件装好但链路不通”。
4. **契约先定死**：D1 冻结信封/命名/DLQ/健康/trace/账本；后续域按契约接入。
5. **不造全家桶**：调度、集成、湖表、目录、语义引擎用成熟件；只自研入口与缺失胶水。

## 2. 总体架构

### 2.1 结构视图（4 层）

```text
入口层     统一门户 + 开放 API + BI（Superset）
控制面     配置 / 元数据 / 指标 / 调度 / 质量 / 血缘 / 权限 / 审计 / 成本 / 告警 / 资源 / 模型
数据面     接入 → 湖仓 → 计算 → 语义 → 服务 → AI
基础设施   Kafka / MinIO / Iceberg / Doris / Flink / Spark / PG / Redis / K8s
```

### 2.2 数据流（5 跳）

```text
源 → ①接入(D3) → ②入湖(D2) → ③计算(D4) → ④语义(D6) → ⑤服务/BI(D9) → ⑥AI 问数(D10)
```

### 2.3 9 个能力域与 12 个控制中心

- **9 域**：① 数据集成 ② 存储底座 ③ 计算引擎 ④ 统一目录 ⑤ 开发工作台 ⑥ 数据治理 ⑦ 语义与服务 ⑧ AI 工程化 ⑨ 平台控制面与运营。
- **12 中心**是控制面职责，不是 12 个新域：权限、配置、元数据、指标、调度、质量、血缘、审计、告警、资源、模型、成本。
- 落点：权限/质量→D8；配置/调度→D5；元数据/血缘→D7；指标→D6；告警/资源→D0/D5；模型→D10；成本→D8/D11；统一控制台/跨域编排/注册/trace/台账→D11。

### 2.4 规模假设

| 档位 | 源表 | 日增 | API QPS | 集群 |
|---|---|---|---|---|
| PoC | 1 | ≤10MB/s | — | 8C32G |
| 试点 | 10 | 500GB | 50 | 3×16C64G |
| 生产 | 50 | 5TB | 500 | 6+×32C128G |

### 2.5 核心契约

| 契约 | 作用 |
|---|---|
| `Envelope` | 统一信封：源/表/批次/时间/水位/错误码 |
| `TableRef` | 湖表/快照/分区的统一引用 |
| `MetricDef` / `MQL` | 指标定义与查询语言（MQL→SQL） |
| `LineageEvent` | 表/字段/指标血缘事件 |
| `Policy` | 权限/脱敏/租户/配额策略 |
| `QueryRequest` | 查询网关的鉴权/限流/审计入口 |

## 3. 能力域与选型

| 域 | 选型 | 说明 |
|---|---|---|
| ① 数据集成 | SeaTunnel（Zeta） | 批/流/CDC 统一入口，DLQ 按原因枚举 |
| ② 存储底座 | Iceberg + MinIO + Doris | 湖为真相源，Doris 只做 serving |
| ③ 计算引擎 | Flink / Spark / Doris | 流/批/OLAP 分工 |
| ④ 统一目录 | DataHub | 技术/业务/运行时元数据 + 血缘 + 授权 |
| ⑤ 开发工作台 | DolphinScheduler + StreamPark | DS 唯一编排；StreamPark 托管实时 |
| ⑥ 数据治理 | 自研规则 + DataHub/OpenLineage | 质量阻断、权限、脱敏、审计、成本、多租户 |
| ⑦ 语义与服务 | 自研 `metric_def` + Calcite + 查询网关 + Superset | 指标唯一口径，API/BI 同源 |
| ⑧ AI 工程化 | NL→MQL + 评测集 + 诊断 | LLM 只产 MQL，不直产 SQL |
| ⑨ 平台控制面与运营 | 控制台/API + 跨域编排 + trace/成本/台账 | D11；跨域总控，不是 D5 的任务调度 |

**明确不选**：自研调度/集成/湖表/语义引擎；Cube.js（Node 生态）；Griffin/Sqoop/Flume/NiFi；模型网关（归 AI 平台 D8）。

## 4. 自研边界

| 类型 | 内容 | 说明 |
|---|---|---|
| 1 入口 | 统一门户 + 开放 API | 只做入口与聚合 |
| 5 胶水 | 契约 / 配置生成与接入作业管控 / 元数据上报 / 指标语义层 / 查询网关 | 开源之间缺失的连接层 |
| 4 后置件 | 推式接入网关 / 文件接收 / 成本归因 / 标签层 | 规模触发后再做 |
| 不建 | 模型网关 / MCP / 沙箱 | 由 AI 平台 D8 拥有，本平台 D10 调用 |

## 5. D 阶段路线

| 阶段 | 能力域 | 建什么 | 端到端证明 | 依赖 |
|---|---|---|---|---|
| **D0** | 基础设施 | Kafka/MinIO/PG/Redis、compose、Prometheus/Grafana/Alertmanager/OTel | 组件起得来，dummy 链路通 | — |
| **D1** | 契约与控制内核 | 信封/命名/DLQ；注册、健康、trace、账本最小版；**不含门户/配置/作业提交** | dummy 源注册 → 健康/trace/账本可查 | D0 |
| **D2** | 存储底座 | Iceberg/MinIO、Doris、Catalog | 建表、写入、快照/查询可复现 | D1 |
| **D3** | 数据集成 | SeaTunnel 批/流/CDC、断点续传、DLQ | 源 → Kafka → Iceberg 可查，重放两次不变 | D2 |
| **D4** | 计算引擎 | Flink/Spark/Doris 计算 | 批/流任务跑通，状态/checkpoint 可查 | D2、D3 |
| **D5** | 开发工作台与调度 | 模板 A/B/C、门户、配置生成、DS 唯一编排、StreamPark 托管、发布 SOP | 新增源 = 门户填一份表单 | D3、D4 |
| **D6** | 语义 | ODS→DWD→DWS、`metric_def`、MQL→SQL | 指标一处定义多处复用、改定义自动生效 | D2–D5 |
| **D7** | 统一目录 | DataHub、表级/字段级血缘、影响分析 | 任一指标可追到源表；字段级 ≥90% | D2–D6 |
| **D8** | 数据治理 | 质量规则/阻断/SLA/标准；RBAC/脱敏/审计/成本/多租户 | 脏数据阻断、越权被拒、PII 掩码、成本可分摊 | D2–D7 |
| **D9** | 服务化 | 查询网关（鉴权/限流/审计）、API 生命周期、Superset | API 与看板同口径；先能管才能放 | D6–D8 |
| **D10** | AI 工程化 | NL→MQL、100 题评测、诊断助手、模型网关调用 | 问数 ≥80%；日志证明不直产 SQL | D6、D9 + AI 平台模型网关 |
| **D11** | 控制面与运营 | 统一控制台/API、跨域编排、注册、trace、监控、成本、台账、可替换性 | 一条命令拉起全部已接入域；端到端闭环 + 成本/台账 | D0–D10 |
| **D12** | 生产化 | HA、备份恢复、TLS/加密、滚动升级、生产档压测、多租户、SLO | 杀节点不中断、备份可恢复、升级可回滚、压测达标 | D0–D11 + 真实环境（K8s/生产） |

**顺序**：`D0 → D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9 → D10 → D11 → D12`。

## 7. 工期、人力与风险

**人力假设**：1 名数据/后端主线 + 1 名数据工程 + 1 名平台运维；D5 额外 0.5 名前端口。

| 阶段 | 周期 | 说明 |
|---|---|---|
| D0 | 2–3 周 | 组件一条命令 |
| D1 | 2–3 周 | 契约/注册/健康/trace/账本 |
| D2 | 2–3 周 | Iceberg/Doris |
| D3 | 3–4 周 | SeaTunnel 批/流/CDC |
| D4 | 2–3 周 | Flink/Spark/Doris |
| D5 | 4–6 周 | 门户/DS/StreamPark/发布 |
| D6 | 4–6 周 | 分层建模/语义 |
| D7 | 3–4 周 | DataHub/血缘 |
| D8 | 4–6 周 | 质量/权限/审计/成本/多租户 |
| D9 | 4–6 周 | 查询网关/API/BI |
| D10 | 4–6 周 | NL→MQL/评测 |
| D11 | 4–6 周 | 控制面/闭环/台账 |
| D12 | 8–12 周 | 生产化 |
| **合计** | **46–68 周** | 3 FTE；实际按人力缩放 |

**主要风险**：

| # | 风险 | 对策 |
|---|---|---|
| 1 | 范围膨胀（12 中心全做） | D11 只做跨域控制面能力（控制台/编排/注册/trace/成本/台账/可替换性），其余中心归 D5/D6/D7/D8 |
| 2 | 最后才集成 | D0/D1 先建薄底座与契约内核；每域完成即注册 |
| 3 | 服务早于治理 | D8 必须在 D9 前；无权限/审计不开 API |
| 4 | 语义层过重 | 先 `metric_def` + MQL→SQL 最小闭环，再扩指标 |
| 5 | 质量规则滞后 | D8 前移质量阻断；D9 前必须有脏数据阻断证据 |
| 6 | AI 期望过高 | 100 题 ≥80%；只做 NL→MQL，不做通用 ChatBI |
| 7 | 生产化拖延 | D12 独立阶段；未过 D12 不承诺生产可用 |
| 8 | 两平台重叠 | 模型网关/湖仓/调度归属写死；未定前不新增实现 |

**关键取舍**：Iceberg vs Delta → Iceberg（与 AI 共用）；SeaTunnel vs Flink CDC → SeaTunnel 统一入口；DS vs Airflow → 数据任务 DS、模型任务 Airflow；Doris vs ClickHouse → Doris（湖上 serving）；自研语义 vs Cube.js → 自研最小语义层。
