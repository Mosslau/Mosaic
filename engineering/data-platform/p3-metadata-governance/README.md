# 元数据与治理（P3）

> 状态：⬜ 未开始
> 所属平台与单元：data-platform · P3 元数据与治理（类别：期）
> 对应文档：../通用数据平台建设路线.md（工程路线：§6 P3 排期、§7 V27–V32 通过标准）；../../roadmap/智能通用大数据平台工程师.md（职业路线）

## 目标

**可信**（血缘与质量说得清）、**可控**（权限与脱敏管得住）、**可算账**（成本能分摊）。

本单元是**能力层**（形态：能力层）：它不交付新的业务链路，而是把治理能力一次性建成，之后每条链自动继承（"治理内建"）；因此它的验收不看链路，看**台账、审批、审计与配额是否真的生效**。

## 范围与不做

- **范围**：元数据采集（Doris / Iceberg / Kafka 周期入 DataHub）；血缘上报器（含**字段级**，标注置信度；表级已在 P2 落地）；影响分析；权限与脱敏（表级 + 字段级、PII 打标与掩码、审批流）；成本归因（存储 + 计算按项目 / 数据集分摊）；治理看板；多租户四层对齐；资源与配额（DS 队列 / 租户、K8s、存储）。
- **不做**：对外 API（P4）、完整 Ranger 集成、计费。

## 技术栈

- **DataHub 完整部署**（GMS + 前端 + Elasticsearch + 元数据库复用平台 PostgreSQL——P0 已验证兼容性，见其 V5）
- **平台内 RBAC**（起步方案；权限中心一处配置，下发到 Doris 行策略 / 列授权 / 掩码视图与网关规则）
- **Doris audit log 采集** → 审计中心
- **Grafana**（治理看板：资产 / 质量 / 成本）
- 配额机制：DS 队列与租户配额、K8s 资源配额、存储配额（口径按 §2.6 档位）

## 系统架构

```text
【元数据与血缘采集】
  Doris / Iceberg / Kafka 的库表字段 ──周期采集──▶ DataHub
  SeaTunnel / DolphinScheduler / Spark 作业血缘 ──上报器（字段级，带置信度）──▶ DataHub
        （表级血缘已在 P2 随加工模板落地；本期补字段级并提升覆盖率）
  DataHub ──▶ 影响分析：改一个字段 → 列出受影响的下游表 / 指标 / API

【权限与审计链路】
  权限中心（一处配置）
      ├─▶ Doris：行策略 / 列授权 / 掩码视图（PII 打标 → 掩码）
      ├─▶ 查询网关：鉴权规则（P4 生效）
      └─▶ 审批流：申请 → 审批 → 生效 → 到期回收
  Doris audit log ──采集──▶ 审计中心（授权 / 查询 / 导出可追溯到人、时间、对象）

【治理面】
  成本归因：存储（GB·天）+ 计算（CU·时）→ 按项目 / 数据集分摊 → 报表
  四层租户对齐：DS 租户 = DataHub domain = Iceberg namespace = Doris database（§2.4）
  资源配额：DS 队列 / 租户 · K8s · 存储
```

## 前置与复用

- **前置单元**：**P2**（分层模型 + 表级血缘 + 指标字典，字段级血缘在其基础上补全）；**P1**（配置库、DLQ、审计日志来源）。
- **前置条件**：DataHub 完整部署的资源预算已算清（P0 只用了采集能力）；权限模型的角色清单与 PII 打标规则经评审；DS 租户模型与 Iceberg namespace / Doris database 的四层映射先定死（§2.4，后补等于全量迁移）。
- **复用**：不复用 `algorithms/` 的实验；复用 P0 的 DataHub 兼容性结论与 P1 的链路口径。
- **产出被谁引用**：P4（网关鉴权与脱敏规则来自本期）、P6（生产化按租户配额与成本口径压测）。

## 验收标准

- [ ] **V27** 影响分析可用 —— 改一个字段 → 列出受影响的下游表 / 指标 / API，与人工核对一致
- [ ] **V28** 越权被拒 + 审计 —— 无权限查询被拒或返回空，**且有审计记录**
- [ ] **V29** PII 脱敏生效 —— 无权限用户查 PII 只看到掩码值
- [ ] **V30** 字段级血缘覆盖率 —— 核心表字段级血缘 ≥ 90%，随任务变更**自动更新**（表级随 P2 落地，见 V21）
- [ ] **V31** 成本可分摊 —— 报表按项目 / 数据集出数，误差可解释
- [ ] **V32** 多租户隔离 —— 建第二个租户 → 其任务、元数据、湖表、仓表对第一个租户不可见（四层各验一次）

**交付物**：DataHub 全量部署 + 血缘上报器（字段级）+ 权限 / 脱敏 / 审批流 + 成本归因报表 + 治理看板 + 多租户四层对齐 + 资源配额方案。

## 实施笔记

- **开工前置条件**（2026-09 拟定）：① DataHub 完整部署（GMS + 前端 + ES + 元数据库）的资源预算与扩容后的宿主规格；② 角色清单与数据分级（哪几类字段算 PII）经业务评审；③ 四层租户映射（DS 租户 / domain / namespace / database）先定形状再建资源。
- **待决策项**：① 字段级血缘的实现路线（SQL 解析 / 作业自报 / 混合）——直接影响覆盖率与维护成本；② 成本单价的基准（存储 GB·天、计算 CU·时）与折旧口径；③ 审批流的粒度（按表 / 按字段 / 按项目）。
