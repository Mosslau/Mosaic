# 数据平台（data-platform）

> 定位：Mosaic 第 ③ 部分的通用数据平台——以「集成成熟开源 + 薄自研胶水」构建企业级 Data+AI 数据平台，对标 DataWorks / WeData 的能力集。
> 当前状态：**设计阶段（设计文档 v42 · 待评审）；实现未开工**——本目录下没有代码、没有实测记录、没有部署清单。

## 定位与状态

**本页是视图，不是真相源。** 架构、选型、契约、验收标准的定义一律在两份平台级文档里（见「文档地图」）；本页只维护三件事：**能力域覆盖视图、单元状态、文档与目录导航**。

文档体系按 `engineering-docs` skill 的**四层文档模型**组织：L1 平台索引（本页）/ L2 方案设计 + L3 实施设计（合体为一份中文文档）/ L4 单元定义（7 份，已就位）。

## 边界与校验

**与 `engineering/ai-platform/` 的分工（v36 定稿）**：本平台拥有 ① 数据集成 / ② 存储底座（含 Iceberg 湖与对象存储）/ ③ 计算引擎 / ④ 统一目录 / ⑤ 开发工作台 / ⑥ 数据治理 六个域的通用能力，以及 ⑦ 的指标语义层；AI 平台拥有 ⑧ 的应用层、**模型出口 / 模型网关**（p5 底座，与 MCP 网关 / 沙箱一起只建一次）与 GPU / 训练 / 推理队列。**凭据以 Vault 为唯一来源**（按平台分 path/policy），K8s Secret 仅作注入通道。GPU 与 K8s 集群两边共用、队列分开。

**校验**：本域文档按 `engineering-docs` skill 的**场景 D 完成度清单**人工核对（骨架齐全 / 索引 ↔ 目录双向 / 状态与日期一致 / 编号一致 / 覆盖矩阵无空域 / ✅ 有实测证据）——当前无自动化脚本。

**维护规则**：① 完成一条 V 的实测记录 → 更新本页单元索引表的状态与日期；② 设计文档升版（章节或 V 编号变化）→ 同步本页的指针、V 列与版本号；③ **目录只在单元定义或真实产物出现时新建**，不为未开工的期预建空目录；④ 本页不复制结论，冲突以设计文档为准。
