# engineering —— 工程系统部分

> 定位：Mosaic 第 ③ 部分的两个**并列平台**——[`ai-platform/`](ai-platform/)（模型与智能侧）与 [`data-platform/`](data-platform/)（数据供给侧）。两者都以「成熟开源集成 + 薄自研胶水」构建。
> 建设路线按**能力域 D 阶段**组织：每个阶段建设一个能力域，阶段结束必须有一条端到端证明；D0/D1 先建薄底座与契约内核，后续每个域完成即注册，最后做控制面收口与生产化。

## 两个平台

| 平台 | 定位 | 建设阶段 | 验收 |
|---|---|---|---|
| [`ai-platform/`](ai-platform/) | 数据（语料/向量/湖仓）+ 算力（K8s/GPU）+ 模型（微调/推理）+ 应用（RAG/Agent）共栈 | **D0–D10（11 段）** | `A0-1` … `A10-6` |
| [`data-platform/`](data-platform/) | 湖仓为真相源 + 控制面 12 中心 + 语义层唯一口径 | **D0–D12（13 段）** | `V0-1` … `V12-5` |

> 验收编号按阶段重新编：`A<阶段>-<序号>` / `V<阶段>-<序号>`；不再使用旧的 A1–A62 / V1–V48。

## 企业级横向设计基线（跨平台附录）

> 版本：v1 · 适用范围：`data-platform` / `ai-platform`
> 定位：两个平台共用的企业级横向设计维度。平台路线只写差异值，不重复本节。

### 0. 范围与非目标矩阵

| 事项 | 决策 | 理由 | 重新评估触发 |
|---|---|---|---|
| 自研湖表 / 调度 / 集成 / 推理引擎 | 不做 | 用 Iceberg / DolphinScheduler / SeaTunnel / vLLM 等成熟件 | 开源件无法满足关键 SLO、成本或合规 |
| 多云、商业计费 | 不做 | 单云单区域优先，计费不进入本期 | 客户强制多云或对外商业化 |
| 多区域 / 跨境部署 | 首期不做 | 单区域多 AZ 优先；跨境需合规评审 | 客户强制多区域或跨境 |
| 预训练、RLHF/DPO | **平台支持**（接口 + 小样本），不做大规模实跑 | 提供训练/对齐/checkpoint/评测入口；不承诺 GPU·天级实跑 | 有稳定 GPU 预算、数据与评测团队 |
| 多模态训练 | **平台支持**（数据 + 训练接口），小样本验证 | 支持图文/音视频 manifest 与训练入口 | 业务数据成立且需要生产规模 |
| 标注 / 合成数据平台 | **平台支持接入**，不建标注 UI | 外部标注/合成数据以 manifest 接入，质量抽检 | 月增标注 > 1 万条，或 3 个业务复用 |
| Feature Store | **最小特征库**（离线 + 在线一致性） | 指标层之外的 ML 特征复用 | 特征场景增多再扩 |
| 业务本体 | **D6 扩展**：轻量本体（10 实体/20 关系/50 术语/10 规则） | 让 Agent 理解实体/关系/规则；不做 OWL 推理 | 场景扩大再升级 |
| 企业知识引擎 | **AI D3 扩展**：文档理解/多模态检索/实体链接 | 让 Agent 引用文档并挂到结构化实体 | 全量知识图谱不做 |
| 数据飞轮 / 反馈闭环 | **平台支持**反馈日志/回流，不自动训练 | 先可追溯，回流需人工审批 | 反馈稳定、评测集需月度更新 |
| 分布式文件系统 / RDMA / GPUDirect | **平台支持**接口与 benchmark，不承诺生产规模 | 单机链路优先，接口先留 | 多机训练、IO 利用率 > 80%、checkpoint > 10 min |
| 模型评测 / 安全护栏 / 持续评测 | **必做**（AI D3/D9/D10 扩展） | 评测门禁与护栏是上线前提 | 已纳入 AI D3/D9/D10 |
| 分析 SQL / 数仓建模（学习轨） | **必做**（roadmap T1-S，计入路线阶段） | 平台 D6 有分层建模；独立训练放 T1-S | 已计入路线 59 阶段 |

### 1. NFR / SLO

| 项 | 初始目标（待评审，数据 D12 / AI D10 前固化） | 说明 |
|---|---|---|
| 可用性 | PoC 不承诺；试点 ≥ 99.5%；生产 ≥ 99.9% | 按入口/查询/推理分别统计 |
| API P95 | 数据查询 ≤ 2 s；AI 问答 ≤ 10 s | AI 另定 TTFT/TPOT，见 AI 路线 |
| 吞吐 | 按各平台 §2.4 规模档位 | 峰值按 1.5× 均值估 |
| 错误预算 | 生产 0.1%/月 | 超预算冻结非紧急发布 |
| 容量余量 | 峰值 ≤ 70% | 预留故障切换与突发 |
| RTO / RPO | RPO ≤ 15 min；RTO ≤ 4 h | PoC 不承诺，生产前演练 |

**关键决策**：SLO 在网关/查询入口统一采集；按租户出 SLO；没有 SLO 不承诺生产可用。

### 2. 安全与合规

- **信任边界**：用户/API → 控制面 → 数据面 → 存储/GPU，逐段鉴权。
- **身份**：SSO/OIDC 接入企业 IdP；服务间 mTLS；禁止共享账号。
- **授权**：RBAC 起步，ABAC 用于数据行/列级；租户隔离在网关与存储双层校验。
- **加密**：传输 TLS；静态加密 + KMS；密钥轮换；Vault 是唯一凭据源。
- **网络**：DMZ / 应用 / 数据 / 管理分区；对象存储与数据库不暴露公网；默认拒绝出站。
- **审计**：登录、授权、查询、导出、模型调用全审计；审计日志不可篡改，接 SIEM。
- **供应链**：镜像签名、SBOM、依赖漏洞扫描；禁止未知来源模型/数据集。
- **数据生命周期**：公开/内部/机密/PII 分级；保留、归档、删除、法律保留、同意、数据驻留、许可。
- **合规**：等保/GDPR/SOC 2 等按实际适用；数据 D12 / AI D10 前完成一次安全与合规评审。

### 3. HA / DR

- **拓扑**：首期单区域多 AZ；多区域不做，触发条件写入范围矩阵。
- **目标**：RPO ≤ 15 min、RTO ≤ 4 h（待评审）；核心查询与推理优先恢复。
- **故障模式**：节点、AZ、对象存储、元数据、Kafka、GPU 节点、外部模型 API 逐项列降级策略。
- **降级**：LLM 可切 mock/备用模型；检索可降级为关键词；查询可转只读/缓存。
- **备份**：湖表快照 + 元数据 + 配置 + 密钥；保留周期与恢复演练在数据 D12 / AI D10 固化。
- **演练**：每季度一次恢复演练；杀节点/断网/坏盘至少各一次。

### 4. 运维、组织与 RACI

- **on-call**：平台 owner + SRE 双线；P0/P1 15 分钟响应。
- **runbook**：接入、发布、回滚、备份恢复、租户扩容、模型切换、数据回填。
- **事故**：P0–P3 分级；24 h 内出初步复盘，P0/P1 一周内出改进项。
- **变更**：需求/设计/发布/回滚四类变更；生产变更必须关联工单与审计。
- **角色**：平台 owner、数据工程、AI 工程、SRE、安全、产品；RACI 在 D0/D1 定稿，至少覆盖变更/事故/发布/权限/成本。

### 5. 物理拓扑

- **网络区**：DMZ（入口）/ 应用区 / 数据区 / 管理区；跨区默认拒绝。
- **K8s**：两平台共用集群、队列分开；GPU 节点独立节点池；系统组件与业务隔离。
- **存储**：MinIO + Iceberg 由数据平台拥有；AI 平台只通过 Catalog/网关访问。
- **GPU**：整卡优先；MIG/拓扑感知放 D10 触发；GPU 节点不打普通业务 Pod。
- **多 AZ**：首期单区域多 AZ；跨区域复制不做。

### 6. 多租户与 FinOps

- **租户模型**：数据平台按业务域/部门；AI 平台按团队/模型/应用。
- **隔离**：首期逻辑隔离（命名空间 + 权限 + 配额）；大客户/强合规可物理隔离。
- **配额**：网关 QPS、队列并发、GPU 卡数、存储容量、模型 token 五类配额。
- **Noisy neighbor**：队列 fair-share + 限流 + 优先级；D6/D8 落地。
- **成本**：统一标签（平台/租户/业务/环境）；showback 先行，chargeback 后置。
- **单位经济**：每 GB 入湖、每万次查询、每百万 token、每 GPU·小时。

### 9. 跨平台契约（数据 ↔ AI）

| 契约 | 方向 | 关键字段 | 规则 |
|---|---|---|---|
| `EntityRef` | 数据 → AI | `entity_type`、`entity_id`、`version`、`source`、`policy` | 文档中的设备/合同/工单必须能挂到实体；无实体不编造 |
| `MetricRef` | 数据 → AI | `metric_id`、`definition_version`、`snapshot`、`dimensions` | 指标必须引用已发布 `metric_def`；禁止 AI 自造口径 |
| `EvidenceRef` | 双向 | `source_type`（表/文档/图片/视频）、`locator`、`snapshot`、`hash`、`policy` | 任何事实性结论必须带证据；证据可回到原表/原文/原片段 |
| `Policy` | 共享 | `subject`、`resource`、`action`、`tenant`、`purpose` | 检索与回答都校验；默认拒绝，越权内容不返回 |

**四条硬规则**：

1. AI 回答涉及结构化事实时，至少带一个 `EntityRef` 或 `MetricRef`。
2. 任何事实性结论必须带 `EvidenceRef`；没有证据只能给“推测”并标注。
3. 检索、生成、建议动作都必须过 `Policy`；权限不因 RAG 或 Agent 绕过。
4. 两条线共用同一套评测：实体链接准确率、指标口径正确率、引用准确率、越权拦截率。

契约变更必须升版本；破坏性变更要先改双方契约测试，再改实现。
