# engineering —— 工程系统部分

> 定位：Mosaic 第 ③ 部分的两个**并列平台**——[`ai-platform/`](ai-platform/)（模型与智能侧）与 [`data-platform/`](data-platform/)（数据供给侧）。两者都以「成熟开源集成 + 薄自研胶水」构建。
> 建设路线按**能力域 D 阶段**组织：每个阶段建设一个能力域，阶段结束必须有一条端到端证明；D0/D1 先建薄底座与契约内核，后续每个域完成即注册，最后做控制面收口与生产化。

## 两个平台

| 平台 | 定位 | 建设阶段 | 验收 |
|---|---|---|---|
| [`ai-platform/`](ai-platform/) | 数据（语料/向量/湖仓）+ 算力（K8s/GPU）+ 模型（微调/推理）+ 应用（RAG/Agent）共栈 | **D0–D10（11 段）** | `A0-1` … `A10-6` |
| [`data-platform/`](data-platform/) | 湖仓为真相源 + 控制面 12 中心 + 语义层唯一口径 | **D0–D12（13 段）** | `V0-1` … `V12-5` |

> 验收编号按阶段重新编：`A<阶段>-<序号>` / `V<阶段>-<序号>`；不再使用旧的 A1–A62 / V1–V48。

## AI 平台：D0–D10

| 阶段 | 能力域 | 获得能力 | 依赖 |
|---|---|---|---|
| D0 | 基础设施 | 底座一条命令起停 | — |
| D1 | 契约与控制内核 | 服务可注册、trace/账本可查 | D0 |
| D2 | 数据与语料 | 语料可复现 | D1 |
| D3 | 检索与知识 | 知识可问答、引用可溯源 | D2 |
| D4 | 存储与版本 | 数据/索引可版本化 | D2、D3 |
| D5 | 推理与服务 | 模型可服务 | D1、D4（可选） |
| D6 | 算力与调度 | 算力可管理、可计量 | D0 |
| D7 | 训练与微调 | 微调可复现 | D6 |
| D8 | Agent 与运行时 | 运行时可插拔 | D3、D5 |
| D9 | 控制面与运营 | 平台可闭环 | D0–D8 |
| D10 | 生产化 | 生产可用 | D0–D9 + 真实环境 |

**顺序**：D0 → D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9 → D10。
有 GPU 时 D6 提到 D5 前；无 GPU 时 D5 先用 mock/API 做逻辑层。

## 数据平台：D0–D12

| 阶段 | 能力域 | 获得能力 | 依赖 |
|---|---|---|---|
| D0 | 基础设施 | 组件起得来、dummy 链路通 | — |
| D1 | 契约与控制内核 | 源可注册、trace/账本可查 | D0 |
| D2 | 存储底座 | 建表/写入/快照可复现 | D1 |
| D3 | 数据集成 | 数据进得来 | D2 |
| D4 | 计算引擎 | 批/流计算跑通 | D2、D3 |
| D5 | 开发工作台与调度 | 新增源 = 门户填表单 | D3、D4 |
| D6 | 语义 | 指标一处定义多处复用 | D2–D5 |
| D7 | 统一目录 | 表/字段/指标血缘可追 | D2–D6 |
| D8 | 数据治理 | 质量可拦、权限可控、成本可算 | D2–D7 |
| D9 | 服务化 | 数据取得出、先管后放 | D6–D8 |
| D10 | AI 工程化 | 数据问得准 | D6、D9 + AI 模型网关 |
| D11 | 控制面与运营 | 平台可闭环 | D0–D10 |
| D12 | 生产化 | 生产可用 | D0–D11 + 真实环境 |

**顺序**：D0 → D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9 → D10 → D11 → D12。
