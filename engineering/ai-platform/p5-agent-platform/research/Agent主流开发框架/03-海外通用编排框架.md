## 机制速览（编排框架的通用机制）

海外编排框架的机制分四条路线，选型先看你要哪条：

| 路线 | 机制核心 | 代表 |
|:--|:--|:--|
| **图状态机** | 节点 + 边 + **可持久化状态（checkpointer）**——中断/恢复/重放基于状态快照 | LangGraph |
| **角色编排** | crew = 角色（role/goal/backstory）+ 任务 + 流程（sequential/hierarchical），序列化 YAML | CrewAI |
| **轻量委托** | Agents as Tools + Handoffs（对话控制权移交）两个原语 | OpenAI Agents SDK |
| **对话协商** | ConversableAgent 双 agent 对话迭代收敛 | AutoGen（转维护） |

**共同底座**：工具调用（MCP/函数调用）+ 可观测（tracing）+ 状态持久化——三件套是"生产可用"的最低门槛。

---
### 机制深挖：LangGraph 的图状态机数据流

```
定义 State(共享状态 schema) → 定义 Node(LLM/工具/条件函数) → 定义 Edge(流转/条件边)
  → compile() → 执行: 状态沿边流转，每步写入 State → Checkpointer 快照(可中断/恢复/重放)
```

**机制要点**：LangGraph 与普通 DAG 的本质区别是 **State 是一等公民**（完整机制要点见 [../AgentLoop演进与设计/01-演进机理.md](../AgentLoop演进与设计/01-演进机理.md) §5，不重复）。

## LangChain / LangGraph — 生产级事实标准

**定位**：LangChain 生态的编排双雄——LangChain 提供链/组件抽象，LangGraph 提供图状态机编排（节点 + 边 + 状态），是生产部署的**事实标准**（LangChain 月下载 3,900 万，远超其他框架）。

**特点**：
- LangGraph：显式图编排（Graph Engineering 的代表实现）——收敛路径画在图上，支持分支/循环/回退/Checkpointer 状态持久化
- 人机协同与可观测性生态最强（LangSmith tracing、hub）
- 与 [`Agent工程范式演进.md`](../Agent工程范式演进.md) 中 **Graph Engineering 层**直接对应

**适合**：生产级复杂工作流；需要图编排 + 状态持久化 + 可观测的团队。

## DeepAgents — LangChain 官方多 Agent harness

**定位**：LangChain 官方出品的 batteries-included 多 Agent harness——构建在 LangGraph 之上的开箱即用层（不是新的图引擎，而是图状态机的产品化上层）。

**特点**：
- 双模式编排：**Workflow**（显式图流程）与 **Handoff**（对话控制权交接）两种多 Agent 协作模式
- batteries-included：记忆、工具调用、human-in-the-loop（HITL）开箱即用，无需从 LangGraph 原语手动拼装
- 与 LangGraph 同源：需要底层控制时可直接落到 LangGraph 自定义节点/边；平台无关部署

**适合**：LangChain 生态内要快速搭多 Agent、又不想碰图原语的团队；作为 LangGraph 的上层产品化入口（对应 [Agent工程范式演进.md](../Agent工程范式演进.md) 的 Graph Engineering 层）。

## CrewAI — 角色驱动多 Agent

**定位**：角色驱动多 Agent 协作框架，上手最快（月下载 520 万）。

**特点**：crew = 角色（role/goal/backstory）+ 任务 + 流程（sequential/hierarchical）；CrewAI Flows 事件驱动；YAML 定义 crew。

**适合**：快速验证多 Agent 协作；文档产线三角色 crew（研究者/写作者/审校者）等场景（数据见 [`Agent工具与框架合集.md`](../Agent工具与框架合集.md)）。

## AutoGen — 对话式多 Agent 鼻祖（转维护）

**定位**：微软出品的对话式多 Agent 框架鼻祖（ConversableAgent 对话模式）。

**特点**：⭐ 6.1万；开创多 Agent 对话协作范式；**已转入维护模式**——微软建议新项目迁移到 Microsoft Agent Framework。

**适合**：学习多 Agent 对话范式的历史参考；存量项目维护。

## Microsoft Agent Framework — AutoGen + SK 合并继任

**定位**：微软把 AutoGen 与 Semantic Kernel 合并后的统一继任框架。

**特点**：.NET 企业级首选；多语言（C#/Python/TS）；Workflow 与 Agent 统一模型；企业级（Azure 集成、可观测）。

**适合**：.NET/微软生态企业；需要微软官方支持路径的团队。

## OpenAI Agents SDK — 轻量 Handoff

**定位**：OpenAI 官方轻量多 Agent 框架（openai-agents-python，月下载 1,030 万）。

**特点**：Agent = LLM + 指令 + 工具 + guardrails + handoffs；Agents as Tools 与 Handoffs 两个原语；支持 Sandbox Agent（容器内执行）；Tracing 内建。

**适合**：OpenAI 生态最简路径；Python AI 应用层快速嵌入。

## Google ADK — 层级 Agent 树

**定位**：Google 官方 Agent Development Kit——层级 Agent 树 + Gemini/Vertex 深度集成，原生多模态。

**特点**：Agent 树（父 Agent 委派子 Agent）；Gemini 多模态（图像/音频/视频）优势；Vertex AI 企业级工具；A2A 协议支持。

**适合**：Gemini/Google Cloud 生态；多模态 Agent 场景。

## Claude Agent SDK — Claude 生态

**定位**：Anthropic 官方 Agent SDK（Python/TS），Claude 生态的开发入口。

**特点**：强调安全护栏（guardrails）；与 Claude Code 同源的 Agent 能力；工具调用 + sub-agent。

**适合**：Claude 生态开发者；需要 Anthropic 官方支持的团队。

## LlamaIndex — RAG / 文档密集型

**定位**：RAG / 文档密集型 Agent 框架——数据框架（Data Framework）路线。

**特点**：检索、索引、文档解析能力最全；Agent + 数据工具；适合知识密集型应用。

**适合**：RAG 深度场景；文档密集型 Agent。

## Pydantic AI — 类型安全

**定位**：Pydantic 团队出品的类型安全 Agent 框架，FastAPI 风格开发体验。

**特点**：结构化输出类型安全（Pydantic 校验）；依赖注入式工具；测试友好。

**适合**：Python 类型安全洁癖团队；需要强结构化输出的后端集成。

## smolagents — 极简 Code Agent

**定位**：Hugging Face 的极简 Code Agent——核心约千行代码。

**特点**：Agent 直接写代码执行（Code Agent 范式）；极简透明、易读易改；Hugging Face 生态。

**适合**：想理解 Agent 内核的人；轻量嵌入式 Agent。
