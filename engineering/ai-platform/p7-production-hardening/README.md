# 生产化（p7）

> 状态：⬜ 未开始
> 所属平台与单元：ai-platform · p7 生产化（类别：系统）
> 对应文档：../AI平台建设路线.md（工程路线：§6 p7、§7 A55–A62）；../../roadmap/大模型数据中心平台工程师.md（职业路线）

## 目标

把 p0–p6 的「平台闭环」推进到「生产可用」：节点故障自愈、备份恢复经演练、TLS/静态加密、滚动升级、生产档压测、多租户强化、真实 GPU 数字补齐。

一句话可检验：**杀掉一个节点/实例后服务不中断、数据不丢；一次备份能在干净环境恢复；一次升级可回滚；一次生产档压测给出 TTFT/TPOT/tokens/s/P95 与瓶颈。**

## 范围与不做

- 范围：K8s 多副本与节点池、备份恢复、TLS/静态加密/密钥轮换、滚动升级/回滚、生产档压测、多租户隔离与配额、SLO/告警/值班、真实 GPU 验证。
- 不做：多机房容灾、自动弹性伸缩、商业计费、多云；不重写 p0–p6 的业务组件，只在部署与运维层加固。
- 不做：把 p6 的集成逻辑推倒重来；p7 只补「生产可用」缺口。

## 技术栈

| 层 | 技术基线 |
|---|---|
| 编排与 HA | Kubernetes（Helm / Operator）、多副本、PodDisruptionBudget、GPU 节点池 |
| 备份恢复 | PostgreSQL PITR、MinIO 版本控制 / Iceberg 快照、Milvus / 向量索引备份、MLflow 产物备份 |
| 安全 | cert-manager、TLS、存储静态加密、Vault 密钥轮换 |
| 发布 | 滚动升级、canary、回滚 |
| 观测 / 压测 | Prometheus + Grafana + Alertmanager + OTel；k6 / locust |

## 系统架构

```text
用户 / 业务
   │ TLS
   ▼
多副本服务（p1 检索 / p4 推理 / p5 Agent）
   │
   ├─ 存储：PG · 对象存储 · Iceberg · 向量库 · MLflow
   ├─ 备份：PG PITR / 快照 / 版本控制 → 恢复演练
   ├─ 发布：滚动 / canary / 回滚
   └─ 观测：Prometheus / Grafana / Alertmanager / OTel → SLO
```

- 不改 p0–p6 的接口，只在部署、备份、安全、发布、观测层加固；
- 所有备份、恢复、升级、压测都有 SOP 与演练记录，不用「应该可以」代替实测。

## 验收标准

- [ ] **A55 节点故障自愈**：杀掉一个节点/实例，服务不中断、数据不丢，恢复时间有记录
- [ ] **A56 备份恢复演练**：PG PITR + 对象/Iceberg 快照 + 向量索引 + MLflow 产物，在干净环境恢复；RPO/RTO 有记录
- [ ] **A57 TLS / 静态加密 / 密钥轮换**：外部端点全 TLS；存储静态加密；Vault 轮换后旧凭据失效
- [ ] **A58 滚动升级 / 回滚**：升级一个组件期间零失败请求；可回滚；有演练记录
- [ ] **A59 生产档压测**：并发梯度 ≥3 档，给出 TTFT / TPOT / tokens/s / P95 + GPU 利用率/队列 + 瓶颈归因
- [ ] **A60 多租户隔离 / 配额**：两个租户互不可见；配额生效；越权有审计
- [ ] **A61 SLO / 告警 / 值班**：SLO 定义、告警规则、至少一次真触发演练、runbook
- [ ] **A62 真实 GPU 数字补齐**：A27/A54 中「未在真实卡上验证」的项全部实测；GPU·秒/成本对账

## 实施笔记

- **2026-10-30 新增**：p6 是平台闭环，不等于生产可用；p7 专门补 HA、备份、加密、升级、压测、多租户、真实 GPU。
- **顺序**：先 HA 与备份（A55/A56），再安全与发布（A57/A58），最后压测/多租户/SLO（A59–A62）。
- **依赖**：p0–p6 全部；优先依赖 p3 的 K8s/GPU、p4 的推理服务、p5 的模型网关。
- **风险**：备份未演练等于没有备份；生产档压测需要真实卡；多租户先做 namespace/queue/配额，再做数据面隔离。
- **不做成「再做一个平台」**：p7 不引入新业务组件，只做生产化加固与演练。
