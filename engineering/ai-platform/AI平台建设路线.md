# AI 平台建设路线

> 版本：v01 · 待评审
> 形态：**方案设计 + 实施设计合体**——§1–§4 回答“建什么”，§5–§8 回答“怎么建、怎么验、花多少”。
> 定位：AI 平台的当前架构与建设路线；业务/职业路线见 [`roadmap/大模型数据中心平台工程师.md`](../../roadmap/大模型数据中心平台工程师.md)。

## 1. 设计目标与原则

**目标**：以「成熟开源集成 + 薄自研胶水」构建企业级 AI 数据中心——数据、算力、模型、应用共栈，能跑通“语料 → 检索 → 模型 → Agent → 平台闭环”的完整链路。

四条原则：

1. **集成平台，不自研平台**：向量库、推理引擎、湖表、K8s、Agent 框架都用成熟件；只在入口和开源之间的粘合层自研。
2. **一个阶段一个能力域**：阶段结束必须有端到端证明，不接受“组件装好但链路不通”。
3. **契约先定死**：D1 先冻结 `AssetRef` / `Answer` / `Service` / `Ledger`，后续域按契约接入。
4. **真实数字**：吞吐、延迟、成本、GPU·秒必须有实测；无卡时只做逻辑层并如实标注。

## 2. 总体架构

### 2.1 结构视图（5 层）

```text
入口层     控制台 + 开放 API
控制面     编排 / 契约 / 注册 / trace / 监控 / 成本 / 台账
数据面     语料 → 湖仓 → 检索 → 训练 → 推理 → Agent
算力层     K8s + Volcano + GPU Operator + 队列/配额
存储层     对象存储 + Iceberg + 向量库 + PG/Redis
横切       可观测 · 权限与审计 · 成本 · 多租户
```

### 2.2 数据流（6 跳）

```text
语料/问题 → ①加工(D2) → ②入湖(D4) → ③检索(D3) → ④微调(D7) → ⑤推理(D5) → ⑥Agent(D8) → 答案+引用+成本+台账
```

### 2.3 控制面（6 中心）

编排、契约、可观测、成本、治理台账、评测。D1 先建最小版（注册/健康/trace/账本），D9 扩成完整控制面。

### 2.4 规模假设与降级

| 档位 | 语料 | 算力 | 推理并发 | 目标 |
|---|---|---|---|---|
| 逻辑层 | ≤1GB | mock | 1 | 链路与契约可跑 |
| 单机集成 | 10GB | kind + 单卡 | 1/4/8/16 | 当前目标 |
| 生产 | TB 级 | 多节点多卡 | 64+ | D10 生产化 |

**无 GPU 降级口径**：组件能力不变，降级的是“真实数字”；D5 先用 mock/API，D6 等卡，所有未在真实卡上验证的结论必须标注。

## 3. 能力域与选型

| 域 | 选型 | 说明 |
|---|---|---|
| ① 数据与语料 | Python + PySpark + MinHash/LSH + tokenizer + embedding | 解析/清洗/去重/分片/embedding |
| ② 存储与版本 | Iceberg + MinIO + 向量库（Milvus/faiss） | 语料与向量同一次提交 |
| ③ 算力与调度 | K8s + Volcano + GPU Operator | 队列/优先级/配额/账本 |
| ④ 训练与微调 | LoRA/QLoRA + MLflow | 可复现微调与产物登记 |
| ⑤ 推理与服务 | vLLM（OpenAI 兼容）+ 量化 | TTFT/TPOT/tokens/s/P95 |
| ⑥ 检索与知识库 | 混合检索 + Rerank + 引用 | 答案可溯源、负例不编造 |
| ⑦ Agent 与运行时 | RuntimePort + agent-core + 四框架适配 | 至少两个运行时 |
| ⑧ 平台控制面与运营 | 控制台/API + 编排 + trace + 成本 + 台账 | 一条命令拉起、可替换 |

**明确不选**：自研向量库/推理引擎/湖表/K8s 调度器；不做框架全家桶；不做多云与商业计费（规模触发后再议）。

### 核心契约

| 契约 | 作用 |
|---|---|
| `AssetRef` | 语料/分片/向量/模型的统一引用（含版本/快照） |
| `Answer` | 答案 + 引用 + 置信/无依据标记 |
| `Service` | 服务注册、健康、版本、路由 |
| `Ledger` | tokens / GPU·秒 / 存储 / 成本事件 |
| `RuntimePort` | Agent 运行时的发布、事件流、审批、隔离 |

## 4. 自研边界

| 类型 | 内容 | 说明 |
|---|---|---|
| 1 入口 | 控制台 + 开放 API | 只做入口与聚合，不重造业务 |
| 6 胶水 | 契约 / 注册 / 配置 / trace / 成本 / 台账 | 开源之间缺失的连接层 |
| 1 内核 | RuntimePort + agent-core | 证明运行时契约，不做框架全家桶 |
| 底座 | 模型网关 / MCP 网关 / 沙箱 / Vault / 可观测 | 只建一次，所有运行时共享 |

**不做**：通用工作流引擎、模型训练框架、每个框架的全功能覆盖、多云控制面。

## 5. D 阶段路线

| 阶段 | 能力域 | 建什么 | 端到端证明 | 依赖 |
|---|---|---|---|---|
| **D0** | 基础设施 | K8s/compose、MinIO、PG、Vault、Prometheus/Grafana/Loki/OTel；一条命令起停 | 干净环境一条命令起底座，dummy 服务健康可查 | — |
| **D1** | 契约与控制内核 | `AssetRef` / `Answer` / `Service` / `Ledger`；注册、健康、trace、账本最小版 | dummy 服务注册成功，一次调用可查 trace + 账本 | D0 |
| **D2** | 数据与语料 | 解析/清洗/去重/分片/embedding；语料与向量产物 | 10GB 级（或等比例）加工全链可复现，四类计数对账 | D1 |
| **D3** | 检索与知识 | 混合检索 + Rerank + `/ask` + 引用 + 评测集 | 答案带可点引用，负例不编造，30 题有数字 | D2 |
| **D4** | 存储与版本 | Iceberg 语料/向量同一次提交、snapshot、compaction | 同一 `snapshotId` 可复现数据与索引 | D2、D3 |
| **D5** | 推理与服务 | OpenAI 兼容服务、vLLM/mock 双适配、量化、限流、压测 | 同一 SDK 只改 `base_url`；TTFT/TPOT/P95 有数字 | D1、D4（可选） |
| **D6** | 算力与调度 | K8s + Volcano + GPU Operator + 队列/配额/账本 | 队列/优先级/配额生效；`已分配+空闲=总量`；GPU·秒可归集 | D0 |
| **D7** | 训练与微调 | LoRA/QLoRA + MLflow + 数据/超参/种子入档 | 一次微调可复现，产物登记，指标可追 | D6 |
| **D8** | Agent 与运行时 | RuntimePort + agent-core + 框架适配 + 沙箱/MCP/网关 | 两个运行时通过同一契约发布与运行 | D3、D5 |
| **D9** | 控制面与运营 | 统一控制台/API、编排、注册、trace、监控、成本、台账、可替换性 | 一条命令拉起全部已接入域；端到端闭环 + 成本/台账 | D0–D8 |
| **D10** | 生产化 | HA、备份恢复、TLS/加密、滚动升级、生产档压测、多租户、SLO、真实 GPU | 杀节点不中断、备份可恢复、升级可回滚、压测达标 | D0–D9 + 真实环境 |

**顺序**：`D0 → D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9 → D10`。
有 GPU 时 D6 提到 D5 前；无 GPU 时 D5 先用 mock/API，D6 等卡。

**D8 说明**：Part 1（research / tutorials / frameworks 方案）已完成；D8 的验收从运行时代码开始，资料完成不算 D8 完成。

| D9 | `A9-1` 一条命令拉起全部；`A9-2` 端到端闭环；`A9-3` trace/成本/台账；`A9-4` 可替换性 |
| D10 | `A10-1` 节点故障自愈；`A10-2` 备份恢复；`A10-3` TLS/加密/轮换；`A10-4` 滚动升级/回滚；`A10-5` 生产档压测；`A10-6` 多租户/配额/SLO + 真实 GPU |

## 7. 工期、人力与风险

**人力假设**：1 名 AI/后端主线 + 0.5 名数据工程（D2/D4）+ 0.5 名平台运维（D6/D9/D10）。

| 阶段 | 周期 | 说明 |
|---|---|---|
| D0 | 2–3 周 | 底座一条命令 |
| D1 | 2–3 周 | 契约/注册/trace/账本 |
| D2 | 3–4 周 | 语料全链 |
| D3 | 3–4 周 | 检索/引用/评测 |
| D4 | 2–3 周 | Iceberg 版本 |
| D5 | 3–4 周 | 推理/压测 |
| D6 | 4–6 周 | K8s/GPU/账本 |
| D7 | 2–3 周 | LoRA/MLflow |
| D8 | 4–6 周 | RuntimePort/多运行时 |
| D9 | 4–6 周 | 控制面/闭环 |
| D10 | 6–10 周 | 生产化 |
| **合计** | **35–52 周** | 扣除 D8 Part 1 约 2 周，净剩余约 **33–50 周** |

**主要风险**：

| # | 风险 | 对策 |
|---|---|---|
| 1 | 无 GPU，真实数字缺失 | 逻辑层/真实层分离；D10 的 `A10-6` 清零并标注 |
| 2 | 外部 LLM/embedding 不可复现 | 本地兜底 + 三态声明（已验证/未验证/无法验证）+ 复现命令 |
| 3 | 单机内存打穿 | 分批起 + 轻量替代；先骨架后全量 |
| 4 | 契约漂移 | D1 冻结契约 + 契约测试 + D9 可替换性 |
| 5 | D8 Part 1 越做越重 | Part 2 门禁：评审定稿 + 首个落地对象后才进编码 |
| 6 | 与数据平台重叠 | 模型网关/湖仓/调度归属写死；未定前两边都不新增 |
| 7 | RAG 质量自说自话 | 30 题评测 + 负例 + 消融；无评测不上线 |
| 8 | “文档=交付” | 每个 D 阶段必须有实测证据；文档不算完成 |

**关键取舍**：自研内核 vs 框架全家桶 → 选内核；vLLM vs Triton → 选 vLLM；Airflow vs DolphinScheduler → 模型任务 Airflow、数据任务 DS；Milvus vs faiss → Milvus 主、faiss 兜底。
