# AI 平台建设路线

> 形态：**方案设计 + 实施设计合体**——§1–§4 回答“建什么”，§5–§8 回答“怎么建、怎么验、花多少”。
> 定位：AI 平台的当前架构与建设路线；业务/职业路线见 [`roadmap/大模型数据中心平台工程师.md`](../../roadmap/大模型数据中心平台工程师.md)。

## 1. 设计目标与原则

**目标**：以「成熟开源集成 + 薄自研胶水」构建企业级 AI 数据中心——数据、算力、模型、应用共栈，能跑通“语料 → 检索 → 模型 → Agent → 平台闭环”的完整链路。

四条原则：

1. **集成平台，不自研平台**：向量库、推理引擎、湖表、K8s、Agent 框架都用成熟件；只在入口和开源之间的粘合层自研。
2. **一个阶段一个能力域**：阶段结束必须有端到端证明，不接受“组件装好但链路不通”。
3. **契约先定死**：D1 先冻结 `AssetRef` / `Answer` / `Service` / `Ledger`，后续域按契约接入。
4. **真实数字**：吞吐、延迟、成本、GPU·秒必须有实测；无卡时只做逻辑层并如实标注。

## 2. 总体架构

### 2.1 结构视图（5 层）

```text
入口层     控制台 + 开放 API
控制面     编排 / 契约 / 注册 / trace / 监控 / 成本 / 台账
数据面     语料 → 湖仓 → 检索 → 训练 → 推理 → Agent
算力层     K8s + Volcano + GPU Operator + 队列/配额
存储层     对象存储 + Iceberg + 向量库 + PG/Redis
横切       可观测 · 权限与审计 · 成本 · 多租户
```

### 2.2 数据流（6 跳）

```text
语料/问题 → ①加工(D2) → ②入湖(D4) → ③检索(D3) → ④微调(D7) → ⑤推理(D5) → ⑥Agent(D8) → 答案+引用+成本+台账
```

### 2.3 控制面（6 中心）

编排、契约、可观测、成本、治理台账、评测。D1 先建最小版（注册/健康/trace/账本），D9 扩成完整控制面。

### 2.4 规模假设与降级

| 档位 | 语料 | 算力 | 推理并发 | 目标 |
|---|---|---|---|---|
| 逻辑层 | ≤1GB | mock | 1 | 链路与契约可跑 |
| 单机集成 | 10GB | kind + 单卡 | 1/4/8/16 | 当前目标 |
| 生产 | TB 级 | 多节点多卡 | 64+ | D10 生产化 |

**无 GPU 降级口径**：组件能力不变，降级的是“真实数字”；D5 先用 mock/API，D6 等卡，所有未在真实卡上验证的结论必须标注。

### 2.5 关键设计决策

| 决策 | 选择 | 理由 | 触发 / 代价 |
|---|---|---|---|
| GPU 调度 | 首期整卡 + Volcano 队列 fair-share | 简单、可计量；MIG 收益依赖卡型 | 卡利用率 <40% 或多团队争抢时评估 MIG/拓扑 |
| 推理隔离 | 单模型单实例 → 多模型池化；D5 先 vLLM 单实例 | 先保证兼容与压测基线 | 模型数 >5 或显存碎片严重时池化 |
| 训练数据通路 | 首期本地 NVMe + 单机 DataLoader；分布式 FS/RDMA 由 T2-C TDP-8/9 提供接口/benchmark | 单机 10GB 链路优先 | 多机训练、IO 利用率 >80%、checkpoint >10min |
| 评测门禁 | D3 30 题 → 100 题回归；D7 前后对比；D9 看板 | 无评测不上线 | 题目更新/模型切换必须回归 |

## 3. 能力域与选型

| 域 | 选型 | 说明 |
|---|---|---|
| ① 数据与语料 | Python + PySpark + MinHash/LSH + tokenizer + embedding | 解析/清洗/去重/分片/embedding；训练集 packing/配比/去污染/数据卡；标注/合成/多模态/文档加工 |
| ② 存储与版本 | Iceberg + MinIO + 向量库（Milvus/faiss） | 语料与向量同一次提交 |
| ③ 算力与调度 | K8s + Volcano + GPU Operator | 队列/优先级/配额/账本 |
| ④ 训练与微调 | LoRA/QLoRA + MLflow + DataLoader/checkpoint | 可复现微调；预训练/RLHF/DPO/多模态训练支持；数据通路吞吐与恢复 |
| ⑤ 推理与服务 | vLLM（OpenAI 兼容）+ 量化 | TTFT/TPOT/tokens/s/P95 |
| ⑥ 检索与知识库 | 混合检索 + Rerank + 引用 + 知识引擎 | 答案可溯源、负例不编造；文档可链接到实体 |
| ⑦ Agent 与运行时 | RuntimePort + agent-core + 四框架适配 | 至少两个运行时 |
| ⑧ 平台控制面与运营 | 控制台/API + 编排 + trace + 成本 + 台账 | 一条命令拉起、可替换 |

**明确不选**：自研向量库/推理引擎/湖表/K8s 调度器；不做框架全家桶；不做多云与商业计费（规模触发后再议）。

### 核心契约

| 契约 | 作用 |
|---|---|
| `AssetRef` | 语料/分片/向量/模型的统一引用（含版本/快照） |
| `Answer` | 答案 + 引用 + 置信/无依据标记 |
| `Service` | 服务注册、健康、版本、路由 |
| `Ledger` | tokens / GPU·秒 / 存储 / 成本事件 |
| `RuntimePort` | Agent 运行时的发布、事件流、审批、隔离 |

## 4. 自研边界

| 类型 | 内容 | 说明 |
|---|---|---|
| 1 入口 | 控制台 + 开放 API | 只做入口与聚合，不重造业务 |
| 6 胶水 | 契约 / 注册 / 配置 / trace / 成本 / 台账 | 开源之间缺失的连接层 |
| 1 内核 | RuntimePort + agent-core | 证明运行时契约，不做框架全家桶 |
| 底座 | 模型网关 / MCP 网关 / 沙箱 / Vault / 可观测 | 只建一次，所有运行时共享 |

**不做**：通用工作流引擎、模型训练框架、每个框架的全功能覆盖、多云控制面。

## 5. D 阶段路线

| 阶段 | 能力域 | 建什么 | 端到端证明 | 依赖 |
|---|---|---|---|---|
| **D0** | 基础设施 | K8s/compose、MinIO、PG、Vault、Prometheus/Grafana/Loki/OTel；一条命令起停 | 干净环境一条命令起底座，dummy 服务健康可查 | — |
| **D1** | 契约与控制内核 | `AssetRef` / `Answer` / `Service` / `Ledger`；注册、健康、trace、账本最小版 | dummy 服务注册成功，一次调用可查 trace + 账本 | D0 |
| **D2** | 数据与语料（含训练数据工程/多模态数据/文档加工） | 解析/清洗/去重/分片/embedding；训练集 packing/配比/去污染/数据卡；标注/合成接入；多模态数据 manifest；文档/多模态加工（PDF/OCR/表格/音视频切片） | 10GB 级加工全链可复现；训练集 manifest 与数据卡可重建；标注/合成、多模态与文档加工可检索 | D1 |
| **D3** | 检索与知识（含持续评测/知识引擎） | 混合检索 + Rerank + `/ask` + 引用 + 评测集；100 题回归/漂移基线；企业知识引擎（文档理解、多模态检索、跨模态引用、实体链接） | 答案带可点引用；评测可回归；文档能链接到结构化实体，引用可追溯 | D2 |
| **D4** | 存储与版本 | Iceberg 语料/向量同一次提交、snapshot、compaction | 同一 `snapshotId` 可复现数据与索引 | D2、D3 |
| **D5** | 推理与服务 | OpenAI 兼容服务、vLLM/mock 双适配、量化、限流、压测 | 同一 SDK 只改 `base_url`；TTFT/TPOT/P95 有数字 | D1、D4（可选） |
| **D6** | 算力与调度 | K8s + Volcano + GPU Operator + 队列/配额/账本 | 队列/优先级/配额生效；`已分配+空闲=总量`；GPU·秒可归集 | D0 |
| **D7** | 训练与微调（含预训练/对齐/多模态训练支持） | LoRA/QLoRA + MLflow + 数据/超参/种子入档；预训练/继续训练、RLHF/DPO、多模态训练入口；高级数据通路 | 一次微调可复现；预训练/对齐/多模态支持有小样本 smoke；数据通路吞吐与 checkpoint 恢复有数字 | D6 |
| **D8** | Agent 与运行时 | RuntimePort + agent-core + 框架适配 + 沙箱/MCP/网关 | 两个运行时通过同一契约发布与运行 | D3、D5 |
| **D9** | 控制面与运营（含质量/反馈） | 统一控制台/API、编排、注册、trace、监控、成本、台账、可替换性；质量看板/漂移/反馈日志 | 一条命令拉起全部已接入域；质量/反馈可查 | D0–D8 |
| **D10** | 生产化（企业级/护栏/数据飞轮） | HA、备份恢复、TLS/加密、滚动升级、压测、多租户、SLO、安全护栏、数据飞轮闭环；NFR/SLO、安全、运维/RACI、拓扑、FinOps、AI 治理 | 杀节点不中断、备份可恢复、升级可回滚、压测达标；护栏生效、飞轮闭环；企业级评审项全绿 | D0–D9 + 真实环境 |

**顺序**：`D0 → D1 → D2 → D3 → D4 → D5 → D6 → D7 → D8 → D9 → D10`。
有 GPU 时 D6 提到 D5 前；无 GPU 时 D5 先用 mock/API，D6 等卡。

**D8 说明**：Part 1（research / tutorials / frameworks 方案）已完成；D8 的验收从运行时代码开始，资料完成不算 D8 完成。

### 5.1 D10 生产化（企业级）

- **NFR/SLO**：可用性、TTFT/TPOT/P95、错误预算、容量余量。
- **安全**：IAM、租户隔离、KMS、网络分区、审计、供应链。
- **HA/DR**：RTO/RPO、多 AZ、故障模式、降级、备份恢复演练。
- **运维/RACI**：on-call、runbook、事故分级、变更管理。
- **拓扑/多租户/FinOps**：GPU 池、配额、TCO、showback。
- **AI 治理**：评测门禁、护栏、漂移、飞轮、版权/IP、人工兜底。
- **验收**：`A10-1`–`A10-9`；企业级要求只在这里落。

| 维度 | AI 平台取值/决策 |
|---|---|
| 可用性 / P95 | 试点 ≥99.5%，生产 ≥99.9%（暂定）；TTFT/TPOT 由 D5 实测后定 |
| RTO / RPO | RPO ≤15min、RTO ≤4h（暂定） |
| 租户模型 | 团队/模型/应用；逻辑隔离优先 |
| GPU 容量 | 单机单卡 → 多节点多卡；整卡优先，MIG 后续 |
| AI 治理 | 模型卡/数据卡、评测门禁、输入输出护栏 |

## 7. 工期、人力与风险

**人力假设**：1 名 AI/后端主线 + 0.5 名数据工程（D2/D4）+ 0.5 名平台运维（D6/D9/D10）。

| 阶段 | 周期 | 说明 |
|---|---|---|
| D0 | 2–3 周 | 底座一条命令 |
| D1 | 2–3 周 | 契约/注册/trace/账本 |
| D2 | 5–7 周 | 语料全链 + 训练数据工程 |
| D3 | 3–4 周 | 检索/引用/评测 |
| D4 | 2–3 周 | Iceberg 版本 |
| D5 | 3–4 周 | 推理/压测 |
| D6 | 4–6 周 | K8s/GPU/账本 |
| D7 | 5–7 周 | LoRA/MLflow + 训练数据通路 |
| D8 | 4–6 周 | RuntimePort/多运行时 |
| D9 | 4–6 周 | 控制面/闭环 |
| D10 | 6–10 周 | 生产化 |
| **合计** | **40–59 周** | 扣除 D8 Part 1 约 2 周，净剩余约 **38–57 周** |

> D2/D3/D7/D9/D10 新增的扩展验收按增量实现；上表是主链基线，开工时按扩展范围重估。
