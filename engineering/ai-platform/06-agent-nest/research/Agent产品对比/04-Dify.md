# Dify 详细介绍

> 出品方：LangGenius｜形态：Web 平台（自托管 Docker / 云）｜模型：数十家 Provider 统一接入｜数据快照：2026-08，参数以官方文档为准
> 
> 一句话：开源 LLM 应用/Agent **平台**——低代码/无代码构建 Agent 应用、RAG 知识库与工作流，自带 LLMOps（可观测、评估、提示词管理）。Star 15.3 万，LLM 应用平台类头部项目。

---

## 1. 定位与形态

Dify 与前三个产品最大的不同：它**不是给开发者写代码用的工具，而是让产品/业务团队"搭"Agent 应用的平台**。你不需要写循环，你在画布上拖出循环。

- Web 平台：可视化画布编排
- 自托管（Docker Compose 一键起全套）或云端 SaaS
- 应用以 API 形式对外提供服务（可被外部系统调用）

## 2. 应用类型

| 类型 | 说明 | 典型场景 |
|:--|:--|:--|
| **Chatbot** | 对话式应用（简单问答） | 客服、FAQ |
| **Agent** | 对话 + 工具调用（Function Calling / ReAct） | 带工具的助手 |
| **Workflow** | 无对话的自动化流水线 | 数据处理、定时任务 |
| **Chatflow** | 带对话状态的工作流 | 复杂对话流程 |

## 3. 可视化工作流（核心编排模型）

Workflow / Chatflow 是 **DAG 图编排**——收敛路径在图上"画死"（Graph Engineering 思路的产品化）：

**常见节点**：
- **LLM 节点**：调用模型（可配 prompt 模板、变量引用）
- **Agent 节点**：模型驱动的工具调用循环（见下节）
- **知识检索节点**：从知识库检索相关文档
- **条件/分支节点**：按变量/分类器走不同路径
- **代码节点**：执行 Python/JS 代码
- **HTTP 节点**：调用外部 API
- **工具节点**：调用插件市场里的工具
- **Answer / 直接回复节点**：输出结果给用户

**设计含义**：循环的边界由**图**定义——分支、回退、循环边都显式可见；业务审批、合规路径可以画成固定流程，不会被模型"自由发挥"跳过。

## 4. Agent 节点：隐式循环被关进节点

> 这是"自由度与确定性在一个节点内达成平衡"的设计：图管结构、节点管行为、轮数管成本。

Agent 节点是工作流里**唯一允许模型自由调用工具**的地方：

| 策略 | 机制 | 特点 |
|:--|:--|:--|
| **Function Calling** | 模型输出结构化工具调用（原生函数调用语义） | 精确、省 token |
| **ReAct** | 推理（Reasoning）→ 行动（Acting）交替 | 灵活、可处理复杂推理 |

- 可配置**最大迭代轮数**（硬约束——防止死循环烧预算）
- 节点内循环结束 → 输出沿 DAG 继续流转

## 5. RAG 知识库

企业知识问答开箱即用：

```text
文档上传 → 解析 → 分段（chunking）→ Embedding → 向量入库
  → 查询时检索（含 rerank 重排序）→ 组装上下文 → LLM 生成带引用的回答
```

- 支持多种文档格式；分段策略可调
- 混合检索、重排序、引用溯源
- 知识库与应用解耦，可多应用复用

## 6. LLMOps（面向生产的可观测）

Dify 是四款产品中唯一把**运维**做成产品的：

- **会话日志**：完整对话与工作流轨迹
- **标注与评估**：人工标注、打分、对比不同 prompt/模型的效果
- **提示词版本管理**：线上版本可回滚
- **成本追踪**：按应用/按会话统计 token 消耗

## 7. 多模型与插件市场

- **多 Provider**：OpenAI / Anthropic / DeepSeek / 通义 / 智谱等数十家统一接入，一个应用可配多模型 fallback
- **插件市场**：工具插件（搜索、浏览器、数据库、办公…）、模型插件、扩展插件——图形化安装；支持接入 **MCP 服务器工具**（与 CC/Codex/dsh 的共同协议）

## 8. 企业化能力

- **多租户**：工作空间隔离
- **RBAC**：角色权限（成员/管理员）
- **SSO**：企业单点登录
- **API 开放**：应用封装为 API，供业务系统调用
- **私有化部署**：数据不出内网（对数据合规场景是关键卖点）

## 9. 部署

- Docker Compose 自托管（推荐生产）
- 云端托管（免运维）
- 社区版开源（**Dify Open Source License**，Apache-2.0 派生带例外条款）+ 企业版（高级功能闭源）

## 10. Agent Loop 设计

### 10.1 核心机制拆解（L3+）

> 本节为 §2-§6 各节的机制复述，细节以上文对应节为准。

**① 工作流 DAG 引擎执行机制**

| 环节 | 机制 |
|:--|:--|
| 节点执行契约 | 每个节点 = 输入变量集 → 执行 → 输出变量集；变量在节点间显式绑定（上游输出 → 下游输入） |
| 数据流 | 沿 DAG 边传递：变量作用域分全局（应用级）与局部（节点级）；条件节点按表达式分流 |
| 并行分支 | 无依赖的分支节点并行执行，汇合点等齐（同步屏障） |
| 状态传递 | Chatflow 的会话变量跨轮持久（对话状态），Workflow 无状态（一次性执行） |
| 错误处理 | 节点失败 → 错误分支/重试配置/整流失败策略（图级容错，非模型自愈） |

**② Agent 节点迭代机制（隐式循环）**

| 策略 | 循环机制 |
|:--|:--|
| Function Calling | 模型输出结构化工具调用 → 平台执行工具 → 结果回填 → 再次请求模型 → 直到模型不再请求工具或达最大轮数 |
| ReAct | 推理（Reasoning）与行动（Acting）交替：模型先输出思考再调用工具，循环到无工具调用 |
| 硬约束 | 最大迭代轮数（防死循环）+ 每次工具调用的超时/失败策略（重试/跳过/报错） |

**③ RAG 检索机制管线**

```
文档 → 解析(版面/表格还原) → 分段(chunk 大小/重叠/结构感知) → Embedding → 向量库
  → 查询: 向量检索 + 关键字检索(混合) → Rerank(重排模型打分) → 组装上下文(带引用) → LLM 生成
```

| 环节 | 机制要点 |
|:--|:--|
| 分段 | chunk 大小与重叠可调；结构感知（按标题/段落切分，保语义完整） |
| 检索 | 向量相似度 + 关键字 BM25 混合（recall 与 precision 平衡） |
| 重排 | rerank 模型对候选打分排序（精排），显著提升 top-k 命中质量 |
| 引用溯源 | 生成结果回链源文档片段（企业可信要求） |

**④ 多租户隔离机制**

| 层 | 隔离机制 |
|:--|:--|
| 数据 | 工作空间（Workspace）级数据隔离，跨空间不可见 |
| 资源 | 每租户模型调用配额、速率限制（成本隔离） |
| 权限 | RBAC 角色（成员/管理员/只读）按空间授权 |
| 部署 | 私有化部署时物理/逻辑隔离可选（合规要求） |

```text
（应用层：显式图）
用户输入 → Chatflow DAG 开始
  → 知识检索节点（RAG）→ 条件节点（分支）→ Agent 节点 ═══> Answer 节点 → 返回
                                    ↓（Agent 节点内部：隐式循环）
                              function-calling / ReAct 策略
                              模型推理 → 工具调用 → 结果回填 → 迭代（≤ 最大轮数）
                              → 节点结束，输出沿 DAG 继续流转
```

**设计特征**：
- **循环归属"图"**：收敛路径显式定义，分支/回退/循环边可见可控
- **隐式循环被关进节点**：自由度只在 Agent 节点内存在，且受"最大迭代轮数"硬约束
- 工作流可定时触发（自动化任务）+ 人机协同（Chatflow 中间可插人工确认节点）
- 可观测是平台级的：每次运行都有日志与成本记录

## 11. 优劣势与适合场景

**优势**：零代码上手（业务团队可用）；显式工作流可审计可审批（合规友好）；LLMOps 开箱即用；RAG 管线完整；多租户/SSO/私有化。

**劣势**：不是编码 Agent（不能直接改你的代码库）；隐式循环受限（开放式探索任务不适合）；深度定制受平台边界限制；重度定制仍需写代码节点/插件。

**适合**：产品/业务团队快速上线 Agent 应用；企业知识库问答、客服、内部工具自动化；需要可视化运维、审批流与合规的场景。
