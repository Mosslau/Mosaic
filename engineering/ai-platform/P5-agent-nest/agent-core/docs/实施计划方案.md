# agent-core 实施方案（分阶段路线图）

> 版本：v0.2 · 状态：**设计存档**（2026-08-27 决定暂不开发，文档归档于 agent-core/docs）
> 定位：**完全自研的 agent-core**（Rust，不依赖任何 Agent 框架），作为 [frameworks/](../frameworks/README.md)
> 统一平台底座的**第五个运行时适配器**（与 agentscope / langchain-graph / codex / dsh 四框架适配器并列）——
> 详见[技术设计](./技术架构方案.md)第 1 节
> 前置阅读：[技术设计](./技术架构方案.md)
> 总原则：**每个阶段以 `cargo test` 全绿 + 文档更新为完成标准；垂直切片交付，不做大爆炸。**

## P1 核心引擎（⏸ 暂停）

### 目标
得到一个**无服务端依赖、可独立测试的引擎内核**：模型调用全链路（多提供商 + 路由 +
重试 + fallback + 流式）、工具全链路（注册 + 校验 + 执行 + 超时 + 截断）、Agent 主循环
（流式 + hooks + 轮次上限 + 取消）。

### 交付物

| 交付 | 内容 | 文件 |
|---|---|---|
| agent-types | ContentBlock/Message/ToolDef/Session/Usage/StopReason | `crates/agent-types/` |
| agent-llm | Provider 端口、Anthropic 适配器、OpenAI 兼容适配器（OpenAI/DeepSeek/Qwen/GLM 共用）、SSE 解析、LlmError、重试策略、ModelRouter | `crates/agent-llm/` |
| agent-core | Tool trait + 注册表 + schema 校验、Hook trait、AgentRuntime 主循环、SessionStore 端口（内存实现）、迷你 JSON-schema 校验器 | `crates/agent-core/` |
| agent-tools | bash / read_file / write_file / glob（路径沙箱 + 按行截断） | `crates/agent-tools/` |
| 测试 | mock HTTP 服务器（两种协议形态）、提供商契约测试、路由/退避单测、主循环集成测试（脚本化 FakeProvider） | `crates/*/tests/` |
| CI | fmt + clippy + test + build | `.github/workflows/ci.yml` |

### 验收标准
1. `cargo test --workspace` 全绿；`cargo clippy --workspace -- -D warnings` 干净
2. Provider 契约测试覆盖：chat 非流式 / 流式事件序列 / 错误分类（429/529/400/401）/
   Retry-After 尊重 / fallback 切换 / 流中错误上抛
3. 主循环测试覆盖：单轮结束、多轮工具循环、hook 阻断、工具超时、轮次上限、取消
4. 工具测试覆盖：路径穿越拒绝、输出截断、原子写
5. CI 在 GitHub Actions 上跑通（先本地验证等价命令）

### 预估工作量
3-5 个工作日（单人，含全套测试）· 约 3,500 行 Rust

### 风险与缓解
| 风险 | 缓解 |
|---|---|
| 各提供商协议细节差异（thinking/缓存/用量字段） | Provider 契约测试锁定归一化行为；差异记录在适配器注释 |
| 流式 + 重试交互复杂 | 明确"仅首事件前可重试"语义，测试锁定 |
| jsonschema 依赖体积/API 变动 | P1 用自研迷你校验器（required + 类型），P3 换正式库（端口隔离） |

## P2 服务端化

### 目标
引擎变成**可对外服务的进程**：HTTP API + SSE 流式推送 + 会话持久化 + 多租户骨架。

### 范围
1. `agent-server`（axum）：`POST /v1/sessions`（建会话）、`POST /v1/sessions/:id/run`
   （执行，SSE 流式返回 AgentEvent）、`GET /v1/sessions/:id`、`DELETE`、`GET /v1/healthz|readyz`
2. `SessionStore`：trait 已完成，P2 提供 PostgreSQL 实现（sqlx，迁移脚本）
3. 多租户骨架：API key 认证（服务级）、tenant_id 注入与校验、租户级模型路由表与密钥池
4. 配置系统：分层（默认 ← 文件 ← 环境变量 ← 租户覆盖）；JSON/TOML
5. 指标：tracing 结构化日志 + Prometheus 基础指标（调用量/延迟/错误/工具执行）
6. 并行工具批执行（tutorials/rust s13 模式）：同轮多 tool_use 并行、按序配对
7. 取消：`POST /v1/sessions/:id/cancel`（CancellationToken 贯穿工具执行）

### 验收标准
- curl 全流程：建会话 → 跑一个"写文件 + 读回"任务（本地 mock LLM）→ SSE 事件完整
- 并发 20 会话无状态错乱；取消后工具进程被击杀、会话落盘
- PostgreSQL 会话重启可恢复（模拟重启后 GET 历史 + 续跑）

> 已知限制：取消 / 故障重试时工具副作用可能已发生（幂等键在 P5 引入）；P2 期间以
> "破坏性工具默认走审批"缓解。

### 预估工作量
4-6 个工作日

## P3 安全与策略（可进企业内网的门槛）

### 范围
1. **策略引擎 `agent-policy`**：权限模式（default / acceptEdits / plan / 全审批）、
   规则文件（YAML：工具/路径/命令模式白黑名单）、LLM 辅助判定（可选）、审批队列 API
2. **沙箱**：bash 执行器 landlock/seccomp（rustix）起步；超时整组击杀（进程组）、
   内存/CPU 配额（rlimit）；容器化部署文档（OCI/gVisor）
   （landlock/seccomp 为 **Linux 专用**：本地 macOS 开发以路径沙箱降级，Linux CI 固化测试）
3. **密钥管理**：租户密钥池（内存加密 + 环境注入），日志脱敏（mask 规则），
   禁止密钥进上下文
4. **审计日志**：审批决策、工具调用摘要（输入 schema 化 + 输出截断）、会话操作，
   只追加存储（文件/DB）
5. **成本预算**：单价表 + 会话/租户 token 与金额双预算；超限降级/拒新轮
6. **MCP 真实传输**：stdio/SSE/HTTP + OAuth，服务器级沙箱与工具白名单

### 验收标准
- 绕过测试：路径穿越（symlink/`..`）、命令注入样本全部被拒（测试固化）
- 审批流：plan 模式无批准不执行破坏性工具；审计日志可回放完整决策链
- 预算：租户超限自动降级模型，日志有记录

### 预估工作量
5-8 个工作日

## P4 上下文与记忆

### 范围
1. **prompt 缓存**：system/tools 常驻缓存段（cache_control 断点）；缓存命中率指标；
   缓存感知的消息组装（增量续写）
2. **压缩管线生产化**：s08 四层 + reactive compact；摘要保留可缓存前缀；
   压缩触发自适应（按 provider 上下文窗口比例）
3. **记忆分级**：工作记忆（会话）→ 长期记忆（`agent-memory`：文件/向量，LLM 抽取 +
   合并去重，移植 s09 三子系统）
4. **技能系统**：SKILL.md 目录 + 按需加载 + 语义检索（技能多时）

### 验收标准
- 长会话（>50 轮）稳定运行，缓存命中率 >50%（mock 验证 cache_read 计数）
- 记忆跨会话生效（测试：会话 A 写入 → 会话 B 检索到）
- 压缩后语义不丢（抽查摘要保留关键事实）

### 预估工作量
4-6 个工作日

## P5 可靠性工程

### 范围
1. **mock-LLM 确定性 E2E**：录制真实对话（anthropic/openai 格式）→ 回放；全链路回归
   （HTTP 入口 → 引擎 → 工具 → 断言 transcript）
2. **幂等与持久化**：任务级幂等键（同一 user 请求重放不重复副作用）、
   会话增量 checkpoint、工具结果缓存（同输入同输出，TTL）
3. **熔断**：provider 连续失败 → 熔断窗口（半开探测）
4. **故障演练**：注入 429/529/超时/断流 → 断言恢复路径（脚本化 chaos 测试）
5. **负载测试**：会话吞吐、长流内存曲线（无泄漏）、工具并发上限

### 验收标准
- 录制回放 E2E 覆盖 20+ 场景，全部断言通过
- 熔断/恢复有测试固化；负载 1h 内存平稳
- 幂等重放不产生重复文件副作用（测试）

### 预估工作量
4-6 个工作日

## P6 编排与产品化

### 范围
1. 任务图与调度（s12 模式 + 持久化）、cron 触发（s14 select! 模式）
2. 多代理：子代理（独立会话/预算继承）、团队消息总线、协议状态机、看板认领
   （s15-17 模式生产化：进程隔离、租约、at-least-once）
3. 编码场景：worktree 隔离（s18）、git 工具集
4. gRPC 接口（tonic）+ OpenAPI 文档；CLI（参考客户端）、TUI、IM 适配器示例
5. 发布：Dockerfile、K8s manifests、Helm、配置样例、运营手册

### 验收标准
- 多代理场景（拆任务→并行→汇总）端到端可跑；失败子代理可重试不阻塞
- CLI 可用；IM 适配器示例可对接企业微信/Slack
- 部署手册按步骤可复现

### 预估工作量
6-10 个工作日（可拆分多轮迭代）

## 测试策略总纲

| 层级 | 内容 | 位置 |
|---|---|---|
| 单元 | 校验器/解析器/路由表/截断/路径 | 各 crate `src/**` 内嵌 |
| 契约 | Provider 对两种协议形态的归一化行为 | `agent-llm/tests/` |
| 集成 | 主循环 × 工具 × hooks × 恢复 | `agent-core/tests/`、`agent-tools/tests/` |
| E2E | 录制回放（P5） | `tests/e2e/` |
| 负载 | 吞吐/内存/并发（P5） | `tests/load/`（独立 bin） |

原则：**不为测试而测试，每条测试对应一条生产事故或一个协议细节**；
流式事件序列用"期望事件流"断言，不用 sleep。
