## 机制速览（TS 阵营的通用机制）

**共同机制**：① **流式 UI**——SSE/WebSocket 增量渲染（打字机效果），前端实时看到模型输出；② **工具调用协议**——函数调用 schema + 参数校验（TS 类型安全天然契合）；③ **可视化引擎**——拖拽节点 + 数据流连接（工作流即代码）。

**代表拆解**：
- **Vercel AI SDK（流式）**：`useChat`/`useAssistant` hooks 把"模型流 + 工具调用"封装为前端状态机——工具结果回流触发 UI 更新，是前端接入 Agent 的事实标准
- **n8n（集成）**：400+ 系统连接器作为"工具注册中心"，Agent 节点直接调用企业系统——机制在"连接器抽象"，而非模型层

---
### 机制深挖：Vercel AI SDK 的流式状态机

```
useChat():
  input 提交 → 请求模型(SSE 流) → 逐块渲染(打字机)
    → 工具调用请求 → 执行工具 → 工具结果回流 → 继续流式生成
  → 完成 → 更新 messages 状态(前端状态机驱动 UI)
```

**机制要点**：`useChat` 把"模型流 + 工具调用 + 消息历史"封装为一个前端状态机——工具结果回流触发 UI 更新（不是简单拼接），这是"前端 Agent"与"后端 API 调用"的本质区别。

## n8n — 工作流自动化 + AI

**定位**：工作流自动化平台（400+ 系统集成）+ AI 节点，把 Agent 接入企业现有系统。

**特点**：400+ 集成（企业系统开箱即用）；AI Agent 节点（LLM/工具/记忆）；可视化编排；⚠️ **fair-code 许可**（商用需订阅）。

**适合**：需要把 Agent 接进企业系统（CRM/数据库/IM）的自动化场景。

## LangFlow — 可视化拖拽编排

**定位**：LangChain 的可视化版本——拖拽构建 Agent/工作流。

**特点**：⭐ 15.4万；LangChain 生态的可视化入口；组件丰富；可导出代码。

**适合**：不想写代码但想用 LangChain 生态的团队。

## Mastra — TS 全栈 Agent 框架

**定位**：TypeScript 全栈 Agent 框架——一个框架覆盖 Agent、工作流、RAG、记忆、工具。

**特点**：TS 类型安全；Agent + Workflow + RAG + Memory 一体化；生产级特性（可观测、测试）；被 Replit Agent 3 采用。

**适合**：TS 全栈团队；需要"一体化"而非拼接的 Agent 框架。

## Vercel AI SDK — 流式 UI 事实标准

**定位**：Vercel 的 AI SDK——流式 UI + 工具调用的事实标准（前端接入 LLM 的标准方式）。

**特点**：Streaming UI（打字机效果）；useChat/useAssistant 等 React hooks；多 Provider；与 Next.js 深度集成。

**适合**：前端/全栈项目接入 LLM 流式交互；Next.js 生态。

## Flowise / SuperAGI — 可视化与 GUI 平台

**定位**：Flowise = 可视化 LLM 链路编排（LangChain 风格拖拽）；SuperAGI = 带 GUI 的自主 Agent 平台。

**特点**：Flowise 上手快、社区大；SuperAGI 强调自主 Agent 的图形化管理（任务面板、Agent 商店）。

**适合**：Flowise → 快速可视化验证；SuperAGI → 图形化管理自主 Agent。
