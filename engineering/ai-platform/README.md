# AI 平台（ai-platform）

> 定位：Mosaic 第 ③ 部分的 AI 平台——数据（语料 / 向量 / 湖仓）+ 算力（K8s / GPU）+ 模型（微调 / 推理）+ 应用（RAG / Agent）共栈，以「成熟开源集成 + 薄自研胶水」构建企业级 AI 数据中心。
> 当前状态：**设计阶段（平台路线文档 v9 · 待评审）**；7 个单元中 `p5-agent-platform` 进行中（Part 1 沉淀已完成，A38–A40 达成），其余 6 个未开工。

## 定位与状态

**本页是视图，不是真相源。** 架构、选型、边界、契约与验收标准的定义都在 [`AI平台建设路线.md`](AI平台建设路线.md)（L2 方案设计 + L3 实施设计合体）；本页只维护三件事：**单元状态、能力域覆盖视图、文档与目录导航**。

文档体系按 `engineering-docs` skill 的**四层文档模型**组织：L1 平台索引（本页）/ L2 方案设计 + L3 实施设计（合体一份）/ L4 单元定义（7 份，已就位）。

## 依赖与开工顺序

| 编号 | 单元 | 前置算法实验（`algorithms/`） | 前置单元 | 受什么约束 |
|---|---|---|---|---|
| p0 | AI 数据基础 | `05-generative/mini-rag`（向量化口径）、`02-statistical-ml/kmeans`、`pca`；**去重算法需新增手写实验** | —— | 数据规模（10GB 需流式 / Spark） |
| p1 | RAG 数据平台 | `mini-rag`（内核）、`04-transformer/attention`（Rerank 原理）、`kmeans`、`pca` | p0 | 向量库与 LLM 外部依赖 |
| p2 | 向量化数据湖 | `mini-rag`（索引口径）、`kmeans`（布局 / 聚簇）、`pca`（压缩分析） | p0 | 表格式与对象存储 |
| p3 | Kubernetes + GPU 调度 | 无直接复用（基础设施编排）；`01-search/a-star` 的"可解释评估"思想可类比 | —— | **真实 GPU + K8s（最大约束）** |
| p4 | 训练与推理平台 | `04-transformer/mini-gpt`、`mini-transformer`、`attention`（prefill/decode 与 KV Cache） | p3（算力，可选） | GPU / 量化工具链 |
| p5 | Agent 平台 | 自身在 Part 1 沉淀，编码期再回访相关实验 | p1 / p4（作为工具与模型来源） | 沙箱与运行时依赖 |
| p6 | AI 数据中心平台整合 | 复用前六个单元，不直接依赖单个算法实验 | p0–p5 全部 | 单机资源（Compose 起步） |

开工顺序建议：**先纵切两端（p0 数据入口 + p4 推理出口）**，再补中间（p2 存储版本、p1 检索），最后做受硬件约束的 p3 与集成层 p6。

> 交叉约束：**p3 是唯一受硬件门槛限制的单元**（无 GPU 时只能做逻辑层验证，其验收已拆成"逻辑层 / 真实层"两层）；**p6 可增量推进**（骨架先行，每完成一个单元就把它的成果接进来），因此不必等前面全部完成。

## 边界与校验

**与 `engineering/data-platform/`（自 v2 定稿）**：本平台拥有 ⑧ 平台控制面与运营（**模型出口 / 模型网关**、MCP 网关、沙箱、可观测，与 p5 底座一起只建一次）、GPU / 训练 / 推理队列；data-platform 拥有 ① 数据集成 / ② 存储底座（Iceberg 湖与对象存储）/ ③ 计算引擎 / ④ 统一目录 / ⑤ 开发工作台 / ⑥ 数据治理 与 ⑦ 指标语义层，其 p4 作为模型网关的**调用方**。**凭据以 Vault 为唯一来源**（按平台分 path/policy），K8s Secret 仅作注入通道。K8s 集群两边共用、队列分开。

**与 `algorithms/`**：单元的「复用的算法实验」段是本平台与算法线的闭环，必须显式列出用到的实验（没有就写明"无——原因"）；实验自身的手写纪律与写作规范归 `mindspring-lab` skill。

**与 `languages/`**：`languages/` 承载语言与工程纪律的**语义层**（讲"应该怎么做、为什么"），本平台交付**可运行系统与实测数字**（真调度、真推理、真压测、真成本）；同一个概念两处出现时不重复造文档。

**校验**：按 `engineering-docs` skill 的**场景 D 完成度清单**人工核对（四层齐 / 骨架齐 / 索引 ↔ 目录双向 / 状态与日期一致 / 编号一致 / 覆盖矩阵无空域 / ✅ 有实测证据）——当前无自动化脚本。

**维护规则**：① 完成一条 A 编号的实测记录 → 更新单元 README 与索引表的状态 / 日期；② 路线文档升版（章节或 A 编号变化）→ 同步本页的 A 区间与版本号；③ 目录只在单元定义或真实产物出现时新建；④ 本页不复制结论，冲突以路线文档为准。
