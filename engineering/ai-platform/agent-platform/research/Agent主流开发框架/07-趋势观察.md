# 趋势观察（2026）

> 撰写时点：2026-08（引用的 Star 数据见 [README.md](README.md) 主表）。五大趋势详解。与 [`../Agent工程范式演进.md`](../Agent工程范式演进.md) 的六层演进栈相互印证。

---

## 1. Stars 与下载量讲两个故事

**现象**：Dify（15.3万）、OpenClaw（38.8万）、Hermes（23.6万）等平台/成品与现象级项目 Star 暴涨；而 LangChain 生态（月下载 3,900 万）才是真正的生产部署王者。

**解读**：
- **Star = 关注度**，**下载量 = 真实生产使用**——两者经常背离
- 成品/平台类项目更"上镜"（演示效果好），框架类靠生产落地积累
- 选型时别只看 Star：LangChain 的 3,900 万月下载 vs 很多万 Star 项目，前者才是"生产里跑着的"

## 2. 框架向"平台化 + 工程化"收敛

**现象**：企业关注点从"能不能跑"转向"能不能长期跑"——状态持久化、人工审批（HITL）、可观测性、多租户与权限管控成为标配。

**解读**：
- 纯 Agent 循环只是第一步，**循环外的工程**（记忆、治理、观测）决定成败
- Dify 的 LLMOps、LangGraph 的 Checkpointer、Codex 的 goal 预算都是这个方向的产物
- 与 [AgentLoop演进与设计/03-标准设计.md](../AgentLoop演进与设计/03-标准设计.md) 的组件清单直接对应

## 3. 国产框架优势

**现象**：国内框架的中文文档、国产模型适配、私有化部署形成差异化；海外框架强在编排深度与观测生态。

**解读**：
- **国内**：AgentScope（多语言私有化）、Dify（平台+LLMOps）、DB-GPT（数据智能）、RAGFlow（文档解析）各有专精
- **海外**：LangGraph（图编排）、CrewAI（上手快）、OpenAI/Google/Anthropic（厂商生态）
- 选型关键：**数据合规**（国产/私有化）vs **生态深度**（海外框架）的取舍

## 4. 微软系整合

**现象**：AutoGen 转入维护模式，统一并入 Microsoft Agent Framework（AutoGen + Semantic Kernel 合并）。

**解读**：
- 大厂框架进入"收敛期"——多框架并存 → 官方统一继任
- 对用户：新项目直接选继任框架，老项目规划迁移
- 信号：框架选型要考虑**厂商维护承诺**，闭源/半官方框架尤其

## 5. Agent 形态扩展：从对话式走向"能动手"

**现象**：浏览器操控（browser-use）、电脑操控（OpenClaw）、GUI 操作（Codex Computer Use）成为新热点——Agent 不再只是"说话"，而是"动手做事"。

**解读**：
- 对应 [Agent工程范式演进.md](../Agent工程范式演进.md) 中"控制权迁移"的延伸——从对话到执行
- 与 Loop Engineering 结合：能动手的 Agent + 自主循环 = 真正的"数字员工"
- 注意：动手能力带来**安全边界**问题（沙箱、权限、审批）——这是 Codex 沙箱模型的背景

---

> **一句话总览**：关注度看 Star、生产看下载量；框架在收敛（平台化 + 工程化）、形态在扩张（能动手）；国产强在合规落地、海外强在生态深度。
