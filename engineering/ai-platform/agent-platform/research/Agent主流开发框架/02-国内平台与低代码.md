## 机制速览（平台类的通用机制）

**共同机制**：① **工作流 DAG 引擎**——可视化节点编排（LLM/工具/条件/分支），收敛路径画在图上；② **RAG 管线**——文档解析 → 分段 → Embedding → 检索 → 重排序；③ **多租户隔离**——工作空间、RBAC、资源配额。

**代表拆解**：
- **RAGFlow（文档解析）**：版面分析（PDF/扫描件/表格还原）→ 结构化 chunking → 引用溯源——把"解析质量"作为 RAG 的第一性，这是它区别于通用平台的关键机制
- **Coze（渠道分发）**：Bot 封装为跨渠道运行时（飞书/微信/抖音统一接口）——平台的价值在"一次构建、多渠道分发"

---
### 机制深挖：FastGPT 的流程编排与 RAG

```
用户输入 → 意图识别/对话分类 → 知识库检索(向量+全文) → 引用组装 → LLM 生成 → 输出
```

**机制要点**：FastGPT 的"知识库问答专精"本质是**检索优先 + 引用强约束**——生成必须带引用（可信）、检索失败走兜底话术（不编造）；对比 RAGFlow：FastGPT 轻（部署/资源）、RAGFlow 重（文档解析质量），取舍点是"文档复杂度 vs 部署成本"。

## Dify — LLM 应用/Agent 平台

**定位**：开源 LLM 应用/Agent 平台，RAG + 可视化工作流 + 私有化部署，全球 LLM 应用平台类头部项目。

**特点**：
- 可视化工作流（Workflow/Chatflow DAG）+ Agent 节点（Function Calling / ReAct 策略）
- RAG 知识库管线完整（解析→分段→Embedding→重排序）
- LLMOps 开箱即用（日志、评估、提示词版本管理、成本追踪）
- 数十家模型 Provider 统一接入，多模型 fallback

**适合**：业务团队快速搭 Agent 应用；企业知识库问答、客服、内部工具自动化；私有化合规场景。

**深对比**：Dify 的显式工作流编排与 Agent Loop 设计见 [`Agent产品对比/04-Dify.md`](../Agent产品对比/04-Dify.md)。

## Coze 扣子 — 零代码 Bot 平台

**定位**：字节跳动的零代码 Bot 平台，Coze Studio 已开源——拖拽搭建、插件生态丰富、一键发布到飞书/微信/抖音等渠道。

**特点**：
- 零代码：非技术团队可用
- 插件生态：大量现成工具插件
- 渠道分发：一键发布到国内主流 IM/内容平台
- 开源版（Coze Studio）可自托管

**适合**：非技术团队快速上线对话 Bot；需要国内渠道分发的场景。

## FastGPT — 知识库问答专精

**定位**：知识库问答专精的开源平台，政企/制造业落地多，部署轻。

**特点**：知识库问答为主（对标 Dify 的轻量替代）；部署简单、资源占用低；流程编排支持基础多轮。

**适合**：纯知识库问答场景；政企/制造业；资源受限的私有化部署。

## RAGFlow — 深度文档解析 RAG

**定位**：深度文档解析驱动的 RAG 引擎——把"文档解析质量"作为 RAG 的第一性。

**特点**：⭐ 8.9万；文档解析（PDF/Office/扫描件）质量业内领先（版面分析、表格还原）；引用溯源。

**适合**：文档密集型企业（合同、论文、手册）；对解析质量要求高的 RAG 场景。

## MaxKB — 开源知识库问答

**定位**：飞致云出品的开源知识库问答系统，客服与工单场景。

**特点**：安装简单（一条命令）；知识库问答 + 简单 Agent；与飞致云生态（1Panel 等）集成。

**适合**：客服与运维知识库；中小团队快速落地。

## 阿里云百炼 / 腾讯云 ADP / 百度千帆 AppBuilder

**定位**：三大云厂商的企业级 Agent 开发平台。

**特点**：
- 闭源 SaaS/私有化：企业级治理（多租户、权限、审计）
- 深度绑定自家模型与云生态（通义/混元/文心）
- 偏私有化合规：数据不出内网

**适合**：已在对应云生态内、需要企业级合规治理的大型组织。
