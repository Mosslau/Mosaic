## 一、能力全景（9 个能力域 · 50 项）

## 二、通用的 12 条扩展轴

| # | 扩展轴 | 典型做法 |
|---|---|---|
| 1 | 模型提供方 | Provider 注册表 + 参数映射 |
| 2 | 工具 | MCP / 插件 / 内置注册 |
| 3 | 沙箱后端 | Provider 接口 + 工厂 |
| 4 | 存储后端 | Repository / Port |
| 5 | 队列 / 消息 | 抽象投递语义 |
| 6 | 协议 | 适配器层（AG-UI / A2A / OpenAI） |
| 7 | 认证方式 | 认证中间件 / 依赖注入 |
| 8 | 权限策略 | 策略引擎（allow / deny / ask） |
| 9 | 记忆与检索 | 存储 + 召回策略 |
| 10 | 事件类型 | 联合类型扩展 |
| 11 | 调度器 | Cron / 外部调度 |
| 12 | 插件机制 | entry_points / 动态加载 |

**通用判断**：不是所有轴都要抽——抽之前先问"会不会换、有没有第二个实现"。

## 三、本项目抽象成了 7 个端口

| 端口 | 抽象的是什么变化 | 为什么抽象 | 不抽象会怎样 |
|---|---|---|---|
| **RunLifecycle** | 跨域原子事务（入队/审批的 Lua） | 4 个 key 必须一次写；换存储时语义要保留 | 幂等被打碎，出现"有状态无消息" |
| **Queue** | 投递语义（读/接管/确认/重试/死信/深度） | 可能换 Redis Stream → 其它 MQ；测试要替身 | 编排里出现 `xadd`，换队列要改编排 |
| **State** | 状态投影 + 三套锁 + 配额 | 锁与状态可能换存储；测试要替身 | 锁逻辑散落，无法单测 |
| **Events** | 事件发布 / 读取 | 回放、协议适配都要读；测试要替身 | SSE 与编排耦合 |
| **File** | 附件存储 | Redis 只是当前选择，未来对象存储 | 编排直接拼 Key |
| **Sandbox** | 隔离执行（已有 4 个后端） | 实现数已 ≥2；安全边界必须可插 | 换后端要改编排 |
| **AgentFactory** | Agent 框架 | 框架会升级/替换；唯一 import 点 | 框架类型泄漏到编排 |

**设计依据（最关键一条）**：端口按**事务边界**切，不按数据归属切——否则原子性会被拆散。

## 四、没做成端口、但可扩展的 6 处

| 扩展点 | 扩展方式 | 改动规模 |
|---|---|---|
| **工具** | MCP 配置声明（零代码） | 0 |
| **事件类型** | 事件联合类型 + 枚举 | 2 文件 + 下游 |
| **模型提供方** | 适配器 + 注册表 + 白名单 | 2–3 文件 |
| **协议** | `adapters/protocol`（消费事件，不改编排） | 新增一层 |
| **配置** | 6 组配置，新增一组 | 1 文件 |
| **能力开关** | 快照字段（默认关闭） | 3 处（模型 / 校验 / 装配） |

**共同点**：这些是"契约扩展"而不是"替换实现"——用联合类型、注册表和字段开关解决，不引入新端口。

---

## 五、故意不抽象的 4 处

| 对象 | 理由 |
|---|---|
| **Clock** | 没有第二实现；测试用时间冻结即可 |
| **NetworkPolicy** | 纯函数（DNS 缓存 + 私网判定），抽象只增加间接层 |
| **Documents** | 纯函数解析（CSV / XLSX / PDF），无状态可依赖 |
| **Metrics** | 鸭子类型注入（真实 OTel / 测试内存 reader），不值得建 Protocol |

**判据**："有第二个实现或需要测试替身"才建端口；四条都不满足，就不建。

## 六、完整能力里，本项目**尚未抽象**的部分

| 能力 | 现状 | 何时需要抽象 | 建议 |
|---|---|---|---|
| **权限策略引擎** | 只有布尔 `interrupt_on`（全问 / 不问） | 需要 allow / deny / ask + 规则持久化时 | 新增 `PermissionPort`（策略查询 + 决策记录） |
| **记忆 / 检索** | Redis List + 条目上限，无相关度召回 | 需要跨会话语义检索时 | 新增 `MemoryPort`（写入 / 召回 / 删除） |
| **RAG / 向量库** | 未实现 | 需要文档问答时 | 新增 `RetrieverPort`，与记忆分开 |
| **模型路由 / 降级** | 单 provider | 需要主备或按成本路由时 | 在 `AgentFactory` 内部加路由表，不新增端口 |
| **调度（Cron）** | 无 | 需要定时报表 / 巡检时 | 放控制面，或新增 `SchedulerPort` |
| **计费 / 账单** | 只有 token 计量 | 需要对外计费时 | 独立服务，运行时只出用量事件 |
| **第三方插件** | 明确不做（D15） | 有外部生态需求时 | 在装配层之上加 entry_points 发现，端口不变 |
| **评估体系** | 无 | 需要 Prompt 回归 / 质量度量时 | 独立离线系统，消费事件与轨迹 |

**共同点**：都是"现在没有第二个实现、也没有调用方"，按 YAGNI 不抽；需要时再按 §八 的流程加，**端口只增不改**。

## 七、什么时候该抽端口（判定标准）

| # | 判据 | 反例 |
|---|---|---|
| 1 | 已有或确定会有 **≥2 个实现** | 只有 Redis 一种存储 → 只抽语义，不抽泛化 |
| 2 | 需要**测试替身**才能测核心逻辑 | 时间、随机数用 monkeypatch 即可 |
| 3 | 有**安全 / 合规边界**（必须可替换实现） | 沙箱后端（4 个） |
| 4 | 是**跨团队契约**（别人依赖你的接口） | 控制面 ↔ 运行时 |

四条都不满足 → 写成普通函数或具体类。
**抽象的成本是永久的，收益是一次性的。**

## 八、扩展操作流程（新增一类扩展的 5 步）

| 步 | 动作 | 产物 |
|---|---|---|
| 1 | 判断类型：**换实现**（→ 端口）还是**加契约**（→ 联合类型/注册表/字段） | 一句结论 |
| 2 | 若是端口：先用 §七 四条判据自检，不满足则不建 | 自检记录 |
| 3 | 定义语义与失败方式（不定义实现细节）：方法、错误分类、超时归属 | 契约摘要 |
| 4 | 实现 + 注册：适配器实现、装配层注册、配置项（默认关闭） | 1–3 个文件 |
| 5 | 验收：契约测试（真实现 + 替身同套断言）+ 故障路径测试 + 文档 | 测试与文档 |

**硬约束**：新增扩展不得修改已有的分层、端口语义与事务边界。

## 十、一句话总结

**一个完整 agent 服务的能力面很宽（9 域 50 项），但真正值得抽象的只有 7 个变化点**：

> 事务（RunLifecycle）、投递（Queue）、状态（State）、事件（Events）、文件（File）、隔离（Sandbox）、框架（AgentFactory）。

其余能力（工具、事件类型、模型、协议、配置、开关）靠**契约扩展**而非端口；
再其余（权限策略、记忆检索、RAG、调度、计费、评估）**现在不抽**，因为还没有第二个实现——等有需求再加，端口只增不改。
