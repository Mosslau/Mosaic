| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 文档日期 | 2026-08-21 |
| 定位 | 项目全流程导航——从立项到运营的阶段地图 |

## 全流程地图

```
准备期          建设期（20 周）                                运营期
─────         ────────────────────────────                ─────
阶段0          M0     M1      M2      M3      M4           阶段5
立项    →    验证 → MVP  → 多租户 → 生态  → 商业化   →   运维
评审          门禁   端到端  +企微   +飞书   +计费        交接
  │           │      │      │       │       │              │
  ▼           ▼      ▼      ▼       ▼       ▼              ▼
业务+技术    技术   单租户  企微    飞书    上线          灰度→全量
双门禁       门禁   闭环    上线    RAG    压测
```

**三道关键门禁贯穿全程**：

```
立项双门禁 ──→ M0 技术门禁 ──→ 各阶段验收 ──→ M4 上线门禁
(业务+实证)    (0.3/0.4/0.5/0.6)  (垂直切片)      (渗透+压测+灰度)
```

**关键路径**（任一延误即影响总工期）：
`0.3/0.4/0.5/0.6 → 1.5 发布引擎 → 2.3 工作区隔离 → 2.9 企微 → 3.1 MCP 网关 → 4.5 压测 → 4.10 上线`

## 阶段 0：立项准备（M0 之前，约 1~2 周）

| 项 | 内容 |
|---|---|
| **目标** | 拿到"开工许可"——业务+技术双门禁都过 |
| **关键活动** | ① 业务规模确认（≥10 租户或对外商业化？见实施计划 §1.1.1）<br>② M0 技术实证（在本机/dev 把扩展点实际跑通，而非静态分析）<br>③ 立项评审（向决策者陈述，争取资源） |
| **前置条件** | AgentScope 版本锁定、≥1 个模型 API Key、dev 基础设施（K8s/PG/Redis/Milvus/MinIO）申请、KMS/Vault 排期、企微/飞书资质排期 |
| **产出** | 立项决议 + 资源到位 + 《扩展点验证报告》 |
| **门禁** | 业务判断通过 **且** M0 实证通过，才允许进 M1 |

> **当前状态**：架构方案/实施计划已定稿（可评审），技术地基已做源码级实证。**下一步即启动本阶段的"M0 技术实证"**——在本机装 AgentScope 2.0.6 实际装配跑通扩展点。

---

## 阶段 M0：技术验证（W1–W2，2 周）

| 项 | 内容 |
|---|---|
| **目标** | 把架构依赖的每个框架能力点跑通留证，消灭"假设性设计" |
| **关键任务** | 环境搭建(0.1)、最小 SSE 对话(0.2)、身份覆盖(0.3)、Workspace 子类(0.4)、工厂签名(0.5)、凭证链路(0.6)、KB 抽象(0.7)、MCP+权限五档(0.8)、非请求路径 tenant(0.8b)、压测基线(0.9) |
| **产出** | POC 报告 + 扩展点验证清单 |
| **门禁（Go/No-Go）** | 0.3/0.4/0.5/0.6 四项**必须全过**；任一失败触发回退预案（fork 打补丁，或自建薄服务层 +3 周并砍一渠道） |
| **团队** | 后端 B 为主，后端 A / DevOps / QA / 架构师配合 |

---

## 阶段 M1：MVP（W3–W6，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 单租户端到端闭环：Admin 能配模型/Agent/发布，用户能在 Web 对话 |
| **关键交付** | 代码基座（control-plane + runtime）、JWT 认证、模型管理、Agent CRUD、发布物化引擎 v1、会话 API（SSE + 断线补流）、Web 端 v1、Admin v1、CI/CD |
| **特点** | 此阶段**不做多租户隔离**，但所有表结构/代码路径预留 tenant_id（从第一天就存在，避免后期迁移） |
| **验收** | Admin 发布一个 ReActAgent，用户多轮对话 + 断线重连可续；凭证密文落库、日志无明文 |

---

## 阶段 M2：v1.0 多租户完整版（W7–W10，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 多租户隔离 + RBAC + Hub 三中心 + **企微上线** + 审计（首个可称"企业级"的版本） |
| **关键交付** | 租户体系（CRUD/邀请/角色）、contextvar 全链路、TenantWorkspaceManager、隔离性测试套件（纳入 CI 红线）、SkillsHub、MCPHub v1、发布引擎 v2（权限五档映射）、审计服务、企微适配器、Admin v2、配额中间件 |
| **验收** | 两租户互不可见 + 隔离套件 100% 通过；带 Skill+MCP 的 Agent 一键启用；企微单聊/群聊可用；管理操作与工具调用 100% 落审计 |

---

## 阶段 M3：v1.5 生态与安全增强（W11–W14，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 飞书渠道 + MCP 网关（凭证注入+审批）+ RAG 全链路 + 计量底座 |
| **关键交付** | MCP 网关 v1（协议代理/凭证注入/限流熔断/审计）、高风险审批流（挂起/回调/过期）、MCPHub 切网关、RAGHub（文档解析/切块/Embedding 管线 + Milvus 租户命名）、kb_search 检索工具、飞书适配器、多端审批、计量服务 |
| **验收** | 写操作 MCP 未审批挂起、批准后执行、全程审计；跨租户 RAG 检索为空；用量报表与模型账单误差 <5% |

---

## 阶段 M4：v2.0 商业化与规模化（W15–W20，6 周）

| 项 | 内容 |
|---|---|
| **目标** | Agent 市场 + 版本治理 + 计费 + 压测加固 + **生产上线** + 运维交接 |
| **关键交付** | Agent 市场（分类/搜索/启用/升级策略）、版本治理、计费、沙箱生产化（e2b）、300 并发压测调优、可观测性完善、安全渗透、自定义角色、灾备演练、灰度上线、Runbook |
| **验收** | 300 并发下首 token P95≤3s、SSE 断连率<1%、无跨租户泄露；渗透高中危清零；账单可对账；灰度 2 周无 P1 故障 |

---

## 阶段 5：运营期（M4 之后）

| 项 | 内容 |
|---|---|
| **运维交接** | Runbook（12 个预设故障场景处置）、告警分级（P1 15min / P2 2h / P3 次日）、值班机制 |
| **例行维护** | 凭证轮换（季度）、AgentScope 版本评估（每里程碑）、备份恢复演练（季度）、审计归档（月度） |

## 各阶段速查表

| 阶段 | 周期 | 时间盒 | 一句话目标 | 门禁/验收 | 关键交付 |
|---|---|---|---|---|---|
| 0 立项 | 1~2 周 | 前期 | 业务+技术双门禁 | 业务判断 + M0 实证 | 立项决议 + 资源 |
| M0 验证 | 2 周 | W1–W2 | 验证扩展点可行 | 0.3/0.4/0.5/0.6 全过 | POC 报告 |
| M1 MVP | 4 周 | W3–W6 | 单租户端到端 | 发布→对话→重连 | Web 聊天 + 发布 |
| M2 v1.0 | 4 周 | W7–W10 | 多租户+企微 | 隔离套件 100% | 隔离 + RBAC + Hub |
| M3 v1.5 | 4 周 | W11–W14 | 生态与安全 | 审批流 + RAG 隔离 | 网关 + 飞书 + 计量 |
| M4 v2.0 | 6 周 | W15–W20 | 商业化+上线 | 渗透+压测+灰度 | 市场 + 计费 + Runbook |
| 5 运营 | 持续 | 上线后 | 稳定运行 | 告警分级响应 | Runbook + 维护 |

**总计**：约 20 周建设期（M0~M4）+ 前期立项 1~2 周；团队 5.5~6 人；全量投入约 600 人日。
