## 1. 概述
### 1.1 背景与目标
将 OpenAI Codex——以 CLI / 桌面（Codex.app）/ IDE 形态交付的编码 Agent——从"个人工具"升级为**服务端部署、多租户、可审批、可审计的企业级 Agent 平台**。平台目标：

1. **服务端化**：Codex 执行能力收敛为平台服务（API + SSE 事件流），Web / IDE 插件 / Open API 均可提交任务并实时观测执行过程。
2. **集中治理**：平台管理员统一管理 Agent 配置（AGENTS.md / config.toml / Skills / MCP / 预算模板）、租户配额、审批策略与密钥。
3. **可审批**：沙箱之外的敏感操作（出网、系统目录写入、高风险 MCP 写操作）进入人工审批流。
4. **可审计可重放**：任务的 checkpoint 快照与完整历史全量留档，任何一步可回滚 / 重放复现。
5. **成本可控**：goal token 预算作为硬边界，超预算强制停止。

### 1.2 技术基座与平台化定位
> Codex 是 OpenAI 的编码 Agent，三大差异化：**沙箱安全** + **会话可重放** + **Goal 跨会话追踪**。形态为 CLI / 桌面 / IDE，会话状态落盘 SQLite（`state_5.sqlite` / `history.jsonl` / `goals_1.sqlite`）。Codex 为**闭源订阅产品**（OpenAI 生态、模型绑定 OpenAI）——平台不得修改引擎，只能外部编排。

平台化定位一句话：**Codex 是执行内核（黑盒），平台是控制面**。

- **控制面全部自建**：租户/用户/RBAC、Agent 模板与发布、审批中心、审计、计量、配额、密钥、MCP 网关。
- **执行侧（Codex Runner）自建编排**：进程级驱动 codex CLI、沙箱工作区、事件流解析、goal 预算执行、checkpoint 归档——全部通过"进程编排 + 配置注入 + 产物解析"实现，不触碰引擎内部。

> **关键前提（M0 验证项）**：素材确认 Codex 形态为 CLI / 桌面 / IDE，**没有公开服务端 API 的证据**；"Codex 可被服务端驱动（headless 可用性）"是全部架构的地基，必须在 M0 实证通过（见实施计划任务 0.3）。

### 1.3 设计原则
| 原则 | 说明 |
|---|---|
| 黑盒执行、白盒编排 | Codex 闭源不可改；平台所有能力 = 进程编排 + 配置注入 + 产物解析，不依赖引擎内改动 |
| 沙箱即安全边界 | 执行边界由 Codex workspace-write 沙箱强制（而非提示词约束）；沙箱外操作收敛到审批中心 |
| 预算即硬边界 | 每任务创建 goal 实例并注入 token 预算；预算耗尽强制停止（Codex 原生 hard stop） |
| 可重放即可审计 | checkpoint（state_5.sqlite）与 history.jsonl 全量留档；审计结论必须可重放复现 |
| 隔离边界收敛 | 租户隔离收敛在进程 / 工作区 / 凭证 / 配额四条路径；新资源类型必须登记隔离策略 |
| 订阅前提先行 | 闭源订阅 + 模型绑定 OpenAI；商用条款、订阅配额、数据合规是立项硬前提 |

### 1.4 术语表
| 术语 | 含义 |
|---|---|
| 控制面 | 自建管理服务：租户/RBAC、Agent 模板、发布物化、审批中心、审计计量、配额、MCP 网关 |
| Codex Runner（执行侧） | 自建服务：驱动 codex CLI 进程、解析产物、出事件流、执行 goal 预算 |
| 工作区（workspace） | 每次任务独立的沙箱工作目录，Codex 在其中读写（writable_roots 限定） |
| writable_roots | Codex 沙箱中允许写入的根路径集合（原生机制） |
| checkpoint | Codex 会话按分段（segment）自动落盘的状态快照（state_5.sqlite），可重放 / 回滚 |
| history.jsonl | Codex 会话完整历史（模型输入 / 工具调用 / 结果），可追溯与审计 |
| goal | Codex 跨会话目标实例（含 token 预算与完成状态，goals_1.sqlite） |
| 物化（Materialize） | 发布时把 Agent 配置渲染为执行侧工作区模板（AGENTS.md / config.toml / skills / MCP 配置） |
| 审批中心 | （平台化扩展）沙箱外敏感操作的人工审批服务 |

### 2.2 两进程模型
| 进程 | 职责 | 状态 | 存储 |
|---|---|---|---|
| **control-plane** | 租户/RBAC、Agent 模板与版本、发布物化、审批中心、审计、计量、配额、MCP 网关、密钥管理 | 有状态（业务数据） | PostgreSQL + MinIO |
| **codex-runner**（执行侧） | Session 调度、驱动 codex CLI、事件流解析（history.jsonl → SSE）、goal 预算执行、checkpoint 归档、工作区管理 | 无状态（任务状态在落盘文件 + Redis） | 任务工作区（PVC/MinIO）+ Redis |

职责边界：**控制面永远不参与单条任务的执行链路**；执行侧永远不查询业务数据库。两者的同步通道只有两条：① 发布物化（控制面 → 执行侧的单向写入）；② 产物归档（执行侧 → 对象存储 / 审计库的单向写入）。

### 2.3 关键交互流程
**流程一：Admin 发布 Agent（物化流）**

```
Admin → 控制面: 保存 Agent 配置（AGENTS.md 字段 + config.toml 模板 + skills/mcp/预算模板引用）
控制面: 生成 agent_release 不可变快照（版本号 + 渲染模板 + 资源锁定版本）
控制面 → 执行侧: 物化工作区模板（AGENTS.md / config.toml / skills/ / MCP 配置 / 预算模板）
控制面 → DB: 写入 tenant_agent_bindings（可见范围与启用状态）
```

**流程二：用户提交任务（执行流）**

```
用户 → Web/IDE/API → API Gateway → control-plane（鉴权 + 配额校验）→ codex-runner
codex-runner:
  ① 分配任务容器：拉起独立 Codex Runtime Pod（工作区 + config.toml + AGENTS.md）
  ② 创建 goal：create_goal(任务目标, token 预算) → goals_1.sqlite（预算硬边界）
  ③ 驱动 codex CLI 执行：update_plan 建计划 → 模型推理 → 工具调用（沙箱权限判定）
     → 结果回填 → 更新 plan → 继续（并行子代理受预算与并发配额约束）
  ④ 事件流：解析 history.jsonl → 结构化事件 → SSE 推送给客户端
  ⑤ 停止判定：goal 预算耗尽（hard stop）/ 任务完成 / 审批超时 / 会话超时
  ⑥ 归档：state_5.sqlite + history.jsonl + 产物 → 对象存储；审计事件上报计量
```

**流程三：沙箱外敏感操作（审批流，平台化扩展）**

```
任务容器默认断网，出网走 MCP 网关（白名单）
  → Codex 发起需升级的敏感操作（出网 / 系统目录 / 高风险 MCP 写操作）
  → 平台审批中心生成审批单（挂起操作）→ 推送审批卡片（Web / IM）
  → 审批人批准 → 网关放行 / 注入凭证执行；拒绝 → 操作失败并记录
  → 全程审计；票据 10 分钟过期（过期即拒绝并释放任务资源）
```

## 3. 核心架构决策（ADR）
### ADR-001：Codex 为闭源黑盒执行内核，平台只做进程级外部编排
- **背景**：初版曾设想"基于 Codex 二次开发"以获取引擎内钩子。
- **决策**：Codex 闭源订阅（OpenAI 生态、模型绑定 OpenAI），平台不修改引擎、不依赖引擎内钩子；全部平台能力通过进程编排 + 配置注入 + 产物解析实现（headless 驱动 codex CLI、注入 AGENTS.md/config.toml、解析 history.jsonl）。
- **理由**：素材明确 Codex 为闭源订阅产品（劣势：闭源订阅、模型绑定 OpenAI）；引擎内改动不可行也不可持续（版本升级即失效）。
- **影响**：拦截点只能是进程外（网络/凭证网关、审批前置、产物解析审计）；素材指出 Codex 生态 hooks 体系成熟度略逊 Claude Code（§10 劣势），凡需要"引擎内钩子"的能力降级为"网关 + 产物解析"实现。
- **代价**：M0 必须先验证"Codex 可被服务端驱动"（headless 可用性），不通过则本路线不成立（见实施计划 R-1）。

### ADR-002：workspace-write 沙箱 + writable_roots 是执行安全边界；升级操作映射审批中心
- **背景**：Codex 默认运行在 workspace-write 沙箱：读项目文件始终允许、写仅限 writable_roots、写系统目录需批准、网络默认受限需 require_escalated 升级。
- **决策**：把沙箱作为执行安全边界——循环的边界由沙箱强制而非模型自觉；平台为每次任务分配独立工作区，writable_roots 收敛到该工作区；沙箱外的敏感操作（系统目录、网络升级、高风险工具）统一收敛到审批中心（平台化扩展：把"用户批准"集中化、异步化、可审计化）。
- **理由**：安全放进运行时而非提示词约束（素材 §2 设计含义）；approval 策略（auto-approve / ask）是执行闸门（素材 §9）。
- **影响**：任务容器默认断网；出网必须经 MCP 网关或显式审批；审批超时 / 拒绝即停止该操作并记录。

### ADR-003：goal token 预算为成本硬边界（双层成本闸门）
- **决策**：每个租户任务创建 goal 实例时注入 token 预算；预算耗尽触发 Codex 原生 hard stop，进程终止并归档。控制面租户配额 + 执行侧 goal 预算构成**双层成本闸门**。
- **理由**：goal 系统原生支持"目标 + token 预算 + 完成状态"跨会话追踪；**预算是硬边界而非建议值**，超预算强制停止（素材 §4.1）；这是企业成本可控的关键设计（素材 §4 / §10 优势）。
- **影响**：任务必须显式 create_goal，不允许无预算裸跑；预算消耗实时上报计量；预算耗尽的任务自动归档并通知发起人。

### ADR-004：checkpoint 重放/回滚是审计与可复现的基础
- **决策**：任务结束即把 state_5.sqlite（分段 checkpoint）与 history.jsonl（完整历史）全量归档到对象存储；平台提供只读重放 API（从指定分段重建上下文继续复盘）与回滚（丢弃分段后的执行，仅限未交付产物）。审计调查以"可重放复现"为完成标准。
- **理由**：会话按 segment 自动落盘快照，"任意一步可复现"；不可重放的循环是黑盒（素材 §4.2 / §8）。
- **影响**：归档存储成本随任务量增长，采用冷热分层（热态 7 天 / 冷态 90 天 / 合规保留按政策）；重放永不回写生产状态。

### ADR-005：多租户隔离收敛在进程 / 工作区 / 凭证 / 配额四条路径
- **决策**：Codex 无原生租户概念，平台不强求引擎感知租户，把隔离收敛到四个自研强制点：① 进程隔离（每任务独立容器）；② 工作区隔离（路径前缀 `tenants/{tid}/` + writable_roots）；③ 凭证隔离（KMS 加密、按租户注入、不出网关）；④ 配额隔离（控制面租户配额 × goal 预算）。
- **理由**：进程级隔离对黑盒最可靠（不依赖引擎内部状态）；收敛后用少量代码审查 + 集成测试覆盖全部隔离面。
- **影响**：任务隔离粒度 = 进程粒度，容器密度低（每任务一容器）；以并发上限与资源限额管理密度成本；任何新增资源类型必须在四条路径之一登记隔离策略（写入开发规范）。

### ADR-006：MCP 流量一律经平台网关
- **决策**：Codex 原生支持 MCP 工具（素材 §3），但私有 MCP 需按租户注入凭证、高风险写操作需审批、调用需审计——三者要求流量经平台 MCP 网关。Agent 配置的 MCP endpoint 一律指向网关。
- **网关职责**：协议代理（HTTP / SSE / Stdio 托管）、按租户注入凭证（真实 Key 不出网关）、写操作审批联动（与审批中心同源）、调用审计、限流。
- **影响**：任务容器出网白名单收敛到网关地址；stdio 类 MCP 由网关托管为进程，对外统一暴露 HTTP。

## 4. 基于 Codex 真实机制的设计
> 本节每条先列素材确认的机制事实，再给平台化设计；标注"（平台化扩展）"的为平台自研，非 Codex 原生能力。

### 4.1 workspace-write 沙箱 + writable_roots + require_escalated
**机制（素材 §2）**：

| 操作 | 权限 |
|---|---|
| 读取项目文件 | 始终允许 |
| 写入项目文件 | 仅限 writable_roots 内 |
| 写入系统目录 | 需用户批准 |
| 网络访问 | 默认受限，需 require_escalated 升级 |
| Shell 命令 | 沙箱内执行 |
| GUI 操作 | 通过 Computer Use |

**平台化设计**：

- 每任务独立工作区，writable_roots 收敛为 `tenants/{tid}/tasks/{task_id}/`（物化引擎渲染 config 时写入）；
- 任务容器网络默认断开，出网仅允许 MCP 网关地址（平台化扩展：沙箱网络策略 + 网关白名单）；
- require_escalated 的"用户批准"集中化为审批中心（平台化扩展，见 §5.3）；
- Computer Use 默认禁用（平台化扩展：企业默认不接受 GUI 自动化，可配置按租户开启）。

### 4.2 会话 checkpoint 重放/回滚（state_5.sqlite / history.jsonl）
**机制（素材 §4.2 / §8）**：会话按分段（segment）自动落盘快照（模型输入 + 工具调用 + 结果 + 上下文状态）；重放 = 从指定分段重建上下文继续；回滚 = 丢弃该分段之后的执行。落盘文件：`state_5.sqlite`（会话状态）、`history.jsonl`（历史）、`archived_sessions/`（归档）。

**平台化设计**：

- 归档流水线（平台化扩展）：任务结束 / 硬停止 → 打包 state_5.sqlite + history.jsonl + 产物 → MinIO `archive/tenants/{tid}/tasks/{task_id}/`；
- 重放服务（平台化扩展）：只读 API，返回指定分段的事件序列与上下文快照，供审计与任务复盘页使用；
- 回滚约束：仅限未交付产物（未合入代码库的任务可回滚重跑）；已交付任务只能重放复盘，不回滚事实。

### 4.3 Goal 系统跨会话追踪 + token 预算硬停止
**机制（素材 §4.1）**：`create_goal(目标, token预算) → goals_1.sqlite 持久化`；`get_goal(id)` 恢复目标 + 已耗预算 + 完成状态；`update_goal(id, 进度)`；预算耗尽 → 强制停止（hard stop）｜目标完成 → 标记 done。goal 与 checkpoint 配合：**checkpoint 保"会话内可回退"，goal 保"会话间可续跑"**。

**平台化设计**：

- 租户任务 = goal 实例：任务创建时 create_goal，预算来自"Agent 模板默认预算 × 租户配额"；
- 跨会话续跑（平台化扩展）：任务中断后新会话 get_goal 恢复继续迭代（需发起人显式确认续跑）；
- 硬停止联动（平台化扩展）：预算耗尽 → kill 任务容器 + 归档 + 通知发起人 + 审计落库；
- 预算消耗实时上报计量（usage_records）。

### 4.4 update_plan 一等公民
**机制（素材 §3）**：update_plan 创建 / 更新任务计划；plan 与 goal 是一等公民——循环不只是"调用工具"，而是"有计划地调用工具、朝着目标迭代"。

**平台化设计**：把计划事件解析进任务时间线（事件流服务），前端任务页展示"当前计划 / 当前步骤 / 进度"；计划是任务可预期性与可观测的核心载体（对齐素材 §9 的循环设计）。

### 4.5 AGENTS.md 项目记忆
**机制（素材 §5）**：与 CLAUDE.md 同构的项目规范文件；✅ 写项目定位、目录架构、技术栈主线、构建命令、文档规范、Codex 自定义配置（Agent/Command/Skill/MCP/Hook/Plugin 声明）；❌ 不写模糊指令、一次性上下文、会过时的细节。

**平台化设计**：

- Agent 配置的发布物化 = 渲染 AGENTS.md + config.toml 到工作区模板（平台化扩展：字段化管理，Admin 填字段 → 平台渲染）；
- 技能 / 命令声明从 Hub 资源解析后注入 AGENTS.md 的配置段；
- 平台生成"任务上下文"段（任务目标、涉及仓库、租户隔离提示），其余内容由 Agent 模板作者维护。

### 4.6 Skills / Plugins / Agents 子代理
**机制（素材 §7）**：Skills 三级渐进加载（Discovery → Activation → Execution），SKILL.md 含 About / Workflow / Rules，社区 Skills 经 skill-installer 安装；Plugins 能力插件化；Agents 子代理系统独立上下文运行子循环、支持并行。

**平台化设计**：

- SkillsHub（平台化扩展）：SKILL.md 包版本化 + 上架安全扫描 + 发布时物化到工作区 `skills/` 目录；
- Plugins 白名单（平台化扩展）：仅平台登记版本可用；
- 子代理并行度配额（平台化扩展）：任务级并发子代理上限，受 goal 预算约束（并行烧 token 更快，预算仍是硬边界）。

### 4.7 MCP 工具
**机制（素材 §3）**：任意 MCP 工具可接入（如 codegraph_explore）。

**平台化设计**：MCPHub + 网关（ADR-006）：MCP 资源注册、工具白名单按 Agent 模板、凭证按租户注入、写操作审批联动、调用审计。

### 4.8 config.toml 配置
**机制（素材 §6）**：模型配置（默认模型、推理努力级别）、Provider 定义（多 Provider 接入）、插件、市场（skills 市场）、项目信任（可信项目列表）、桌面偏好。

**平台化设计**：

- config.toml 由物化引擎按发布快照渲染（模型绑定 OpenAI 生态——模型配置只允许 OpenAI 系，平台不承诺多模型路由）；
- Provider 定义按租户凭证注入（平台化扩展：租户 API Key 经 KMS 解密后注入任务环境，明文不出任务容器）；
- 项目信任 = 平台登记的仓库白名单（任务只能指向授权仓库，平台化扩展）；桌面段在企业服务端形态下不使用。

## 5. 多租户与安全模型
### 5.1 隔离模型（四条强制路径，ADR-005）
| 路径 | 机制 | 强制点 | 绕过代价 |
|---|---|---|---|
| 进程 | 每任务独立容器（PID / 文件系统 / 网络命名空间隔离 + 资源限额） | Runner 调度器 | 需突破容器逃逸 |
| 工作区 | 路径前缀 `tenants/{tid}/` + writable_roots 限定 | 物化引擎 + config 渲染 | 需逃逸沙箱 |
| 凭证 | KMS 加密存储、按租户注入、明文不出网关/容器 | 密钥管理 + MCP 网关 | 需拿到解密密钥 |
| 配额 | 控制面租户配额 × goal token 预算双层闸门 | 配额服务 + 预算执行器 | 需绕过执行器 |

### 5.2 身份与上下文
- 平台 JWT（RS256 + JWKS 轮换）；任务创建时把 tenant_id / user_id / role 写入任务元数据与 AGENTS.md 任务上下文段；
- 执行侧不解析业务鉴权，只认任务元数据（任务在创建时已通过控制面鉴权与配额校验）；
- 服务账号（CI / 流水线）经 Open API 提交任务，同样受租户配额约束。

### 5.3 审批中心（平台化扩展）
| 项 | 设计 |
|---|---|
| 触发 | 沙箱外敏感操作：出网升级（require_escalated 语义）、系统目录写入、高风险 MCP 写操作（risk_level=write） |
| 生命周期 | 生成审批单（挂起操作）→ 推送（Web / IM）→ 批准 / 拒绝回调 → 10 分钟过期（过期拒绝并释放任务资源） |
| 审批人 | 租户管理员或任务发起人；高危操作强制"他人审批"（禁止自审） |
| 联动 | 凭证吊销时强制过期关联 pending 审批单；批准前重新校验凭证与配额仍有效 |
| 审计 | 审批人身份、操作、时间、结果全量落审计 |

### 5.4 密钥管理
- API Key / Secret 经 KMS/Vault 加密存储；任务容器凭证在创建时一次性注入（环境变量），用后即弃；
- MCP 网关内明文仅内存瞬时存在，禁止入日志（日志脱敏中间件）；
- 凭证吊销即时生效：删除任务侧凭证引用 + 过期关联审批单（安全事件不等归档周期）。

### 5.5 审计模型（双层）
| 层 | 内容 | 存储 | 用途 |
|---|---|---|---|
| Codex 原生产物 | history.jsonl（模型输入 / 工具调用 / 结果）+ state_5.sqlite（分段 checkpoint） | 对象存储归档 | 可重放复现、调试 |
| 平台结构化审计 | 任务创建 / 审批 / 凭证 / 预算 / 计量事件（tenant_id/user_id/agent/action/result） | PostgreSQL（追加写） | 查询、报表、合规 |

### 5.6 数据隔离矩阵
| 数据类型 | 存储 | 隔离机制 |
|---|---|---|
| 业务元数据（租户/用户/Agent/审计） | PostgreSQL | 行级 tenant_id + 应用层强制过滤 |
| 任务工作区 | 容器 PVC + MinIO | 路径前缀 `tenants/{tid}/` + writable_roots |
| 凭证 | KMS 加密 | 按租户归属标记，网关 / 容器内注入 |
| 归档产物（checkpoint / history） | MinIO | bucket 路径前缀 `tenants/{tid}/` |
| 任务执行 | 独立容器 | 进程 / 网络命名空间隔离 |

## 6. 可观测性与运维
### 6.1 事件流（执行侧 → 客户端）
history.jsonl 解析为结构化事件，经 SSE 推送：

```
event: task_start    data: {task_id, agent, budget_tokens, ts}
event: plan_update   data: {plan_id, current_step, progress}      # update_plan 解析
event: step          data: {step_id, tool, input_digest}          # 工具调用
event: tool_result   data: {step_id, tool, output_digest, tokens}
event: goal_budget   data: {goal_id, spent, limit, remaining}     # 预算消耗
event: approval      data: {ticket_id, operation, summary}        # 待审批
event: task_end      data: {task_id, status(completed|budget_stop|rejected|timeout), usage}
event: error         data: {code, message}
```

### 6.2 指标 / 日志 / 追踪 / 告警
| 维度 | 方案 |
|---|---|
| 指标 | Prometheus：任务 QPS、goal 预算消耗率、turn 时长、SSE 断连率、审批挂起数、容器启动耗时、预算硬停止数 |
| 日志 | Loki 聚合；结构化 JSON；统一 trace_id（task_id 串联控制面 / 执行侧 / 网关） |
| 追踪 | OpenTelemetry：任务 → 事件流 → MCP 调用全链路 span |
| 告警 | 预算逼近阈值、审批挂起堆积、容器失败率、checkpoint 归档失败、凭证即将过期 |

### 6.3 部署拓扑（K8s）
```
Namespace: agent-platform
├── ingress-nginx                # TLS 终结、限流
├── control-plane   Deployment×2    # FastAPI；HPA 2~6
├── codex-runner    Deployment×3    # 调度 + 事件流 + 预算执行；HPA 3~10（活跃任务数）
├── task-pods       动态创建          # 每任务独立容器（codex CLI headless，平台化扩展）
├── mcp-gateway     Deployment×2
├── reconciler      CronJob(15min)  # 归档对账：孤儿任务 / 缺失归档补传 / 清理
├── postgres(外部 HA) / redis / minio / kms
└── monitoring: prometheus + grafana + loki
```

### 6.4 非功能性需求
| 指标 | 目标 |
|---|---|
| 任务创建 API（P95） | ≤ 1s |
| 首个事件 task_start（P95） | ≤ 10s（含容器拉起，M0 压测校准） |
| 峰值并发任务 | 50（M0 压测校准） |
| SSE 断连率 | < 1%（断线可补流重连） |
| 平台可用性 | 99.9%（控制面故障不影响进行中任务） |
| 审计完整性 | 管理操作 100%；任务事件 ≥ 99.99% |
| 隔离性 | 跨租户访问用例 100% 拦截（上线门禁） |
