## 1. 概述

### 1.1 目标

在 18 周内交付一套可生产运营的企业级 Agent 编排平台：以 LangGraph 图状态机为编排唯一模型，支撑复杂工作流编排、人机协同（HITL）、多 Agent 团队（DeepAgents 双模式）、Checkpointer 驱动的可中断/恢复/重放，LangSmith 统一可观测。Python 技术栈，多租户、审批、密钥、版本治理由平台自建。

### 1.2 实施策略

1. **POC 先行（门禁制）**：本路线的全部地基系于三个机制能力点——Checkpointer 中断/恢复/重放、LangSmith 接入、DeepAgents 双模式。M0 验证不通过则不允许进入 M1，并触发架构回退预案（见 §6 R-1）。
2. **垂直切片交付**：每个阶段交付"可真实使用"的端到端能力（定义工作流 → 发布 → 执行 → 会话 → 可观测），尽早暴露集成风险。
3. **控制面优先、执行引擎做薄**：自建工作量集中在控制面（图定义/版本/租户/审批/密钥）；执行引擎复用 LangGraph，只做扩展点装配与快照/会话服务，代码量刻意最小。
4. **机制验证前置**：中断/恢复/重放与 HITL 用例从 M0 起即纳入 CI 门禁，而不是上线前补测。

### 1.3 前置条件

| 项 | 要求 | 责任方 | 时间 |
|---|---|---|---|
| LangGraph / LangChain / DeepAgents 版本锁定 | 确认生产使用的具体版本号并冻结（含 checkpointer 后端兼容性） | 架构师 | M0 开始前 |
| 模型资源 | 至少 1 个可用模型（GPT/Qwen/DeepSeek 任一）API Key + Embedding 模型 | 采购/Admin | M0 第 1 周 |
| LangSmith | LangSmith 账号/私有化部署评估、tracing 接入权限 | DevOps | M0 第 1 周 |
| 基础设施 | K8s 集群（dev/staging/prod）、PostgreSQL、Redis 资源申请 | DevOps | M0 第 1 周 |
| 密钥管理 | KMS 或 Vault 可用 | 安全/DevOps | M1 开始前 |
| 渠道资质 | 企微/飞书应用资质（如接入渠道） | 业务方 | M2 开始前 |

## 4. 阶段详细计划

### M0 — 技术验证（W1–W2，2 周）

**目标**：把架构依赖的每一个机制能力点全部跑通并留证，消灭"假设性设计"。**本阶段是本路线的核心风险关口**——图状态机的 Checkpointer 中断/恢复/重放、LangSmith 接入、DeepAgents 双模式三者任一不成立，架构即需回退。

| # | 任务 | 输出物 | 负责人 | 工时 |
|---|---|---|---|---|
| 0.1 | 环境搭建：dev K8s、PostgreSQL、Redis、LangSmith 接入 | 可用 dev 环境 | DevOps | 3d |
| 0.2 | 跑通最小图：State Schema → Node → Edge → compile() → 执行，一次完整 run | 可运行 demo | 后端 B | 2d |
| 0.3 | **Checkpointer 验证（核心风险点）**：执行中点中断 → 从快照恢复（resume）→ 重放（replay）；验证 State 在恢复后保持一致、节点幂等性 | 验证代码 + 记录 | 后端 B | 3d |
| 0.4 | **HITL 验证**：中断 → 人工改 State → 恢复，确认"人机协同天然成立"的机制在平台代码中可用 | 验证代码 + 记录 | 后端 B | 2d |
| 0.5 | **LangSmith 接入验证（核心风险点）**：tracing 打通（节点级调用链、模型 token/延迟）、hub prompt 管理、trace 按 run_id 关联快照 | 验证代码 + 记录 | 后端 B + DevOps | 2d |
| 0.6 | **DeepAgents 双模式验证（核心风险点）**：Workflow 模式（显式图流程）与 Handoff 模式（对话控制权交接）各跑通一个多 Agent 场景；验证 HITL/记忆/工具调用开箱即用 | 验证代码 + 记录 | 后端 B | 3d |
| 0.7 | 条件边与回退验证：分支/循环/回退在图上的显式声明、收敛由拓扑保证 | 验证代码 + 记录 | 后端 B | 2d |
| 0.8 | 压测基线：单 Pod 并发 run 容量、首 token 延迟、Checkpointer 快照读写耗时 | 压测报告 | QA + DevOps | 2d |
| 0.9 | 编写《机制验证报告》，召开 M0 门禁评审 | 报告 + 评审结论 | 架构师 | 1d |

**门禁标准（Go/No-Go）**：
- 0.3（Checkpointer 中断/恢复/重放）、0.5（LangSmith 接入）、0.6（DeepAgents 双模式）**三项必须全部通过**——任一失败，触发回退预案（见 §6 R-1）。
- 其余项允许有"已知绕过方案"的结论（例如 DeepAgents 不满足生产约束则回退纯 LangGraph 自定义节点，属预期内路径）。

### M1 — MVP（W3–W6，4 周）

**目标**：单租户（platform 默认租户）端到端闭环：Admin 能定义图工作流、发布；用户能触发执行、看节点进度、处理 HITL 确认。此阶段不做多租户隔离，但所有表结构和代码路径按多租户设计预留（tenant_id 字段从第一天就存在）。

| # | 任务 | 输出物 | 负责人 | 工时 |
|---|---|---|---|---|
| 1.1 | 代码基座：control-plane（FastAPI + SQLAlchemy + Alembic）与 runtime（LangGraph 装配）两个模块骨架 | 可构建部署的骨架 | 全员 | 3d |
| 1.2 | 用户与认证：JWT 签发（RS256 + JWKS）、登录、API 层接入 | 认证链路 | 后端 A+B | 4d |
| 1.3 | 工作流定义：State Schema + Node/Edge 的声明式配置（YAML/JSON）、图编译校验 | 图定义能力 | 后端 A+B | 5d |
| 1.4 | 模型与工具装配：模型引用、函数工具注册、节点类型（LLM/工具/条件）落地 | 节点装配 | 后端 B | 4d |
| 1.5 | 发布物化引擎 v1：校验 → release 快照 → 编译产物缓存 → 绑定 | 发布流程 | 后端 A | 4d |
| 1.6 | 执行与会话：创建 run（绑 release）→ 图执行 → SSE 事件流（node_start/node_end/hitl/done）→ Checkpointer 快照落库 | 执行链路 | 后端 B | 5d |
| 1.7 | HITL v1：命中 hitl 节点 → 挂起 → Web 确认/改参 → 恢复执行 | HITL 流程 | 后端 B + 前端 | 4d |
| 1.8 | Web 端 v1：工作流运行视图（节点进度、HITL 确认卡片、流式输出）、Admin 图定义页 | 前端 v1 | 前端 | 8d |
| 1.9 | CI/CD：镜像构建、staging 自动部署、Alembic 迁移流水线 | 流水线 | DevOps | 3d |

**验收标准**：
- Admin 定义一个"LLM 节点 + 工具节点 + HITL 节点 + 条件边"的工作流并发布；用户触发执行，全程 SSE 可见节点进度；HITL 节点挂起后人工确认可继续。
- 执行中途手动中断 run，从 Checkpointer 快照恢复后续跑；日志中无明文密钥。

## 5. 关键路径与依赖

```
M0(机制验证) ─门禁→ M1 ─→ M2 ─→ M3 ─→ M4
                         │      │
关键路径：0.3 Checkpointer → 1.6 执行链路 → 2.3 快照隔离
         → 2.9 企微 → 3.3 DeepAgents 生产化 → 4.1 压测 → 4.6 上线
```

主要跨阶段依赖：

- LangSmith 账号/私有化部署必须 M0 第 1 周就绪（阻塞 0.5 验证）；
- KMS/Vault 不晚于 M1 第 1 周就绪（阻塞密钥管理 2.7）；
- 企微/飞书资质不晚于 M2/M3 第 1 周就绪，否则渠道任务顺延；
- 每个阶段的"验收测试"任务依赖该阶段全部开发任务完成，预留 buffer 不压缩。

## 6. 风险管理

| # | 风险 | 阶段 | 概率/影响 | 应对 |
|---|---|---|---|---|
| R-1 | **M0 机制验证失败**（Checkpointer 中断/恢复/重放不可行、LangSmith 接入受阻、DeepAgents 双模式不满足生产约束） | M0 | 中/极高 | **回退预案**：① DeepAgents 不满足 → 回退纯 LangGraph 自定义节点实现多 Agent（同源，工期 +1 周）；② Checkpointer 后端不满足 → 换存储后端（Redis ↔ PostgreSQL 切换）或 fork 打补丁并向上游提 PR；③ 最坏方案——执行引擎退回"LangChain 链式 + 自建状态服务"，工期 +3 周，范围砍 M3 渠道之一 |
| R-2 | LangGraph/LangChain 版本升级 Breaking Change | 全程 | 中/中 | 版本冻结；每里程碑评估一次升级必要性；升级必须过中断/恢复/重放用例 + 全量回归 |
| R-3 | Checkpointer 快照容量与性能瓶颈（长 run 快照膨胀） | M2–M4 | 中/中 | M0 压测基线实测快照读写耗时；快照压缩 + TTL 归档；大状态拆分为子图状态 |
| R-4 | 前端进度滞后（工作流画布可视化工作量大） | M3 | 中/中 | M3 起每周燃尽跟踪；预案：增加 0.5 前端人力或裁剪画布编辑（先只读视图 + YAML 编辑） |
| R-5 | 图建模规范缺失导致工作流质量失控（节点非纯函数、State 膨胀） | M1 起 | 中/中 | 图建模规范写入开发规范；代码评审强制；评审 Checkpointer 可重放性用例 |
| R-6 | 模型端点不稳定影响验收 | M1 起 | 中/低 | 验收环境配置双模型互为备份；计量按实际调用归集 |
| R-7 | 范围蔓延（业务方要求开放探索型任务进平台） | M2 起 | 高/中 | 变更管理流程；探索型任务默认走"Loop 内核 + 图编排外层"折中或 backlog，不影响 M4 上线 |

## 9. 上线与运维交接

**上线 checklist（M4-W18）**：生产环境配置复核（密钥/域名/TLS）→ 快照存储容量评估 → 监控告警联通 → 灰度租户开通 → 48h 观察 → 全量开放 → 发布公告。

**运维交接物**：

1. **Runbook**：预设故障场景处置（Checkpointer 快照损坏、快照存储不可用、LangSmith 中断、MCP 上游挂掉、凭证过期、SSE 雪崩、HITL 票据僵死等）；
2. **告警响应分级**：P1（全平台不可用/数据泄露嫌疑）15 分钟响应；P2（单租户/单工作流故障）2 小时；P3（性能退化）次日；
3. **例行维护**：密钥轮换（季度）、LangGraph/LangChain 版本评估（每里程碑）、快照清理对账（月度）、备份恢复演练（季度）。
