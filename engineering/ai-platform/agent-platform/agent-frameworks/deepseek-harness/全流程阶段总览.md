## 全流程地图

```
准备期          建设期（22 周）                                运营期
─────         ──────────────────────────────                ─────
阶段0          M0      M1      M2      M3      M4           阶段5
立项    →    验证 →  MVP  → 多租户 → 生态  → 生产    →   运维
评审          门禁   端到端  +审批   +安全   上线          交接
  │           │      │      │       │       │              │
  ▼           ▼      ▼      ▼       ▼       ▼              ▼
业务+技术    版本    单租户  审批/  能力   压测→          灰度→全量
双门禁       快照    闭环    MCP    扩展   上线
            锁定           网关    渗透
```

**三道关键门禁贯穿全程**：

```
立项双门禁 ──→ M0 技术门禁 ──→ 各阶段验收 ──→ M4 上线门禁
(业务+实证)  (版本稳定+快照锁定) (垂直切片)   (压测+渗透+灰度)
```

**关键路径**（任一延误即影响总工期）：
`0.3/0.4/0.5/0.6 → 1.5 发布引擎 → 1.6 会话链路 → 2.2 多租户作用域 → 2.6 MCP 网关 → 4.1 压测 → 4.5 上线`

**贯穿全程的验收红线**：事件日志重放/恢复能力——M0 建立重放一致性测试基线后，每个里程碑验收都必须通过"日志投影 vs 实际会话行为逐事件比对"（ADR-006）。

## 阶段 0：立项准备（M0 之前，约 1~2 周）

| 项 | 内容 |
|---|---|
| **目标** | 拿到"开工许可"——业务+技术双门禁都过 |
| **关键活动** | ① 业务规模确认（≥N 个真实租户或对外商业化需求）<br>② M0 技术实证（本机跑通 dsh、确认 developer preview 现状可接受）<br>③ 立项评审（向决策者陈述，争取资源） |
| **前置条件** | dsh 版本确认、≥1 个模型 API Key（DeepSeek 优先）、Node 环境、dev 基础设施申请、KMS/Vault 排期 |
| **产出** | 立项决议 + 资源到位 |
| **门禁** | 业务判断通过 **且** M0 实证通过，才允许进 M1 |

> **当前状态**：架构方案/实施计划已定稿（可评审）。**下一步即启动"M0 技术验证"**——在本机安装 dsh v0.1.1-rc.2，实测版本稳定性并锁定版本与插件快照。

---

## 阶段 M0：技术验证（W1–W2，2 周）

| 项 | 内容 |
|---|---|
| **目标** | 验证 dsh 版本稳定性（developer preview 破坏性变更）+ 锁定 dsh 与插件版本快照 + 建立事件日志重放基线 |
| **关键任务** | 环境搭建(0.1)、双 profile 跑通(0.2)、**版本稳定性验证(0.3)**、**插件快照锁定(0.4)**、平台插件骨架(0.5)、**重放一致性基线(0.6)**、事件域契约(0.7)、恢复机制(0.8)、AgentRegistry(0.9)、压测基线(0.10) |
| **产出** | POC 报告 + 版本/插件快照清单 + 重放基线 |
| **门禁（Go/No-Go）** | 0.3 版本稳定性**必须通过**；0.4 快照锁定**必须完成**；0.5/0.6/0.7 **必须通过**；任一失败触发回退预案（fork 稳定版自维护补丁，或暂缓升级） |
| **团队** | 后端 B 为主，后端 A / DevOps / QA / 架构师配合 |

## 阶段 M1：MVP（W3–W7，5 周）

| 项 | 内容 |
|---|---|
| **目标** | 单租户端到端闭环：Admin 配模型/Agent/发布，用户 Web 对话，事件日志完整落库 |
| **关键交付** | 代码基座（control-plane + dsh runtime）、JWT 认证、模型管理、Agent 模板 CRUD、发布物化引擎 v1（快照含插件清单）、会话 API（SSE + resume）、事件日志存储与查询、Web v1、Admin v1、CI/CD（含快照漂移检测） |
| **特点** | 此阶段**不做多租户隔离**，但所有表结构/代码路径预留 tenant_id（从第一天就存在） |
| **验收** | Admin 发布 Agent、用户多轮对话 + 断线重连可续；**重放一致性测试通过**；密钥密文落库、日志无明文；profile 无漂移 |

---

## 阶段 M2：v1.0 多租户完整版（W8–W12，5 周）

| 项 | 内容 |
|---|---|
| **目标** | 多租户隔离 + 审批中心 + 密钥管理 + MCP 网关 v1 + 计量（首个可称"企业级"版本） |
| **关键交付** | 租户体系（CRUD/角色/强制过滤）、多租户作用域插件（Session/Agent 命名 + 隔离）、隔离性测试套件（CI 红线）、审批中心（tools/pre-execute 拦截）、密钥管理、MCP 网关 v1、计量服务（事件派生）、Admin v2、事件回放查看器 |
| **验收** | 两租户互不可见（隔离套件 100%）；高风险工具未审批不放行；计量与账单误差 <5%；回放查看器可按 step 重放任意会话 |

---

## 阶段 M3：v1.5 生态与安全增强（W13–W17，5 周）

| 项 | 内容 |
|---|---|
| **目标** | 能力插件目录扩展 + 沙箱生产化 + 安全渗透与整改 |
| **关键交付** | 能力目录 v2（goal/plan/todo、workflow、subagent 引入并快照）、沙箱生产化（e2b 优先）、compaction 策略落地、guard 护栏、schedule 定时任务（含非请求路径租户上下文）、三硬边界平台化、事件存储冷层、安全渗透 |
| **验收** | 能力插件全部快照锁定、卸载即解除；生产沙箱 e2b 或等价隔离；渗透高中危清零；三硬边界按租户生效并留档 |

---

## 阶段 M4：v2.0 生产上线（W18–W22，5 周）

| 项 | 内容 |
|---|---|
| **目标** | 性能压测与加固、可观测性完善、计费、灰度上线、运维交接 |
| **关键交付** | 300 并发压测调优、事件写入吞吐验证、可观测体系（告警含事件延迟/存储增长/重放失败率）、计费、灾备演练、灰度上线、Runbook（含 dsh 版本升级流程与门禁） |
| **验收** | 300 并发下首 token P95≤3s、事件无积压、断连率<1%、无跨租户泄露；**重放一致性全量回归通过**；灰度 2 周无 P1 故障 |

---

## 阶段 5：运营期（M4 之后）

| 项 | 内容 |
|---|---|
| **运维交接** | Runbook（预设故障场景处置）、告警分级（P1 15min / P2 2h / P3 次日）、值班机制 |
| **例行维护** | **dsh 版本升级评估（每月，过三重门禁：重放回归 + 隔离套件 + 快照漂移）**、插件快照刷新（每季度）、备份恢复演练（季度）、事件归档（月度）、审计留存（按合规） |

## 各阶段速查表

| 阶段 | 周期 | 时间盒 | 一句话目标 | 门禁/验收 | 关键交付 |
|---|---|---|---|---|---|
| 0 立项 | 1~2 周 | 前期 | 业务+技术双门禁 | 业务判断 + M0 实证 | 立项决议 + 资源 |
| M0 验证 | 2 周 | W1–W2 | 版本稳定 + 快照锁定 | 0.3/0.4/0.5/0.6/0.7 全过 | POC 报告 + 快照清单 + 重放基线 |
| M1 MVP | 5 周 | W3–W7 | 单租户端到端 | 发布→对话→重连 + 重放一致 | Web 聊天 + 发布 + 事件存储 |
| M2 v1.0 | 5 周 | W8–W12 | 多租户+审批 | 隔离套件 100% + 审批流 | 隔离 + 审批 + MCP 网关 + 计量 |
| M3 v1.5 | 5 周 | W13–W17 | 生态与安全 | 插件可装卸 + 渗透清零 | 能力目录 + 沙箱 + 护栏 |
| M4 v2.0 | 5 周 | W18–W22 | 压测+上线 | 压测达标 + 灰度无 P1 | 上线 + Runbook |
| 5 运营 | 持续 | 上线后 | 稳定运行 | 告警分级响应 | Runbook + 月度版本评估 |

**总计**：约 22 周建设期（M0~M4）+ 前期立项 1~2 周；团队 6~6.5 人。
