## 1. 概述

### 1.1 目标

在 22 周内交付一套**以 DeepSeek Harness（dsh）为底座的企业级多租户 Agent 平台引擎**：租户开箱使用平台发布的 Agent，平台提供多租户隔离、审批、审计、计量与能力按需装卸（插件目录），并具备"任意 step 可从事件日志重建回放"的企业级可观测能力。

### 1.2 实施策略

| # | 策略 | 说明 |
|---|---|---|
| 1 | **版本快照优先（门禁制）** | dsh 是 developer preview，破坏性变更频繁。M0 的首要任务不是"跑通功能"，而是**验证版本稳定性并锁定 dsh 版本 + 全部依赖插件版本快照**；锁定的快照构成后续所有阶段的基线，未过 M0 门禁不允许进入 M1 |
| 2 | 垂直切片交付 | 每个阶段交付"可真实使用"的端到端能力，尽早暴露集成风险；dsh 机制验证逐项留证，消灭假设性设计 |
| 3 | 事件日志贯穿验收 | **事件日志重放/恢复能力作为全程验收项**（ADR-006）：M0 建立重放一致性测试基线，此后每个里程碑验收都包含"日志投影 vs 实际会话逐事件比对" |
| 4 | 控制面优先，运行面做薄 | 自建工作量集中在控制面（租户/审批/计量/审计查询）；运行面只做"平台插件 + profile 定制"，代码量刻意最小，降低对 dsh 上游升级的敏感度 |
| 5 | 能力先冻结、再扩展 | M1/M2 只用素材快照中已验证成熟的核心能力（tools/session/sandbox/guard 等），goal/workflow/e2b/acp 等复杂能力到 M3 按插件引入并快照 |

### 1.3 前置条件

| 项 | 要求 | 责任方 | 时间 |
|---|---|---|---|
| dsh 版本确认 | 确认生产使用版本（素材为 v0.1.1-rc.2）并冻结 | 架构师 | M0 开始前 |
| Node 运行环境 | Node ≥ 18 + npm（`npx @deepseek-ai/dsh web` 可运行） | DevOps | M0 第 1 周 |
| 模型资源 | ≥1 个可用模型 API Key（DeepSeek 优先，另备一个备用模型） | 采购/Admin | M0 第 1 周 |
| 基础设施 | K8s（dev/staging/prod）、PostgreSQL、Redis、对象存储 | DevOps | M0 第 1 周 |
| 密钥管理 | KMS 或 Vault 可用 | 安全/DevOps | M1 开始前 |

## 4. 阶段详细计划

### M0 — 技术验证（W1–W2，2 周）

**目标**：验证 dsh 版本稳定性（developer preview 破坏性变更）与插件树可定制性，**锁定 dsh 版本 + 全部依赖插件版本快照**，建立事件日志重放基线。M0 不通过不允许进入 M1。

| # | 任务 | 输出物 | 负责人 | 工时 |
|---|---|---|---|---|
| 0.1 | 环境搭建：Node 环境、dev K8s、PostgreSQL、Redis、对象存储 | 可用 dev 环境 | DevOps | 2d |
| 0.2 | 安装 dsh v0.1.1-rc.2，跑通 `web` / `headless` 两个内置 profile，完成一次对话 | 可运行 demo | 后端 B | 2d |
| 0.3 | **版本稳定性验证**：连续跑 7 天观察破坏性变更/崩溃/事件日志异常；核对素材快照中的机制（插件树、事件域、turn/step、瀑布拦截点）与当前版本是否一致 | 版本稳定性报告 | 后端 B | 4d |
| 0.4 | **插件版本快照锁定**：枚举能力插件（goal/plan/todo/skill/subagent/sandbox/hooks/schedule/workflow/compaction/mcp/lsp/terminal/code-runtime/e2b/guard/acp 等）与 dsh-base 依赖，锁定版本并固化 profile 基线配置 | 快照清单 + 基线 profile | 后端 B + 架构师 | 3d |
| 0.5 | 验证插件树定制：自制一个最小平台插件（贡献 service + 监听 agent/* 事件），经 bundle + patch 挂入并验证卸载即解除 | 平台插件骨架 | 后端 B | 3d |
| 0.6 | **重放一致性基线**：跑一组标准任务（含工具调用、失败重试），从 SessionEvent 用 deriveMessages 重建模型历史，逐事件比对实际会话行为 | 重放一致性测试 + 基线报告 | 后端 B + QA | 3d |
| 0.7 | 验证三层事件域契约：session/* 持久性（跨重载存活）、agent/* 活体协调、capability 事件挂策略 | 验证代码 + 记录 | 后端 B | 2d |
| 0.8 | 验证恢复机制：request-error 瀑布（`{ kind: 'retry' }` 拥有恢复）与 compaction 代际推进 | 验证代码 + 记录 | 后端 B | 2d |
| 0.9 | 验证 AgentRegistry 生命周期：create/resume、双检查进入、AgentHandle.dispose | 验证代码 + 记录 | 后端 B | 2d |
| 0.10 | 压测基线：单实例并发会话容量、事件写入吞吐（事件日志是核心存储资产） | 压测报告 | QA + DevOps | 2d |
| 0.11 | 编写《扩展点验证报告》与《版本快照锁定清单》，召开 M0 门禁评审 | 报告 + 评审结论 | 架构师 | 1d |

**门禁标准（Go/No-Go）**：

- 0.3（版本稳定性）**必须通过**——若 dsh 在验证期发生无法规避的破坏性变更，触发回退预案（见 §6 R-1）；
- 0.4（快照锁定）**必须完成**——版本 + 插件快照清单是后续全部开发基线；
- 0.5 / 0.6 / 0.7 三项**必须通过**——插件树定制、重放一致性、事件域契约是平台地基；
- 其余项允许"已知绕过方案"结论（如 compaction 行为不符预期则先禁用它，M3 再评估）。

- 密钥以密文落库，日志中无明文；profile 快照无漂移。

## 5. 关键路径与依赖

```
M0(版本稳定+快照锁定) ─门禁→ M1 ─→ M2 ─→ M3 ─→ M4
   关键路径：0.3/0.4/0.5/0.6 → 1.5 发布引擎 → 1.6 会话链路
            → 2.2 多租户作用域 → 2.6 MCP 网关 → 4.1 压测 → 4.5 上线
```

主要跨阶段依赖：

- dsh 版本升级评审（R-1 应对）可能插入 M1~M3 任一阶段，架构师需每周跟踪上游 release；
- KMS/Vault 不晚于 M1 第 1 周就绪（阻塞密钥加密）；
- e2b 商务/资源不晚于 M3 第 1 周确定，否则沙箱走 docker 备选；
- 每个阶段"验收"任务依赖该阶段全部开发任务完成，预留 buffer 不压缩。

|---|---|---|---|---|
| R-1 | **dsh developer preview 破坏性变更**（API/事件形态/插件接口变动） | 全程 | 高/高 | **版本快照锁定为基线**（M0 完成）；每周跟踪上游 release；升级必须过"重放一致性回归 + 隔离性套件 + 快照漂移检测"三重门禁；**回退预案**：快照基线不满足新需求时 fork 稳定版并自维护补丁，或暂缓升级至安全期 |
| R-2 | 插件版本漂移（依赖升级导致行为变化） | 全程 | 中/高 | CI 内置 profile 漂移检测；发布物化时插件版本随 Agent 快照锁定 |
| R-3 | Cordis 学习曲线陡，团队上手慢 | M0–M1 | 中/中 | M0 全员实操（0.5 任务本身就是培训）；架构师沉淀《dsh 机制速查》文档；外部咨询可选 |
| R-4 | 多租户作用域映射失败（dsh 作用域机制不满足隔离需求） | M0–M2 | 低/高 | M0 验证 0.5/0.7 先行；**回退**：Session/Agent 命名强制 + 平台插件在 agent/* 事件上做访问控制兜底 |
| R-5 | 事件日志存储增长失控（append-only 是核心资产也是成本） | M2 起 | 中/中 | 热/温/冷三层 + 归档策略（M3.7）；容量监控告警；按租户配额 |
| R-6 | 模型端点不稳定影响验收 | M1 起 | 中/低 | 验收环境配置双模型互为备份；计量按实际调用归集 |
| R-7 | 范围蔓延（租户提新需求） | M2 起 | 高/中 | 变更管理流程（§9）；新需求默认进 v2.x backlog，不影响 M4 上线 |

## 9. 变更与范围管理

- **基线**：本计划 + 架构方案 v0.1 为范围基线；里程碑验收标准变更需架构师 + 产品负责人双签。
- **变更流程**：需求方提变更单 → 影响评估（工期/架构/安全/**dsh 版本影响**）→ 纳入下一里程碑或 backlog。
- **阶段评审**：每里程碑结束召开评审会，输出《里程碑验收报告》（含重放一致性回归结果），确认或调整后续计划。
- **进度透明**：双周迭代 + 每周站会同步燃尽；R-1~R-7 风险每周复核状态。
