## 全流程地图

```
准备期          建设期（18 周）                                运营期
─────         ────────────────────────────                ─────
阶段0          M0     M1      M2      M3      M4           阶段5
立项    →    验证 → MVP  → 多租户 → 生态  → 生产     →   运维
评审          门禁   端到端  +审批   +多Agent 上线         交接
  │           │      │      │       │       │              │
  ▼           ▼      ▼      ▼       ▼       ▼              ▼
业务+技术    机制   图工作流 版本治理  MCP网关  灰度→全量
双门禁       门禁   闭环    企微上线  LangSmith 压测
```

**三道关键门禁贯穿全程**：

```
立项双门禁 ──→ M0 机制门禁 ──→ 各阶段验收 ──→ M4 上线门禁
(业务+实证)   (0.3/0.5/0.6)   (垂直切片)    (渗透+压测+灰度)
```

**关键路径**（任一延误即影响总工期）：
`0.3 Checkpointer → 1.6 执行链路 → 2.3 快照隔离 → 2.9 企微 → 3.3 DeepAgents 生产化 → 4.1 压测 → 4.6 上线`

## 阶段 0：立项准备（M0 之前，约 1~2 周）

| 项 | 内容 |
|---|---|
| **目标** | 拿到"开工许可"——业务+技术双门禁都过 |
| **关键活动** | ① 业务规模确认（≥N 个真实租户或对外商业化需求）<br>② 技术实证（在本机/dev 把三大机制能力点实际跑通：Checkpointer 中断/恢复/重放、LangSmith 接入、DeepAgents 双模式）<br>③ 立项评审（向决策者陈述，争取资源） |
| **前置条件** | LangGraph/LangChain/DeepAgents 版本锁定、≥1 个模型 API Key、LangSmith 账号、dev 基础设施（K8s/PG/Redis）申请、KMS/Vault 排期 |
| **产出** | 立项决议 + 资源到位 + 《机制验证报告》 |
| **门禁** | 业务判断通过 **且** M0 实证通过，才允许进 M1 |

---

## 阶段 M0：技术验证（W1–W2，2 周）

| 项 | 内容 |
|---|---|
| **目标** | 把架构依赖的每个机制能力点跑通留证——**本路线核心风险关口** |
| **关键任务** | 环境搭建(0.1)、最小图执行(0.2)、**Checkpointer 中断/恢复/重放(0.3)**、HITL 改 State 恢复(0.4)、**LangSmith 接入(0.5)**、**DeepAgents 双模式(0.6)**、条件边与回退(0.7)、压测基线(0.8) |
| **产出** | POC 报告 + 机制验证清单 |
| **门禁（Go/No-Go）** | 0.3 / 0.5 / 0.6 三项**必须全过**；任一失败触发回退预案（DeepAgents 回退自定义节点 +1 周；Checkpointer 换存储后端或 fork 打补丁；最坏自建状态服务 +3 周并砍一渠道） |
| **团队** | 后端 B 为主，后端 A / DevOps / QA / 架构师配合 |

---

## 阶段 M1：MVP（W3–W6，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 单租户端到端闭环：Admin 能定义图工作流并发布，用户能触发执行、看节点进度、处理 HITL 确认 |
| **关键交付** | 代码基座（control-plane + runtime）、JWT 认证、工作流定义（State/Node/Edge 声明式 + 图编译校验）、模型与工具装配、发布物化引擎 v1、执行与会话（SSE + Checkpointer 落库）、HITL v1、Web 运行视图 + Admin 图定义页、CI/CD |
| **特点** | 此阶段**不做多租户隔离**，但所有表结构/代码路径预留 tenant_id（从第一天就存在，避免后期迁移） |
| **验收** | 发布一个"LLM + 工具 + HITL + 条件边"工作流，用户全程 SSE 可见节点进度；HITL 挂起后人工确认可续跑；手动中断后从快照恢复；日志无明文密钥 |

---

## 阶段 M2：v1.0 多租户完整版（W7–W10，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 多租户隔离 + RBAC + 工作流版本治理 + 审批 + **企微上线** + 审计（首个可称"企业级"的版本） |
| **关键交付** | 租户体系（CRUD/角色）、contextvar 全链路、快照/会话租户隔离、隔离性测试套件（CI 红线）、工作流版本治理、审批模型 v1（票据化）、密钥管理（KMS）、审计服务、企微适配器（含 HITL 确认卡片）、Admin v2 |
| **验收** | 两租户互不可见对方工作流/run/快照/会话，隔离套件 100% 通过；重新发布后存量 run 仍按旧版本执行；HITL 票据挂起/批准/拒绝/过期全流程可用；管理+执行+审批 100% 落审计 |

---

## 阶段 M3：v1.5 生态安全增强（W11–W14，4 周）

| 项 | 内容 |
|---|---|
| **目标** | MCP 网关（凭证注入 + 工具审批）+ DeepAgents 多 Agent 生产化 + LangSmith 评估完善 + RAG 工具接入 |
| **关键交付** | MCP 网关 v1（协议代理/凭证注入/限流熔断/审计）、工具级审批流（写操作挂起/回调/过期、与凭证吊销联动）、DeepAgents Workflow/Handoff 生产化（不满足处回退自定义节点）、RAG 工具节点、LangSmith 评估集 + tracing 网关代理（脱敏）、飞书/嵌入页、工作流画布可视化 |
| **验收** | 写操作 MCP 未审批挂起、批准后执行、全程审计；审批期间凭证吊销则票据联动过期；DeepAgents 双模式各跑通一个多 Agent 场景且 trace 完整、按租户隔离；评估集可对工作流输出做回归评估 |

---

## 阶段 M4：v2.0 生产上线（W15–W18，4 周）

| 项 | 内容 |
|---|---|
| **目标** | 性能与安全加固 + **生产上线** + 运维交接 |
| **关键交付** | 200+ 并发压测调优（快照读写瓶颈、HPA、SSE 断连率）、可观测完善（Prometheus/Grafana + LangSmith 打通）、安全渗透（含快照越权读）、沙箱与执行加固、灾备演练、灰度上线、Runbook |
| **验收** | 200+ 并发下首 token P95≤3s、SSE 断连率<1%、无跨租户泄露；渗透高中危清零；中断/恢复/重放全量回归通过；灰度 2 周无 P1 故障 |

---

## 阶段 5：运营期（M4 之后）

| 项 | 内容 |
|---|---|
| **运维交接** | Runbook（快照损坏/存储不可用/LangSmith 中断/MCP 上游挂掉/HITL 票据僵死等故障处置）、告警分级（P1 15min / P2 2h / P3 次日）、值班机制 |
| **例行维护** | 密钥轮换（季度）、LangGraph/LangChain 版本评估（每里程碑）、快照清理对账（月度）、备份恢复演练（季度）、审计归档（月度） |

## 各阶段速查表

| 阶段 | 周期 | 时间盒 | 一句话目标 | 门禁/验收 | 关键交付 |
|---|---|---|---|---|---|
| 0 立项 | 1~2 周 | 前期 | 业务+技术双门禁 | 业务判断 + M0 实证 | 立项决议 + 资源 |
| M0 验证 | 2 周 | W1–W2 | 验证三大机制能力点 | 0.3/0.5/0.6 全过 | POC 报告 |
| M1 MVP | 4 周 | W3–W6 | 单租户端到端 | 定义图→发布→执行→HITL | Web 运行视图 + 图定义 |
| M2 v1.0 | 4 周 | W7–W10 | 多租户+审批+企微 | 隔离套件 100% + 版本不变量 | 隔离 + 版本治理 + 审计 |
| M3 v1.5 | 4 周 | W11–W14 | 生态与安全 | 工具审批 + 多 Agent trace 完整 | MCP 网关 + DeepAgents |
| M4 v2.0 | 4 周 | W15–W18 | 加固+上线 | 渗透+压测+灰度 | 压测报告 + Runbook |
| 5 运营 | 持续 | 上线后 | 稳定运行 | 告警分级响应 | Runbook + 维护 |

**总计**：约 18 周建设期（M0~M4）+ 前期立项 1~2 周；团队 5~5.5 人。
