# 教程写作标准

这个标准用于编写任务导向教程。它回答的核心问题是：读者要完成什么任务，需要哪些前置条件，每一步做什么，如何知道已经成功。

它不是仓库模板。教程不是参考手册；不要在正文铺满字段清单和完整 API，应把扩展内容链接到权威文档。

## 事实标注与证据规范

以下规范在整个 skill 家族中统一使用。SKILL.md 与本 reference 冲突时，以本 reference 为准。

### 事实标签词表

每条关键结论必须带且只带下列标签之一：

| 标签 | 含义 | 可用于 |
| --- | --- | --- |
| `源码确认` | 直接读到源码、配置或 schema 得到的结论 | 结构、签名、默认值、常量 |
| `运行确认` | 亲自执行命令并观察到输出 | 耗时、计数、退出码、实际报错 |
| `规范确认` | 来自规范、RFC、官方文档或论文 | 语义、协议约定、算法性质 |
| `文档确认` | 只来自二手文档或口头说明 | 背景、意图，不得作为行为依据 |
| `设计意图` | 作者目标，未验证是否达成 | 动机、规划，不得写成现状 |
| `未验证` | 尚无法确认 | 一切推测与待办 |

### 标签用法

- 每条关键结论在句末标注，例如：“`solve` 的默认启发式为 `manhattan`（源码确认，`<文件>:<行号>`）。”
- 能被源码直接读到的结论不要标 `运行确认`；能运行的结论不要标 `规范确认`。
- 全局标签可写在文档开头的状态行，但局部结论必须单独标注。
- 无法给出标签的结论不得写入正文。

### 证据书写

- **数字**：每个被报告的数字必须能追溯到命名的脚本、命令或来源；无法追溯的数字不得写入。禁止把未运行过的实验写成运行结果。
- **命令与输出**：每条命令与它的实际输出成对给出；只给命令不给输出视为未实测。
- **预期输出标记**：每个预期输出标注 `[固定]`（与版本/环境无关，如文件存在、断言通过）或 `[随环境/版本变化]`（如耗时、内存、时间戳）；无法判断时标 `[随环境/版本变化]`。
- **不适用**：某章节在本对象上不适用时，写“不适用”并给一句理由，不留空、不省略。
- **禁止占位**：交付文档不得残留任何未填充的占位段落（例如以括号包裹的提示句）。
- **完整性检查**：正文中每个“待验证”“不适用”“无此项”都必须指向具体原因或后续动作。

## 教程定位

先给结论：

- 读者完成教程后会得到一个可运行结果
- 面向什么背景的读者
- 预计时间和所需环境
- 本教程不覆盖什么
- 与仓库其他教程或文档的关系

## 前置条件

列出开始前必须满足的条件：

- 操作系统、运行时、包管理器和版本
- 仓库目录、配置、密钥或外部服务
- 数据集、模型、硬件或 API 配额
- 已完成的教程或已知概念

每项前置条件都要能检查。例如给出 `python --version` 或文件是否存在，而不是只写“需要安装依赖”。

## 最终结果与验证标准

先说明成功状态，让读者知道终点：

- 生成什么文件、服务、模型或结果
- 哪些输出应出现
- 如何判断教程已经完成

## 任务步骤

按可执行顺序组织。每步包含：

- 动作：创建、修改、运行什么
- 命令、代码或文件位置
- 预期结果
- 常见偏差和原因

步骤应能连续执行。不要把读者导向没有链接的“前面章节”。

## 示例代码

示例必须可复现：

- 代码与当前仓库或文档版本一致
- 注明运行环境
- 输入、输出或日志格式清楚
- 正常例和至少一个失败例

不要给只展示接口但不展示结果的半成品示例。

## 练习或扩展

如果教程包含练习，说明：

- 练习要修改什么
- 读者应观察什么变化
- 如何验证答案
- 是否提供参考答案

练习不是把教程重写一遍。每个练习应测试读者对真实步骤的理解。

## 排障

列出教程中读者最可能遇到的问题：

- 症状
- 最常见原因
- 检查方式
- 修复方法
- 何时应查看参考文档或仓库 issue

## 下一步

给出继续学习的真实入口：

- 完成后的下一个任务
- 相关教程、实验或工程项目
- 权威参考文档

## 事实与验证

教程中的命令、路径、版本和输出必须有来源：

- 教程是否已按当前仓库实际运行
- 命令来源是 README、Makefile、脚本还是手动实验
- 哪些输出依赖版本或环境

未验证步骤不能和已验证步骤混写。
