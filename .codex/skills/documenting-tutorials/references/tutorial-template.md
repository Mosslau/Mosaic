# 教程文档模板

这个模板用于编写任务导向教程。它回答的核心问题是：读者要完成什么任务，需要哪些前置条件，每一步做什么，如何知道已经成功。

教程不是参考手册。不要在正文铺满字段清单和完整 API，应把扩展内容链接到权威文档。

## 教程定位

先给结论：

- 读者完成教程后会得到一个可运行结果
- 面向什么背景的读者
- 预计时间和所需环境
- 本教程不覆盖什么
- 与仓库其他教程或文档的关系

## 前置条件

列出开始前必须满足的条件：

- 操作系统、运行时、包管理器和版本
- 仓库目录、配置、密钥或外部服务
- 数据集、模型、硬件或 API 配额
- 已完成的教程或已知概念

每项前置条件都要能检查。例如给出 `python --version` 或文件是否存在，而不是只写“需要安装依赖”。

## 最终结果与验证标准

先说明成功状态，让读者知道终点：

- 生成什么文件、服务、模型或结果
- 哪些输出应出现
- 如何判断教程已经完成

## 任务步骤

按可执行顺序组织。每步包含：

- 动作：创建、修改、运行什么
- 命令、代码或文件位置
- 预期结果
- 常见偏差和原因

步骤应能连续执行。不要把读者导向没有链接的“前面章节”。

## 示例代码

示例必须可复现：

- 代码与当前仓库或文档版本一致
- 注明运行环境
- 输入、输出或日志格式清楚
- 正常例和至少一个失败例

不要给只展示接口但不展示结果的半成品示例。

## 练习或扩展

如果教程包含练习，说明：

- 练习要修改什么
- 读者应观察什么变化
- 如何验证答案
- 是否提供参考答案

练习不是把教程重写一遍。每个练习应测试读者对真实步骤的理解。

## 排障

列出教程中读者最可能遇到的问题：

- 症状
- 最常见原因
- 检查方式
- 修复方法
- 何时应查看参考文档或仓库 issue

## 下一步

给出继续学习的真实入口：

- 完成后的下一个任务
- 相关教程、实验或工程项目
- 权威参考文档

## 事实与验证

教程中的命令、路径、版本和输出必须有来源：

- 教程是否已按当前仓库实际运行
- 命令来源是 README、Makefile、脚本还是手动实验
- 哪些输出依赖版本或环境

未验证步骤不能和已验证步骤混写。
