# Documenting Tutorials

## 使用边界

此 skill 用于以下任务：

- 编写让读者完成一个真实任务的教程
- 为仓库实验、工具或系统补充可跟随的动手教程
- 把已有笔记整理成带验证路径的学习材料
- 改写无法运行、步骤不连续的教程

此 skill 不用于：

- 写完整 API 参考或字段手册
- 解释系统或框架的整体架构
- 写营销式能力介绍
- 只列命令，不给预期结果和验证方式

## 写作前确认

开始前确认：

- 读者：入门者、实验复现者还是工具使用者
- 教程终点：读完能做哪个具体任务
- 教程时长和前置依赖：环境、数据、模型、硬件或账号
- 可复现方式：哪些步骤必须由实际运行验证
- 教程边界：什么内容应链接到参考文档而不是重复

## 写作流程

1. 先运行一次目标任务，记录关键输出、报错和验证点。
2. 已有教程和笔记可作为事实线索与读者上下文，但不能替代码运行验证背书，也不应为适配本地仓库风格而让步骤不可复现。
3. 按任务步骤组织，不用章节堆砌背景知识。
4. 每步给出动作、预期结果和常见偏差。
5. 示例中的命令、代码和数据要与当前仓库版本一致。
6. 最后提供验证清单，读者能判断教程是否成功完成。

## 写作质量门

最终交付前必须满足：

- 第一段说明读者能完成的任务和所需前置条件
- 每一步可独立执行，依赖关系清楚
- 命令、代码、文件和路径与仓库现状一致
- 示例至少覆盖正常路径和一个常见失败路径
- 环境版本、安装方式和数据来源清楚
- 预期输出能区分“应出现”和“版本可能变化”
- 教程不替代参考文档；深水区应给出链接
- 教程必须按当前实现实际运行或给出明确复现条件
- 教程终点是读者完成一个学习/复现任务，不是把生产故障处置流程伪装成教程步骤
