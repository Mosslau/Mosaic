# Explaining Systems

## 使用边界

此 skill 用于以下任务：

- 解释一个可运行系统的整体架构和端到端行为
- 解剖一个框架，说明设计思想、核心抽象和内部实现
- 解剖一个项目代码库，说明目录职责、入口点、运行方式和改动路径
- 从代码、运行结果和文档中验证架构结论

此 skill 不用于：

- 解释单个算法
- 写语言特性说明
- 单独讲解一个架构模式
- 只复述 README 内容，不做源码和运行验证

## 写作前确认

先判断解剖对象属于哪一种：

| 对象 | 判定依据 | 使用的 reference |
| --- | --- | --- |
| 系统 | 有部署、运行环境、组件协作和服务行为 | `references/system.md` |
| 框架 | 提供可复用抽象、API 和扩展点，强调如何被调用 | `references/framework.md` |
| 项目代码库 | 是一组仓库源码，重点是文件结构、入口和改动路径 | `references/project.md` |

随后确认：

- 读者：用户、开发者、架构师还是维护者
- 文档目的：理解系统、改造框架、接手项目、排障还是选型
- 文档范围：只解释一个模块、一条链路还是整个对象
- 对象事实：路径、版本/提交、运行环境或文档声称覆盖的时间点
- 可验证来源：源码文件、运行命令、配置、测试、实际输出或现有文档
- 不确定点：哪些结论目前只能标记为假设

## 写作流程

1. 先发现对象的真实入口和事实来源：README、配置、测试、脚本、部署文件及源码都可以提供线索，但不能替代源码和运行验证。
2. 按对象选择对应的 `references/` 写作标准；仓库已有文档或模板只作为待验证素材，不能优先于本 skill 的准确性要求。
3. 从入口点开始追踪一条真实的端到端链路，而不是只按目录名猜模块职责。
4. 对每个模块或流程结论找到源码位置并验证。
5. 区分“从代码确认”“从运行确认”“从文档确认”和“尚未验证”四类陈述。
6. 按“对象做什么、怎么运行、怎么改、会怎么失败”组织内容；没有观察或运行能力的对象要给出源码路径和验证入口。

## 写作质量门

最终交付前必须满足：

- 不把 README 或目录名当作架构事实
- 开头能识别对象、范围、版本/提交状态，并区分“设计意图”“源码现状”“文档声明”和“尚未验证”
- 每条关键链路都能追踪到入口、模块和代码位置
- 模块职责有边界，不把所有文件笼统列为“核心模块”
- 状态、数据流和调用流没有相互矛盾
- 扩展、部署、调试和失败场景被说清
- 文档包含可执行的复现方式或清晰的源码入口
- 没有源码或运行证据支撑的内容被显式标为未验证，而不是写成已验证架构
