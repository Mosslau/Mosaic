# Documenting API Contracts

## 使用边界

此 skill 用于以下任务：

- 说明 HTTP、RPC、消息或事件接口的契约
- 解释请求、响应、消息、错误和状态转移规则
- 分析接口版本、迁移和破坏性变更
- 判断文档描述的是规范约定还是当前实现

此 skill 不用于：

- 解释整个系统或框架的架构
- 写语言特性说明
- 写普通 API 入门教程
- 只复述 OpenAPI 或代码注释，不验证实现

## 写作前确认

开始前确认：

- 读者：客户端开发者、服务端开发者、测试者还是架构师
- 文档目的：理解契约、排障、做兼容性判断，还是评审接口设计
- 文档类型：规范性契约、描述当前实现的参考，还是迁移说明
- 权威来源：代码、测试、OpenAPI/AsyncAPI、protobuf、RFC 或已有规范
- 当前行为与规范不一致时，先记录差异，不擅自改写规范

## 写作流程

1. 找到接口所有者和权威定义，例如服务代码、测试、schema 或 API 文档。
2. 检查仓库是否已有契约模板或相邻接口文档，沿用本地约定。
3. 从入口出发追踪真实链路，确认请求如何被校验、路由、处理和返回。
4. 只写由代码、测试、schema 或运行结果支持的字段和行为。
5. 分开写“规范要求”“当前实现”和“尚未验证”三类结论。
6. 用可执行请求或测试示例说明正常路径、错误路径和边界路径。

## 写作质量门

最终交付前必须满足：

- 明确读者依赖的是契约还是实现观察
- 请求、响应、消息字段和类型与实际 schema 一致
- 错误分类清楚：传输错误、业务错误、校验错误和重试策略不混在一起
- 状态转移表列出合法事件、非法事件和结果
- 幂等、超时、重试和并发行为有具体说明
- 版本兼容和破坏性变更范围写清
- 示例可复现，关键结论可追溯到源码、测试或运行结果
- 未验证的假设显式标注，不写成确定行为
