# Documenting API Contracts

## 使用边界

此 skill 用于以下任务：

- 说明 HTTP、RPC、消息或事件接口的契约
- 解释请求、响应、消息、错误和状态转移规则
- 分析接口版本、迁移和破坏性变更
- 判断文档描述的是规范约定还是当前实现

此 skill 不用于：

- 解释整个系统或框架的架构
- 写语言特性说明
- 写普通 API 入门教程
- 只复述 OpenAPI 或代码注释，不验证实现

## 写作前确认

先判定接口种类，它决定哪些章节适用：

| 接口种类 | 判定依据 | 适用章节 |
| --- | --- | --- |
| 网络接口 | HTTP/RPC，有独立部署的服务与客户端 | 全部章节，含传输错误、幂等、超时、重试、版本 |
| 消息/事件接口 | 有 topic、生产者与消费者、异步投递 | 全部章节，重试与幂等按投递语义写 |
| 进程内接口（库/模块） | 同一进程内被调用，无传输层 | 只写签名、默认值、前置条件、哨兵值、异常分类、确定性；传输/超时/重试/版本各写「不适用」并说明理由 |

随后确认：

- 读者：客户端开发者、服务端开发者、测试者还是架构师
- 文档目的：理解契约、排障、做兼容性判断，还是评审接口设计
- 文档类型：规范性契约、描述当前实现的参考，还是迁移说明
- 权威来源：代码、测试、OpenAPI/AsyncAPI、protobuf、RFC 或已有规范
- 是否存在机器可读 schema；不存在时按「输出契约」走源码模式
- 是否存在同一个接口的多份实现；存在时先确定唯一权威实现并写明
- 当前行为与规范不一致时，先记录差异，不擅自改写规范

## 写作流程

1. 找到接口所有者和权威定义。当同一接口存在多份实现时，以「被真实调用方导入/调用的那一个」为权威实现，并在文档中写明其余实现与它的关系（别名、旧版、重复实现）。
2. 已有接口文档和 schema 只作为事实线索，不能因为仓库模板更短或风格不同而降低本 skill 的标准；发现规范、代码和文档不一致时记录差异。
3. 判定接口种类，据此决定章节取舍；不适用章节写「不适用」而不是留空。
4. 从入口出发追踪真实链路，确认请求如何被校验、路由、处理和返回。
5. 只写由代码、测试、schema 或运行结果支持的字段和行为。
6. 分开写“规范要求”“当前实现”和“未验证”三类结论。
7. 用可执行请求或测试示例说明正常路径、错误路径和边界路径。

## 输出契约

交付前确认以下四项，缺一项即视为未完成：

- **语言**：正文跟随当前仓库主要文档语言（本仓库为中文）；字段名、错误码、命令保留原文。
- **位置与命名**：按 `<接口名>.md` 命名；已有接口文档目录时放入其中。
- **位置与命名优先级**：调用方显式指定的路径或文件名优先；未指定时按本 skill 的命名规则。
- **完整性**：不得残留任何未填充的占位段落（例如以括号包裹的提示句）。
- **事实标注**：未验证内容必须显式写「未验证」或「来源确认」，不得以留空或省略代替；结论来自来源材料而非本人核对时，用「来源确认」。

**源码模式（降级）**：没有机器可读 schema、也没有可运行服务时，不因此停止写作。改为：签名与默认值从源码提取并标注「源码确认」；前置条件、哨兵值、异常来源一并从源码提取；写清“本文以源码为权威，无 schema 可对照”；把需要运行才能确认的行为（实际错误码、超时值）列入「待验证清单」。

本 skill 的说法若与 `references/api-contract-standard.md` 冲突，以该 reference 为准。

## 写作质量门

最终交付前必须满足：

- 文档开头一段写明接口名称、接口种类（网络/消息/进程内）、文档类型（规范性契约/当前实现参考/迁移说明）和覆盖版本
- 文档开头声明读者应依赖的是契约还是实现观察；二者并存时分别标注
- 字段说明与实际 schema 或源码一致；每个字段给出类型、必填性、默认值和可空性
- 存在多份实现时，写出唯一权威实现及其位置，并说明其余实现为什么不是权威
- 不适用章节（如无状态接口的状态转移表、纯函数的超时重试）显式写「不适用」并给出理由；留空或省略即不合格
- 错误分类按接口种类给出；网络接口区分传输/校验/业务/权限错误并写明可重试性，进程内接口给出异常类型分类
- 涉及任务、作业、订单或会话时，用状态转移表列出合法事件、非法事件和结果；不涉及则声明不适用
- 幂等、超时、重试和并发行为：网络与消息接口给出具体值或明确“未定义”；进程内接口写明不适用
- 版本兼容与破坏性变更范围写清；无版本机制时声明“当前无版本策略”
- 每个示例可复现并附命令与预期输出；关键结论可追溯到源码位置、测试或运行结果
- 每个被报告的数字或行为都能追溯到源码、测试或运行输出；无法追溯的不得写入
- 未验证的假设显式标注，不写成确定行为

## 与其他 skill 的边界

- 若重点是存储实体、字段与迁移，改用 `documenting-data-models`。
- 若重点是整个系统或框架的架构，改用 `explaining-systems`。
- 若重点是语言语法与语义，改用 `documenting-language-features`。
- 若用户只是提问、不要求产出文档，直接用对话回答。
