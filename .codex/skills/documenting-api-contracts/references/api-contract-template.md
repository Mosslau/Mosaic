# API 契约文档模板

这个模板用于说明 API、协议或接口契约。它回答的核心问题是：客户端可以依赖什么，服务端实际实现了什么，错误和状态变化如何表现，版本变化会破坏谁。

模板不是让每节都写满。与本契约无关的部分删除，读者需要的信息不要拆到无法导航的零散文件中。

## 契约定位

先给结论：

- 接口名称、协议类型和消费方
- 文档是规范性契约还是当前实现参考
- 一句话说明该接口解决什么问题
- 本契约不覆盖哪些内容
- 与相邻接口、服务或系统的边界

## 权威来源与所有权

说明哪些来源具有最高权威，避免实现和文档互相矛盾：

- 服务代码位置
- schema、OpenAPI/AsyncAPI 或 protobuf 文件
- 契约测试和集成测试位置
- 接口负责人或维护模块
- 当规范与实现不一致时，应记录差异而不是擅自改写规范

## 接口入口

列出可访问入口和调用前提：

- base URL、端口、域名或消息 topic
- 请求使用的协议、序列化和认证方式
- 开发、测试、生产环境的差异
- 如何确认入口可用

## 操作或消息清单

对 HTTP/RPC 接口或消息事件逐项说明：

- 方法、路径或操作名
- 用途和典型调用方
- 请求字段、响应字段和主要约束
- 是否同步返回、异步返回或需要轮询/回调
- 限流、超时、大小和配额限制

不要复制完整 OpenAPI 内容。字段细节可以链接到 schema，文档解释接口语义、状态和错误行为。

## 数据与消息结构

当字段含义不能从类型直接看出时说明：

- 字段名、类型、必填性和默认值
- 字段的业务含义和取值约束
- 日期时间、枚举、单位、编码和 null 语义
- 分页、排序、过滤和批量操作约定
- 请求校验失败时的具体表现

## 认证、授权与安全

覆盖调用方真正需要知道的内容：

- 认证方式、token 过期和刷新方式
- 权限或 scope 要求
- 敏感字段如何处理
- 传输安全和信任边界

## 错误与失败语义

错误不能只列一个 HTTP 状态码。说明：

- 传输错误、校验错误、业务错误和权限错误的区分方式
- 错误响应的结构和可读诊断信息
- 哪些操作可以安全重试，哪些不能
- 幂等键、重试上限、退避和超时默认值
- 部分成功、批量失败和补偿操作的约定

## 状态与生命周期

如果接口涉及任务、作业、订单或会话，用状态表说明：

- 合法状态集合
- 每个合法转移的事件和调用方
- 非法转移会发生什么
- 状态由谁创建、谁推进、谁清理
- 并发写入、过期、取消和中断时的保证

## 版本与兼容性

说明版本策略：

- 当前支持哪些版本
- 新增字段和可选字段是否视为兼容
- 哪些变更属于破坏性变更
- 弃用字段、移除接口和迁移路径如何公布
- 旧客户端与新服务端的行为差异

## 示例调用流

给出一条真实端到端调用路径：

1. 调用方准备请求和认证
2. 请求到达后的校验、路由和权限检查
3. 核心处理逻辑和状态变化
4. 成功响应或错误返回
5. 客户端重试或恢复路径

示例必须来自代码、测试或实际运行记录。

## 实现映射与验证

把文档结论对应到代码入口：

- 请求处理入口和核心函数
- 校验、状态机或事务所在位置
- 集成测试或契约测试
- 可复现的 curl、脚本或测试命令

## 事实标注

关键结论使用可验证标签，例如“契约文件确认”“源码确认”“测试确认”“运行确认”“尚未验证”。不要把客户端示例中的假设写成已实现行为。
