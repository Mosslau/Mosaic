# Documenting Data Models

## 使用边界

此 skill 用于以下任务：

- 说明实体、字段、类型和校验约束
- 解释表、集合或对象之间的关系
- 说明索引、唯一性和数据生命周期
- 分析 schema 变更、迁移和兼容性

此 skill 不用于：

- 解释具体算法
- 解释 API 或消息契约
- 写系统架构总览
- 把 ORM 模型或 SQL 原样复制到文档中

## 写作前确认

先判定模型类型，它决定哪些约束章节适用：

| 模型类型 | 判定依据 | 适用章节 |
| --- | --- | --- |
| 关系型/事务型 | 有库表、主外键、事务 | 全部章节，含唯一性、级联、软删除、时间戳 |
| 分析型/湖仓 | 有分区、schema evolution、批式写入 | 约束章节只写分区与演进规则；唯一性/级联写「不适用」 |
| 向量型 | 有 embedding、向量索引 | 约束章节写维度、距离度量、索引重建；唯一性/级联写「不适用」 |
| 文件集合/对象模型 | 文件、目录、序列化对象或内存 dataclass | 只写字段、类型、可空性、不变量与生命周期；其余写「不适用」 |

随后确认：

- 读者：数据工程师、后端开发者、模型训练者还是架构师
- 文档目的：理解数据、设计迁移、排查数据问题，还是评审模型
- 数据范围：单库、多库、文件集合、对象模型还是消息持久化数据
- 权威来源：schema、迁移文件、ORM、类型定义、种子数据和测试
- 模型版本标识：迁移版本号、提交哈希或代码位置；无版本机制时写明“无版本标识”
- 是否存在同一实体的多份定义；存在时先确定唯一权威定义
- 当前模型与代码实际使用是否一致

## 写作流程

1. 从 schema、迁移、ORM 或代码中的真实类型出发，不按目录名猜字段。
2. 已有模型文章和 ERD 只作为事实线索或导航上下文，不能替代 schema、迁移、测试和运行验证。
3. 判定模型类型，据此决定约束章节的取舍；不适用章节写「不适用」并说明理由，不留空。
4. 识别实体、字段、约束、关系、索引和数据生命周期。
5. 用查询、测试或种子数据验证关系、唯一性和约束。
6. 将“模型设计意图”和“当前 schema 行为”分开写。
7. 对迁移给出兼容路径；不存在迁移时显式写「当前无迁移」，不把计划中的迁移写成已完成状态。
8. 记录跨字段不变量与哨兵值，例如“空值”用哪个特殊值表示、两个字段之间的互斥或蕴含关系。

## 输出契约

交付前确认以下四项，缺一项即视为未完成：

- **语言**：正文跟随当前仓库主要文档语言（本仓库为中文）；字段名、类型名与 SQL 片段保留原文。
- **位置与命名**：按 `<模型名>.md` 命名；已有数据文档目录时放入其中。
- **位置与命名优先级**：调用方显式指定的路径或文件名优先；未指定时按本 skill 的命名规则。
- **完整性**：不得残留任何未填充的占位段落（例如以括号包裹的提示句）。
- **事实标注**：未验证内容必须显式写「未验证」或「来源确认」，不得以留空或省略代替；结论来自来源材料而非本人核对时，用「来源确认」。

**无 schema 模式（降级）**：没有 schema、迁移或数据库可查时，不因此停止写作。改为：字段与类型从 ORM、类型定义或代码中的真实结构提取并标注「源码确认」；写清“本文以代码类型为权威，无 schema 可对照”；把需要查库才能确认的内容（实际索引、真实数据分布）列入「待验证清单」；不得虚构迁移或索引。

本 skill 的说法若与 `references/data-model-standard.md` 冲突，以该 reference 为准。

## 写作质量门

最终交付前必须满足：

- 文档开头一段写明存储系统/模型名称、模型类型（关系型/分析型/向量型/文件集合）、模型版本标识（迁移号、提交哈希或代码位置，无版本机制则声明），以及本文描述的是设计目标还是当前状态
- 每个核心实体的字段都给出类型、默认值、可空性与业务含义；不适用字段写「不适用」而非省略
- 同一实体存在多份定义时，写出唯一权威定义及其位置，并说明其余定义与它的差异
- 跨字段不变量和哨兵值被写出，例如“路径为空时代价为 `inf`”“`path is None` 与 `cost == inf` 等价”
- 关系说明真实存在，不把相似命名字段当成外键；每条关系能对应到 schema、类型定义或代码位置
- 唯一性、级联、软删除和时间戳规则：适用时写清，不适用时写「不适用」并说明理由（例如内存模型无级联概念）
- 索引与常见查询路径对应，不罗列所有索引；每条索引说明它支撑哪个查询
- 迁移一节：有迁移则给出前置条件、向后兼容方式、回滚风险与验证方式；无迁移则显式写「当前无迁移」
- 数据来源、写入频率、保留期、删除方式四项齐全；每一项有明确取值或「不适用」
- 示例或验证方式可复现，并给出命令与预期输出
- 每个被声称的结构或约束都能追溯到 schema、类型定义或源码位置；无法追溯的不得写成事实

## 与其他 skill 的边界

- 若重点是接口字段、错误与状态机，改用 `documenting-api-contracts`。
- 若重点是整个系统或框架架构，改用 `explaining-systems`。
- 若重点是算法本身，改用 `explaining-algorithms`。
- 若用户只是提问、不要求产出文档，直接用对话回答。
