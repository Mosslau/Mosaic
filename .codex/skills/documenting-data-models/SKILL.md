# Documenting Data Models

## 使用边界

此 skill 用于以下任务：

- 说明实体、字段、类型和校验约束
- 解释表、集合或对象之间的关系
- 说明索引、唯一性和数据生命周期
- 分析 schema 变更、迁移和兼容性

此 skill 不用于：

- 解释具体算法
- 解释 API 或消息契约
- 写系统架构总览
- 把 ORM 模型或 SQL 原样复制到文档中

## 写作前确认

开始前确认：

- 读者：数据工程师、后端开发者、模型训练者还是架构师
- 文档目的：理解数据、设计迁移、排查数据问题，还是评审模型
- 数据范围：单库、多库、文件集合、对象模型还是消息持久化数据
- 权威来源：schema、迁移文件、ORM、类型定义、种子数据和测试
- 当前模型与代码实际使用是否一致

## 写作流程

1. 从 schema、迁移、ORM 或代码中的真实类型出发，不按目录名猜字段。
2. 已有模型文章和 ERD 只作为事实线索或导航上下文，不能替代 schema、迁移、测试和运行验证。
3. 识别实体、字段、约束、关系、索引和数据生命周期。
4. 用查询、测试或种子数据验证关系、唯一性和约束。
5. 将“模型设计意图”和“当前 schema 行为”分开写。
6. 对迁移给出兼容路径，不把计划中的迁移写成已完成状态。

## 写作质量门

最终交付前必须满足：

- 每个字段都说明类型、默认值、可空性、约束和业务含义
- 开头能识别存储系统/模型名称、schema 版本和文档描述的是设计目标还是当前 schema
- 关系说明真实存在，不把相似命名字段当成外键
- 唯一性、级联、软删除和时间戳规则写清
- 索引与常见查询路径对应，不罗列所有索引
- 迁移说明前置条件、回滚风险和兼容影响
- 数据来源、去向和保留策略有明确结论
- 示例或验证方式可复现
- 未从代码或 schema 确认的结论不能写成事实
