# 数据模型写作标准

这个标准用于说明实体、字段、约束、关系、索引和数据生命周期。它回答的核心问题是：系统保存了什么，字段如何取值，实体如何关联，改动 schema 会带来什么风险。

它不是仓库模板。不是每个数据库或模型都需要长篇说明；选择读者最需要的信息，其他内容链接到 schema、迁移和代码，但所有结论仍要可追溯。

## 模型定位

先给结论：

- 数据模型服务什么业务问题
- 主要写入方和读取方
- 数据是事务性、分析性、向量性还是配置性
- 文档描述的是当前 schema 还是设计目标
- 与相邻模型或存储系统的边界

## 权威来源

列出事实来源和优先级：

- 数据库迁移文件
- ORM、schema 或类型定义
- 服务中实际读写该数据的代码
- 种子数据、测试数据和生产数据样本
- 数据治理或模型评审文档

## 实体与字段

对核心实体使用字段表说明：

- 字段名、数据库类型或语言类型
- 是否必填、默认值、可空性
- 唯一性、枚举、范围和其他校验
- 字段的业务含义
- 字段由谁写入、何时写入

字段说明应从 schema 或类型定义核对，不能只按名称猜语义。

## 关系

说明关系是否存在，以及如何建立：

- 一对多、多对多、可选关系和继承关系
- 关系使用外键、联合键、中间表还是隐式 id
- 删除、更新和级联行为
- 关系是否在应用层保证
- 循环引用和孤儿记录如何处理

## 约束与不变量

写清系统必须保持的规则：

- 唯一性约束及其边界
- 数值、长度、格式和业务规则校验
- 软删除、版本号、审计字段的语义
- 并发下由谁保证一致性
- 约束被违反时的可观察行为

## 索引与查询路径

不要罗列全部索引。说明：

- 主要查询和写入模式
- 每个索引支持哪个查询路径
- 复合索引的字段顺序
- 分区、分片、向量索引或全文索引
- 写入放大、热点和过期索引风险

## 数据生命周期

说明数据从产生到删除的路径：

- 数据来源和入口
- 数据更新频率和生命周期
- 归档、清理、TTL 和保留策略
- 软删除与硬删除的区别
- 导出、备份和恢复入口

## 存储与序列化

如果存储方式影响语义，说明：

- 数据库、表、集合或对象存储位置
- JSON、二进制、向量或其他序列化格式
- 字符集、时区、精度和数值范围
- 多环境 schema 差异

## 迁移与兼容

对每个相关迁移说明：

- 改动内容和前置条件
- 向后兼容方式：加列、默认值、双写、回填还是版本迁移
- 回滚路径和数据丢失风险
- 哪些服务版本在迁移期间同时读取数据
- 迁移完成后如何验证数据一致

## 示例与验证

给出可复现检查方式：

- 查看 schema 或迁移的命令
- 查询种子数据验证关系的 SQL、脚本或 API
- 验证约束被违反时系统行为的测试
- 文档结论对应的代码位置

## 事实标注

对关键结论使用可验证标签，例如“迁移文件确认”“ORM 确认”“测试确认”“运行确认”“尚未验证”。不要把设计意图写成当前 schema 行为。
