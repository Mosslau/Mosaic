# Documenting Runbooks

## 使用边界

此 skill 用于以下任务：

- 编写故障诊断和恢复流程
- 记录发布、回滚、扩缩容或数据恢复步骤
- 说明某类告警或错误对应的处置路径
- 把散落在聊天、笔记中的运维步骤整理成可执行 runbook

此 skill 不用于：

- 解释系统整体架构
- 写功能使用教程
- 写 API 参考或算法说明
- 记录从未在真实环境执行过的假设流程

## 写作前确认

开始前确认：

- 读者：值班工程师、开发工程师还是运维负责人
- runbook 目标：诊断、修复、回滚、备份还是发布
- 触发条件：告警、错误、用户反馈还是已知事件
- 可执行来源：真实命令、日志位置、配置、脚本和验证方式
- 风险边界：哪些步骤需要权限、哪些情况下必须停止并升级

## 写作流程

1. 找到真实服务和环境入口，不凭记忆写目录或命令。
2. 检查仓库是否已有 runbook 模板或相邻文档，沿用本地约定。
3. 先写触发条件和停止条件，再写诊断与处置。
4. 用日志、指标、配置或命令确认每个判断点。
5. 对破坏性操作明确前置检查、备份、回滚和执行权限。
6. 用真实或接近真实的测试环境验证步骤，再标记验证方式。

## 写作质量门

最终交付前必须满足：

- 读者能根据症状判断本 runbook 是否适用
- 诊断步骤给出具体命令、日志位置或查询入口
- 修复和回滚步骤不遗漏停机、备份和恢复验证
- 破坏性操作有明确的停止条件和升级联系人
- 步骤顺序正确，不能依靠读者脑补环境差异
- 命令、脚本、路径和版本与当前系统一致
- 验证方式能证明故障已恢复
- 未实测的步骤显式标注，不与已验证步骤混在一起
