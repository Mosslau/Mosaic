# Documenting Language Features

## 使用边界

此 skill 用于以下任务：

- 解释一个语法结构为什么这样设计
- 说明一个语言特性的语义和运行时行为
- 解剖编译、类型检查或执行阶段如何处理一个特性
- 解释多个特性如何组合、互相限制或产生歧义
- 说明版本变更、兼容性和迁移影响

此 skill 不用于：

- 写通用语言入门教程
- 列 API 文档或函数签名
- 解释整个框架
- 解释一个算法或系统架构

## 写作前确认

开始前确认：

- 读者：语言使用者、框架作者、编译器实现者还是学习编程的人
- 文档目的：学会使用、理解设计、做兼容性判断，还是阅读实现
- 特性范围：语法、语义、类型系统、运行时、工具链还是生态惯例
- 权威来源：语言规范、官方参考、编译器源码、RFC、教程或示例代码
- 本地约束：仓库是否有语言特性说明模板或相关文档

## 写作流程

1. 先读语言规范或官方资料，确认术语和精确行为，不以二手教程为准。
2. 检查仓库内是否有同类文档，沿用标题层级和示例风格。
3. 在起草前加载 `references/language-feature-template.md`。
4. 将“语言现状”“设计动机”“历史原因”分开写，不要混成同一层叙述。
5. 用最小可运行示例验证关键语义；不能运行的示例要说明错误来自哪一阶段。
6. 对边界行为给出编译、解释、执行或类型检查的可观察结果。

## 写作质量门

最终交付前必须满足：

- 特性动机和语法形式先讲清，再讲内部实现
- 每个示例都有预期行为和可复现方式
- 合法例、非法例和边界例都被覆盖
- 特性与其他特性的交互没有被忽略
- 设计权衡写清，不能只说优点
- 编译、运行、类型或版本行为与规范或实验一致
- 不确定的语义不能写成确定结论
