# Explaining Algorithms

## 使用边界

此 skill 用于以下任务：

- 解释一个算法的设计动机和核心思想
- 说明一个数据结构的性质、操作和复杂度
- 为已有实验代码补充算法说明，或解释源码中的算法实现
- 对比两个相近算法并说明适用边界

此 skill 不用于：

- 解释语言语法、语言特性或框架 API
- 写系统架构总览
- 写软件项目 README
- 写通用教程或完整课程
- 把“按某仓库模板补标题”当成文档任务

## 写作前确认

开始正文前先确定以下信息，并把结论记录到工作笔记中：

- 读者：学习算法的人、实现者、代码评审者，还是工程负责人
- 文档目的：理解原理、复现实验、选型，还是维护实现
- 文档类型：理论学习文档、实验实现说明、源码算法注释，还是对比说明
- 对象事实：对象名称、版本或上下文中能唯一标识算法/数据结构的依据
- 事实来源：权威教材、论文、源码文件、测试、运行输出或实验代码
- 非目标：本算法文档明确不解释什么
- 交付形态：纯理论说明、源码实现说明、实验对照说明，还是选型对比

## 写作流程

1. 先确定写作对象是纯理论主题、已有实现、实验对照还是多个候选方案，再选择该文档必须回答的核心问题；不逐节填空。
2. 用源码、规范、测试或运行记录建立事实基线。已有 README 或同主题文档只作为事实线索和引用上下文，不能替代本 skill 的质量标准，也不能因为要适配仓库模板而降低准确性。
3. 如果对象已有实现，先读源码和测试再写；纯理论主题没有实现时，明确写成理论说明或“示例为示意”，不虚构文件和函数。
4. 在起草前加载 `references/algorithm-standard.md`，只选择与当前任务相关的部分。
5. 按“结论先行”写作：文档、章节和段落先给结论，再给依据。
6. 对每个关键结论标注来源或验证方式，并把无法验证的内容写成“尚未验证”。

## 写作质量门

最终交付前必须满足：

- 输入、输出和假设写得足够具体，读者能判断该算法是否适用于自己的问题
- 文档开头能看出对象是谁、属于算法还是数据结构、当前状态和作者声称的事实来源
- 核心思想可以用一句话说清
- 正确性论证不是“看起来对”，而是有可检查的步骤或不变量
- 数据结构说明覆盖操作语义、不变量和复杂度，不把数据模型与算法文档混为一类
- 复杂度说明给出前提，例如数据规模、稀疏图还是稠密图、最好/最坏/平均/期望情形
- 实现部分与真实代码对应；如果没有真实实现，则不出现“文件 `impl.py` 会做某事”这类虚构表述
- 示例覆盖正常例、边界例或反例
- 明确写出局限、失效场景和相近算法的替代关系
- 来源记录区分教材/论文、官方文档、源码、测试/运行记录和尚未验证的假设
