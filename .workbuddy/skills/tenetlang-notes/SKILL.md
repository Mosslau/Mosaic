# TenetLang 学习笔记写作规范

## Overview

TenetLang 仓库的 `languages/` 目录是多门主流语言的系统化学习笔记库，最终服务于「学习 → 分析 → 合成 Tenet 语言」的闭环。本 skill 定义每个阶段的四层交付物标准——**知识文档 + 示例代码（examples/）+ 代码练习（exercises/）+ 综合项目（project/）**——并规范 Roadmap 与阶段目录的重构流程，保证任何一门语言、任何一个阶段写出来都长一个样。本 skill 只含规范与模板，不维护任何语言的现状快照（哪门语言有几个阶段、完成到哪，以各 roadmap 文件与磁盘目录为准）。

## 目录结构

```
languages/<语言缩写>/                  # c, cpp, go, java, py, rs
├── <语言名>.md                        # Roadmap 总览（如 c.md, python.md）
└── ph01-<主题>/ ~ phNN-<主题>/        # N 个阶段目录（N 按语言复杂度定）
    ├── XX-<主题>.md                   # 知识文档（主文档，必含，编号与目录一致）
    ├── examples/                      # 文档示例的完整可运行版本（推荐）
    ├── exercises/                     # 代码练习：题目 + 参考实现（推荐）
    └── project/                       # 阶段综合项目（推荐）
```

规则：
- 阶段数不固定：由每门语言的 Roadmap 自行规划（可为任意 N）。唯一硬约束是 **Roadmap 中每个阶段必须对应一个 ph 目录**（承诺必须可兑现）；反向允许目录先行——先建 phXX 目录再回头在 roadmap 中补该阶段小节，但完成后两边必须对齐。skill 不断言任何具体语言当前有多少阶段，以各语言 roadmap 文件为准
- 阶段目录命名：`ph<两位数>-<kebab-case 主题>`，如 `ph04-memory-mgmt`；编号必须连续，重构删并阶段后重排编号
- 主文档文件名：`<两位数>-<主题>.md`，与目录主题一致，如 `ph04-memory-mgmt/04-memory-mgmt.md`
- 四层交付物：`.md` 知识文档是骨架必含；`examples/` `exercises/` `project/` 是肉身，重构/完善阶段时逐步补齐（完成度检查时按四层统计）
- 所有代码文件必须实际编译/运行验证通过后才能写入仓库，示例代码在文档中注明验证环境（编译器/解释器版本）

存量兼容原则：仓库早期笔记可能与本规范有出入（章节命名、子结构、是否有代码层）。执行任何任务时**以本 skill 为准**，不通过模仿旧笔记来推断规范；旧笔记的偏差在完成度检查（场景 D）中记录为待升级项，而非视为另一种合法格式。

## 工作流

### 场景 A：重构 Roadmap

对已有语言的 roadmap 做结构调整（改阶段切分、重排顺序、补全未展开阶段）：

1. 先读现有 `<语言名>.md` 与全部已有 ph 目录，列出「roadmap 承诺的阶段」与「磁盘实际存在的阶段」的差异清单
2. 确定新的阶段划分（数量、主题、顺序），与用户确认后再动手——重构 roadmap 是破坏性操作
3. 按新划分增删并改 ph 目录，重排编号保持连续
4. 更新 `<语言名>.md` 中全部阶段小节与 `📖 详细展开版见` 链接，保证链接与目录一一对应
5. 目录改名/迁移时，同步修正其他阶段笔记中的交叉引用。用以下命令找出全部引用点后逐个更新：
   ```bash
   # 找出引用了旧编号的全部笔记（以 ph04 为例，逐个旧编号执行）
   grep -rn "ph04" languages/ --include="*.md"
   # 复核：确认没有遗漏的悬挂相对链接
   grep -rn "](./ph" languages/ --include="*.md"
   ```
6. 提交前跑一遍完成度检查（场景 D）确认无悬挂链接

### 场景 B：重构/补全某个阶段

把已有阶段升级为四层完整交付物（知识文档 + 示例代码 + 代码练习 + 综合项目）：

1. 读对应语言的 Roadmap 总览，确认该阶段定位（前置阶段、为后续铺垫什么）
2. 评估现状：主文档章节是否齐全（对照 `references/phase-template.md`）、有无 examples/exercises/project
3. 补写或重写主文档，按模板章节结构执行
4. 补代码层（结构见下节「阶段代码层结构」）：
   - `examples/`：把文档中的代码片段提取为完整可运行文件
   - `exercises/`：每阶段 3~5 题，题目描述 + 参考实现分离（`exercises/README.md` 出题，`exercises/sol-*.ext` 给参考解）
   - `project/`：Roadmap「推荐项目」小节的落地，含 `project/README.md`（需求说明 + 验收标准）+ 完整源码
5. 所有代码本地编译/运行验证通过后再写入；文档中标注验证环境
6. 保持与同语言其他阶段的交叉引用（「属于 phXX 的内容，这里不展开」），编号变更后同步更新
7. 提交前跑一遍完成度检查（场景 D），确认本阶段四层交付物无缺口、无悬挂链接——编号变更后此步不可省略

### 场景 C：新增一门语言

1. 创建 Roadmap 总览 `languages/<缩写>/<语言名>.md`，模板见 `references/roadmap-template.md`
2. 规划阶段切分（按「阶段切分节奏」：基础 → 核心机制 → 生态/工程化 → 进阶专题），阶段数按语言复杂度定
3. 创建全部阶段目录骨架（至少含主文档占位）
4. 逐个阶段按场景 B 的标准填充四层交付物
5. 提交前跑一遍完成度检查（场景 D），重点做 roadmap ↔ 目录双向核对——批量新建时链接与目录名失配最常见

### 场景 D：完成度检查

分两层执行：**第 1~3 步是存在性检查**（全量、快速，只判"在不在"），**第 4 步是内容质量检查**（深检，判"对不对、全不全、齐不齐"）。被场景 A/B/C 作为提交前验收调用时，可只对本批涉及的目录跑深检。

1. 遍历 `languages/*/`，按四层标准逐项检查：
   - Roadmap 是否存在、其列出的每个阶段是否都有对应 ph 目录与有效链接（双向核对：roadmap → 目录、目录 → roadmap 小节）
   - 每阶段：主文档是否存在且章节齐全 / examples 是否存在 / exercises 是否存在 / project 是否存在
2. 输出完成度矩阵（语言 × 阶段 × 四层交付物），标注缺口。矩阵统一用以下格式：
   ```markdown
   ## 完成度矩阵（YYYY-MM-DD）

   图例：✅ 完整 | 🟡 存在但不完整 | ❌ 缺失

   | 语言 | 阶段 | 主文档 | examples | exercises | project | 备注 |
   |------|------|--------|----------|-----------|---------|------|
   | c    | ph01-basic-syntax | ✅ | ✅ | 🟡 只有 2 题 | ❌ | 练习需补到 3~5 题 |
   | c    | ph02-func-module  | ✅ | ❌ | ❌ | ❌ | |
   | …    | … | | | | | |

   ### 缺口汇总
   - <语言>/<阶段>：<缺什么、建议动作>
   ```
3. 顺带检查格式硬伤：表格列数一致、标题前空行、链接 `./` 前缀
4. **内容质量深检**（存在性全绿不代表合格，逐项核对）：
   - **文档章节完整性**：对照 `references/phase-template.md`，7 章是否齐全、顺序是否正确，边界声明（"不涉及 X，属于 phYY"）是否真有且指向的阶段编号存在
   - **Roadmap ↔ 阶段笔记内容对齐**：roadmap 的「学习内容/练习/推荐项目」与阶段笔记的 3 节内容、exercises 题目数、project 项目是否对得上，杜绝"roadmap 说做 A 项目、project/ 里却是 B"
   - **知识点覆盖核对**：阶段笔记 3.x 小节是否覆盖 roadmap 该阶段「学习内容」列出的全部知识点；有无漏讲、有无超纲讲了声明不涉及的内容
   - **代码时效性**：examples/exercises/project 的代码按文档标注的验证环境重新编译/运行一次，确认仍然通过——工具链升级后老代码可能已失效；题解分离是否保持（README 不泄答案、sol-* 与题目一一对应）
   - **交叉引用有效性**：全部 `phXX` 提及与相对链接（含「下一阶段」导航）逐一核实指向的阶段存在且主题对得上；首尾阶段的导航边界是否正确（首阶段无"上一阶段"、末阶段无"下一阶段"或明确标注终点）
   - **格式一致性**：对照「Markdown 排版规范」逐项核对（标题层级不跳级、表格列数、代码块语言标注、链接 `./` 前缀、术语写法统一等）
   - 输出格式：深检发现的问题并入缺口汇总，格式 `- <语言>/<阶段>：[深检] <问题>：<建议动作>`
5. 记录与本规范的偏差（旧章节命名、缺失代码层等），标记为待升级项，不作为新内容的参照

## Roadmap 总览规范（`<语言名>.md`）

必须包含的元素，按顺序：

1. **标题**：`# <语言> 语言学习 Roadmap`
2. **导语**（blockquote）：一句话说明这门语言的学习定位/应用方向（如 C 面向系统底层、KV 存储引擎）
3. **N 个阶段**（数量按语言复杂度定，与磁盘 ph 目录一一对应），每阶段固定小节：
   - `### 目标` — 一句话，可检验
   - `### 学习内容` — 知识点列表
   - `### 必会概念` — 核心心智模型列表（区别于"学习内容"，这里是必须内化的认知）
   - `### 示例` — 一段可运行代码或目录结构示意
   - `### 练习` — 3~5 个动手题
   - `### 阶段验收` — 自检标准（"能……"句式）
   - `### 推荐项目` — 1~2 个综合小项目
4. 每个阶段标题下方加链接行：`> 📖 详细展开版见 [phXX-主题/XX-主题.md](./phXX-主题/XX-主题.md)`

## 阶段详细笔记规范（`phXX-主题/XX-主题.md`）

必须包含的章节，按顺序：

1. `# <语言> <阶段主题>阶段` + 一句 blockquote 导语
2. `## 1. 概述` — 阶段定位 + 覆盖维度表格 + 边界声明（明确"不涉及 X，属于 phYY"）
3. `## 2. 来源与演变` — 该主题的历史背景、标准/版本演进表格、本文的基线说明
4. `## 3. 语法与参数` — 主体内容，3.1/3.2/... 小节展开，代码示例 + 表格为主
5. `## 4. 底层原理`（可选但推荐）— 该主题的实现机制/内存模型/编译器视角
6. `## 5. 使用场景`（推荐，存量笔记普遍有）— 该知识在真实工程中的用途、什么场景选它/不选它
7. `## 6. 代码示例` — 完整可运行示例（指向 `examples/` 目录中的文件，文档内嵌关键片段）
8. `## 7. 总结` — 关键要点回顾 + 阶段验收清单 + 指向 `exercises/`、`project/` 的入口 + `### 下一阶段` 导航链接（串联学习路径）

## 阶段代码层结构

每个阶段的代码交付物按此组织：

```
phXX-<主题>/
├── 01-<主题>.md
├── examples/                 # 文档示例的完整版
│   ├── README.md             # 每个示例一句话说明 + 运行命令
│   └── ex01-*.ext ...        # 可独立编译/运行
├── exercises/                # 代码练习
│   ├── README.md             # 题目列表：每题含目标、提示、验收标准（不附答案）
│   └── sol-01-*.ext ...      # 参考实现（与题目一一对应）
└── project/                  # 阶段综合项目
    ├── README.md             # 需求说明、功能清单、验收标准、扩展方向
    └── <项目源码>            # 完整可构建
```

规则：
- 练习题的参考实现必须与题目分离存放（README 出题，sol-* 给解），方便学习者先自己做
- `project/` 对应 Roadmap 该阶段「推荐项目」小节，选 1 个落地即可，不求全
- 代码风格与该语言社区主流规范对齐（如 C 用 `-Wall -Wextra` 零警告、Rust 过 `clippy`、Python 过 `ruff`）
- 编译型语言的 examples/project 附构建说明（Makefile/CMakeLists.txt/Cargo.toml 或 README 中的单行编译命令）

## 写作风格约定

- 语言：简体中文，技术术语保留英文原文（如 Translation Unit、ownership）
- 结构：多用表格对比维度，代码块带语言标注（```c / ```rust / ```text）
- 代码示例：必须可编译/可运行，带行内注释解释关键点
- 阶段隔离：每个阶段笔记自带边界声明，不超纲、不重复后续阶段内容
- 交叉引用：提到其他阶段时用 `phXX` 缩写格式（如"属于 ph02 函数与模块化阶段"）
- 基线明确：涉及标准/版本时，写明本文以哪个版本为基线（如"本文示例以 C99 为基线"）

## Markdown 排版规范

适用于 `languages/` 下全部 `.md` 文件（roadmap、阶段笔记、代码层 README）。场景 D 深检的「格式一致性」按本节核对。

**标题层级**
- `#` 仅用于文档主标题，全文档唯一（roadmap 是 `# <语言> 语言学习 Roadmap`，阶段笔记是 `# <语言> <阶段主题>阶段`）
- 阶段笔记章节固定 `## 1.` ~ `## 7.`，主文档内小节 `###`（3.1/3.2/...），最多用到 `####`，禁止跳级（`##` 后直接 `####`）
- 标题编号连续：数字 + 点 + 空格（`## 1. 概述`）
- **标题前必须留一个空行**——最常见的格式硬伤就是标题紧贴上一段正文（存量笔记曾全文档一致性地犯）。多数渲染器容错，但严格 CommonMark 解析器会把 `文字\n## 标题` 当段落延续；检查方法：`grep -B1 '^#' <file> | grep -v '^$'` 看有无紧邻行
- 章节内小节标题（如「### 示例 2」）同样适用空行规则，不能因是 `###` 就豁免

**段落与列表**
- 一段一个意思；超过 ~5 行的段落考虑拆成列表或表格
- 并列要点用无序列表 `-`；有顺序的步骤用有序列表 `1.`
- 列表缩进 2 空格一层；列表项内容较长时用「**加粗引导词**：内容」格式
- 中英文之间加空格（如「使用 ownership 管理内存」），数字与中文同理

**代码块**
- 一律带语言标注：```c / ```rust / ```text 等；目录结构、ASCII 图统一用 ```text
- 文档内嵌片段注明来源文件与验证环境（`// examples/ex01-*.c —— 一句话说明`）
- 多步命令块带序号注释，每步一条命令（如 `# 1. 编译期插入计数` / `# 2. 运行`），不要把无注释的编译+运行多行堆在一个块里
- 正文提到代码标识符、命令、文件名时用行内反引号（`gcc`、`main()`、`ph04-memory-mgmt/`）
- 「故意出错」的示例代码，块内首行注释必须写明运行前提（如 `/* 必须用 -fsanitize=address 编译运行, 否则勿运行 */`），防止读者裸跑出事故

**表格**
- 多维对比一律用表格，不用散文罗列；表头精简、单元格一行内写完
- 列数全表一致；前后各留空行

**引用块与提示**
- blockquote（`>`）固定用途：文档导语（一句话定位）、roadmap 的阶段链接行（`> 📖 详细展开版见 [...]`）、阶段内容隔离声明（「属于 phYY 阶段，这里不展开」）
- 代码示例章节开头的「运行前提/安全提示」说明（如"示例 1 必须加 -fsanitize 编译，裸跑有崩溃风险"）也允许用 blockquote——这是第四种合法用途，其他情况不要用
- 警告/易错点用 `> ⚠️` 或 `> **注意**` 引导，与正文区分

**图（mermaid / ASCII）**
- 流程图、时序图、状态机、结构关系图优先用 ```mermaid 代码块（GitHub、VS Code、Obsidian 均原生渲染）
- 简单线性流程、内存布局、编译管线等结构规整的图也可用 ```text ASCII 图（箭头统一用 `──▶` / `◀──` / `│` / `▼`），终端 `cat` 可读
- 选择原则：关系复杂（分支、循环、多对多）用 mermaid；线性/网格状布局用 ASCII 更紧凑
- mermaid 图节点文字用简体中文；图前用一句话说明图表达什么，图后解释关键路径
- ASCII 图内含中文时注意等宽对齐会错位（中文字符占 2 列），注释尽量放行尾用 `←` 引导、不参与对齐，或改用纯英文标注

**阶段笔记总结章节**
- 第 7 章的小节命名以 `references/phase-template.md` 为准（关键要点 / 阶段验收清单 / 动手练习 / 阶段项目 / 下一阶段）；自行发明的同义小节名（如「进入下一阶段前」「阶段验收标准」）视为与模板的偏差，场景 D 记录为待升级项
- 允许在模板小节之外追加小节（如「跨语言对比」——为 analysis/ 与 Tenet 合成积累素材时推荐追加），追加小节放在模板小节之间逻辑顺的位置即可

## 阶段切分节奏（新增/重构语言时参照）

| 区间 | 大致占比 | 内容性质 |
|------|---------|---------|
| 打基础 | 前 ~25% | 语法、核心数据类型、函数/模块化 |
| 核心机制 | 中 ~30% | 该语言区别于其他语言的核心机制（如 C 的指针/内存、Rust 的所有权、Python 的数据模型） |
| 生态与工程化 | 后 ~30% | 标准库/第三方生态、构建工具、测试、并发 |
| 进阶专题 | 末 ~15% | 应用领域专题（Web/数据库/系统编程）或深水区（UB/JVM/可移植性） |

总阶段数按语言复杂度伸缩。各语言当前实际切分以各自 roadmap 文件（`languages/<缩写>/<语言名>.md`）为准——skill 不维护任何语言的现状快照（现状会过期，规范不过期）。
