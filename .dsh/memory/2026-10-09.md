  - 5×5 四连追赶曲线：MCTS 50 次模拟 2:4 **落败**，1000 次 6:0 **反超**，4000 次仍是 6:0 但多花 3 倍时间
    （追平点成本比 9×，4000 次档 18×）
- 结论落成一句可判定的选择标准：**这棵树你还算不算得动**——
  算得动用 AB（同强度快一个量级），算不动用 MCTS（不保证最优，但时间预算内必给答案）

# 2026-10-09（续三）· 新增实验 `p01-search/uninformed-search` —— 补上路线清单缺的三个算法

基线：`main @ 9d4d2fd`（工作区未提交：本段记录的整批新增）

## 为什么做

场景 C 评估时发现：路线文档 2.2.1 列了八个"代表算法"，但 `p01-search` 只实现了后四个
（A\* / Minimax / Alpha-Beta / MCTS）；**DFS / BFS / UCS 三个没有实验**
（BFS 只作为对照存在于 a-star 的 `baseline.py` 里）。
而且它们是 A\* 的**前置**——没有它们，A\* 实验只能"自己跟自己比"。

## 交付

- `impl.py`：三个算法**共用一套主循环骨架**，只换"取出节点"的结构（栈 / 队列 / 堆）；
  统一返回 `SearchResult(path, cost, expanded, peak_frontier, order)`
- `baseline.py`：对照版——按路径加载 `../a-star/impl.py`（绕开同名模块遮蔽）
- `demo.py`：五组实验（小图取出顺序 / 无权图对照 / 带权图 / DFS 顺序依赖 / UCS vs A\*）
- `test_impl.py`：21 个用例，含 BFS 对 A\* 独立参考的差分验证、UCS 对 Bellman-Ford 式松弛的验证
- `make_teaching_assets.py` + 2 张图（扩展顺序热力图 / 代价与内存）
- `exercises/`：5 题 + 3 个可运行参考解（实跑记录进 README）
- `project/`：8 数码 IDA\*（`eight_puzzle.py`）
- README 两篇式（含 Mermaid 主循环）+ 索引登记（插在 A\* **之前**，体现学习顺序）

## 实测结论

- 无权图上 BFS 与 UCS **完全等价**（平均代价 38.4 = 38.4，扩展 267 = 267）
- DFS 扩展最少（143 vs 267，少 46%）但代价最大（62.4 vs 38.4，**多走 62%**）
- **DFS 的内存尖峰反而最大**（49 vs BFS 的 17）——推翻"DFS 省内存"的直觉
- 带权地形上 BFS 最差**贵 72%**（它保证步数，不保证代价）
- 同一图换邻接顺序，DFS 的步数在 **55 / 83 / 121** 间跳（2.2 倍）
- A\*(large_g) 比 UCS 少扩展 **41.5%**（h 的价值，为 a-star 实验做前置）
- 8 数码：IDA\* 11,419 节点 vs IDS 26,325（少 56.6%）；depth=14 单例上 309 vs 2,398,470（7,762×）
