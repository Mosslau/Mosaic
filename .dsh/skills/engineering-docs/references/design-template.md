# L2 方案设计模板

> 用于 `<platform>/方案设计.md`；也可作为"合体文档"的**上篇**（下篇为实施设计，见 `plan-template.md`）。
> **八节固定顺序，节名不得改**；缺的节保留标题并写"暂无"，不许默默删节。

---

```markdown
# <平台名> 方案设计

> 版本：v<N> · <待评审 / 已评审>
> 定位：<这个平台是什么；本文档回答什么（架构与选型），不回答什么（排期与验收，见实施设计）>

## 1. 定位与判据

<平台目标；平台级判据（结构判据 + 横切判据：什么样的架构才算成立）；与相邻域的边界>

## 2. 总体架构

<结构视图：分层 + 每层装什么；数据流视图：一条数据从源到消费的完整旅程；两条"读图要点">

## 3. 能力域与选型

<能力域划分（后续 L1 覆盖矩阵的行就是这里定义的域）+ 每个域的职责、首选/备选、成熟度依据>
<末尾必须有「明确不选」清单：不选什么、为什么不选>

## 4. 自研边界

<哪些必须自研（入口/胶水），哪些一律用开源；每块自研给复杂度量级>
<后置自研件：触发条件 + 启用前评审>

## 5. 契约与规范

<事件/接口契约、命名规范、幂等与错误枚举、参数规范、可照抄的模板>
<没有事件契约的平台写"本平台无事件契约"，并说明服务接口契约在哪定义>

## 6. 环境与规模假设

<部署形态（开发/生产、单机/集群）；规模档位（如 PoC / 试点 / 生产三档），并注明"假设值，何时回填">

## 7. 可用性与容灾口径

<每个组件的原生 HA 与数据保护能力；自研件的状态策略；备份/恢复原语；哪些留到生产化阶段>

## 8. 与仓库内其他域的关系

<复用哪些域、与哪个平台重叠、重叠处谁拥有；与 algorithms/ 的关系（如适用）>
```

---

## 写作要点

1. **本章不定排期**：出现"第几周""哪一期做什么"就说明内容放错了层——移到 L3
2. 第 ③ 节的域划分是后面所有覆盖矩阵的行定义，改名要同步 L1 矩阵与 L3 的单元说明
3. 第 ④ 节的"自研边界"必须可判定：看到一块新工作，能立刻判断它该不该自研
4. 每条选型给"成熟度依据"（TLP / 事实标准 / 社区活跃），并写"多久复查一次"
5. 合体形态：`## 上篇 · 方案设计` 下放本模板的 8 节，`## 下篇 · 实施设计` 下放 L3 的 8 节；两篇之间保持相对链接
