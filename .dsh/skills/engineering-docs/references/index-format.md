# L1 单元索引表格式规范

> 用于各平台 `README.md` 的「单元索引表」（L1 第 ② 节）。
> **列序是契约**：前 5 列的顺序与含义固定；附加列一律排在契约列之后。
> 表格之外出现的链接（依赖顺序表、文档地图、覆盖矩阵）不属于索引表，不按本规范解析。

## 契约列（前 5 列，顺序固定）

```markdown
| 编号 | 单元 | 一句话验收 | 状态 | 完成日期 |
|---|---|---|---|---|
| <01 或 P0> | [<单元名>](<编号-单元>/) | <一句话可检验目标> | ⬜/🚧/✅ | <YYYY-MM-DD 或空> |
```

规则：

- **编号**：与单元目录名前缀一致——**建设单元统一用 `P<编号>-`**（`P1`、`P2`…；`P0` 可作前置探针）。同一平台内唯一，**默认一族**；自研件不作为单元（见 SKILL.md 硬约定 1），确有独立单元时用 `G` 族并**按族分表**
- **单元**：相对本平台目录的目录链接，形如 `P1-text-corpus-pipeline/` 或 `P0-选型验证/`（带不带结尾 `/` 均可）。**该单元目录尚未创建时写纯文本、不造悬空链接**，并在附加列（如「目录」）里给出将来要建的目录名；目录一旦创建，必须改回链接
- **一句话验收**：可检验的目标，不写"基本可用"
- **状态**：与单元 README 首行状态符一致（不一致即硬伤）
- **完成日期**：✅ 必须填，且与单元 README 一致；⬜/🚧 留空

## 附加列（可选，必须排在完成日期之后）

平台可按需追加列，例如：

| … | 完成日期 | 形态 | 验收编号区间 | 开工后目录 |
|---|---|---|---|---|

- 附加列的列名与含义由各平台自定，但**不得插进前 5 列之间**；自研件（入口 / 胶水）不进本表——它们是单元的交付物，登记在承载单元的「交付物 / 目录导航」段
- 推荐附加列 **形态**（描述单元在这条路线里的角色，不改变单元性质）：`探针` 一次性连通性 / 兼容性验证｜`纵切` 一条端到端链路（可演示业务价值）｜`能力层` 横向能力（被多条链复用）｜`收口` 把已有链路做到生产级或集成为闭环｜`入口` 系统入口
- 平台级文档（方案设计 / 实施设计）不在本表登记，它们出现在 L1 的「文档地图」节

## 双向一致性

索引表与磁盘目录必须双向对齐：

- 磁盘上的单元目录（`[0-9][0-9]-*` 或 `P[0-9]-*`）必须在索引表里登记
- 索引表登记的单元必须有对应目录——**例外**：尚未开工的单元（状态 ⬜ 且附加列已写出将来要建的目录名）允许目录不存在，此时不参与双向核对；目录一旦创建，两向都必须对齐

## 解析失败处理

表格行中出现链接但不符合上述形态时，应记 🟡 警告而非静默跳过——看到此类警告先对照本规范检查列序（本规范是后续任何校验脚本的解析契约）。
