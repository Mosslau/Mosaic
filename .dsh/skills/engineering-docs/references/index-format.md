# L1 单元索引表格式规范

> 用于各平台 `README.md` 的「单元索引表」（L1 第 ② 节）。
> **列序是契约**：前 5 列的顺序与含义固定；附加列一律排在契约列之后。
> 表格之外出现的链接（依赖顺序表、文档地图、覆盖矩阵）不属于索引表，不按本规范解析。

## 契约列（前 5 列，顺序固定）

```markdown
| 编号 | 单元 | 一句话验收 | 状态 | 完成日期 |
|---|---|---|---|---|
| <01 或 P0> | [<单元名>](<编号-单元>/) | <一句话可检验目标> | ⬜/🚧/✅ | <YYYY-MM-DD 或空> |
```

规则：

- **编号**：与单元目录名前缀一致（系统类 `01`…`NN`；期类 `P0`…`P6`）。同一平台内唯一
- **单元**：相对本平台目录的目录链接，形如 `01-text-corpus-pipeline/` 或 `P0-选型验证/`（带不带结尾 `/` 均可）
- **一句话验收**：可检验的目标，不写"基本可用"
- **状态**：与单元 README 首行状态符一致（不一致即硬伤）
- **完成日期**：✅ 必须填，且与单元 README 一致；⬜/🚧 留空

## 附加列（可选，必须排在完成日期之后）

平台可按需追加列，例如：

| … | 完成日期 | 验收编号区间 | 开工后目录 |
|---|---|---|---|

- 附加列的列名与含义由各平台自定，但**不得插进前 5 列之间**
- 平台级文档（方案设计 / 实施设计）不在本表登记，它们出现在 L1 的「文档地图」节

## 双向一致性

索引表与磁盘目录必须双向对齐：

- 磁盘上的单元目录（`[0-9][0-9]-*` 或 `P[0-9]-*`）必须在索引表里登记
- 索引表登记的单元必须有对应目录

## 解析失败处理

表格行中出现链接但不符合上述形态时，应记 🟡 警告而非静默跳过——看到此类警告先对照本规范检查列序（本规范是后续任何校验脚本的解析契约）。
