# L4 单元定义模板

> 用于 `<platform>/<编号-单元>/README.md`（单元 = 系统 / 期 / 自研件）。
> **骨架固定，节名不得改**；可选段只有两个：「范围与不做」「目录导航」。其余新增段落须先改 `SKILL.md`。

---

```markdown
# <单元名>

> 状态：⬜ 未开始 | 🚧 进行中 | ✅ 已完成（YYYY-MM-DD）
> 所属平台与单元：<平台> · <编号> <单元名>（类别：系统 / 期 / 自研件）
> 对应文档：<上游文档相对路径，如 ../实施设计.md 或 ../../roadmap/<路线>.md>

## 目标

<这个单元解决什么问题？端到端输入输出是什么？一句话可检验>

## 范围与不做

- 范围：<本单元覆盖什么>
- 不做：<明确不覆盖什么、留给哪个单元/什么时候>（没有"不做"就写"无——原因"）

## 技术栈

<主框架、组件、基础设施，含版本基线；期类单元写"装什么">

## 系统架构

<模块划分与数据流向，配文字版架构图（```text ASCII 图）；期类单元画本期的链路>

## <前置与复用>

<段名按平台固定：
 - ai-platform：`## 复用的算法实验`——用到 algorithms/ 里哪些手写实验的原理/代码，带相对链接；没有就写"无"及原因
 - data-platform：`## 前置与复用`——依赖哪些上游单元/既有能力，带相对链接>

## 验收标准

- [ ] <全局验收编号> <可验证条目，"能……"句式>
- [ ] <……>

<编号引用 L3 的全局验证清单（如 V10 / A3）；✅ 门槛 = 全部打勾且每条有实测证据（命令 + 输入 + 观察结果）>

## 实施笔记

<关键决策、踩坑、版本坑、设计取舍；随手记不事后补，每条注明日期>
```

---

## 写作要点

1. **元信息头 3 行是契约**：状态符与索引表一致；编号与目录名前缀一致；`对应文档` 指向上游文档（路线 / 方案设计 / 实施设计）
2. 「验收标准」写成**能/不能**，不写"基本可用""尽量"；每条前面挂全局编号
3. 「系统架构」追求准确而非美观：模块方框 + 数据流向箭头即可
4. 单元内的真实产物（报告、脚本、部署清单、代码、实测记录）直接放在本目录，不另建无编号子目录
5. 单元内可加「目录导航」段（有子目录/代码时必写），格式：文件 × 角色 表格
