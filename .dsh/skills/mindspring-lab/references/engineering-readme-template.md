## 写作要点

1. 「系统架构」用图说话：模块方框 + 数据流向箭头，文字版图即可，不追求美观追求准确
2. 「验收标准」是状态推进到 ✅ 的门槛：全部打勾且每条有验证证据（三态声明）
3. 「复用的算法实验」是 MindSpring 的核心闭环——工程项目不是孤立的 Demo，是算法实验原理的工程化落地；写这一段时先翻 `algorithms/README.md` 索引
4. 「实施笔记」的复利最高：环境坑、版本坑、设计取舍，记给三个月后的自己看
5. 工程项目普遍依赖外部服务（Redis、向量库、GPU）——本机跑不了的部分如实标「未在本环境验证」，写清读者怎么补环境验证
