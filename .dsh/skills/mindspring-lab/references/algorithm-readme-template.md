- 「基础篇」：生活类比（开车导航）→ 核心量图 → 主循环流程图 → 小地图手算逐步表 → 白话版正确性 → 常见误区 → 自测清单

## 写作要点

1. **数学推导先行**：推导没写完不动手写 impl.py。推导段是给自己看的证明，不是装饰
2. 「设计原理」回答"为什么需要它"——放在演进路线里看（它取代了谁、被谁取代）
3. 「对照」段的重点是**差异原因分析**：框架多做了什么（向量化、正则化、数值稳定性），手写版差在哪
4. 「实验结果」的每个数字必须来自实际运行的输出；跑不了就标「未在本环境验证」并说明缺什么
5. 状态推进到 ✅ 的门槛：六段无占位、双跑对照有实数、验证声明三要素齐全（「基础篇」为推荐项，见 `validate.py --deep`）
6. **五级能力清单是骨架**：基础篇第 7 节的清单（说清 / 走通 / 判断 / 实现 / 迁移）决定练习与项目写什么；每级都要有可判定的检验方式
7. **基础篇的三条纪律**：自足（只读基础篇能走通）、不越界（不引入进阶篇没有的新结论）、数字单源（不复制「实验结果」的数字表，只给结论或指向）
8. **教学素材由脚本生成**：`images/` 下的图 / 流程图 / GIF 一律由 `make_teaching_assets.py` 产出，并断言与 `impl.py` 数字一致；流程图能用 Mermaid 写的就不出图（见 `visual-assets.md`）
9. **练习题解分离**：`exercises/README.md` 出题（四要素、不附答案）、`sol-NN-*` 给参考解；题目按五级能力分级，总量 5–8 题
10. **迁移项目是能力 5 的证据**：`project/` 至少一个可运行的小系统，README 必须有可判定的验收标准
