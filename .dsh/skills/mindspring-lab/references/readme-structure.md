# README 结构规范（两篇式）

> 用途：定义实验 README 的骨架、阅读路线与章节归属。
> 权威关系：本文件是**结构层唯一权威**；基础篇写法见 `learning-path-template.md`，进阶篇写法见 `advanced-track-template.md`，素材见 `visual-assets.md`。
> 读者：写实验文档的人，以及做场景 C 深检的人。

---

## 两条读者路径

结构的目的不是分篇，而是让两类读者**各自有一条能独立走完的路**：

| 读者 | 只读哪一部分 | 读完后能做到 |
|---|---|---|
| 零基础学习者 | 基础篇 | **能懂**（复述规则）· **能算**（手算小例子）· **能自测**（对照能力清单） |
| 复现 / 审查者 | 进阶篇 | **能推导**（跟着公式走）· **能跑**（按命令复现）· **能验证**（核对验证声明） |

由此推出两条硬要求：

1. **基础篇自足**：不依赖进阶篇的术语、公式与数字；零基础读者跳过进阶篇也能走通全部章节
2. **进阶篇自足**：不假设读者读过基础篇；符号自洽、命令可独立执行、结论有数据支撑

同一主题允许在两篇各出现一次，但形态必须不同（见「章节归属判定」）。

## 骨架

```markdown
# <算法名>

> 状态：⬜ 未开始 | 🚧 进行中 | ✅ 已完成（YYYY-MM-DD）
> 对应文档章节：`algorithms/docs/人工智能代表算法演进路线.md` 第 <X.Y.Z> 章
> 阅读路线：零基础读者读「基础篇」（生活类比 → 手算 → 白话证明 → 自测）；要看推导与复现实验读「进阶篇」

<可选：一句话声明算法族 + 目录的对外接口与文件形态；判据见「标题区那句接口声明」>

# 基础篇 · 先搞懂它

<!-- 必需内容七项；节数与切分自定（建议 7–9 节），编号从 1 起连续 -->

## 1. <生活类比：它解决什么问题>       ← 概念图
## 2. <核心量 / 一句话规则>             ← 概念图
## 3. <主循环>                         ← 流程图
## 4. <小地图手算示例>                  ← 分步图 + 逐步表
## 5. <白话版：为什么它是对的>
## 6. <常见误区>                       ← 对比图（如有）
## N. <能力清单 + 自测关卡>             ← 恒定收尾节；中间可插入「动起来看」「自己动手」等

# 进阶篇 · 实验档案

## 目录形态（本算法的"类型"）（可选，不计入编号）

## 1. 设计原理
## 2. 数学推导
## 3. 手写实现要点
## 4. 基线对照 | 框架对照（段名按算法族二选一）
## 5. 实验结果
## 6. 局限与延伸
```

固定约束：

- **编号在两篇都使用**：基础篇 `## 1.` 起连续编号；进阶篇六段固定 `## 1.`–`## 6.`；「目录形态」为可选段，若使用放在六段之前、不占编号（不用时，交付物入口写在「实验结果」或「能力清单」节）
- **六段式是硬契约**：1 设计原理 / 2 数学推导 / 3 手写实现要点 / 4 对照（框架或基线）/ 5 实验结果 / 6 局限与延伸；位置固定在「进阶篇」内、以 `##` 出现——`validate.py` 匹配时会剥掉编号前缀，编号与不编号两种写法都能校验
- 标题区三行 blockquote：状态 / 章节锚点 / 阅读路线（状态与锚点由 `validate.py` 核对）
- **跨节引用用内容名**，不用"第 N 节"（节数随实验浮动）：写「手算示例」节、「能力清单」节，不写"第 4 节"

## 族级导读 `algorithms/<pNN-族>/README.md`（推荐，族内 ≥3 个实验时写）

实验级 README 解决"这个算法怎么学"，但一个族长到三四个实验之后，
读者会缺一份**族级**的东西：这几个实验分别在解决什么问题、彼此什么关系、
该按什么顺序读。这份导读就放在族目录下。

**它不是什么**（避免职责重叠）：

| 文档 | 职责 |
|---|---|
| `algorithms/README.md` | **索引**：实验 ↔ 目录双向核对、状态与日期——唯一的现状快照 |
| `algorithms/<族>/README.md` | **导读**：问题形态分类、实验之间的演进与边界、阅读顺序建议 |
| `algorithms/<族>/<算法>/README.md` | **正文**：该实验的基础篇 + 进阶篇 |

**写作硬要求**：

1. **不重复维护状态**：状态与日期只在 `algorithms/README.md` 索引表里，导读最多给一个链接指过去
2. **不复制实验数字**：遵守「数字单源」——导读只写**结论**（如"节点最少 ≠ 总耗时最短"），
   不搬运实验结果段的表格（那种数字一旦在实验里改了，导读就会漂移）
3. **必须回答四个问题**：每个实验解决什么问题 / 靠什么机制 / **边界在哪** / 六个之间怎么演进
4. **给阅读顺序建议**：按"读者的目的"给分流（入门 / 做博弈 / 做扑克 / 做排班），而不只是一条线性列表
5. **写常见的误读**：把读者最容易搞反的三条点出来（如"MCTS 比 Minimax 先进"）
6. **在索引里留入口**：`algorithms/README.md` 的族标题下用 blockquote 指过来
   （blockquote 不属于索引表，`validate.py` 不解析，因此不会破坏四列契约）

**校验行为**：`validate.py` 的单元发现只 glob `algorithms/p[0-9][0-9]-*/*` 且要求 `is_dir()`，
所以族级 README **不会**被当成实验单元、也**不需要**在索引表登记；
它会被各实验单元的"反引号路径/链接存在性"检查覆盖到（相对路径写错同样会被抓出来）。

## 标题区那句接口声明（可选，但写就要写具体）

标题区三行之下可以加一句，声明**本实验属于哪个算法族、目录的对外接口长什么样**。
它与「各族文件首行 docstring 必须自陈族与接口」（见 `algorithm-families.md`）是同一条约定的
两个位置：docstring 面向改代码的人，这一句面向**打开 README 的读者**——尤其是只学过
`fit` / `predict` 那一套的零基础读者，他们要先知道在这个目录里该找什么。

**合格判据：下面四样里至少写到两样，并且写到的每一样都能在代码里点开核对。**

| 要素 | 说明 | 好的写法 |
|---|---|---|
| 族名 | 用 `algorithm-families.md` 五族总表的**原词** | 搜索求解器（搜索族） |
| 入口 | 调用什么、返回什么；写真实签名，不要写"由自身的形态决定" | `solve(grid, start, goal) -> SearchResult` |
| 文件形态 | 哪个文件扮演对照版，为什么是这个形态 | 对照在 `baseline.py`；没有 `framework.py`，因为没有可训练参数 |
| 交付物入口 | 练习 / 项目 / 素材生成器在哪 | 练习见 `exercises/`，项目见 `project/` |

对照样例（`algorithms/p01-search/a-star/README.md`）：

> 搜索求解器（搜索族）：入口是 `impl.py` 的 `solve(grid, start, goal) -> SearchResult`——吃一张地图
> 与起终点，吐路径、代价、扩展节点数；`baseline.py` 里放对照（Dijkstra）与独立 BFS 参考。
> **没有 `fit` / `predict`**（A* 没有可训练参数，也没有标签 y），所以本目录没有 `framework.py`。

**失效写法**（三个搜索族实验都写过同一个句式，属于"只说自己不是什么"）：

> 搜索求解器：本目录不是 sklearn 估计器，接口由 A* 自身的形态决定。

问题不在"错"，而在**读者拿不到任何可操作信息**：不知道入口函数叫什么、吃什么吐什么、
对照版在哪个文件、为什么没有 `framework.py`。**"不是 X"必须补上"是 Y"**，并且 Y 要能被验证。

> 用了本句就不要再开「目录形态」段重复列表；那一节是**可选**的——两者都会登记交付物入口，
> 选一处写清即可（见「基础篇 / 进阶篇骨架」与 `advanced-track-template.md`）。

## 章节归属判定

### 边界三测试

写下一个章节前先过三个测试，**任一条回答"是"就归进阶篇**：

| 测试 | 问什么 | 判"是"的例子 |
|---|---|---|
| ① 前置测试 | 这段内容是否假设读者已经知道某个术语或工具？ | 提到堆（heapq）、`f` 单调性、复杂度 |
| ② 目的测试 | 读它是为"建立直觉"还是为"复现与审查"？ | 复现命令、耗时、验证声明 |
| ③ 可判决性测试 | 它是解释，还是可证伪的陈述 / 证据？ | 实测数字（361→37）、最优性证明、失效反例 |

### 判定流程

```text
写下一个章节 →
├─ 需要前置术语 / 代码常识？ ──是──▶ 进阶篇
├─ 目的是复现 / 审查 / 证明？ ──是──▶ 进阶篇
├─ 含数字、耗时、复现命令？ ──是──▶ 进阶篇（数字只在「实验结果」出现一次）
├─ 服务于五级清单 1–3 级（说清 / 走通 / 判断）？ ──是──▶ 基础篇
└─ 只是"换个说法的直觉"？ ──▶ 基础篇；若与进阶篇重复且无新信息，删掉
```

### 三条硬规则

1. **数字单源**：实验数字（指标、耗时、扩展数…）只在进阶篇「实验结果」段维护一次；其余位置只给结论或指向，不复制表格
2. **基础篇不越界**：不引入进阶篇没有的新结论；引用实验数字时只给结论（如"多走 4 步"），不给表格
3. **进阶篇不假设前置**：公式符号在段内自洽定义；命令可独立执行；不出现"见基础篇"式的依赖

## 模板族书写约定

本 skill 的 references 按「层」分工，格式必须一致；新增或修改模板时遵守：

| 约定 | 规则 |
|---|---|
| H1 | 一个文件一个 H1，格式「<层>模板（<内容>）」或「<内容>规范」 |
| 抬头 | 紧跟 H1 的三行 blockquote：用途 / 权威关系 / 读者 |
| 一级章节 | **不编号**，用 `## <名称>`（与 `algorithm-families.md`、`index-format.md` 一致） |
| 编号位置 | 阿拉伯编号（`## 1.` / `### 1.1`）只出现在生成文档的 ` ```markdown ` 骨架内 |
| 每层章节顺序 | 骨架 → 逐项判据 → 写作要点 → 自查清单（+ 自含示例） |
| 表格与清单 | 表格统一用 `|---|` 分隔行；自查一律 `- [ ]`，要点一律有序列表 |
| 代码块 | 必须带语言标注（`markdown` / `text` / `python` / `bash`） |

## 与 markdown-style 的关系

- 本 skill 的 reference 文件遵守 `markdown-style`：单一 H1、ATX 标题、标题与代码块前后空行、代码块带语言、图片带 alt
- **显式豁免**：两篇式 README 生成物刻意使用 3 个 H1（文档标题 + `# 基础篇` + `# 进阶篇`）——这是"一份文档、两个读者入口"的结构设计；reviewer 不必重复报「多个 H1」
- 其余生成物（`exercises/README.md`、`project/README.md`）仍是单 H1

## 自查清单

- [ ] 零基础读者只读基础篇：能复述规则、能手算、能对照「能力清单」节自测
- [ ] 复现者只读进阶篇：能跟着推导走、能按命令跑出数字、能核对验证声明
- [ ] 每个数字只出现一次（在「实验结果」），其它位置全是结论或指向
- [ ] 六段齐全且都在 `# 进阶篇` 之下；标题区三行（状态 / 锚点 / 阅读路线）齐全
- [ ] 新写的章节能通过「边界三测试」归位，无两边都写同一层的重复内容
