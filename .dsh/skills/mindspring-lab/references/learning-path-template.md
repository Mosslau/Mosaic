# 学习路径模板（基础篇 / 能力清单 / 练习 / 项目）

> 用于 `algorithms/<pNN-族>/<算法名>/README.md` 的「基础篇」、`exercises/` 与 `project/`。
> 本模板回答一个问题：**怎样算"这个读者真的精通了这个算法"**——把答案写成可检验的关卡，而不是感觉。
> 进阶篇（设计原理 / 数学推导 / 实现 / 对照 / 实测）的模板见 `algorithm-readme-template.md`；素材规范见 `visual-assets.md`。

---

## 一、基础篇（README 前七节）

每节都有"完成判据"——写完自查，达不到就是没写完。

| 节 | 讲什么 | 必需素材 | 完成判据 | 常见失败模式 |
|---|---|---|---|---|
| 1. 生活类比 | 这个算法在解决什么麻烦；不出现术语 | 概念图 | 读者能用自己的话复述"它在解决什么" | 直接丢定义；类比与算法结构对不上 |
| 2. 核心量 / 规则 | 核心量是什么、怎么组合、规则一句话 | 概念图 | 读者能默写规则并解释每个量 | 一节塞进多个概念；量太多没有主次 |
| 3. 主循环 | 循环体、终止条件、数据结构（如"待办清单"） | 流程图 | 读者能按顺序复述循环，并说出何时结束 | 只写结论不写顺序；省略终止条件 |
| 4. 手算示例 | 一张能画在纸上的小地图/小例子，逐步执行 | 分步图 + 逐步表 | 读者能不看资料独立重走一遍 | 例子太大（>10 步）；数字与代码对不上 |
| 5. 白话正确性 | 为什么它是正确的（直觉版） | 可无图 | 读者能说出关键条件（如"不能高估"）与后果 | 抄进阶篇公式；只给结论不给理由 |
| 6. 常见误区 | 4–6 条"看起来对但错"的说法 | 对比图（如有） | 读者能识别错误说法并纠正 | 罗列无痛点的注意事项 |
| 7. 能力清单 + 自测 | 本实验的五级清单 + 3–6 条自测关卡 | — | 每条自测都能判定"过 / 不过" | 写"理解了"这类无法检验的描述 |

写作要点：

- 第 4 节的手算示例要**可复算**：示例数字必须能用 `impl.py` 或生成脚本复现（场景 C 会核对）
- 第 7 节的自测关卡优先写成**预测型**（"把 X 改成 Y，结果会怎样？"），再让读者跑实验验证
- 基础篇不复制进阶篇的数字表：只给结论或指向（数字单源）

## 二、五级能力清单（第 7 节的核心内容）

五级是通用定义，每个实验要把它**具体化**为本算法的版本。示例（A*）：

| 级别 | 通用定义 | A* 的具体化 | 检验方式 |
|---|---|---|---|
| 1 说清 | 讲清问题与规则 | 说出 g / h / f 各是什么，规则是"取 f 最小" | 复述 + 解释哪个量是估计值 |
| 2 走通 | 纸上手算小例子 | 5×5 地图九步手算，能说出"为什么挑它" | 不看资料重走一遍 |
| 3 判断 | 说清正确性条件与边界 | 说出"h 不能高估"的理由，并给一个会高估的坏例子 | 举反例 |
| 4 实现 | 手写并与对照比对 | 跑通 `demo.py`，解释扩展数差异的来源 | 复现实测数字 |
| 5 迁移 | 用到新问题 | 给 8-puzzle 或地形代价地图写一个 A* | `project/` 验收 |

**检查表**（写完后自查）：

- [ ] 每一级都有"检验方式"，且检验方式是可判定的（不是"理解了"）
- [ ] 1–4 级在 README 内有对应段落（分别在基础篇 1–5 节与进阶篇实测）
- [ ] 5 级由 `project/` 承载，项目的验收标准能判定是否达成
- [ ] 五级清单与练习分级一致（见下）

## 三、练习（`exercises/`）

### 目录形态

```text
exercises/
├── README.md            # 出题：每题四要素，不附答案
├── sol-01-<slug>.md     # 参考解（概念/推导类）
├── sol-04-<slug>.py     # 参考解（代码类，可运行）
└── ...
```

### 出题四要素（每题都要有）

1. **目标**：这题练哪一级能力（1–5）
2. **要求**：具体做什么（改哪个文件 / 算什么 / 写什么）
3. **验收标准**：怎么算通过（可判定，如"输出代价与 Dijkstra 一致"）
4. **提示**：卡住时看什么（不给答案）

### 分级要求

| 级别 | 题目形态 | 数量 |
|---|---|---|
| 1 说清 | 复述/解释题（不看资料写出核心量或规则） | ≥1 |
| 2 走通 | 手算题（换一张小地图，逐步表格） | ≥1 |
| 3 判断 | 诊断题（给错误变体，找失效原因 + 反例） | ≥1 |
| 4 实现 | 变体实现题（新约束下改 `impl.py`，与对照对拍） | ≥1 |
| 5 迁移 | 应用题（换成另一个问题，如 8-puzzle / 地形代价） | ≥1 |

练习总量 5–8 题；难度递增，**题面绝不附答案**，参考解放 `sol-NN-*` 且一一对应。

### 参考解要求

- 代码类参考解可独立运行（`python sol-04-*.py`），内置自检（与对照实现对拍或断言已知结果）
- 概念类参考解用最少的字给要点，不复制 README 整段
- 参考解跑过的证据写进 `exercises/README.md` 末尾（命令 + 观察结果）

## 四、迁移项目（`project/`）

### 目录形态

```text
project/
├── README.md            # 需求 / 功能清单 / 验收标准 / 扩展方向 / 运行方式
└── <源码>               # 可构建、可运行；输出结果写入 README
```

### README 必须回答

1. **需求**：把算法迁移到什么场景？与教学示例的差别是什么（新约束：八邻域 / 地形代价 / 新目标函数…）
2. **功能清单**：做到哪几件事（可勾选）
3. **验收标准**：可判定条目，例如"在地形代价地图上找到的路径总代价 ≤ Dijkstra 的 1.0 倍且扩展数更少"
4. **扩展方向**：往哪继续做（换启发式 / 加时限 / 并行）
5. **运行方式**：命令 + 依赖 + 预期输出（含实测结果）

### 项目是能力 5 的证据

项目验收通过 = 迁移能力达成。**没有项目的实验，五级清单最多只能打到 4 级**——这是场景 C 里"✅ 却无项目"提示的含义（推荐项，不阻塞 ✅）。
