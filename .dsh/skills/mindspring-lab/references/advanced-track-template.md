# 档案层模板（进阶篇 · 实验档案）

> 用途：写 `README.md` 的「进阶篇」——设计原理、推导、实现、对照、实测与边界。
> 权威关系：结构与章节归属见 `readme-structure.md`；基础篇见 `learning-path-template.md`；素材见 `visual-assets.md`。
> 读者：复现 / 审查者——只读进阶篇要能推导、能跑、能验证。

---

## 骨架

```markdown
# 进阶篇 · 实验档案

## 目录形态（本算法的"类型"）（可选，不计入编号）

## 1. 设计原理
## 2. 数学推导
## 3. 手写实现要点
## 4. 基线对照 | 框架对照（段名按算法族二选一）
## 5. 实验结果
## 6. 局限与延伸
```

## 逐段判据

| 段 | 写什么 | 完成判据 | 常见失败模式 |
|---|---|---|---|
| 目录形态（可选） | 文件 × 角色 × 接口表（含 `exercises/`、`project/`、生成器） | 每个交付物都有入口 | 只列三件套，练习与项目没登记 |
| 1. 设计原理 | 它解决什么问题、核心思想、在演进路线里的位置 | 读者能说出"它取代了谁、被谁取代" | 直接讲实现；看不出为什么需要它 |
| 2. 数学推导 | 关键公式与推导；正确性条件（如可采纳性 / 一致性） | 推导能复算，符号与 `impl.py` 变量对应 | 推导真空；只有名词罗列 |
| 3. 手写实现要点 | 关键步骤、坑、数据结构选型理由与安全边界 | 读者能照着复现实现 | 贴代码不解释；不写已知边界 |
| 4. 对照 | 与框架 / 基线比什么、差异的**原因** | 差异分析到位，不是只贴数字 | 只给"手写更慢"这类结论 |
| 5. 实验结果 | 环境与种子、指标表、复现命令、验证声明、可视化结论 | 数字来自实跑；验证声明三要素齐全 | 结果空话；数字与素材对不上 |
| 6. 局限与延伸 | 边界、失效场景、引出的后续算法（相对链接） | 每条是一个方向 + 理由 | 只写"还有待完善" |

## 写作要点

1. **数学推导先行**：推导没写完不动手写 `impl.py`——推导段是给自己看的证明，不是装饰
2. 「设计原理」回答"为什么需要它"：放在演进路线里看（它取代了谁、被谁取代）
3. 「对照」段的重点是**差异原因分析**：对照版多做了什么（向量化、正则化、数值稳定性），手写版差在哪
4. 「实验结果」的每个数字必须来自实际运行的输出；跑不了就标「未在本环境验证」并说明缺什么
5. **数字单源**：数字只在本段出现一次；基础篇与其它段引用时只给结论或指向（规则见 `readme-structure.md`）
6. 「目录形态」是**可选**段：用与不用都合规。若使用，表要随目录一起长——新增 `exercises/`、`project/`、生成器后同步登记；若不用，交付物入口写在「实验结果」或基础篇「能力清单」节
7. ✅ 的门槛：六段无占位、双跑对照有实数、验证声明三要素齐全（基础篇 / 练习 / 项目为推荐项，见 `validate.py --deep`）

## 自查清单

- [ ] 六段齐全、顺序正确（1–6 编号）、位于 `# 进阶篇` 之下
- [ ] 「数学推导」能复算，符号与 `impl.py` 变量对应，正确性条件写明
- [ ] 「对照」段有差异原因分析，不是只贴数字
- [ ] 「实验结果」含环境与种子、复现命令、验证声明三要素
- [ ] 全部交付物（练习、项目、素材生成器）在 README 中有入口——「目录形态」段或「实验结果」/「能力清单」节，二选一
- [ ] 全部数字只在「实验结果」出现一次（数字单源）

## 自含示例

- 「实验结果」段：`地图参数：21×21 网格，30% 障碍率，固定种子保证连通` + 指标表（路径长度 47 vs 47 → 最优性断言通过；扩展节点 214 vs 239 → 启发式收益量化）+ `复现方式：python3 demo.py`
- 「局限与延伸」段：每条是一个方向 + 一句话理由 + 相对链接（如 `../<后续算法>/`），把实验串成学习路径
- 耗时类数字标注 `[随环境/版本变化]`，避免被当成永久事实
