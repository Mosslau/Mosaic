**通用数据平台 + AI 平台数据中心。**

把三件事放进同一个仓库：**怎么造语言工具**、**怎么让机器变聪明**、**怎么把系统真正跑起来**。

## 结构判断：不是拼图，是梯子

```text
roadmap（目标函数）      ← 60 个月、四轨、三条职业叙事
      ↑
engineering（主线）      ← 154 篇文档、3.9 万行设计、0 实现   ← 卡在这里
      ↑
languages + algorithms   ← 已封顶，边际收益接近 0
```

[`languages/`](languages/) 1173 篇 md、2325 个代码文件，已经封顶，再做是自我重复；[`algorithms/`](algorithms/) 42/42 完成，是一个完成态的资产。**真正的问题不在底层，在中间那级：主线是 engineering，而 engineering 是空的。**

`engineering/` 唯一的可运行代码是整体迁入的 [`python-agent-runtime`](engineering/ai-platform/agent-platform/agent-service/python-agent-runtime/)（165 项测试），不是在本仓库建起来的；两个平台的 24 个 D 阶段一个都没验收。

所以这个仓库真正缺的不是知识（已经过剩），是**一次真实的、有人用的、有数字的落地**。有了它，职业叙事和对外影响力都会自动打开；没有它，它就停在一份很好的学习档案。

## 校验

一条命令跑全部，各域使用自己的运行环境与 pytest 配置：

```bash
./verify.sh          # 文档契约 + 算法测试 + Agent 运行时
./verify.sh --site   # 追加语言域文档站构建（需网络）
```

退出码：`0` 全部通过 / `1` 有域失败 / `2` 无失败但有域跳过（跳过的域不算通过）。

## 边界

`languages/` 承载**语义与教学**（"应该怎么做、为什么"），`engineering/` 的目标是**真实系统与真实指标**（"跑起来是什么样"）。同一个概念在两处出现时，前者讲清纪律，后者交付可运行的实现与实测数字——不重复造文档。

**状态以各域 README / 设计文档为准；未实现的不按"已跑通"叙述。**

## 为什么叫 Mosaic

三块各自独立的图块拼成一张完整图景：语言、算法、工程。每块可以单独看，合起来才是全貌。
