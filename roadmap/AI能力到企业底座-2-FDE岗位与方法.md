## 2.1 岗位定义

**把客户现场的真实问题，转化为可运行、可验证、可复用的系统。**

定义公式：

> 现场理解 × 工程实现 × 业务闭环 × 产品沉淀

四个因子是乘号，不是加号 —— 任何一项为零，整条链路归零。

## 2.2 五步工作流（含交付证据）

| 步 | 动作 | 关键动作 | 交付证据 |
|---|---|---|---|
| 01 | 进入现场 | 观察真实用户、流程与目标 | 现场场景图（用户、流程、目标三张清单的合称） |
| 02 | 拆清约束 | 厘清数据、权限、成本与卡点 | 约束清单 |
| 03 | 原型验证 | 用最短路径验证关键假设 | 可试用原型 |
| 04 | 系统接入 | 接入业务流程，验证真实使用 | 上线工作流 |
| 05 | 结果复盘 | 评估效果，把反馈变成产品能力 | 指标与产品建议 |

闭环：05 之后有一条**「反馈进入下一轮」**的回流箭头指回 01，形成螺旋，而不是一次性交付。

## 2.3 能力、适用场景与验收

**岗位需要的能力**

- 业务理解与问题拆解
- 快速开发与系统集成
- 跨团队协作与结果复盘

**哪些场景需要 FDE**

- 需求仍有较高不确定性
- 数据、权限与系统需整合
- 现场反馈能持续改进产品

**如何判断闭环成立**（三条同时成立才算）

- 真实用户在用
- 业务指标可验证
- 经验能复用

**交付标准**

> 可用工作流 + 使用证据 + 业务结果 + 产品洞察

## 2.4 进入企业技术过程（8 阶段工程闭环）

从环境接入到持续迭代，构建企业 AI 能力的工程闭环。每个阶段先给流程链路，再列关键活动与技术要点。

阶段之间存在三个判断点：阶段 2 的「是否确定首个场景」（否 → 回到业务梳理）、阶段 6 的「效果是否达标」（否 → 回到真实环境试运行）、阶段 8 的「是否有新场景」（是 → 新场景 / 否 → 结束）。

### 阶段 1 · 企业技术环境接入

流程：`开始` → 对接企业 CIO / IT / 业务负责人 → 梳理企业 IT 架构与现状 → 确认网络、权限、安全与部署环境。

关键活动与技术要点：

- 网络拓扑（内网 / DMZ / VPN）
- 身份认证（AD / LDAP / SSO）
- 现有系统（ERP / MES / CRM / PLM / OA 等）
- 服务器与容器环境（VM / K8s）
- 安全与合规要求

### 阶段 2 · 业务与技术诊断

流程：梳理业务流程与痛点 → 分析数据、系统、人工流程 → 评估技术可行性与 ROI → **是否确定首个场景？**（否 → 回到流程梳理；是 → 进入阶段 3）。

关键活动与技术要点：

- 业务流程梳理
- 痛点与机会识别
- 数据与系统现状分析
- 选择高价值 AI 应用场景

### 阶段 3 · 数据与知识接入

流程：连接企业数据源（DB / API / 文件）→ 数据清洗与标准化 → 构建企业知识库与数据中台 → 建立业务对象与数据映射（企业本体 Ontology）。

关键活动与技术要点：

- 数据库连接（MySQL / Oracle 等）
- API / MCP / 文件接入
- 数据清洗与标准化
- 字段语义与业务映射
- 企业知识库 / 向量库
- 构建业务对象与关系（Ontology）

### 阶段 4 · AI 技术架构搭建

流程：选择大模型与部署方案 → 搭建模型服务层（Model Service）→ 构建 RAG 与知识服务 → 设计 Agent 架构与工具体系（Tools / MCP）。

关键活动与技术要点：

- 模型选型与路由（云 / 本地 / 混合）
- Embedding / Rerank / Model Routing
- RAG 与知识检索
- Agent 架构设计（Planner / Reasoning）
- Tool 集成（MCP / API / SDK）

### 阶段 5 · 业务场景开发

流程：设计业务流程与解决方案 → 开发 Agent / Copilot 与工作流 → 对接企业系统（ERP / MES / CRM 等）→ 完成功能开发与内部测试。

关键活动与技术要点：

- 基于真实业务流程开发
- Agent / Workflow 实现
- 系统集成（API / MCP / RPA）
- 功能开发与单元测试
- 业务规则与权限控制

### 阶段 6 · 现场验证

流程：在真实环境中试运行（真实数据 / 真实用户）→ 收集使用反馈与业务数据 → **效果是否达标？** → 不达标走优化调整（模型 / 数据 / 流程）再回到试运行；达标进入阶段 7。

关键活动与技术要点：

- 真实业务场景验证
- 准确率 / 响应速度 / 使用率
- 业务效果评估（效率 / 成本 / ROI）
- 问题收集与优化调整

### 阶段 7 · 生产环境上线

流程：部署到生产环境（灰度发布）→ 配置权限与安全策略 → 建立监控与告警（日志 / 审计）→ 正式上线与用户推广。

关键活动与技术要点：

- 灰度发布与全量上线
- 权限控制与数据安全
- 模型监控与日志审计
- 稳定性保障与应急预案
- 用户培训与推广

### 阶段 8 · 持续迭代与优化

流程：持续收集使用数据与业务反馈 → 分析问题与优化点 → 迭代优化（模型 / Agent / 场景）→ **是否有新场景？**（是 → 新场景；否 → 结束）。

关键活动与技术要点：

- 使用数据分析与效果评估
- 模型与流程持续优化
- 扩展应用场景
- 建立长期运营与支持机制
- 推动企业 AI 能力不断进化

## 本篇与其他三篇的接口

- **承接第一篇**：五步工作流要的能力，正好落在 L6「工作流玩家」到 L8「业务重构者」这一段；没有 L5–L6 的流程手感，进现场只能做访谈。
- **衔接第三篇**：这 8 个阶段与第三篇的「企业五阶段」是同一件事的两种切法 —— 8 阶段是**单个项目的交付视角**，五阶段是**企业整体建设的视角**。阶段 1–2 对应五阶段的一、二，阶段 3–5 对应三，阶段 6–8 横跨四、五。
- **依赖第四篇**：阶段 3 的数据与知识接入，实际要落到数仓 / 数据湖 / 数据中台的具体件上；数据侧不通，阶段 4 之后的 RAG 与知识库都是空转。
