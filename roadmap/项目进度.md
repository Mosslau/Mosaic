### 前两步缺陷审计整改（2026-09-18，第四轮）

> 起因：对第 1、2 步做整体评估时，对"已标 ✅"的结论逐条复验，发现 10 项实现层面缺陷。
> 修复明细见《接入层设计》§13 增补㉔；下表只记"改了什么、怎么验证的"。

| 类别 | 缺陷（修复前实测） | 处置 | 验证 |
|---|---|---|---|
| **P0 丢数据** | codec flush 写失败/提交失败后仍清空缓冲 → 下次成功 flush 提交更高位移，该批**永久静默丢失**（DLQ 与指标都不涨） | 改为"写出成功 == 提交成功才清空"，失败保留 + 有界退避重试；新增 `codec_flush_failures_total`/`codec_pending_messages` | 单测覆盖全部失败路径（`cmd/server` 0%→37%）；真实 Kafka 硬停实测：`pending_messages` 稳定保留 11 条、失败计数递增、恢复后补写且对账平衡 |
| **P0 假受理** | 网关 `Async:true` → 202/204 早于任何持久化，失败只计数；kafka-go 内部队列无上限（断连期 OOM） | 改**同步投递**（broker 确认后才 202/204）+ 有界重试 | `kafka_write_total{result=error}` 可达、handler 返回 5xx；单测断言"失败必须返回 error" |
| **P0 部署** | Kafka 数据落在容器可写层（`log.dirs=/tmp/kafka-logs`），挂载的卷是死配置 → `down`+`up` 丢全部 topic 与位移 | 显式 `KAFKA_LOG_DIRS=/var/lib/kafka/data` | `down`+`up` 与**引擎重启**后 topic/位移/标记消息全部存活 |
| **P1 安全** | 载荷 VIN 可覆盖 topic VIN（JSON 通道）、帧内 VIN 覆盖信封 VIN（codec）→ EMQX ACL 可被绕过，可伪造他人车辆数据 | 网关强制"载荷 VIN == topic VIN"，不一致 400 | 实测：越权请求由"204 且以他人 VIN 落 Kafka"变为 400 |
| **P1 安全** | 两条 webhook 通道**完全没挂限流**（文档却写"仅全局"）；webhook 密钥非常量时间比较 | 补全局令牌桶 `GlobalWrap` + `crypto/subtle` 比较 | 实测限流生效（20×429 / 34×204） |
| **P1 可用性** | `RATE_PER_DEVICE=0.5`（合法配置）→ 令牌桶容量 0 → x/time/rate 恒拒 → **全量 429** | `config.Load()` fail-fast + `burstFor()` 兜底 ≥1 | 单测覆盖小数速率与非法值 |
| **P1 部署** | 六服务零 `restart:` 策略 → 引擎/宿主重启后容器不自愈（实测 Exited 137） | `restart: unless-stopped` + `mem_limit` + 日志轮转 | 引擎重启后无需人工干预即 6/6 healthy |
| **P1 安全** | 六个服务全部 `0.0.0.0` 发布，含弱口令组件（EMQX Dashboard/Grafana） | 宿主端口统一改绑 `127.0.0.1` | 容器间通信与文档命令不受影响 |
| **P1 安全** | EMQX 节点名随容器 IP 变化（镜像 entrypoint 覆盖 `node.name`）→ 换 IP 即换空 mnesia → 一车一密静默失效 | 固定 `EMQX_NODE__NAME=emqx@127.0.0.1` | 容器重建后凭证存活（201 条）；`security-check` **六项全过** |
| **P2** | `/metrics`+`/debug/pprof` 暴露在业务端口且监听全网卡；限流器 `Close()` 非幂等；dev 模式限流桶 key 无界 | metrics 独立端口、pprof 仅回环、`Close()` 幂等 + 桶容量上限 | 实测业务端口 404 / 指标端口 200 / pprof 仅 127.0.0.1 |
| **文档** | 《GB32960 映射》§5 表 `voltage`/`current` 来源误写 0x01（实现只从 0x08 取）；DLQ stage 枚举三处不一致；指标 HELP 漏枚举；面板 p95 标题不实 | 全部按实现校正 | `scripts/check-docs.sh` 全绿（并修好该脚本对"修订记录"历史行的误报）；新门禁挡住配置项数漂移 |
