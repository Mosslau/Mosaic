# 05 · 上下文管理器（with 语句）

> demo: `python3 demos/05_context_managers.py`

## 1. 设计动机

打开文件忘了关？加锁忘了释放？这类"进入/退出配对"的资源管理
在 C 里靠纪律，在 C++ 里靠 RAII。Python 的命题：
**用 `with` 语句把"进入时准备、退出时清理"变成语言机制**——
`__enter__`/`__exit__` 协议保证清理代码一定执行，无论中途是否异常。

## 2. 机制拆解

```python
with open("data.txt") as f:    # 进入：__enter__ 返回文件对象
    data = f.read()            # 使用
# 退出：无论正常/异常，__exit__ 都会关闭文件
```

**等价展开**（让机制透明）：

```python
f = open("data.txt").__enter__()
try:
    data = f.read()
finally:
    f.__exit__(None, None, None)   # 异常时传入异常信息
```

**为什么优于 try/finally 手写**：配对逻辑（`__enter__`/`__exit__`）
封装在对象里，调用方永远写不错——**资源管理是"协议"，不是"纪律"**。

**contextlib**：用生成器写上下文管理器（`@contextmanager`），
`yield` 前后就是进入/退出。

## 3. 代码验证（demos/05_context_managers.py）

demo 演示：文件自动关闭、自定义 `Timer` 上下文管理器、异常时清理仍然执行。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 多一层抽象 | `with` 到底做了什么，新手要理解协议 |
| 协议约束 | `__exit__` 返回值语义（吞异常）易误用 |
| 嵌套膨胀 | 多个资源嵌套 `with` 缩进变深 |

**换来的**：资源泄漏从"纪律问题"变成"不可能"；代码比 try/finally 短且不可能写错。

## 5. 对 Tenet 的启示

- ✅ **吸收"清理是机制不是纪律"**：Tenet 解释器的环境（Env）离开作用域自动回收
  （Rc/引用计数），与 `with` 的"退出必清理"是同一个哲学——只是 Tenet 用
  运行时自动管理，连 `with` 语法都不需要
- ✅ **吸收"配对操作封装成协议"**：Tenet 的函数调用（进入）与返回值处理（退出）
  由语言统一管理，用户不需要手动配对
- ❌ **拒绝 with/上下文管理器语法**：教学语言无外部资源（文件/网络/锁），
  "退出清理"由解释器自动完成，语法成本为零
- 💡 若未来加文件 IO，再考虑 with 风格，而不是让用户手写 open/close

**一句话**：Python 用 `with` 把资源清理变成语言保证；Tenet 用「作用域 +
引用计数」在解释器内部完成同样的保证，用户甚至感知不到它的存在。
