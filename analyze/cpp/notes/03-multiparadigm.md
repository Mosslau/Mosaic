# 03 · 多范式设计（Multi-paradigm）

> demo: `make && ./demos/03_multiparadigm`

## 1. 设计动机

大多数语言绑定一种范式（Smalltalk 纯 OOP、Haskell 纯函数式）。
C++ 的命题：**一门语言同时容纳过程式、OOP、泛型、模板元编程、函数式，
让每种问题用最合适的范式解决**。代价是语言复杂度急剧膨胀。

## 2. 机制拆解

同一段逻辑，C++ 可以有多种范式表达：

| 范式 | 工具 | 风格 |
|------|------|------|
| 过程式 | 函数、全局状态、指针 | C 遗产 |
| 面向对象 | class、继承、虚函数 | 数据 + 行为捆绑 |
| 泛型 | template | 编译期类型参数化 |
| 模板元编程 | 模板特化 + constexpr | 编译期"计算" |
| 函数式 | lambda、std::function、ranges | 无副作用的组合 |

**关键特性**：范式之间可以**混用**——一个类里可以有虚函数（OOP）、
模板成员（泛型）、lambda（函数式）。这是 C++ 最灵活也最危险的地方：
没有"唯一惯用法"，团队必须自己约定风格。

## 3. 代码验证（demos/03_multiparadigm.cpp）

demo 里同一个"求和"用过程式、OOP、泛型、函数式四种写法实现，输出相同。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 范式大杂烩 | 同一代码库风格分裂，读代码要先判断范式 |
| 学习曲线陡 | 每种范式是一整套心智模型（仓库 lang/cpp 笔记标注"学习曲线高"） |
| 组合爆炸 | 范式交互的坑（如模板 + 继承 + 虚函数）极难排查 |

**换来的**：表达力上限极高；每种问题都有合适的范式；三十年积累的生态。

## 5. 对 Tenet 的启示

- ✅ **吸收"选择范式要克制"的教训**：C++ 的混乱正是"什么都能做"的代价——
  Tenet 刻意**只有一种惯用法**：语句 + 表达式 + 函数，别无其他
- ✅ **吸收"每个特性要有明确职责"**：Tenet 的 4 种语句、7 种表达式
  每个都只干一件事，没有重叠
- ❌ **拒绝多范式并存**：教学语言要"少即是多"；这正是 Go 语言从 C++ 学到的
  教训（Go 同样刻意砍掉继承、泛型等特性，后来才补回泛型）
- 💡 演进时坚持"一个特性解决一个问题"，不要叠加

**一句话**：C++ 证明"范式多 = 灵活但复杂"；Tenet 选择 Go 的路线——
「少特性、一种惯用法」，用克制换取可读性。
