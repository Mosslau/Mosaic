# 04 · STL 设计（容器 / 迭代器 / 算法解耦）

> demo: `make && ./demos/04_stl`

## 1. 设计动机

传统容器库把"数据结构"和"操作"绑在一起（Java 的 `Collections` 静态方法、
Python 的列表方法），每加一种容器就要重复实现所有操作。
STL 的命题：**把"数据存放"（容器）、"遍历方式"（迭代器）、"通用操作"（算法）
三者解耦，让一个算法适用于所有容器**。

## 2. 机制拆解

三个层次，靠**迭代器**这座桥连接：

```cpp
std::vector<int> v = {3, 1, 2};
std::sort(v.begin(), v.end());     // 算法 sort 不认识 vector
std::set<int> s = {3, 1, 2};       // 换容器，算法不变
// std::sort 在 set 上不适用（只读迭代器）——类型系统自动拒绝
```

- **容器**（vector/list/map/set）：负责存储，暴露 `begin()`/`end()`
- **迭代器**：统一"访问序列"的接口（`*it` 取值、`++it` 前进）
- **算法**（sort/find/count/accumulate）：只依赖迭代器接口，不认识具体容器

**组合 > 继承**：STL 没有"所有容器的基类"，而是通过迭代器约束（概念）连接——
一个算法能用哪些容器由迭代器能力（随机访问/双向/单向）决定。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 抽象难懂 | 迭代器概念、begin/end 半开区间是学习门槛 |
| 报错信息差 | 模板算法类型不匹配时错误信息海啸 |
| 调试困难 | 算法内部是黑盒，断点难下 |

**换来的**：算法一次实现、处处复用；容器可替换；组合而非继承。

## 5. 对 Tenet 的启示

- ✅ **吸收"数据与操作解耦"**：Tenet 的 `print` 是内建函数而非对象方法——
  操作（打印）与数据（4 种标量）分离，正是 STL 思想的极简版
- ✅ **吸收"接口约束而非继承"**：Tenet 的函数调用只看"名字 + 参数个数"，
  不依赖类型层次——与 STL 的"算法只依赖迭代器接口"同理
- ❌ **拒绝迭代器/泛型算法**：Tenet 只有 4 种标量 + 一种容器（字符串），
  解耦的收益远小于语法成本
- 💡 若未来加数组，优先设计"统一遍历"（像 Go 的 range），而非 STL 级抽象

**一句话**：STL 用「容器/迭代器/算法」三角解耦实现复用；
Tenet 用「函数调用 + 标量值」拿到最小的解耦，不引入抽象层。
