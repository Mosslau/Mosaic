# 03 · trait 与泛型（零成本抽象）

> demo: `cargo run --bin 03_trait_generics`

## 1. 设计动机

面向对象语言用**继承**表达"是什么"，多态靠虚函数表（vtable）——但继承有经典问题：
菱形继承、脆弱的基类、耦合。Rust 的命题：**不要继承，用 trait 表达"能做什么"；
多态要么编译期展开（零开销），要么显式装箱（dyn）**。

## 2. 机制拆解

**trait = 行为接口**，与数据分离：

```rust
trait Shape {
    fn area(&self) -> f64;   // 只声明行为
}

struct Circle { r: f64 }
impl Shape for Circle {      // 给类型"安装"行为
    fn area(&self) -> f64 { 3.14159 * self.r * self.r }
}
```

**两种多态，两种成本**：

| 方式 | 机制 | 成本 |
|------|------|------|
| 泛型 `fn f<T: Shape>(x: T)` | 编译期**单态化**：每种 T 生成一份代码 | 零运行时开销（像 C++ 模板） |
| `dyn Shape` | 运行时通过 vtable 分发 | 一次间接调用（像 C++ 虚函数） |

**无继承的设计推论**：没有"基类"概念，类型之间的关系由 trait 约束表达，
组合（struct 里放 struct）优先于继承（is-a）。

## 3. 代码验证（demos/03_trait_generics.rs）

demo 里同一个 `area` 分别用泛型（单态化）和 `dyn`（vtable）调用，输出相同。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 无继承 | 习惯 OOP 的人要换思维（组合替代） |
| 孤儿规则 | 不能给外部类型实现外部 trait（限制耦合也限制灵活） |
| trait 对象不通用 | dyn Trait 只支持对象安全的方法 |

**换来的**：组合清晰、无菱形继承、零成本泛型、接口与实现解耦。

## 5. 对 Tenet 的启示

- ✅ **吸收"接口与实现分离"**：Tenet 的内建函数表（`print` 等）就是"trait 思维"——
  调用方只依赖名字，不依赖实现细节
- ✅ **吸收"行为抽象优先于类型层次"**：Tenet 的类型系统是扁平的 4 种标量，
  没有继承、没有层次——天然避免了 OOP 的耦合问题
- ❌ **拒绝完整 trait 系统**：教学语言用「名字即接口」的最简形式
- 💡 未来若加 struct，可参照 trait 而非继承设计"方法"

**一句话**：Rust 用 trait 让"多态"和"零成本"同时成立；
Tenet 用「扁平类型 + 名字调用」拿到同样的解耦收益，零语法成本。
