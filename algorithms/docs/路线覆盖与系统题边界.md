## 5. 13 个系统题：为什么不在 algorithms 做

判断标准：**产物是「一个算法 + 一个 demo」，还是「数据 + 训练 + 服务 + 评测 + 治理」？** 后者是系统题，验收在 engineering。

| 路线小节 | 为什么不是实验 | 工程落点（单元 / 验收） |
|---|---|---|
| 6.2 LLM 技术组成 | 需要预训练与大规模推理，toy 覆盖不了 | p4 推理与服务（A31–A37）、p3 算力（A23–A30） |
| 6.4 多模态大模型 | 需要大模型与多模态数据 | p4 A31 的 OpenAI 兼容接口可接多模态模型（选型阅读） |
| 6.5 视频生成 / 世界模型 | 算力与数据差 3–6 个数量级 | 不做；读 p05 DDPM + 视频生成综述 |
| 7.1 预训练 | 成本 10²–10⁴ GPU·天，不是学习项目 | 不做；p4 只做微调（A33） |
| 7.2 指令微调 | 需要数据 / GPU / 评测集 | p4 A33（LoRA/QLoRA）+ A37 计量 |
| 7.3 对齐（RLHF/DPO） | 需要偏好数据 + 训练基础设施 | p4 扩展；当前 A33 只覆盖 SFT/LoRA，不含 RLHF |
| 7.4 PEFT | 可做，但归 p4 的微调验收 | p4 A33 |
| 7.5 压缩 / 推理优化 | 需要真实模型与服务 | p4 A34（量化）、A35（压测） |
| 8.2 工具调用 | 需要运行时 / 沙箱 / 审批 | p5 A42–A43、A45（MCP 网关） |
| 8.3 Agent | 需要底座 + 运行时 | p5 A38–A46 |
| 8.4 Multi-Agent | 需要多运行时 / 协作协议 | p5 A44/A46 + tutorials s15（教学实现） |
| 9.2 大模型评测 | 需要评测集 / 回归 / 人工反馈 | p1 A10（RAG 评测）、p6 A50（监控）、数据 p5 V38–V44（评测集门槛） |
| 9.3 风险 / 安全 | 需要治理 / 审计 / 权限 | p6 A52（台账 / 审计）、p3 A24–A25（多租户 / 配额） |

> 这 13 项与 engineering「实现 0/14」是同一件事：**在 algorithms 里写 toy 版，等于同一份工作做两遍，第一遍还是废的。**

## 6. 维护规则

1. 新增实验：更新第 2 节计数 + [算法索引](../README.md) + 本文件第 3 节。
2. 工程单元完成：在第 5 节补证据链接（A/V 编号 + 实测记录）。
3. 不把系统题改成 toy 实验；如果一定要教学化，写成「读 + 选型」附录，不单开单元。
4. 「计划内欠账」与「路线未覆盖」分开计数：前者看第 1 节第 1 行，后者看第 2 节合计。
