> 版本：v1 · 2026-11-02
> 定位：**当前唯一总视图**——把「交付完整性 + 验证深度」与「生产应用差距 + 最小落地路径」放在同一份文档里。
> 合并来源：[阶段成熟度评估-2026-10-22.md](阶段成熟度评估-2026-10-22.md)（历史快照）、[生产系统栈与算法应用.md](生产系统栈与算法应用.md)（生产映射详版）、[docs/路线覆盖与系统题边界.md](docs/路线覆盖与系统题边界.md)（覆盖口径）。

## 0. 结论

- **交付完整性：42/42。** 42 个算法都有 README、`impl.py`、`demo.py`、测试、`exercises/`、`project/`、独立对照（`framework.py` 或 `baseline.py`）和 ✅ 完成日期；全仓 **575 passed**。
- **验证深度：3 个 L4 + 39 个 L3 + 0 个 L2/L1，平均 3.07/4。** L2/L1 已清零，但 L4 仍只有 CFR、线性回归、逻辑回归三个。
- **生产就绪：0/5。** 42 个当前全部是 **P0 教学实现**，没有一个到 P1 可服务原型；本文的“最小路径”是到 P1，不是到 P2 生产。
- **一句话：交付已齐，深度已抬到教学级；下一步的瓶颈是 L4 与生产化，不是继续加第 43 个算法。**

## 1. 评估口径

### 1.1 第一维：交付完整性

| 检查项 | 含义 |
|---|---|
| 六件套 | README + `impl.py` + `demo.py` + 测试 + `exercises/` + `project/` |
| 独立对照 | `framework.py`（框架对照）或 `baseline.py`（基线/独立参考）至少一个 |
| 状态/日期 | README 首行 ✅ + 完成日期，且与索引表一致 |
| 测试 | `pytest` 可收集、可运行；本文记录当前用例数 |

**判定**：六件套 + 独立对照 + 状态/日期齐全 = ✅；缺任一项 = ⚠️。当前 **42/42 全 ✅**。

### 1.2 第二维：验证深度

| 等级 | 含义 |
|---|---|
| **L4 深** | 真实/半真实数据或标准基准 + 外部真值 + 强数值/边界测试 + 量化失败分析 + 多基线 |
| **L3 较深** | toy/合成但严谨；核心性质与边界有测试；公平基线；heldout / 种子方差 / 局限量化 |
| **L2 中** | 测试以 shape/smoke 为主；核心反传或生成路径未验证；基线薄 |
| **L1 浅** | 测试仅契约；基线是稻草人；无 heldout |

**判定**：不是“测试越多越深”，而是看**断言是否锁住核心性质**（FD、最优性、heldout、基线公平性、失败模式）。当前：L4 3 个、L3 39 个、L2/L1 0 个。

### 1.3 生产就绪等级

| 等级 | 含义 | 当前 |
|---|---|---|
| **P0 教学实现** | 单机、toy 数据、无服务/监控/权限；用于讲原理和回归 | **42/42** |
| **P1 可服务原型** | 真实/半真实数据 + 服务接口 + 评测集 + 基础监控；单租户可接受 | **0/42** |
| **P2 生产系统** | HA、备份、限流/配额、权限/审计、成本、SLO、压测、灰度 | **0/42** |

> 本文第二部分给的是 **P0 → P1** 的最小路径；P1 → P2 的通用要求见 §5.1。

# 第二部分：每个阶段、每个算法如何到生产

> 当前全部 **P0**。下表给的是 **P0 → P1** 的最小路径：换真实数据/成熟库、补评测与服务、加基础监控；P1 → P2 的通用要求见 §5.1。
> 原则：**教学实现是 oracle，不是 runtime。** 不直接 import `algorithms/`；用成熟库重写服务，把教学实现当固定输入/输出回归基准。

## 4.0 六个通用层

| 层 | 教学实现现状 | P1 要求 | P2 追加 |
|---|---|---|---|
| 数据 | digits/合成/SMALL 语料 | 真实或半真实数据、固定切分、版本化 | 数据质量、漂移、PII、保留策略 |
| 训练 | 单机 numpy/小 torch | 可重跑训练脚本 + 超参/种子入档 | 分布式、训练追踪、模型注册 |
| 推理 | `demo.py` 单次调用 | API/批处理 + 延迟/吞吐基线 | 自动扩缩、灰度、回滚、GPU 池 |
| 评测 | README 指标 + pytest | 固定评测集 + 指标门槛 + 回归 | 线上评测、人工反馈、A/B |
| 观测 | 基本日志/无 | 请求日志、延迟、错误率、模型指标 | Trace、告警、SLO、成本看板 |
| 安全/成本 | 无 | 鉴权、输入校验、依赖锁定 | 多租户、审计、配额、密钥轮换 |

| CNN | 图像分类 | 卷积/BN/残差 | 真实数据、预训练、GPU、Triton | ResNet/EfficientNet + Triton |
| 轻量 CNN | 端侧视觉 | DS 卷积、参数核算 | 量化、TFLite/ONNX、端侧集成 | MobileNet + TFLite |
| 目标检测 | 检测 | 网格/NMS/AP | 真实数据、backbone/FPN、TensorRT | YOLO/Detectron2 + TensorRT |
| 图像分割 | 分割 | U-Net 思想、IoU/Dice | skip、真实数据、服务 | smp + ONNX/Triton |
| RNN/LSTM | 序列基线 | BPTT、门控 | Transformer、真实序列、服务 | GRU/LSTM 基线 → Transformer |
| AutoEncoder | 异常/压缩 | 重构、阈值 | 去噪/VAE、流式 | AE 异常检测 + PR-AUC |
| GAN | 生成/增强 | 对抗训练、覆盖指标 | DCGAN/WGAN-GP、FID、安全 | diffusers/GAN 库 + 评估 |
| GNN | 图分析 | 消息传递、GCN | PyG、GraphSAGE/GAT、大图采样 | PyG + neighbor sampling |
| Deep-RL | 控制/游戏 | DQN、replay/target | Gymnasium、并行环境、安全 | stable-baselines3 + 仿真 |

## 5. 生产化路线（跨阶段）

### 5.1 P1 / P2 门禁

| 门禁 | P1 可服务原型 | P2 生产 |
|---|---|---|
| 数据 | 真实/半真实数据 + 固定切分 + 版本 | 质量、漂移、PII、保留 |
| 模型 | 成熟库重写 + 可重跑训练 | 注册、灰度、回滚 |
| 服务 | API/批处理 + P95/吞吐 | 扩缩、限流、HA |
| 评测 | 固定评测集 + 门槛 | 线上评测 + A/B + 人工 |
| 观测 | 日志/延迟/错误/模型指标 | Trace/告警/SLO/成本 |
| 安全 | 鉴权/校验/依赖锁定 | 多租户/审计/配额/密钥轮换 |

### 5.2 先做哪 1–2 个

不要同时生产化 42 个。建议按“业务价值 ÷ 基础设施成本”选：

| 路线 | 候选 | 理由 | 最小 P1 周期 |
|---|---|---|---|
| A. 企业 RAG | p05 RAG + p04 embedding | 业务价值最高；复用向量库/LLM；评测可定义 | 6–8 周 |
| B. 表格风控/异常 | p02 Boosting/逻辑回归 + 异常检测 | 基础设施最轻；特征管道/监控成熟 | 4–6 周 |
| C. 视觉检测 | p03 CNN/目标检测 + p04 ViT | 有明确指标；需要 GPU/Triton | 8–10 周 |

### 5.3 90 天最小路线

1. **第 1–2 周**：定场景、真实数据、评测集、基线指标；选定成熟库（LightGBM/vLLM/timm/diffusers）。
2. **第 3–6 周**：用成熟库重写服务；保留教学实现做 oracle 回归；补 API、日志、延迟/错误指标。
3. **第 7–10 周**：补评测门槛、鉴权/输入校验、依赖锁定、基础告警；过 P1 门禁。
4. **第 11–12 周**：小流量灰度；决定是否继续 P2；不达标就回到数据/评测，不先上 K8s。
