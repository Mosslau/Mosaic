# 迁移项目：地形代价地图寻路

> 这是「五级能力清单」第 5 级（迁移）的证据：把 A* 从"每步代价恒为 1 的教学网格"搬到**每格代价不同**的地形图上。
> 运行（本目录内）：`../../../../.venv/bin/python terrain_astar.py`

## 需求

教学示例里每一步代价都是 1，A* 的启发式可以直接用曼哈顿距离。真实场景里"路"是有价钱的：走沙地便宜、走沼泽贵。本项目要求：

**给定一张 20×20、每格地形代价为 1–9 的地图，求从起点 (0,0) 到终点 (19,19) 的最小总代价路径，并与 Dijkstra 对照。**

与教学示例的差别（迁移点）：

| 维度 | 教学示例 | 本项目 |
|---|---|---|
| 单步代价 | 恒为 1 | 进入格子的地形代价（1–9） |
| 启发式 | 曼哈顿距离（可采纳） | 不能直接用曼哈顿——要用"每步最小代价 × 曼哈顿"才不高估 |
| 对照 | Dijkstra（h≡0） | 同上，但代价换成了地形代价 |

## 功能清单

- [x] 固定种子生成地形（起点终点强制为 1），保证可复现
- [x] A*：`h = 1 × 曼哈顿距离`（1 是地形代价下界，因此不高估）
- [x] Dijkstra（h ≡ 0）同图对照
- [x] 断言两者总代价一致；报告扩展节点数
- [x] 输出对比图 `out/terrain.png`（地形热力图 + 两条路径）

## 验收标准

1. A* 与 Dijkstra 的**总代价完全一致**（脚本内断言，不一致直接报错）
2. A* 的扩展节点数 **≤ Dijkstra**（启发式有效）
3. 按 README 命令能跑出结果并生成 `out/terrain.png`

## 实测结果（已验证）

```
地形代价地图 20×20（代价 1–9，种子 42）
  A*（h = 1 × 曼哈顿）   总代价 106  扩展 386 格
  Dijkstra（h ≡ 0）      总代价 106  扩展 399 格
  代价一致 ✓；A* 少扩展 3%
```

环境：Python 3.12.3 + numpy + matplotlib（仓库 `.venv`）；命令：`../../../../.venv/bin/python terrain_astar.py`。

## 一个诚实发现：启发式弱，收益就小

本项目只赚了 3% 的扩展数（对比教学地图上的 16.7%）——原因很清楚：**启发式只用了"每步最小代价 = 1"这个最弱的下界**。随机地形上大多数格子代价是 4–6，但启发式假装每步只花 1，于是估计值远远低于真实剩余代价，方向感很弱。

这正是"启发式越紧（仍不高估）→ 扩展越少"的直接演示。

## 扩展方向

- **更紧的启发式**：预计算"剩余区域的最小地形代价"或按行/列做分层下界，重跑对比扩展数
- **八邻域 + 地形**：对角代价按 `√2 × 地形代价` 计算，配合 octile 启发式（见 `../exercises/sol-04-八邻域.py`）
- **多目标/多次查询**：同一张地形上跑 100 组起终点，比较 A* 与双向 A* 的总耗时
- **可视化升级**：把扩展顺序做成动画（参考 `../make_teaching_assets.py` 的 GIF 写法）
