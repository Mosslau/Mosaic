# 第 3 题参考解：欧几里得启发式的坑

**1. 会不会高估？**

不会。只能上下左右走时，真实剩余步数是"横着差几格 + 竖着差几格"（曼哈顿距离）；欧几里得距离 `√(Δr² + Δc²)` 永远不大于它（三角形不等式）。所以欧几里得是**可采纳的**（admissible），不会高估。

**2. 那它安全吗？**

**安全**。四邻域单位代价下，相邻格满足 `|h(n)−h(n')| ≤ 1`，欧氏是 1-Lipschitz，因此 `h(n) ≤ 1 + h(n')`，**既可采纳也一致**；本实现可以安全使用。一般地，A* 还需要**一致性（consistent）**：

```
h(n) ≤ 单步代价 + h(邻居)
```

本实现的 `closed` 集**不重开节点**：一个点第一次被取出处理后就"封存"了。一致性保证"每个点第一次被取出时，它的 g 已经是最小的"，所以封存是安全的；而"可采纳但不一致"的 h 没有这个保证——某个点可能以一个偏大的 g 被过早封存，之后即使发现更短走法也无法再更新，于是**静默**返回次优解（代码不会报错）。

**3. “可采纳但不一致”的反例（必须用人工 h）**

`test_impl.py::test_known_limitation_admissible_but_inconsistent_heuristic`：

- 2×5 全通路网格，起点 (0,0)、终点 (0,4)，最优代价 4；
- 人为设计 `h((0,1)) = 3`、其余为 0——处处可采纳，但 (0,1) 处 `h = 3 > 1 + h((0,2)) = 1`，不一致；
- `insertion` 平局恰好躲过（得 4），`large_g` 平局得 **6**：绕路到达的 (0,2) 先出堆并被封存，(0,1) 之后无法把它松弛回更小的 g。

**注意**：欧氏在四邻域单位代价下是**一致**的，不能拿它构造反例；上面的反例是人工设计的 h。要支持一般“可采纳但不一致”的 h，正确做法是允许重开节点，或使用只保证可采纳的树搜索版本。

**结论**：选择启发式的判据不是"越准越好"，而是"**先看实现的安全线**"——本实现要一致，不一致的 h 哪怕不高估也可能出错。
