# 迁移项目：真实排班（硬约束 + 软约束）

> 这是「五级能力清单」第 5 级（迁移）的证据。教学目录解的是**纯硬约束、有唯一解**的
> 玩具问题（八皇后、数独）；真实排班不一样：约束更多、常常无解、而且**要的是"最不坏"而不是"可行"**。
> 运行（本目录内）：`python3 shift_scheduling.py`（只用标准库，复用 `../impl.py`）

## 需求

**给 5 个人排一周 3 个班次**，同时处理两类约束：

| 类型 | 内容 |
|---|---|
| **硬约束**（必须满足） | 每班人数达标；不能排到"不可用"的班次；同一个人一天不排两个班 |
| **软约束**（尽量满足） | 尽量满足个人偏好；尽量别给同一人连排夜班；各班次尽量均衡 |

**输出**：一张排班表 + 硬约束的独立复核 + 软约束代价的前后对比。

## 迁移点

| 维度 | 教学目录（`../`） | 本项目（`project/`） |
|---|---|---|
| 问题 | 八皇后 / 数独（纯硬约束、有唯一解） | **真实排班**（硬 + 软、多解） |
| 目标 | 找一个可行解 | **可行解里代价最小的那个** |
| 建模技巧 | 变量 = 位置 | 变量 = **"名额"**（每班第 k 个位子）→ 人数约束天然满足 |
| 方法 | 纯 CSP（回溯 + 传播） | **CSP 找可行解 + 局部搜索降代价**（CSP → COP） |

## 功能清单

- [x] 把"每班要几人"建成 CSP（变量 = 名额、取值 = 人名）
- [x] 用前向检查 + MRV/LCV 求硬约束可行解
- [x] **硬约束的独立复核**（不依赖求解器自报）
- [x] 软约束代价函数（偏好 / 连排夜班 / 班次均衡）
- [x] 局部改进：**单点交换 + 2-opt**
- [x] 打印可读的排班表

## 验收标准

1. 按 README 命令能一次跑完并打印排班表
2. 求解结果必须**通过独立的硬约束复核**（脚本内含断言）
3. 局部改进后软代价必须**不升高**（脚本内含断言）
4. 必须体现"**单点交换无效、2-opt 才动得起来**"这个现象（而不是只报一个下降数字）

## 实测结果（已验证）

**环境**：Python 3.13.9（系统 `python3`），只用标准库；本目录内执行 `python3 shift_scheduling.py`。

### 第一步：硬约束可行解

| 指标 | 数值 |
|---|---|
| 变量数 | 28（7 天 × (早 1 + 中 2 + 夜 1) 个名额） |
| 求解节点 | 28 |
| 回退 | 0 |
| 传播 | 42 |
| 独立复核硬约束 | **通过** |
| 初始软代价 | 8.50 |

（回退 0 说明前向检查把死路全在赋值前就剪掉了——这就是传播的价值。）

### 第二步：局部改进

| 指标 | 数值 |
|---|---|
| 改进后软代价 | **−14.80**（比初始 8.50 低 23.30） |
| 接受的移动次数 | 101 |
| 其中 2-opt | **77** |

> 代价可以为负：`PREFER` 里的正分是"想上这个班"，排上了就是收益。

## 结论（三条）

1. **教学 CSP 与真实排班的分界是"目标"**：前者找**可行解**，后者要**可行解里最好的**。
   这就是 CSP 与约束优化（COP）的区别。
2. **两段式是实用做法**：搜索找可行解 + 局部搜索降代价。
   另一条路是把软约束编码进搜索（分支限界），代价是搜索空间显著变大。
3. **局部搜索的邻域必须够大**（本项目最有价值的一条实测）：
   单点交换在这个问题上**接受率为 0**——因为每班人数是定死的，换掉一个人必然破坏人数约束；
   加入 **2-opt（两人互顶）** 之后才动得起来（77 次接受）。
   **邻域定义得太小，局部搜索一步都走不动。**
