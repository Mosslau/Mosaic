## 第 4 题（实现）给数独加一个全局约束传播

**目标**：练第 4 级——实现比"二元约束传播"更强的传播手段。

**要求**：新建 `sol-04-数独传播.py`（只用标准库）。数独的标准传播除了"逐个邻居删值"，
还有一个更强的规则——**唯一余数法（hidden single）**：

> 如果某个**单元**（一行/一列/一宫）里，数字 $d$ 只能放进**一个**格子，
> 那么那个格子**必须是** $d$（即使它的候选数还有很多）。

1. 实现 `propagate_units(domains, units)`：对每个单元反复应用
   - **显式唯一**：某格只剩一个候选 → 定下来，并从同单元其他格删掉该值；
   - **隐式唯一**：某值在单元里只出现一次 → 定到那格。
   直到不再变化。
2. 把它接进求解循环（每步赋值后调用），与 `../impl.py` 的 `ac3` 对比：
   在 `../demo.py` 的 `SUDOKU_HARD` 上，**节点数与耗时各是多少**？
3. **自检断言**：
   - 加了单元传播后，节点数**不比** `ac3` 差；
   - 解仍然合法（用 `../test_impl.py` 里 `check_sudoku` 的思路独立复核）；
   - 传播本身是**幂等**的（连跑两次结果不再变化）。

**验收标准**：脚本能独立运行，断言通过，并给出与 `ac3` 的对照表。

**提示**：`../demo.py` 里有单元的定义（行/列/宫）可以参考；
"隐式唯一"是数独最常用的推理规则，人类解题主要靠它。

## 第 5 题（迁移）把 CSP 用到"考试排考"上

**目标**：练第 5 级——迁移到一个**资源受限 + 有软约束**的真实问题。

**要求**：新建 `sol-05-迁移.py`（只用标准库）。场景：

- 6 门课、3 个时间段、2 间教室；每门课有选课人数，教室有容量；
- **硬约束**：同一时间段同一教室只能排一门课；容量不够的教室不能排；
  有冲突的课程对（学生同时选了两门）不能排在同一时间段；
- **软约束**：尽量让"想选同一时段"的课排一起（给偏好权重）；尽量别让同一间教室连排太多。

1. 建模（变量 = 课程、取值 = `(时间段, 教室)` 组合）并用 `../impl.py` 求可行解；
2. 统计求解节点数、回退数，并**独立复核硬约束**；
3. 加一个软约束代价函数，用**局部搜索**（单点 + 2-opt）改进，报告代价下降；
4. 回答：**这个问题上单点交换的接受率是多少？** 与 `../project/` 的排班问题的结论是否一致？

**验收标准**：给出可行的排考表、硬约束复核结果、软代价前后对比；
第 4 问要用**实测的接受率**回答，并说明"邻域大小"的影响。

**提示**：取值是 `(时间段, 教室)` 的组合，组合数 = 3 × 2 = 6；
先想清楚"两个课程冲突"这件事在约束里怎么表达（提示：约束作用在**时间段**上，而不是完整取值上）。
