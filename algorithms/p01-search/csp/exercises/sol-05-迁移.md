# 参考解：第 5 题（迁移）

代码：`sol-05-迁移.py`（只用标准库）。

## 建模

- **变量 = 课程**（6 门），**取值 = (时段, 教室) 的组合**（时段 3 × 教室 2 = 6 种）
- 容量约束 → 直接在**取值域**里过滤（容量不够的教室不进域）→ 天然满足，不用进约束表
- "冲突课程不能同时段" → 约束作用在**时间段**上（`x[0] != y[0]`），
  而不是完整取值（写成 `x != y` 就变成"不能同教室同时段"，语义偏了）

## 实测

**第一步（求可行解）**：节点 6、回退 0、传播 18、耗时 0.1 ms；独立复核硬约束通过。

**第二步（局部搜索）**：单点交换接受 **377** 次、2-opt 接受 **0** 次；
软代价 **2.00 → 2.00（没有改进）**。

**第三步（枚举全部可行解找全局最优）**：可行解共 **6** 个，**全部**软代价 2.00。

## 三条结论

1. **本题上"局部搜索没有改进"是正确行为，不是缺陷**：全局最优就是 2.00，
   求解器一上来就给到了。**如果不枚举全局最优，就会误判成"局部搜索失效"。**
2. **两个偏好对无法同时满足**：`(算法,编译原理)` 与 `(数据库,机器学习)` 都要求同段，
   但硬约束（环状冲突 + 教室容量）下不存在零代价解——**软约束与硬约束可能是冲突的**。
3. **"局部搜索没改进"有两种完全不同的原因**（对照 `../project/` 的排班项目）：

   | 原因 | 现象 | 对策 |
   |---|---|---|
   | ① **邻域太小** | 一步都走不动（排班项目：单点接受 **0** 次） | 换更大的邻域（2-opt） |
   | ② **已经在最优** | 走动了但代价不降（本题：接受 377 次、代价不变） | 不该乱改 |

   **分清这两者，必须先知道全局最优长什么样**——小实例上可以枚举，
   大实例上只能靠下界估计（这就引出了分支限界）。

## 关于实例可解性的一个教训

我试了三次"给冲突图加跨边让问题更紧"，**三次都不小心做成了不可 3 着色的图**
（求解器直接报无解）。最后老实选了一个**实测确认可解**的构造（纯环）。

**"这个实例有解"必须实跑确认，不能靠推演**——尤其是着色/排班这类约束紧的问题。
