# 迁移项目：深度受限的博弈搜索（四子连珠）

> 这是「五级能力清单」第 5 级（迁移）的证据：教学目录用的是 3×3 井字棋——**最多 9 手、能搜到终局**，
> 所以 `evaluate()` 只要判胜负就够。本项目换一个**搜不到终局**的棋类，补上"深度限制 + 启发式评估"。
> 运行（本目录内）：`python3 connect4_search.py`（只用标准库，不需要 numpy / matplotlib）

## 需求

**给定一个 `size`×`size`、`win_len` 连珠取胜的棋盘，在固定搜索深度下选出招法，并用自对弈量化两件事：**
评估函数的质量、搜索深度，哪个更决定棋力？

与教学示例的差别（迁移点）：

| 维度 | 教学示例（井字棋） | 本项目（四子连珠） |
|---|---|---|
| 能否搜到终局 | 能（最多 9 手，`depth=9` 全展开） | **不能**——只能搜到某个深度就截断 |
| 评估函数 | 只判胜负（`±10 / 0`） | **必须估计**：每条取胜线按占子数折算成 3 的幂 |
| 正确性依据 | 两版搜索结论一致即可 | 没有"标准答案"，只能**自对弈比胜率** |
| 棋盘 | 固定 3×3 | `size` / `win_len` 可配（实验里用到 4×4 三连、5×5 四连、6×6 四连） |

搜索本体**没有重写**：项目直接 `from impl import alphabeta`，只换棋类与评估函数——这正是"迁移"该有的样子。

## 功能清单

- [x] 可配置棋类（`Board.configure(size, win_len)`），不可变状态（`apply` 返回新对象）
- [x] 启发式评估：取胜线按"我占几子 / 对手占几子"折算，权重取 3 的幂
- [x] 复用教学目录的 `alphabeta`，并统计访问节点数（与教学版同一口径）
- [x] 自对弈对局：**每局交换先后手**，并分开统计先手 / 后手战绩
- [x] 三组实验：深度的代价 / 评估质量 / 深度效应

## 实测结果（已验证）

**环境**：Python 3.13.9（系统 `python3`），只用标准库；本目录内执行 `python3 connect4_search.py`。

### 实验一：深度的代价（5×5 四连，空棋盘）

| depth | 访问节点 | 耗时 | 相对上一档 |
|---|---|---|---|
| 1 | 1 | 0.1 ms | — |
| 2 | 26 | 0.9 ms | 26× |
| 3 | 256 | 13 ms | 10× |
| 4 | 3,603 | 135 ms | 14× |
| 5 | 26,657 | 1.16 s | 7.4× |
| 6 | 204,760 | 7.5 s | 7.7× |

**深度是要花钱的**：每加一层大约贵 7–26 倍（分支因子约 25 个空格，剪枝后实际约 8–10 倍）。
本项目实验三因此把深度控制在 2–4。

### 实验二：评估质量决定棋力（4×4 三连，同深度 depth=2，各 6 局交换先手）

| 配置（评估函数） | 胜 | 负 | 和 | 执先手胜 |
|---|---|---|---|---|
| 坏评估（随机分） | 0 | **6** | 0 | 0 |
| 弱评估（只看子力） | 0 | **6** | 0 | 0 |
| 好评估（连线威胁） | 3 | 3 | 0 | 3 |

**结论：同一个搜索、同一个深度，只换评估函数就从 0 胜变成 3 胜。** 而且"只看子力"和"完全随机"
一样惨（都是 0:6）——**子力差是个无用的评估**：连珠游戏里，占了几个格子跟会不会连成四子几乎无关。

> 好评估那一行 3:3 是"自己打自己"，胜负完全由先手决定（执先手 3 局全胜）——这说明
> 4×4 三连的先手优势是压倒性的。实验三因此必须把先手因素单独列出来。

### 实验三：深度效应（6×6 四连，两边同用「好评估」，各 6 局交换先手）

| 深 vs 浅 | 深胜 | 浅胜 | 和 | 深方执先手胜 |
|---|---|---|---|---|
| 2 vs 4 | 3 | 3 | 0 | 3 |
| **3 vs 4** | **0** | **6** | 0 | 0 |
| **2 vs 3** | **6** | **0** | 0 | 3 |

**结论一（偶然但可复现）：深度不是"越深越好"，而是"奇偶要对"。** 深度 3 两战全败、深度 2 却赢了深度 3 六局。
原因很具体：**偶数深度结束在"对手该走"的层**，深 2 至少看得见对手的**一步**即时反制；而**奇数深度 3 结束在"我方该走"的层**，
看不见对手接下来那一步。在四子连珠里"下一手就成四"的威胁极大，所以深度 3 反而比深度 2 更瞎。

**结论二：这也正是"评估函数必须显式处理即时威胁"的证据。** 好评估只数连线占子数，**没有**"对手下一手成四"这一项，
于是它把这个盲区完全暴露给了深度奇偶。真实引擎的做法是：把这类威胁写进评估，或统一用**偶数深度**（同时看双方各一步）。

**结论三（诚实交代不确定的部分）**：`2 vs 4` 打平（3:3，且全部由执先手者获胜）——说明在这个深度区间里，
**先手优势比深度差 2 更决定胜负**；本轮 6 局的样本量不足以区分 2 与 4 的强弱。这一条按"未在本环境验证更强结论"处理，
没有硬凹成"越深越强"。
