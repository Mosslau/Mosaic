## 第 1 题（说清）用自己的话讲规则

**目标**：练第 1 级——能把算法讲给别人听。

**要求**：

1. 用不超过 150 字说明 minimax 在做什么（不许出现"递归""遍历"这种词，讲给没学过算法的人听）。
2. 说清 `α` 和 `β` 分别是谁的底线、分别在哪一层更新。
3. 回答：为什么 `minimax` 与 `alphabeta` 必须给出**完全相同**的招法和分数？

**验收标准**：三问都能答，且第 3 问要说出"剪掉的分支不可能被选中"这个理由，而不是"因为是优化"。

**提示**：看基础篇第 2 节与第 5 节。

## 第 2 题（走通）手算一棵博弈树

**目标**：练第 2 级——纸上能算，不用电脑。

**要求**：下面是一棵三层树（方框 = 我方 max 层，椭圆 = 对手 min 层，最下层是终局评分）：

```text
                    我方 (max)
              ┌────────┼────────┐
              招法 a   招法 b   招法 c
              │        │        │
        对手 (min)  对手 (min)  对手 (min)
         ┌──┼──┐    ┌──┼──┐    ┌──┼──┐
         r1 r2 r3   r4 r5 r6   r7 r8 r9
         4  2  6    4  8  3    1  8  3
```

这棵树是**三层**（根 → 对手层 → 叶子），所以搜索深度取 `depth = 3` 才能走到叶子；
若只给 2，搜索会在对手层就截断（那时用的是"局面评估"，不是叶子分）——这是常见的第一号坑。

1. 不用剪枝，逐层算出三个招法各自的值，再给出根的选择。
2. 换用 alpha-beta（**从左到右**遍历，α/β 初值为 −∞/+∞），写出每一步之后的 α、β，
   并指出**哪一个分支会被剪掉**、剪枝时满足的不等式是什么。
3. 比较 1 和 2 的结论，说明剪枝改了什么、没改什么。

**验收标准**：三问的结论与 `sol-02-手算.md` 一致；第 2 问必须写出具体不等式（如 `β ≤ α`）。

**提示**：α 是"我方已经能保证拿到的最好值"，β 是"对手已经能保证压到的最好值"。先算 a，再算 b 的时候留意 α 已经是多少。

## 第 3 题（判断）这个剪枝条件错在哪

**目标**：练第 3 级——能指出实现里的边界错误。

**要求**：下面是某人对 `alphabeta` 的 max 层实现（伪代码）：

```text
v = -∞
for move in moves:
    v = max(v, alphabeta(child, ..., alpha, beta, ...))
    beta = min(beta, v)          # ← 注意这一行
    if beta <= alpha:
        break
```

1. 指出这一行的错误，并说出正确写法里这一步该更新哪个变量。
2. **实测它的后果**：写个小脚本，把这段错误实现与正确实现放在第 2 题那棵树（以及你自己再编 2–3 棵树）上跑，
   报告两者的 (招法, 分数, 展开叶子数)。回答：**结论被改坏了吗？为什么？**
3. 追加一问：如果把剪枝条件写成 `beta < alpha`（严格小于），结果会错吗？为什么？

**验收标准**：第 2 问必须给出实测数字，并解释"结论为什么没坏"与"什么被破坏了"；
第 3 问答出"不会错结论、只是少剪一些"。

**提示**：这一题的结果与直觉相反——正确答案不是"结论被改坏"，而是"**剪枝收益被整个丢掉、但结论可能仍然正确**"。
想清楚窗口 `(α, β)` 分别在谁手里维护，再想为什么错误地改 `β` 会让剪枝判据失效。参考解 `sol-03-诊断.md` 有全部数字。

## 第 4 题（实现）给搜索加"迭代加深 + 置换表"

**目标**：练第 4 级——把教学实现改造成工程上真正会用的形态。

**要求**：新建 `sol-04-迭代加深.py`（只用标准库），实现：

1. `search_with_budget(state, max_depth, **game)`：从 depth=1 逐层加深到 `max_depth`，**每层都记录最好招法**；
2. **置换表**：用局面做键缓存已算过的值（注意：井字棋局面要能当字典键）；
3. 打印每一层的 (深度, 访问节点数, 选中的招法, 分数)，并断言：
   - 每层选出的招法分数与 `impl.alphabeta` 在**该深度**下的结果一致；
   - 加置换表之后，总访问节点数**不多于**不加的情况。

**验收标准**：脚本能独立运行（`python3 sol-04-迭代加深.py`），自检断言全部通过，并打印逐层表格。

**提示**：置换表的键用 `(tuple(board), player, depth, maximizing)`——只缓存"完整搜完"的层；`demo.TicTacToe` 可以直接复用。

## 第 5 题（迁移）换一个棋类，并让评估函数看见"下一手成四"

**目标**：练第 5 级——把算法搬到新问题，并理解"评估质量 > 深度"。

**要求**：在 [project/connect4_search.py](../project/connect4_search.py) 的基础上新建 `sol-05-威胁评估.py`：

1. 实现一个新的评估函数 `threat_aware`：在原有连线计分之外，**显式加上**"我方下一手能成四"与
   "对手下一手能成四"这两项（对手的威胁要给更大权重）；
2. 让它与项目里原有的 `Board.evaluate` 在 **6×6 四连、深度 2 与深度 3** 下各打 6 局（交换先手）；
3. 报告胜负，并回答：**为什么这个改进能修掉"深度 3 反而不如深度 2"的毛病？**

**验收标准**：脚本能独立运行、结果可复现（固定随机种子）；结论要落到"评估函数必须显式处理即时威胁"这一点上。

**提示**：先跑一遍 `../project/connect4_search.py` 看实验三的结论，再动手改评估。这是本目录最重要的一条工程经验。

## 参考解运行记录

代码类参考解只用标准库（**不需要仓库 `.venv`**）：


**2026-10-09 实跑（Python 3.13.9，系统 `python3`）观察结果**：

- `sol-02`：练习树 depth=3 → 两版都是 `move=b / score=3`；展开叶子 **9 → 7**，剪掉 `c/r8`、`c/r9`。
  （**坑**：这棵树是三层，深度给 2 会在对手层截断——参考解里写明了。）
- `sol-03`：4 棵树 × 3 种写法，错误写法**结论都没被改坏**、但叶子数从 7–8 涨到全部 9 ——
  "剪枝收益被丢掉、结论可能仍然正确"，这是本题的正确答案。
- `sol-04`：迭代加深 1..6 层累计 3,089 次进入 vs 单次 depth=6 的 1,886 次（**迭代加深更贵**，
  换来的是"可随时中断 + 现成排序"）；置换表在单次搜索里几乎无收益、预热后第二次几乎免费。
- `sol-05`：同深度镜像对战（12 局）—— depth=2 档原评估 12:0，depth=3 档 6:6，合计 **18:6**；
  对照项目实验三"深方 0:6"，威胁项确实补上了一部分盲区，但**改评估有代价**（见参考解）。
