# 参考解：第 3 题（判断）

> 这题的结论在实测中与直觉相反，值得逐条看完——**它是本目录最"工程"的一题**。

错误代码（max 层）：

```text
v = -∞
for move in moves:
    v = max(v, alphabeta(child, ..., alpha, beta, ...))
    beta = min(beta, v)          # ← 错在这一行
    if beta <= alpha:
        break
```

## 1. 错在哪

**`β` 是"对手能压到的最好值"，只能由 min 层更新；max 层该更新的是 `α`。**

这一行在 max 层把 `β` 压到"我方刚拿到的分数"上，于是窗口不再满足 `α ≤ β` 的基本含义，
**剪枝的判据被自己毁掉了**：`β ≤ α` 这个条件再也反映不了"对手能否压住我方"。

## 2. 后果：实测结果与直觉不同

`sol-03-诊断.py` 把三种写法放在 4 棵不同的三层树上跑（深度都是 3，全展开是 9 个叶子）：

| 树 | 正确写法 | `swap_var`（本题错误写法） | `drop_window`（忘传窗口） |
|---|---|---|---|
| T1 对称 | move=b score=3，**7 叶子** | move=b score=3，**9 叶子** | move=b score=3，**9 叶子** |
| T2 非对称 | move=b score=4，**7 叶子** | move=b score=4，**9 叶子** | move=b score=4，**9 叶子** |
| T3 前大后小 | move=c score=4，**7 叶子** | move=c score=4，**9 叶子** | move=c score=4，**9 叶子** |
| T4 谷底在后 | move=c score=3，**8 叶子** | move=c score=3，**9 叶子** | move=c score=3，**9 叶子** |

**根的结论一次都没被改坏，但剪枝收益全部丢失**（退化成接近全树展开）。

为什么结论还能对？因为 max 节点返回的值始终是"已展开子节点的最大值"，
在**这些树**里被错误剪掉的子节点恰好不会把最大值抬得更高（T3/T4 里第一个子节点就已经决定了选择）。
**这是运气，不是正确性**：

- 窗口错 ⇒ 该剪的地方剪不动、该展开的地方可能被误判 ⇒ 一旦树更深、更像真实棋局，迟早算出错的选择；
- 而且它**不报错**，只是悄悄多算或少算——这就是最危险的一类 bug。

## 3. 正确写法

| 层 | 更新 | 代码 |
|---|---|---|
| max（我方） | `α` | `alpha = max(alpha, v)` |
| min（对手） | `β` | `beta = min(beta, v)` |

剪枝条件两边都是 **`beta <= alpha`**，放在"算完一个子节点、更新完窗口之后"。
口诀：**谁取极值，就更新属于谁的那一半窗口。**

写成 `drop_window`（递归时不把 `alpha, beta` 传下去）后果与 `swap_var` 一样：
**剪枝完全失效**（每次都从 ±∞ 开始），结论同样不一定错、但"省下的计算"一点不剩。

## 4. 追加一问：写成 `beta < alpha` 会错吗？

**不会错结论，只会少剪一些。** 当 `β == α` 时，那条分支的取值恰好落在边界上：
继续展开它得到的值或等于已保证值、或更差，两者都不改变祖先的选择。所以严格不等号是安全的，
只是放弃了"相等时也能剪"的机会。

**验证方式**：把井字棋空棋盘 depth=9 的剪枝条件从 `<=` 换成 `<`，招法与分数不变、
访问节点数变多——这是"结论不变、收益变小"的又一例，与本题的错误写法同源。

## 5. 本题真正要记住的

1. **"结论没被改坏"不能证明写对了**——本题的错误写法在 4 棵树上结论都对。
2. 判断一个剪枝实现对不对，要看两件事：**与朴素版逐点对拍**（结论）＋ **统计访问节点数**（收益）。
   教学目录的 `test_impl.py` 与 `demo.py` 正是分别覆盖这两件事。
3. 窗口是"双方的承诺"：`α` 归 max、`β` 归 min，**越权改对方那一半，等于把承诺作废**。
