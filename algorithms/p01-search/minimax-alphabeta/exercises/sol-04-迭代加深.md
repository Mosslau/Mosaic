# 参考解：第 4 题（实现）

代码：`sol-04-迭代加深.py`（只用标准库）

## 实现要点

1. **迭代加深**：`for depth in range(1, max_depth + 1)`，每层都完整搜一次、记录该层结论。
2. **浅层结论给深层排序**：上一层选出的招法放到 `ordered_moves` 的最前面。
   这不是锦上添花——它是迭代加深在真实引擎里最值钱的副产品（见下）。
3. **置换表**：键 `((tuple(board), player), depth, maximizing)`，只缓存**精确值**
   （值落在入口窗口 `(a0, b0)` 内部才算精确；被窗口截断的值只是边界，缓存会算错）。
4. **计数口径**：每次进入节点记一次（**含命中缓存的进入**，命中数单列），
   对照组 `count_plain` 手写一份同样口径的 alpha-beta——口径不同的话两组数字没有可比性。

## 实测结果（井字棋空棋盘，Python 3.13.9）

| depth | 本层招法 | 分数 | 本层进入 | 缓存命中 | 参考 alphabeta（单次） |
|---|---|---|---|---|---|
| 1 | 0 | 0 | 10 | 0 | 0 / 0（1 次） |
| 2 | 0 | 0 | 26 | 0 | 0 / 0（10 次） |
| 3 | 0 | 0 | 96 | 0 | 0 / 0（26 次） |
| 4 | 0 | 0 | 206 | 0 | 0 / 0（96 次） |
| 5 | 0 | 0 | 1,009 | 14 | 0 / 0（301 次） |
| 6 | 0 | 0 | 1,742 | 20 | 0 / 0（1,886 次） |

每层的 `(招法, 分数)` 与 `impl.alphabeta` 在同深度下的结果**逐层一致**（脚本内断言）。

## 两个"反直觉"的结论（都来自上表）

1. **迭代加深不是省时间的技巧。** 它把 1..6 层全算了一遍（累计 3,089 次进入），
   而单次 depth=6 只要 1,886 次。它买的是：**随时可以中断**（时间预算型系统的刚需）
   和**一份现成的招法顺序**——不是"总计算量更小"。
2. **置换表在同一次搜索里几乎白搭。** 表空时 depth=6 仍是 1,742 次进入；
   因为单次搜索里每个局面本来就只到达一次。它只在**同一个局面会被反复搜到**时才有价值
   （重复对局、深搜里的换位）。
   预热后再搜同一局面只剩 **1** 次进入——缓存命中，整个搜索直接返回。

**那 1,886 → 1,742 少的 144 次是谁的功劳？** 是第 2 条**浅层排序**（深层的招法顺序变好、剪枝更早生效），
不是置换表。要验证这一点，把 `ordered_moves` 换成直通 `base_moves` 再跑一遍即可。
