## 3. 逐个说清：解决什么 + 边界在哪

### 3.1 无信息搜索 —— 图上找路，但没有任何方向感

三个算法**共用同一套主循环**，唯一区别是「取出规则」：栈（DFS）、队列（BFS）、
按累计代价的堆（UCS）。所以 **BFS 是 UCS 在「每步代价都是 1」时的特例**。

- 解决的问题：DFS 只要「走到」；BFS 求无权图**最少步数**；UCS 求带权图**最小总代价**
- **边界**：
  - **BFS/UCS 的内存是分水岭**——边界要装下整整一层，规模一大就爆
  - 反直觉：**DFS 的边界峰值实测反而最大**（「DFS 省内存」是小规模上的假象，趋势上才成立）
  - 带权图上 **BFS 会次优**（它保证的是步数，不是代价）
- 详细内容见 [uninformed-search/README.md](uninformed-search/README.md)（含手算示例与内存对照图）

### 3.2 A\* —— 同样找路，但要「有方向感」

**A\* 只是把 UCS 的「按 g 排队」换成「按 g + h 排队」**——多出来的 `h` 就是方向感。
本实验用同一张图量化了 h 的全部价值（对照跑 UCS/Dijkstra）。

- 解决的问题：在大图上**又快又准**地找最短路
- **边界**：
  - **h 一旦高估，最优性立刻没了**（本实验用加权 A\* 逐档展示了这个代价）
  - **内存瓶颈**：open 集可能指数膨胀 → 出路是迭代加深（见第 1 个实验的 project）
  - 平局策略**不独立于 h**，它是 h 的下游（本实验逐变量量化过）
- 详细内容见 [a-star/README.md](a-star/README.md)

### 3.3 Minimax / Alpha-Beta —— 有人在跟我作对

把「我取最大、对手取最小」交替递归下去。给出的不是乐观估计，
而是**在最坏情况下的最好结果**（博弈论意义上的最优）。

**Alpha-Beta 解决它的成本问题**：剪掉不可能被选中的分支，**结论完全不变**。

- 解决的问题：完全信息、双人零和的最优决策
- **边界**：
  - **树一大就算不动**，而且它依赖一个**人写出来的评估函数**
  - 限深之后「评估质量 > 搜索深度」（本实验的迁移项目用自对弈量化了这一点）
  - 招法顺序影响剪枝量（但本实验也证明：**浅层重算排序可能净亏**）
- 详细内容见 [minimax-alphabeta/README.md](minimax-alphabeta/README.md)

### 3.4 MCTS —— 树大到算不完，连局面分都估不出来

换掉「评估函数」这个依赖：不再要人给局面打分，而是**随机模拟到终局看谁赢**，
用「模拟出来的胜负频率」代替它。四阶段循环在回答一个问题：
**手上只有 N 次模拟，该把它花在哪些分支上？**

- 解决的问题：**算不清的博弈树**（围棋那类），以及「任何时刻都得给答案」的决策
- **边界**：
  - **存在「最少要给多少次」的门槛**——给不够模拟次数时，它不如一个浅层精确搜索
  - 单次决策**方差大**（靠采样）
  - 裸 UCB1 的探索项与总次数强耦合；**「每次模拟值多少」和「模拟多少次」同样重要**
  - **只处理完全信息**（对手的牌看得见）——这条正是 CFR 的入口
- 详细内容见 [mcts/README.md](mcts/README.md)

### 3.5 CFR —— 我看不到对手的牌

前四个实验都假设「棋盘是大家都看得见的」。扑克里同一步棋，在「对手拿大王」和
「对手拿小王」两种世界里可能是好棋也可能是坏棋，**而你分不清自己在哪个世界里**——
这一下把前面所有办法都堵死了。

CFR 换了个思路：**不去找「最好的那一步」，而是让「后悔」消失**——
每手都记一笔「当时选另一个动作能多赚多少」，按后悔调概率，
直到没有动作值得后悔（= 纳什均衡）。

- 解决的问题：**不完全信息**、双人零和的策略学习（扑克、安全博弈）
- 关键概念差别：**信息集 ≠ 状态**——信息集里**不含对手的私有信息**
- **边界**：
  - 只处理**零和**；一般和博弈要用 CFR 的扩展
  - 本实现遍历整棵博弈树；真实扑克量级必须上**抽象 + 采样**
  - **「接近纳什」不等于「对任意对手收益最大」**（本实验量化了这个反差）
- 详细内容见 [cfr/README.md](cfr/README.md)

### 3.6 CSP —— 根本没有图，只有一堆限制

前五个都在图（或博弈树）上「走」；CSP 的问题是**给一堆变量各挑一个值，
让所有约束同时满足**（八皇后、数独、排课、地图着色）。
搜索空间不是画出来的，而是**约束定义出来的**。

- 解决的问题：约束满足（可行性），并可扩展到约束优化（在可行解里择优）
- 三个标准手段：**回溯**（骨架）、**约束传播**（把「将来必然失败」提前到现在）、
  **启发式**（先挑最受限制的变量、先试最不添乱的值）
- **边界**：
  - **节点最少 ≠ 总耗时最短**——传播越强，单次传播越贵（本实验逐档量化过）
  - **启发式的价值取决于问题结构**——同一套启发式在不同问题上效果可能相反
  - 本实现只做**二元约束 + 硬约束**；真实排班要软约束与全局约束传播
- 详细内容见 [csp/README.md](csp/README.md)（含「再写一遍题」式的排班迁移项目）

## 4. 现实里谁在用：每个实验对应的业务问题

上一节讲的是「算法上解决什么」，这一节讲「**现实里谁在用、解决什么业务问题**」。
每条都标了「什么时候会被换掉」——因为**生产系统里往往不是教科书那个算法**，
而是它的某个变体，或者干脆是另一条路线。

### 4.1 无信息搜索：分层探索与「必须求出精确解」的场合

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| 社交网络的**最短关系链** | 早期社交产品的好友推荐 | 无权图 + 求最少跳数 = 纯 BFS，不需要任何启发式 |
| GPS 导航的**最底层** | 各类地图的最短路内核 | 图太大时必须先做预处理分层，A\* 只跑最后一公里（见下一条） |
| **滑块 / 华容道 / 魔方求解** | 益智求解器、魔方求解器 | 需要**精确最优解**，而且状态空间大 → IDA\*（内存线性） |
| **编译器指令调度** | 部分后端优化 pass | 小规模图上求最短延迟，规模小到可以求精确解 |
| **网络路由**（小型 / 域内） | OSPF 等域内路由 | 本质是带权最短路（Dijkstra = UCS 的同族） |

> **什么时候被换掉**：规模一大，BFS/UCS 的内存就爆（本实验实测过）。
> 出路不是「换个更聪明的搜索」，而是**改变问题表示**——分层、
> 或牺牲最优性换取可解（见 A\* 那条的「有界次优」）。

### 4.2 A\*：只要「在图上找最优路径」，几乎都有它的影子

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| **地图导航** | Google Maps、高德/百度、Mapbox | 边权 = 长度 ÷ 限速 + 实时路况 + 转向惩罚；目标是「最短**时间**」 |
| **网约车 / 外卖派单** | Uber、滴滴、美团 | 接驾路径与配送路径；追求秒级响应 |
| **游戏 NPC 寻路** | Unity NavMesh、Unreal Navigation、各类 3A | 导航网格上找路，且每帧有严格预算 |
| **仓储机器人调度** | 亚马逊 Kiva 系、各类 AGV | 几百台车同图避碰，需要动态重规划 |
| **扫地机器人** | 石头、科沃斯等 | 覆盖路径规划与「回充找最近基座」 |
| **芯片布线 / PCB 走线** | EDA 工具 | 网格上的最短路径 + 约束回避 |

> **什么时候被换掉**：**真实导航不是裸 A\***。全国路网直接搜会慢到不可用，
> 生产实现先做**预处理分层**（把路网压成几百万条捷径），A\* 只在最后一段精修。
> 另外当「最优」不划算时（实时性优先），会退化为**有界次优**（加权 A\* 那一类）——
> 本实验的 `weight` 参数就是这个思路的最小演示。

### 4.3 Minimax / Alpha-Beta：必须考虑「对手会怎么害我」

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| **棋类引擎** | Stockfish（国际象棋）、各类象棋/五子棋引擎 | 完全信息零和博弈，且局面评估函数人类研究了几百年 |
| **已解游戏** | 四子连珠、黑白棋等残局库 | 游戏被「解掉」之后直接查表，本质是穷举 + 剪枝的产物 |
| **安保 / 巡检调度** | 机场安检巡逻、海岸警卫队巡逻排班 | 「**攻方会挑最薄弱点**」——防守方要在最坏情况下最优（Stackelberg 博弈） |
| **对抗性推演** | 军事推演、红蓝对抗仿真、追逃问题 | 双方目标相反，必须假设对手最优 |
| **鲁棒决策 / 风控** | 容量规划、SLA 兜底、minimax regret | 不假设概率分布，只假设最坏情况会发生 |

> **工程现实**：生产棋类引擎里**几乎看不到「minimax」这个名字**——
> 它以「Alpha-Beta + 置换表 + 迭代加深 + 招法排序」这套组合的形式存在。
> 本实验测出的两个结论正是这些引擎要花一半工程量解决的问题：
> **限深之后「评估质量 > 搜索深度」**、**浅层重算排序可能净亏**。

### 4.4 MCTS：模拟便宜、但状态空间大到无法穷举

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| **围棋 AI** | AlphaGo、AlphaZero、KataGo | 分支因子约 250、一盘 150 手 —— 穷举完全不可能 |
| **电动车辆路径规划**（带多约束） | 研究系统已经用 Gumbel AlphaZero | 决策空间巨大、约束多，用蒙特卡洛树来分配有限的评估预算（[来源](https://www.mdpi.com/2624-6511/9/2/21/pdf)） |
| **复杂电子游戏 AI** | 即时战略、MOBA 的宏观决策 | 动作空间巨大、需要长程规划 |
| **化学 / 材料发现** | 逆合成路径规划、分子设计 | 搜索空间爆炸，**而单次评估（模拟实验）很贵**，所以要把预算分配给最有希望的候选 |
| **组合优化与调度** | 车间作业调度、装箱、车辆路径 | 把「逐步做决策」建成树，用随机模拟评估每个决策的后果 |
| **线上资源分配** | 推荐位排序、广告出价、A/B 试验分配 | 本质上就是**多臂老虎机**（MCTS 的选择规则就是 UCB1） |

> **什么时候不划算**：**模拟或评估很贵的时候**。MCTS 的整个前提是「我能低成本地把
> 一条路走到底看结果」；一旦单次模拟要跑一次真实实验或一次昂贵仿真，
> 它的预算就完全不够——那时要靠**学出来的估值网络**来替代模拟。
> 而且本实验实测过：**给不够模拟次数，它不如一个浅层精确搜索。**

### 4.5 CFR：看不到对手底牌、但规则能枚举

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| **扑克 AI** | Libratus、Pluribus、DeepStack | **不完全信息**的标杆：对手的牌看不见，minimax/MCTS 的状态前提失效 |
| **安全博弈** | 机场巡逻、反盗猎、海岸巡逻的调度系统 | 防守方要随机化到「攻击者无法摸清规律」，这正是混合策略的意义 |
| **拍卖 / 议价机制** | 广告竞价策略、双边议价 | 双方都有私有估值（我出价多少对手不知道） |
| **谈判与合同设计** | 自动谈判代理 | 同上：私有信息 + 零和或常和 |
| **医学 / 军事决策** | 带隐藏状态的决策支持 | 诊断结果、敌方位置都是私有信息 |

> **什么时候被换掉**：**博弈树大到无法遍历时**。本实验的实现每轮遍历整棵博弈树，
> 教学规模的 Leduc（144 个信息集）只要 5.2 秒，但德州扑克是 ~10^160 量级——
> 生产系统必须上**抽象**（把相似的牌力合并）+ **采样**（每轮只走一条路径）。

### 4.6 CSP：排班、排课、排线 —— 「没人指望有唯一解」的问题

| 现实问题 | 谁在用 | 为什么是它 |
|---|---|---|
| **考试排考 / 排课** | 各类教务系统、排课软件 | 硬约束（教室容量、冲突课程）+ 软约束（尽量别连排） |
| **护士排班 / 人员轮值** | 医院排班系统、呼叫中心排班 | 班次覆盖、连续工作上限、个人偏好 |
| **航空机组排班 / 航班恢复** | 航司运行控制系统 | 法规约束 + 成本优化；航班延误时的重排是「带软约束的实时 CSP」 |
| **课程表 / 生产计划** | APS 生产排程系统 | 资源与被加工件的多重约束 |
| **数独 / 谜题求解** | 各类求解器 | 纯约束满足，是 CSP 最好的教学演示 |
| **编译器寄存器分配** | 生产编译器的后端 | 图着色问题：变量不冲突才能共用寄存器 |

> **生产现实与教科书的差距**（本实验的迁移项目专门演示了这一点）：
> 1. **真正的目标是「在可行解里选最好的」**，而不是「找一个可行解」——
>    这就是 CSP 与约束优化（COP）的分界，**必须引入软约束与代价**；
> 2. **小实例上局部搜索可能「一步都走不动」**（本实验的排班项目里单点交换接受率是 0，
>    换成 2-opt 才动得起来）——**邻域大小决定局部搜索能不能用**；
> 3. 工业求解器（如 OR-Tools 的 CP-SAT）靠的是**全局约束**（AllDifferent 的专用传播算法），
>    而不是把约束拆成一堆二元约束——本实验的练习第 4 题量化了这两者的差距。

### 4.7 一条贯穿六个实验的工程规律

把上面六张表放在一起看，会发现同一条规律反复出现：

> **这些算法能用，前提是「那条最贵的依赖」足够便宜。**
> 模拟便宜 → MCTS 可用；规则可枚举 → CFR 可用；约束传播便宜 → CSP 可用；
> 评估函数可信 → Minimax 可用；h 好设计 → A\* 可用。
>
> **一旦那条依赖变贵，出路不是「换个更聪明的算法」，而是换掉那条依赖**
> ——用分层换搜索、用学习换模拟、用抽象换遍历、用软约束换「可行即可」。

## 5. 一条「依赖被逐级替换」的链

```
无信息搜索    什么都不依赖 —— 所以慢（全向铺开）
   ↓ 加一个 h
A*           依赖：h（一个不高估的下界）
   ↓ 加一个对手
Minimax      依赖：评估函数（人为给局面打分）
   ↓ 树大到算不完
MCTS         依赖：模拟次数（用随机胜负频率代替评估函数）
   ↓ 看不到对手的牌
CFR          依赖：信息集 + 后悔（不再搜索"世界"，而是学"我该怎么做"）
   ↓ 问题形态变了（没有图，只有约束）
CSP          依赖：约束传播（没有"走法"，只有"允许的组合"）
```

**每一级替换的都是上一级最贵的那个依赖**：设计 h → 写评估函数 → 给够模拟次数
→ 处理信息集 → 处理约束。

## 6. 六个实验划出的边界（没有两条是重复的）

这是本族最值得带走的东西：**每个实验都独立测出了别人的方法在哪失效**。

| 实验 | 它自己测出的边界 |
|---|---|
| 无信息搜索 | BFS/UCS 的**内存**会爆；DFS 的内存优势在小规模上是假的 |
| A\* | **h 高估就失去最优**；平局策略只是 h 的下游 |
| Minimax | **树大就算不动**；限深之后「评估质量 > 搜索深度」 |
| MCTS | **给不够模拟次数就不如浅层精确搜索**；方差大 |
| CFR | **接近纳什 ≠ 最大化利用**；真实规模必须抽象 + 采样 |
| CSP | **节点最少 ≠ 总耗时最短**；启发式价值取决于问题结构 |

## 7. 该读哪个？（按你的目的选）

| 你的目的 | 建议 |
|---|---|
| 入门「搜索」这个概念 | 无信息搜索 → A\*（这两个是一条连续线：先看「没有方向感」多慢） |
| 做棋类 / 对抗性决策 | Minimax → MCTS → 它们的 [project](mcts/project/README.md) 对照（谁在什么规模下更强） |
| 做扑克 / 拍卖 / 安全博弈 | CFR（重点看「信息集 vs 状态」那一节） |
| 做排班 / 排课 / 数独 / 规划 | CSP（重点看「约束传播」与「节点数 ≠ 耗时」） |
| 想理解「哪种方法什么时候失效」 | 每份 README 的「局限与延伸」段，以及上表 |

## 8. 常见的三个误读

- **❌ 「A\* 是 BFS 的改进版」** —— A\* 的直接前身是 **UCS**（按 g 排队）；
  BFS 只是「每步代价都是 1」的特例。要理解 h 的价值，得先看清「没有 h 时」（UCS）多慢。
- **❌ 「MCTS 比 Minimax 先进」** —— 它们解决**不同规模**的问题。
  树能算动时精确搜索同强度下快一个量级；树算不动时 MCTS 才是唯一选择。
  **选择标准不是「哪个算法好」，而是「这棵树你还算不算得动」。**
- **❌ 「CFR 是 MCTS 的变体」** —— 它们处理的前提不同：
  MCTS 假设**完全信息**（一个状态一个值），CFR 处理**不完全信息**（按信息集学习）。
  从 MCTS 到 CFR 不是「改进」，而是**换掉了「世界是公共知识」这个前提**。

## 9. 本族的范围边界（没覆盖什么）

本族只覆盖路线文档 **2.2 符号主义**里的两部分——**搜索**（2.2.1 全部）
与**约束满足**（2.2.2 的第一条）。**2.2.2 逻辑推理的其余四条目前没有实验**：

| 路线文档 2.2.2 列出 | 状态 |
|---|---|
| 约束满足问题 CSP | ✅ [csp](csp/) |
| 命题逻辑 | ⬜ 无实验 |
| 一阶谓词逻辑 | ⬜ 无实验 |
| 归结推理 | ⬜ 无实验 |
| 逻辑规划 | ⬜ 无实验 |

**为什么没做**：这四条属于「知识表示与推理」，与前三类的算法形态差别更大
（不是「搜索一个解」，而是「在形式系统里做推导」），更适合单独成族
（如 `p01b-logic` 之类），而不是塞进搜索族。

**两条由本族实验划出来的、与它们相邻的边界**：

- **约束满足 ≈ 一种受限的逻辑推理**：CSP 的约束就是「命题」，传播就是「受限的推导」；
  把 CSP 做到极致（全局约束、冲突学习）已经接近 SAT/SMT 求解器的方法，
  而 SAT 正是命题逻辑推理的现代工程形态。
- **搜索与规划的分界**：本族做的是「**显式**状态空间上的搜索」；
  一旦问题变成「用逻辑语言描述动作与目标、由求解器自动搜」（PDDL / STRIPS 那一类），
  就跨到了**自动规划**——它的内核仍是 A\* 那一套（启发式 + 最优性），只是状态是生成的。
