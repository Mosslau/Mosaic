# 参考解：第 4 题（实现）

代码：`sol-04-PUCT.py`（只用标准库）

## 选择规则

```
PUCT(s,a) = Q(s,a) + C · P(s,a) · √N / (1 + n)
            Q = value / visits（平均收益，利用）
            P = 先验概率（这步"看起来"多好）
            N = 父节点访问数，n = 该招法访问数
```

与 UCB1 的差别只在探索项：

| | 探索项 | 含义 |
|---|---|---|
| UCB1 | `C√(ln N / n)` | **均匀**补贴：所有没试够的招法机会均等 |
| PUCT | `C·P·√N/(1+n)` | **按先验加权**补贴：看起来好的招法优先被试 |

先验用一个任何棋类都能算的启发式：**走完之后，我方的即时威胁数 − 对手的即时威胁数**，
在根节点 softmax 归一化（保证为正）。就这么弱的先验，也已经把结果拉开了。

## 实测（对精确搜索 alphabeta(depth=9)，先手，各 40 局）

| 选择规则 | iterations | 和 | 负 | 不输率 |
|---|---|---|---|---|
| UCB1 | 10 | 21 | 19 | **52%** |
| PUCT | 10 | 27 | 13 | **68%** |
| UCB1 | 50 | 39 | 1 | 98% |
| PUCT | 50 | 40 | 0 | **100%** |
| UCB1 | 100 | 40 | 0 | **100%** |
| PUCT | 100 | 39 | 1 | 98% |

三档合计不输率：**PUCT 88% vs UCB1 83%**。

## 怎么读

1. **收益主要落在"模拟次数少"的那一档**（10 次：52% → 68%）。这正是 PUCT 的设计目的：
   UCB1 的 `√(ln N / n)` 在总次数很少时区分度极低（实验三里 C=0 反而最好就是这个原因），
   而 PUCT 直接用先验**把次数导向有希望的分支**。
2. **次数给足之后两者打平**（100 次时都是 98%–100%）。先验的价值主要在"次数不够"时兑现——
   这也是它适合围棋这类"永远不可能给够次数"的问题的原因。
3. **单档 1–2 局的差异是小样本噪声**：40 局、固定种子，`98%` 与 `100%` 之间不足以说明谁更强。
   所以脚本断言的是"三档合计不劣于 UCB1"，而不是"每一档都赢"。
