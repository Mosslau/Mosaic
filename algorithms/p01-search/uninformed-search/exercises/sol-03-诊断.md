# 参考解：第 3 题（判断）

三个片段**结论不同**——不是"都有 bug"。这正是本题的考点：**分清"不报错"和"性质不成立"**。

| 片段 | 结论 | 破坏了什么 | 会不会报错 |
|---|---|---|---|
| A（BFS 无判重） | ❌ **真问题** | 工作量从 O(V) 爆成 O(路径数)（9×9 上 1.5 亿次取出） | 不会 |
| B（UCS 无过期判断） | ⚠️ **不破坏正确性**；本实验的图上**连效率差都没有** | 理论上多干活，但网格类图上不触发 | 不会 |
| C（DFS 只在取出判重） | ⚠️ **不破坏正确性**，破坏"内存 O(深度)"这条卖点 | 边界规模从 O(深度) 涨到 O(边数) | 不会 |

## 片段 A：BFS 不在入队时判重

**性质破坏**：正确性没坏（找到的仍是最短），坏的是**"每个节点最多进边界一次"**这条不变式。

实测（全开放 n×n，(0,0) → (n-1,n-1)，取出次数）：

| 图 | 无判重取出 | 有判重取出 | 倍数 |
|---|---|---|---|
| 3×3 | 37 | 9 | 4× |
| 5×5 | 4,491 | 25 | 180× |
| 7×7 | 778,059 | 49 | 15,879× |
| 9×9 | **150,775,347** | 81 | **1,861,424×** |

**为什么**：队列里装的不再是"节点"，而是"**路径**"。同一个节点有几条路能到，它就会被放进队列几次——
路径数随深度**指数增长**，于是 9×9 就要 1.5 亿次取出。

**"会不会死循环"**：**不会**——有限图上路径数有限，队列最终会空。
但"会终止"和"能用"是两回事：它要先把**所有路径**枚举完才停。
实测目标不可达时取出 **20,000,000 次**才自然结束（不是死循环，是活活算完）。

所以 A 的完整答案是：**它不报错、不死循环、结果也对，唯一的问题是工作量**——
队列里装的是**路径**而不是节点，路径数随深度指数增长。

**30 行测试**：

```python
from collections import deque

def bfs_a(grid, start, goal):                      # 待测实现
    q, pops = deque([start]), 0
    while q:
        n = q.popleft(); pops += 1
        if n == goal: return n, pops
        for nb in neighbors(grid, n): q.append(nb)
    return None, pops

def test_a():
    open9 = [[0] * 9 for _ in range(9)]
    # 1) 可达：能结束，但取出次数远大于节点数（81）
    r, pops = bfs_a(open9, (0, 0), (8, 8))
    assert r == (8, 8)
    assert pops > 1000, f"应当大幅超出 81 个节点，实际 {pops}"
    # 2) 目标不可达：会终止，但要枚举完所有路径（取出次数爆炸）
    walled = [[0, 0, 0], [0, -1, 0], [0, 0, 0]]
    assert bfs_a(walled, (0, 0), (9, 9))[1] > 100_000, "不可达时也应付出巨大工作量"

test_a()
```

（`neighbors` 与 `impl.py` 口径一致：四方向、邻居顺序 上/下/左/右。）

## 片段 B：UCS 不判断"过期堆项"

**结论：不破坏正确性。** 代价非负时它仍返回最优解——
因为"过期项"的 `d` 只会**大于等于**已经确定的最短距离，弹出它时不会让任何距离变小。

**而且在本实验的图上，实测连"多干活"都没有**：

| 场景 | 无判断 | impl（有判断） |
|---|---|---|
| 21×21 带权图（seed=200） | 代价 136，扩展 344 | 代价 136，扩展 344 |
| 刻意构造的 2×3 菱形地形（绕路更便宜） | 代价 7，扩展 4 | 代价 7，扩展 4 |

**为什么网格类图上不触发**：节点代价只相差 1–9，导致"到相邻两点的最短路长度差"有界，
于是第一次弹出某节点时它的距离**已经最优**，不会产生"更小的值后来又进来"的情况。
在边上权重差异很大的**一般图**上才会出现重复入堆与重复扩展。

**所以 B 的正确答案是**："它是对的，但省掉了一个**防御性**检查；
在有负权或权差很大的图上会导致重复扩展（而非错误结果）。"
——把 B 当成"错误实现"是过度判断；把它当成"完全没问题"又漏了"重复扩展"这个隐患。

## 片段 C：DFS 只在取出时判重

**正确性没坏**（仍找到解、步数一致），坏的是**内存卖点**：

| 图（seed=42） | 片段 C 栈峰值 | impl（入栈判重）边界峰值 | 步数 |
|---|---|---|---|
| 42 | 125 | 58 | 82（两者相同） |
| 1 | 125 | 71 | 80（两者相同） |
| 2 | 174 | 74 | 70（两者相同） |

全开放 n×n 上，取出次数也涨 2–3 倍（9×9：117 vs 49）。

**为什么**：栈里塞满了"已经访问过、但还会被重新压入"的节点。
DFS 的经典卖点是"空间 O(深度)"，而入栈不判重会把它推成 **O(边数)**——
在网格上就是"多存了几倍"，在稠密图上会差一个数量级。

**30 行测试**：

```python
def dfs_c(grid, start, goal):
    stack, seen, peak = [start], set(), 0
    while stack:
        peak = max(peak, len(stack))
        n = stack.pop()
        if n in seen: continue                     # ← 唯一的防线
        seen.add(n)
        if n == goal: return peak
        for nb in neighbors(grid, n): stack.append(nb)
    return peak

def test_c():
    import impl
    from demo import make_grid
    grid, s, g = make_grid(seed=42)
    peak_c = dfs_c(grid, s, g)
    peak_ok = impl.dfs(grid, s, g).peak_frontier
    assert peak_c > peak_ok * 1.5, f"应当明显更耗内存：{peak_c} vs {peak_ok}"

test_c()
```

## 一句话总结

**三个片段都不报错，但只有一个（A）真的破坏了正确性相关的性质。**
判断"能不能用"之前要问：**这里被我牺牲的是正确性，还是效率，还是内存？**
本实验的三个算法恰好各有一个"可被牺牲的性质"，而它们**不在同一个维度上**。
