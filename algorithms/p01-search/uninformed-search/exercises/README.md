## 第 3 题（判断）三个"看起来都对"的实现

**目标**：练第 3 级——定位"不报错但性质不成立"的实现错误。

**要求**：三个实现片段，分别判断**对不对**，错的要指出"哪条性质被破坏、如何用一个测试发现"。

```python
# 片段 A：BFS 但入队时忘了判重
def bfs_a(grid, start, goal):
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal: return node
        for nb in neighbors(grid, node):
            queue.append(nb)            # ← 没有 seen 集合
```

```python
# 片段 B：UCS 但取出时不做"过期堆项"判断
def ucs_b(grid, start, goal, cost_of):
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, node = heapq.heappop(heap)
        if node == goal: return d
        for nb in neighbors(grid, node):
            nd = d + cost_of(nb)
            if nd < dist.get(nb, float("inf")):
                dist[nb] = nd
                heapq.heappush(heap, (nd, nb))     # ← 没有 if d > dist[node]: continue
```

```python
# 片段 C：DFS 但把"取出时判重"当成唯一防线
def dfs_c(grid, start, goal):
    stack, seen = [start], set()
    while stack:
        node = stack.pop()
        if node in seen: continue
        seen.add(node)
        if node == goal: return node
        for nb in neighbors(grid, node):
            stack.append(nb)           # ← 入栈时不判重
```

**要求**：

1. 分别说明每个片段**是否**破坏性质（有的可能"只是慢"，不破坏正确性——要分清）。
2. 对每个"确实有问题"的片段，写出一个**能在 30 行内跑出来的测试**（给一个具体的小图与期望结果）。
3. 片段 A 在**有环**的图上会发生什么？在**无环**的图上呢？
   （提示：先想清楚"它会不会死循环"，再想"那它到底慢在哪"——这两问的答案不一样。）

**验收标准**：三问结论正确；第 3 问要给出"会不会终止"与"工作量量级"两个结论。

**提示**：想清楚"每个节点最多进边界几次"与"取出时判重"这两件事的关系。

## 第 4 题（实现）手写迭代加深并量化它的重复代价

**目标**：练第 4 级——把学到的内容组合成新算法，并用数字说明代价。

**要求**：新建 `sol-04-迭代加深.py`（只用标准库），实现：

1. `ids(grid, start, goal)`：迭代加深（限深 DFS，深度上限从 1 逐层加深），返回
   `(路径, 深度, 扩展数)`；
2. `bfs_count(grid, start, goal)`：BFS 并统计扩展数（可直接调用 `../impl.py` 的 `bfs`）；
3. 在一张 15×15 以上的随机地图上跑两者，打印对照表：**扩展数、内存尖峰、耗时**；
4. **自检断言**：
   - 两者给出的**步数必须相同**（在无权图上 IDS 与 BFS 都是最优）；
   - IDS 的扩展数必须**大于** BFS（因为它重复搜索浅层）；
   - IDS 的内存尖峰必须**小于** BFS（这是它换来的东西）。

**验收标准**：脚本能独立运行（`python3 sol-04-迭代加深.py`），断言全部通过，并打印对照表。

**提示**：迭代加深的"重复"是**故意的**——用重复的时间换线性的内存。
断言"扩展数更大但内存更小"就是在验证这笔交易真的发生了。

## 第 5 题（迁移）把三个算法用到"带权地图 + 代价上限"的新约束上

**目标**：练第 5 级——迁移到新约束，并理解"目标变了，算法选择就变了"。

**要求**：新建 `sol-05-迁移.py`（只用标准库）。新场景：地图上每格有进入代价 1–9，
但你现在关心的不是"总代价最小"，而是——

> **在总代价不超过预算 B 的前提下，步数最少的那条路。**

1. 说明为什么**原样的 BFS / UCS 都不能直接回答这个问题**（各写一句）。
2. 实现一个能回答它的搜索：状态需要从"位置"扩展成 **`(位置, 已花代价)`**，
   并说明为什么必须把代价放进状态里（否则会漏解）。
3. 在一张 **7×7** 的带权图上跑，报告 `B = 25` 时的最优步数与路径（给复现命令）；
4. 回答：**同一个局面下预算 B 从 25 调到 40，答案会怎么变？先用嘴说，再跑一下验证。**

**验收标准**：给出实测的步数与路径；第 1、4 问的结论要落到"**状态空间的定义决定了能不能搜到解**"这一点上。

**提示**：把代价放进状态会把状态空间放大很多倍——这正是"约束改变 → 状态定义改变 → 搜索代价改变"的完整链条。
