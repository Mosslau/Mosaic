# 迁移项目：把词向量封装成「关系检索」服务

把 `impl.SkipGramNS` 学到的 94×32 词向量接成一个可查询的检索层 `RelationIndex`，
在三个任务上验收。与教学 demo 的差别：

- demo 只在「留出类比题」上打分；这里要维护一个**可裁剪的候选池**（知识库只收某类实体），
  并新增「关系补全」与「同类别检索」两个下游任务；
- demo 直接算余弦；这里把三项能力收敛到 `nearest / analogy / complete` 三个接口；
- 必须回答「配对词要不要排除」——否的则纯度指标会虚高。

## 需求

| 项 | 说明 |
|---|---|
| 输入 | 一份分词后的合成语料（与 demo 同源，`demo.build_corpus(0)`） |
| 输出 | 一个 `RelationIndex`：训练一次，之后按词检索 |
| 新约束 | ① 检索限定候选池；② 必须能排除「配对词/查询词」；③ 三项任务共用同一份向量 |
| 不做 | 不训练新模型、不做真实语料、不做 GPU |

## 功能清单

- [x] `RelationIndex.nearest(word, topk, candidates, block)`：候选池可裁剪、可屏蔽指定词
- [x] `RelationIndex.analogy(a, b, c)`：3CosAdd，自动排除查询词
- [x] `RelationIndex.complete(left, relation)`：在指定关系的右词池里补全搭档
- [x] 任务 A/B/C 的评估与断言

## 验收标准

| 任务 | 指标 | 阈值 | 实测（2026-10-26，seed=0） |
|---|---|---|---|
| A 类比检索 | 留出题 top-1（42 题） | > 0.75 | **0.833** |
| B 关系补全 | 候选池内 top-1（28 对） | > 0.70 | **0.750**（country 10/10，gender 5/6，plural 6/6，tense **0/6**） |
| C 同类别检索 | precision@3（56 词，排除配对词） | > 0.85 | **0.923** |

**已知边界**：B 的时态关系 0/6。6 个过去式动词的向量两两余弦约 0.97，
在「只有 6 个候选」的池子里几乎共线，余弦排序区分不出哪个过去式对应哪个现在式；
这与 demo 里「维度越高、最近邻纯度越低」是同一个现象的两面：
**向量空间保住了「类」，不一定保住「类内身份」**。若要修，方向是加大语料/拉长训练，
或给候选池加结构特征，而不是继续调 `dim`。

## 扩展方向

1. 把候选池换成真实实体表（国家-首都、药品-适应症），接一个 `pandas` 读表；
2. 加 **3CosMul 混合打分**，在 A 上做 A/B 测试（demo 已见 3CosAdd 更好，值得在池内复核）；
3. 把 `complete` 换成**候选重排**：先按字符/拼音召回，再用向量余弦重排；
4. 加 HTTP 层（FastAPI）做成真正的检索服务，用 pytest 固定上面三个阈值。

## 运行方式

```bash
cd algorithms/p04-transformer/word-vectors
../../.venv/bin/python project/search.py
```

依赖：numpy（与实验目录相同，无额外依赖）。预期输出：

```text
索引：94 词 × 32 维（33262 token 语料）
A. 类比检索（42 题留出）top-1      ：0.833
B. 关系补全（候选池内）top-1          ：0.750   {'country-capital': '10/10', ...}
C. 同类别检索 precision@3（排除配对词）：0.923
检索示例：valdoria 的最近关系词 [('valport', 0.89), ...]
验收通过：A/B/C 三项均达到 README 的阈值。
```

耗时约 3 秒（本机，Python 3.13 / numpy 2.5.4）；三项指标为确定性结果，重跑应逐位一致。
