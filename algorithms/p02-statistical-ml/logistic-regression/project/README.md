# 迁移项目：客户转化预测 —— 不平衡 + 代价敏感阈值

## 需求

把逻辑回归用到"转化预测"上。与教学示例的差别是三个**新约束**：

1. **五个业务特征**：访问次数、停留时长、历史订单、优惠敏感度 + 一个噪声特征；
2. **正类只占约 7%**：默认阈值 0.5 会把绝大多数客户判为"不会转化"；
3. **代价不对称**：漏掉一个会转化的客户损失 20，误发一张优惠券成本 1。

数据为合成（`n = 5000`，`seed = 0`），真实 logit：

```
z = 1.1·访问次数 + 0.8·停留时长 + 1.4·历史订单 − 0.6·优惠敏感度 + 0·噪声 − 4.0
```

## 功能清单

- [x] 训练 / 验证 / 测试三段切分（阈值只在验证集上选）
- [x] 默认阈值 0.5 的基线
- [x] `class_weight="balanced"` 的重加权基线
- [x] 在验证集上按 `20·FN + 1·FP` 扫描阈值
- [x] 在测试集上比较三条路线的 accuracy / precision / recall / F1 / 总代价
- [x] 验收断言（AUC、代价、召回、阈值范围）

## 验收标准

1. 测试集 **AUC > 0.80**；
2. 调阈值后的测试**总代价低于默认 0.5**；
3. 调阈值后的**召回高于默认 0.5**；
4. 最优阈值**低于 0.5**；
5. 阈值来自**验证集**（不偷看测试集）。

脚本 `conversion.py` 内逐条断言。

## 实测结果（已验证）

环境：uv（Python 3.13.15 / numpy 2.5.4 / scikit-learn 1.9.1），`seed = 0`。
样本 5000：训练 3000 / 验证 1000 / 测试 1000；正类占比 7.2%。

| 方案 | 阈值 | accuracy | precision | recall | F1 | 总代价 | 判正比例 |
|---|---|---|---|---|---|---|---|
| 默认（阈值 0.5） | 0.50 | **0.9410** | 0.7826 | 0.2500 | 0.3789 | 1085 | 2.30% |
| 重加权 `balanced` | 0.50 | 0.8310 | 0.2657 | 0.7639 | 0.3943 | **492** | 20.70% |
| 默认 + 调阈值 | 0.05 | 0.7620 | 0.2057 | **0.8056** | 0.3277 | 504 | 28.20% |

测试集 **AUC = 0.8887**；验证集选出的阈值是 **0.05**（验证代价 370）。

**三条结论**：

1. **默认阈值 accuracy 最高（0.9410），但代价也最高（1085）**——accuracy 在这里完全误导：
   它只判了 2.3% 的客户为正，漏掉了四分之三的转化。
2. **调阈值把代价从 1085 降到 504**，召回从 0.25 提到 0.81；代价是精确率掉到 0.21。
3. **重加权（492）与调阈值（504）效果接近**，两条路线可以叠加；重加权改变模型，
   调阈值只改决策规则——后者更便宜，但要求你有可靠的验证集。

## 扩展方向

- 把阈值选择改成**两个阈值**（低于下界判负、高于上界判正、中间人工复核）；
- 加**概率校准**（Platt/Isotonic），比较校准前后的代价曲线；
- 用**成本敏感的重采样**（对少数类过采样）替代重加权，比较三条路线；
- 把验证集换成**时间切分**（用过去预测未来），检查阈值是否仍然稳定。
