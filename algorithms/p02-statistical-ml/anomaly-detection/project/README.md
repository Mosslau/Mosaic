# 迁移项目：真实 one-class 异常检测 —— 手写数字 0 vs 其他

## 需求

把异常检测用到真实高维数据上。与教学示例（二维高斯 + 远处异常）的差别是三个**新约束**：

1. **真实像素**：`load_digits` 的 8×8 数字，64 维；
2. **one-class**：训练只用数字 0（120 张），测试 = 未见的 0（58 张）+ 其他数字（100 张）；
3. **三种方法对照**：IsolationForest / LOF / KDE，阈值都用训练集 5% 分位。

## 功能清单

- [x] 只用正常样本训练三种检测器
- [x] 测试集 AUC、精确率、召回率、报警数
- [x] 阈值与分数方向统一（越大越异常）
- [x] 6 条验收断言

## 验收标准

1. IForest AUC **≥ 0.90**；
2. LOF AUC **≥ 0.90**；
3. KDE AUC **≥ 0.90**；
4. IForest 精确率 **≥ 0.80**；
5. LOF 精确率 **≥ 0.80**；
6. 三种方法召回率都 **≥ 0.90**。

脚本 `digits.py` 内逐条断言。

## 运行方式

```bash
cd algorithms/p02-statistical-ml/anomaly-detection/project
uv run python digits.py
```

依赖：numpy + scikit-learn（数据/指标）；运行约 1 秒。

## 实测结果（已验证）

环境：uv（Python 3.13.15 / numpy 2.5.4 / scikit-learn 1.9.1），`seed = 0`。

| 方法 | AUC | 精确率 | 召回率 | 报警数 |
|---|---|---|---|---|
| IsolationForest | 1.000 | 0.952 | 1.000 | 105 |
| LOF | 1.000 | **0.971** | 1.000 | 103 |
| KDE | 1.000 | 0.633 | 1.000 | 158 |

**四条结论**：

1. **三种方法都能把"其他数字"排到前面**（AUC 都是 1.000），但阈值表现差很多。
2. **IF/LOF 的 5% 阈值可用**：精确率 0.95/0.97；LOF 略好。
3. **KDE 的 AUC 完美、精确率只有 0.63**：排序没错，但密度阈值偏松——AUC 与阈值指标是两回事。
4. **one-class 的代价**：模型只见过 0，其他数字里有些写法接近 0，会被漏报/误报；阈值要按业务定。
