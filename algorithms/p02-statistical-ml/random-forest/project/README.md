# 迁移项目：真实 10 分类上的随机森林 —— 手写数字

## 需求

把随机森林用到真实多分类数据上。与教学示例（二维 moons）的差别是三个**新约束**：

1. **真实数据**：sklearn `load_digits`，1797 个 8×8 手写数字、64 维像素、10 个类别；
2. **不切验证集**：用 **OOB** 选树数，训练集之外只留测试集做最终报告；
3. **稳定性**：跨 5 个随机种子比较单树与森林的测试准确率波动。

## 功能清单

- [x] 单树基线（`n_trees=1, max_features=None`）
- [x] 树数扫描（10/25/50/100）的 OOB 与测试准确率
- [x] 用 OOB 选"够用就好"的树数
- [x] 跨种子稳定性（单树 vs 森林）
- [x] 像素重要性前 5
- [x] 7 条验收断言

## 验收标准

1. 测试集覆盖 **10 个类别**；
2. 森林测试准确率 **≥ 0.92**；
3. OOB 与测试差距 **≤ 0.05**；
4. 森林不差于单树 **1 个百分点以上**；
5. 选中的树数 **≤ 100**；
6. 森林跨种子标准差 **< 单树**；
7. 特征重要性归一化。

脚本 `digits.py` 内逐条断言。

## 运行方式

```bash
cd algorithms/p02-statistical-ml/random-forest/project
uv run python digits.py
```

依赖：numpy + scikit-learn（数据加载用）；运行约 10–15 秒。

## 实测结果（已验证）

环境：uv（Python 3.13.15 / numpy 2.5.4 / scikit-learn 1.9.1），`seed = 0`。

**树数扫描**：

| n_trees | OOB | 测试 acc | 耗时(s) |
|---|---|---|---|
| 10 | 0.8497 | 0.9537 | 0.34 |
| 25 | 0.9348 | 0.9704 | 0.86 |
| 50 | 0.9610 | 0.9778 | 1.91 |
| 100 | **0.9706** | 0.9759 | 3.52 |

OOB 在 100 棵时仍在缓慢上升，按"最大值 0.005 内"选中 **100 棵**（网格上界）；测试 **0.9759**、OOB **0.9706**。
**注意**：这是"边界选中"，不是"提前停"；要验证 OOB 饱和点，需要把网格扩到 200 棵以上。

**稳定性（5 个种子）**：

| 模型 | 测试 acc 均值 | 标准差 |
|---|---|---|
| 单树 | 0.8137 | 0.0195 |
| 森林（100 棵） | **0.9767** | **0.0025** |

**重要性前 5 的像素**：x21(0.051)、x26(0.042)、x36(0.041)、x42(0.039)、x43(0.038)
——集中在 8×8 图像的中部，符合"数字主体在中心"的直觉。

**四条结论**：

1. **OOB 与测试同量级**（0.9706 vs 0.9759，差 0.005），可以直接用来选树数，不必再切验证集。
2. **森林相对单树是量级提升**：0.8137 → 0.9767；单树在 10 分类上非常不稳（±0.02）。
3. **树数收益递减**：10→50 棵测试从 0.9537 到 0.9778，再往上基本持平；OOB 仍在缓升，说明"预测饱和"早于"OOB 饱和"。
4. **重要性是模型内的关联**：中部像素重要，只说明森林主要靠它们区分数字，不是因果。

## 扩展方向

- 用 **置换重要性** 与不纯度重要性对照，检查像素重要性是否稳定；
