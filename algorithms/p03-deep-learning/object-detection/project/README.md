# 迁移项目：多目标场景检测

把教学实验的 1–2 个目标迁移到 **2–3 个目标、允许部分重叠** 的巡检式场景：
目标重叠时颜色阈值会把多个目标并成一个连通域，正好检验"网格预测 + NMS"是否
补上了经典流水线的结构性洞。

## 1. 需求

- 数据：32×32 灰度合成图，每图 2–3 个目标（矩形/椭圆），两两 IoU ≤ 0.35；
- 可表示性约束：每个目标的中心必须落在不同网格（8×8 单类网格头，一格只能
  负责一个目标）；违反时重新采样场景；
- 模型：复用教学实验的 TinyYOLO-lite（4×4 池化 → 3×3 卷积 → 8×8 头）；
- 对照：颜色阈值 + 连通域基线，同一测试集；
- 指标：mAP@0.5、P、R、单图延迟；NMS 与置信度阈值只在 val 上选。

## 2. 功能清单

- [x] 场景生成器 `make_scene_dataset`：固定 seed、2–3 目标、中心格不冲突；
- [x] 训练/验证/测试三划分：640 / 160 / 200，seed 100/101/102；
- [x] NMS 阈值在 val 上按 AP 选，conf 在 val 上按 F1 选，test 只评估一次；
- [x] 与阈值基线同测试集对比 mAP / P / R / 延迟；
- [x] 验收断言（mAP > 0.80、比基线高 0.20 以上、recall > 0.85）。

## 3. 验收标准

1. 测试集 mAP@0.5 **> 0.80**；
2. 比颜色阈值基线高 **0.20 以上**；
3. 测试 recall **> 0.85**；
4. 只依赖 numpy（`impl.py` 无 sklearn / torch），固定 seed 可复现。

## 4. 运行方式

```bash
cd algorithms/p03-deep-learning/object-detection
uv run python project/detect_scene.py
```

依赖：numpy（仓库 `algorithms/pyproject.toml` 已声明）。本机实跑输出（2026-10-26）：

```text
场景：train 640 / val 160 / test 200；测试集 494 个目标，平均 2.47 个/图
训练：100 轮，loss 4.111 → 1.291，1.2s
NMS 阈值（val 选）：0.5；conf（val 选）：0.10
TinyYOLO-lite   mAP@0.5 0.931  P 0.879  R 0.953  0.523 ms/图
阈值+连通域      mAP@0.5 0.535  P 0.838  R 0.628  0.133 ms/图
基线参数（val 选）：thr 0.55 / min_area 10 / conf 0.35
验收通过：mAP 0.931 > 0.80，且比基线高 0.395
```

**读法**：模型 mAP 高 0.396，主要来自 recall（0.953 vs 0.628）——基线把重叠目标
并成一个连通域，漏掉其中一个；模型给每个目标中心格一个预测，再用 NMS 去重。
基线 precision 仍不低，因为它在"没重叠"的图上几乎不会误检。

## 5. 扩展方向

1. **更密的目标**：把 8×8 网格换成 16×16，或给每格 2 个 anchor，缓解"一格一目标"；
2. **多类别**：objectness 后接类别头，NMS 改成按类执行；
3. **更强基线**：分水岭 / 形态学开运算 / 自适应阈值，检验差距是否仍来自重叠；
4. **真实图像**：把合成图换成摄像头灰度图，观察光照/纹理变化下阈值法如何失效；
5. **端侧延迟**：把模型导出为定点推理，比较 0.5 ms/图还能压到多少。
