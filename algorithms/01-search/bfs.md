# BFS 广度优先搜索

> 状态：📖 理论文档（无对应实验目录，作为 01-search 家族基础篇）
> 对应文档章节：`roadmap/人工智能代表算法演进路线.md` 第 2.2.1 章

## 设计原理

**解决什么问题**：在图/树中找**步数最少**的路径（无权图最短路径），或按层系统遍历所有节点。

**核心思想一句话**：像水波一样从起点一圈一圈向外扩——永远优先扩展最早加入的节点（队列，FIFO），第 k 层全部访问完才碰第 k+1 层。

**为什么存在**：当边没有权重（或权重全为 1）时，"离起点近的先探索"这个简单规则恰好保证第一次到达任何节点时走的就是最短路径。它是所有最优性搜索的起点——UCS 是它的加权推广，A* 是它的定向推广。

## 数学推导

设分支因子 b，解深度 d。

| 量 | 复杂度 | 说明 |
|---|---|---|
| 时间 | O(b^d) | 最坏扩展完 d 层所有节点 |
| 空间 | O(b^d) | 队列要存整个 frontier（最宽的一层） |

**最优性证明思路**：队列的 FIFO 性质保证节点按 g（深度）非递减顺序出队。假设终点 G 在深度 d 首次出队，任何尚未发现的路径深度 ≥ d+1 > d，不可能更短。故首次到达即最短。

**BFS = UCS 的特例**：当所有边权 c(n,n') = 1 时，g(n) = 深度，按 g 最小扩展 ≡ 按深度最小扩展 ≡ FIFO 队列。所以 BFS 的正确性是 UCS 正确性的直接推论。

## 手写实现要点

```python
from collections import deque

def bfs(start, goal, neighbors):
    queue = deque([(start, [start])])
    visited = {start}
    while queue:
        node, path = queue.popleft()
        if node == goal:
            return path
        for nb in neighbors(node):
            if nb not in visited:
                visited.add(nb)          # 入队时标记，而非出队时
                queue.append((nb, path + [nb]))
    return None
```

**容易踩的坑**：

- **入队时标记 visited，不是出队时**：否则同一节点会被重复入队，队列指数膨胀。这是 BFS 最常见的 bug
- 用 `deque.popleft()`，别用 `list.pop(0)`——后者 O(n)，整体退化成 O(n²)
- 与 DFS 一样，存整条 path 会复制内存；大图上应存父指针 `{child: parent}`，找到后回溯重建
- 双向 BFS：起点终点同时扩，复杂度从 O(b^d) 降到 O(b^(d/2))——前提是从终点也能反向生成邻居

## 框架对照

无框架接口（基础原语），变体遍布各处：

| 场景 | 对应物 |
|---|---|
| 无权图最短路 | BFS 本身 |
| 树的层序遍历 | BFS（按层打印、锯齿遍历） |
| 迷宫连通性检查 | BFS 洪泛填充（flood fill） |
| 社交网络"二度人脉" | 限深 BFS |
| 地图生成连通性验证 | demo 里保证起点终点可达的工具函数 |

**对照基线**：DFS。同图对比路径长度（BFS 最短）与内存（BFS 更大）。

## 实验结果（预期）

- 无权网格上 BFS 找到的路径长度 = 曼哈顿/欧氏下界，必为最短
- frontier 大小随深度指数增长——这是它让位于 UCS/A* 的根本原因
- 水波状扩展的可视化：完美的同心圆（网格上为菱形/正方形波前）

## 局限与延伸

- **局限**：边权不一致时"步数最少 ≠ 代价最小"，BFS 失效；内存 O(b^d) 是硬瓶颈
- **延伸**：
  - 边有权重 → **UCS / Dijkstra**（按 g 而非按层扩展）
  - 知道终点方向 → **A***（g + h 定向扩展）
  - 两端都有信息 → 双向 BFS / 双向 A*
  - 超大图近似 → Beam Search（每层只保留 top-k，LLM 解码即此思想）
