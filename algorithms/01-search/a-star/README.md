# A* 启发式搜索

> 状态：✅ 已完成（2026-09-14）
> 对应文档章节：`roadmap/人工智能代表算法演进路线.md` 第 2.2.1 章

搜索求解器：本目录不是 sklearn 估计器，接口由 A* 自身的形态决定。

## 设计原理

A* 要解决的是**"最优性"与"方向感"不可兼得**的问题。在它之前的无信息搜索各占一头：BFS / 一致代价搜索（UCS，即 Dijkstra）保证最优，但对终点一无所知，只能以起点为圆心向四周全向膨胀——大量扩展节点浪费在背离终点的方向；贪心最佳优先搜索有方向感（只朝终点冲），却会一头撞进死胡同，不保证最优。

A* 的核心思想一句话：**把"已经付出的代价" g(n) 和"到终点的估计代价" h(n) 加在一起作为扩展优先级 f(n) = g(n) + h(n)**。g 保住最优性（不敢忽略已付出的真实代价），h 提供方向感（优先扩展看起来离终点近的节点）。可以证明：只要 h 不高估真实代价，这个简单的加法同时拿到两者——最优性来自 Dijkstra，效率来自方向感。

放在演进路线里看：A* 是符号主义搜索的集大成者——它之前的 DFS/BFS/UCS 是"无信息"的蛮力，它之后的 Minimax / MCTS 把搜索从"单人寻路"推进到"双人博弈"。Dijkstra 本身就是 h ≡ 0 的 A* 特例——本实验的 `baseline.py` 正是用一行 `heuristic=lambda a, b: 0` 复用 `solve()` 来证明这一点。

## 数学推导

记：g(n) 为起点到 n 的实际代价（`impl.py` 的 `g_score`），h(n) 为 n 到终点的估计代价（`heuristic`），h\*(n) 为真实最优代价，C\* 为最优路径总代价。扩展优先级：

```
f(n) = g(n) + h(n)        # open 堆按 f 排序
```

**可采纳性（admissible）**：h(n) ≤ h\*(n)，即启发式永不高估。四方向网格上曼哈顿距离可采纳：每走一步 |Δrow|+|Δcol| 最多减 1，所以曼哈顿距离是真实步数的下界。

**最优性证明**（反证）：设 A* 弹出一个次优终点 G'，g(G') > C\*。最优路径上必有一个节点 n 已进 open 集但尚未扩展（最优路径的起点已扩展，终点未达，沿路径找第一个未扩展者；其祖先都已最优扩展，故 g(n) 已是实际最优值）。于是：

```
f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* < g(G') = f(G')
```

f(n) < f(G') 意味着堆会先弹出 n 而非 G'——矛盾。故 A* 弹出终点时 g(goal) = C\*，最优性得证。

**一致性（consistent，更强的条件）**：h(n) ≤ c(n, n') + h(n')，即估计差不超越单步真实代价。一致性蕴含沿任意路径 f 单调不减，于是**每个节点首次弹出即最优、只需扩展一次**——`impl.py` 的 `closed` 判重与"过期堆项跳过"正是依赖这个性质才安全。曼哈顿距离在四方向网格上满足一致性（每步 c = 1，h 最多减 1）。

**最优效率（optimal efficiency）**：最优性只回答"找到的解对不对"，另一个同样经典的问题是"A* 的工作量是不是任何可采纳算法里最小的"。结论是：**A* 必然扩展每一个 f(n) < C\* 的节点，且（平局处理得当的话）只扩展这些节点**（Dechter & Pearl 1985）。论证分两半：

- **f(n) < C\* 的节点躲不掉**：一致性下沿任意路径 f 单调不减，故 n 的祖先们 f 值都不超过 f(n) < C\*，会比终点（f = C\*）先弹出，n 迟早入堆；而只要 n 在堆里，f(n) < C\* 就保证它先于终点弹出。换言之，**任何保证最优的算法都必须扩展这些节点**——它们与终点的"竞争"在信息不足时无法裁决。
- **f(n) > C\* 的节点不扩展**：它们排在终点之后，终点弹出时搜索已结束。

于是效率的全部不确定性集中在 **f(n) = C\* 的边界集**上：扩展其中多少，由平局破解（tie-breaking）决定。这精确解释了实验二的现象——无障碍网格上曼哈顿 h 处处是紧的，所有自由节点 f ≡ C\*（边界集 = 全图），insertion 平局退化为全图扩展 361 个节点，而 large_g 平局（同 f 优先扩展 g 大、即离终点更近者）直冲终点只扩展 37 个，恰好是路径本身的长度，达到下界。

**与 Dijkstra 的关系**：令 h ≡ 0 则 f = g，退化为一致代价搜索。Dijkstra 是 A* 的特例，A* 是注入启发式信息的 Dijkstra——`baseline.py` 一行 lambda 即证。

## 手写实现要点

对应 `impl.py`，纯 Python（`heapq` + `itertools`），无需 numpy——网格寻路的瓶颈在堆操作次数，不在数值计算：

- **open 集 = 最小堆，堆项 `(f, tie, node)` 三元组**：`heapq` 按 f 排序，第二键 `tie` 做平局破解。两种策略由 `tie_break` 参数选择：`"insertion"` 用 `itertools.count()` 按入堆先后弹出（顺带避免节点不可比时的 `TypeError`）；`"large_g"` 取 `-g`，同 f 时优先扩展更靠近终点的节点。**平局破解不是工程细节而是效率的一阶因素**——实验二显示同一算法仅换平局策略，无障碍地图上扩展数从 361 掉到 37（理论下界）。
- **加权接口 `weight`**：入堆键取 `g + w·h` 即加权 A*。`w=1` 退化为标准 A*（测试逐点验证两种调用结果一致）；`w>1` 只保证 w-次优，最优性断言不适用——实验三量化这条对换曲线。
- **closed 延迟删除 + 过期堆项跳过**：节点只在**出堆时**判 closed；同一节点可能以更差的 g 多次入堆，旧副本弹出时已在 closed 中，直接 `continue`。这省掉了"堆内查找并删除"的 O(n) 操作，是手写堆版 A* 的标准技巧。
- **g_score 松弛更新**：仅当 `g2 < g_score.get(nb, inf)` 时才更新父指针 `came_from` 并把新副本压入堆——这正是"数学推导"段 f(n) 单调性论证的代码落点。
- **安全性依赖一致性条件**：本实现不做节点重开（closed 中的邻居直接跳过），因此要求 h **一致**才能用"首次弹出即最优"。失效面比"不可采纳"更宽：**可采纳但不一致**的 h 同样可能把某节点以更差的 g 过早封进 closed，悄悄给出次优解——代码不会报错。曼哈顿距离在四方向网格上一致，故安全。
- **输入校验与无解判定**：起终点越界或落在障碍上抛 `ValueError`；堆空而未达终点即无解，`path=None`、`path_cost=inf`；demo 的 `make_grid` 用拒绝采样 + BFS 洪泛保证连通，故演示路径必有解。

## 基线对照

搜索算法没有 sklearn / PyTorch 式的同名框架接口可调（networkx 的 `astar_path` 属现成图算法，手写纪律禁用），对照对象取**基线算法 Dijkstra**。

- **对照的写法本身就是论点**：`baseline.py` 不重新实现 Dijkstra，而是一行 `solve(grid, start, goal, heuristic=lambda a, b: 0)` 复用手写 A*——"Dijkstra = h≡0 的 A* 特例"从数学推导段的论断直接落成代码，两版共享同一套堆逻辑与 `SearchResult`，排除实现差异干扰。
- **量化什么**：启发式 h 的收益。两版路径代价必须一致（demo 用断言锁死最优性），差异只体现在**扩展节点数**——h 每提供一个正确方向信息，就少扩展一批背离终点的节点。
- **差异原因**：Dijkstra 的 f=g 不含任何终点信息，扩展集合主体是 {n : g(n) ≤ C\*}（代价同心圆式全向膨胀）；A* 扩展 {n : f(n) ≤ C\*}，两者差集的主体恰是"代价可达但方向背离终点"的节点。收益因此分两层：**启发式削减必扩展集**（f > C\* 的节点 A\* 不碰、Dijkstra 会碰），**平局破解削减 f = C\* 边界集上的浪费**（边界两边各有多少落入平局，由 tie_break 决定）。主对照的 10.5% 只是第一层在这张小地图上的兑现；实验二显示无障碍地图上第一层收益为零（所有节点 f ≡ C\*，没有可削减的）、第二层收益却是 361 vs 37 的十倍量级——h 的潜力有多大，取决于地图让 f 值分出多少层。另外 h 不是免费的：每次入堆多算一次曼哈顿距离，小地图上两者耗时接近，收益主要体现在扩展节点数而非墙钟时间。

## 实验结果

**地图参数**：21×21 网格，30% 障碍率，四方向移动，固定种子 `seed=42` 保证起点 (1,1) 与终点 (19,19) 连通。

### 实验一：A* vs Dijkstra 主对照

| 指标 | A* | Dijkstra | 结论 |
|---|---|---|---|
| 路径节点数 `len(path)` | 47 | 47 | 完全一致 |
| 路径代价 `path_cost` | 46 | 46 | **最优性断言通过**（= 节点数 − 1，单步代价恒为 1） |
| 扩展节点 | 214 | 239 | A* 少扩展 25 个（10.5%） |
| 耗时 | 0.58 ms | 0.54 ms | 单次运行值，随环境与机器波动 `[随环境/版本变化]` |

注意口径：demo 断言锁的是**代价** 46（`g_score[goal]`），表格第一行的 47 是**节点数**——最优路径 (1,1)→(19,19) 走 46 步、经 47 格。

### 实验二：平局破解策略 × 障碍率

同一代价下，仅切换 `tie_break` 参数（insertion = 按入堆序，large_g = 同 f 优先扩展 g 大者）：

| 地图 | insertion | large_g | 最优代价 |
|---|---|---|---|
| 无障碍（19×19 内部全自由） | 361 | **37** | 36 |
| 30% 障碍（seed=42） | 214 | 199 | 46 |

无障碍时曼哈顿 h 处处是紧的，所有自由节点 f ≡ C\*——必扩展集为空（不存在 f < C\* 的节点），扩展多少全由平局策略兑现：insertion 退化为全图扩展，large_g 直冲终点达到理论下界（37 = 路径节点数）。障碍使 g 绕路、f 值分层后，平局的影响减弱（214→199 只省 15），启发式对必扩展集的削减（实验一的 25 个）才开始占主导。**结论：网格 A* 的工程实现里，平局破解与启发式设计同等重要**——这也是「数学推导」段最优效率定理的直接推论。

### 实验三：加权 A*（f = g + w·h，30% 障碍图，large_g 平局）

| w | 扩展节点 | 路径代价 | 相对最优 |
|---|---|---|---|
| 1.0 | 199 | 46 | +0.0% |
| 2.0 | 141 | 46 | +0.0% |
| 3.0 | 131 | 48 | +4.3% |
| 5.0 | 133 | 58 | +26.1% |

w ≤ 2 时仍命中最优代价（扩展数已降 29%）；w = 3 起为代价变差区——高估 h 让搜索更早冲向终点，最优性让位于速度。w>1 时扩展数与代价的关系不再是单调保证，而只是 w-次优界（cost ≤ w·C\*）。

**验证声明（已验证）**：Python 3.13.12（仓库 `.venv`，`.python-version` 锁定 3.13），本目录内执行 `../../../.venv/bin/python demo.py`（或任何 ≥3.10 的 `python3 demo.py`——`demo.py` 类型标注用了 `list | None` 语法，≤3.9 会在导入时报 `TypeError: unsupported operand type(s) for |`）；输入为 21×21 网格、30% 障碍率、`seed=42`（拒绝采样 + BFS 洪泛保证起点 (1,1) 与终点 (19,19) 连通）→ 观察到输出：实验一两算法 `path_cost` 均为 46（断言通过）、`nodes_expanded` 214 vs 239；实验二两地图 × 两平局策略断言全部最优，输出上表四个扩展数；实验三 w=1.0/2.0/3.0/5.0 对应代价 46/46/48/58。另有 `.venv/bin/python -m pytest algorithms/01-search/a-star/ -v`：15 例全过（10 个 seed 的最优性参数化、无障碍下界、无解判定、输入校验、w=1 一致性、加权有解性，0.07s）（2026-09-14 复跑确认）。

**可视化结论**：ASCII 渲染中 Dijkstra 的 closed 集向四周铺开，A* 的 closed 集朝终点方向明显拉伸——**启发式把搜索从"全向膨胀"拉成"定向收缩"**。

## 局限与延伸

- **内存瓶颈**：open 集可能指数膨胀 → IDA*（迭代加深，内存线性）
- **h 设计**：可采纳性是安全线；多个可采纳 h 取 max 仍可采纳
- **平局破解**：本实验已量化（实验二：361→37），更系统的做法是直接按 (f, −g) 字典序排序，或学习到的平局策略
- **牺牲最优换速度**：加权 A* 已内建为 `weight` 参数（实验三：w=2 省 29% 扩展仍最优，w=3 起付出代价）→ 有界次优的进一步形式：ARA\*、Focal Search
- **网格专用加速**：JPS（Jump Point Search，利用对称性剪枝）
- **Agent 语境**：A* 是"符号规划"经典代表，与 LLM Agent 的搜索规划（Tree of Thoughts、MCTS）一脉相承 → 本目录下一实验：`../minimax-alphabeta/`、`../mcts/`
