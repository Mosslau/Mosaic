# 01 · 动态类型与鸭子类型

> demo: `python3 demos/01_dynamic_typing.py`

## 1. 设计动机

C/C++/Java 的类型检查在编译期：变量类型写死，传错类型编译失败。
Python 的命题：**类型是值运行时才有的属性，变量只是名字——"如果它走路像鸭子、
叫起来像鸭子，那它就是鸭子"**。开发者体验优先：不用写类型、代码更短、
迭代更快。

## 2. 机制拆解

```python
def double(x):
    return x * 2

double(21)        # → 42（int）
double(2.5)       # → 5.0（float）
double("ab")      # → "abab"（字符串！乘法被重载为重复）
double([1, 2])    # → [1, 2, 1, 2]（列表！）
```

同一个函数，四种类型，四种行为——**类型检查发生在运行时**（`x * 2` 能不能算，
取决于 `x` 自己有没有实现 `__mul__`）。这就是"鸭子类型"：不检查类型，
只检查"你支持我要的操作吗"。

**代价**：传错类型不会在编译期报错，运行时才炸；性能上每次操作都要动态分发。

## 3. 代码验证（demos/01_dynamic_typing.py）

demo 演示：同一函数处理多种类型、鸭子类型（任何有 `quack` 方法的对象都能传）、
以及类型错误的运行时爆炸。

## 4. 代价与取舍

| 代价 | 说明 |
|------|------|
| 运行时才报类型错 | 大型项目里 50% 的 bug 是低级类型错误 |
| 性能差 | 每次操作动态查找方法（比静态分发慢一个数量级） |
| 可读性下降 | 没有类型签名，"这个参数是什么"要靠文档/约定 |
| 工具链补偿 | 需要 mypy/pyright 等第三方工具补类型检查 |

**换来的**：上手极快、代码最短、灵活（monkey patch、鸭子类型）、REPL 交互极佳。

## 5. 对 Tenet 的启示

- ✅ **吸收"REPL/交互式体验"**：Python 的 REPL 是它最好的老师——
  Tenet 的 `repl` 子命令（三端都有）就是继承这一点
- ✅ **吸收"鸭子类型的精神但加静态约束"**：Tenet 的 `print` 接受任意类型的值
  （int/float/bool/string），这正是"鸭子类型"的最小形式；
  但 Tenet 是**静态类型**——类型写在标注里，错误在解释阶段尽早暴露
- ❌ **拒绝完全动态类型**：Tenet 选了 C/Go 路线（静态标注），
  但用"解释执行"继承了 Python 的快速迭代体验——**静态类型 + 解释执行**，
  这是 Python 与 C 的折中
- 💡 若未来加类型推断（`let x = 42`），正是在吸收 Go 的 `:=`

**一句话**：Python 把类型检查推迟到运行时换开发速度；Tenet 用「静态标注 +
解释执行」同时拿到类型安全和快速迭代。
